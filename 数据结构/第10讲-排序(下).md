# 第 10 讲 排序（下）：快速排序、表排序与桶/基数排序

> 本讲依据视频 114–123（10.1 快速排序、10.2 表排序与物理排序、10.3 桶排序与基数排序、10.4 排序算法比较）整理。
> 学习目标：掌握快速排序的选主元、子集划分与 cutoff 优化；理解表排序与物理排序的环分解；理解桶排序、基数排序（LSD/MSD）打破 O(N log N) 下界的原理；能横向比较各排序算法。

## 一、快速排序

### 1. 算法概述

快速排序是实际应用中"最快"的内排序算法，采用分而治之：先挑一个主元 pivot，把序列划成"小于等于 pivot"与"大于等于 pivot"两部分，再递归排序左右两块。主元在划分完成后被**一次性放到它最终的正确位置**，之后再也不移动——这是它比插入排序快的关键（插入排序里一张牌可能被移动很多次）。

- 最好情况：每次主元恰好等分序列，T(N) = 2T(N/2) + O(N) = O(N log N)；
- 最坏情况：主元每次都是最小（或最大）元素，划分成空 + N−1，退化为 O(N²)。

快排的特点是细节多、易写错：主元选不好、划分太慢，都会让它"不快"。

### 2. 选主元

最蠢的做法是直接取 A[0]：若输入本就有序，每次都把主元划到最左端，递归 N−1、N−2……叠加成 O(N²)。

常用 **Median-of-Three**：取左、中、右三个位置元素的中位数作主元。三步交换后保证 A[left] ≤ A[center] ≤ A[right]，再把中位数藏到 A[right−1]，于是真正只需划分 left+1 到 right−2 这一段。它比每次调随机函数便宜得多。

### 3. 子集划分

用两个"指针" i（从左向右）、j（从右向左）：

- i 右移直到遇到 ≥ pivot 的元素（报警）；
- j 左移直到遇到 ≤ pivot 的元素；
- 若 i < j，交换 A[i]、A[j]，继续；
- 当 i 越过 j（i−j < 0）划分结束，把 pivot（藏在 right−1）与 A[i] 交换，主元落位。

**元素等于主元怎么办**：若遇到相等就跳过指针，全相等数据会把主元划到端点，退化成 O(N²)；宁可相等也停下做交换——虽然交换看似无用，但能让主元大致居中，保证 O(N log N)。

**小规模 cutoff**：递归有进栈出栈开销，当子段长度小于阈值 cutoff（如几十）时停止递归，直接调用插入排序。这是工程上的重要优化。

### 4. 算法实现

Quicksort(A, left, right)：先 Median3 选主元并藏到 right−1；i 从 left、j 从 right−1 起双向扫描交换；划分完把主元换到 A[i]；递归 Quicksort(left, i−1) 与 Quicksort(i+1, right)；子段太小时改调 Insertion_Sort。外层再套一个符合统一接口的 Quick_Sort(A, N)，内部调用 Quicksort(A, 0, N−1)。

快排平均 O(N log N) 且常数小，实战最快；但最坏 O(N²)、递归需 O(log N) 栈空间、且**不稳定**。

## 二、表排序与物理排序

### 1. 表排序（间接排序）

当每个待排元素是庞大结构体（一整本书、一部电影）时，移动元素本身代价极高。表排序**不动原始数据**，只移动一个指针数组 table：初始 table[i] = i（第 i 个位置放 A[i]）；对 table 做排序，比较的是 A[table[i]] 的关键字，交换的只是 table 里的下标。

若只需按序输出，直接按 table[0], table[1], … 的顺序输出 A[table[i]] 即可，一本书都不用搬。

### 2. 物理排序

若最后必须把元素物理上排好序，利用"**N 个元素的排列一定由若干个独立环组成**"这一事实可在线性时间内完成：

- 从 table[0] 出发沿 table 走，回到起点即构成一个环；
- 对每个环：把环首元素暂存临时位，沿环依次把应到位的元素搬过去；每放好一本就把 table[i] 置为 i（标记已到位），用于判断环是否走完；
- 环长为 1（table[i] == i）的元素本来就在位，不用动。

移动次数最坏约 3N/2（每个环 2 个元素），整体 O(mN)，m 为单个元素复制代价。元素越大，表排序越划算。

## 三、桶排序与基数排序

基于比较的排序有 O(N log N) 的下界；若利用"关键字本身"的信息，可突破到近乎线性。

### 1. 桶排序

当关键字取值范围很小（如成绩 0–100）时，为每个取值建一个桶（链表）：读入一个元素就插到对应桶表头；最后按桶号从小到大依次输出。时间 O(N + M)，M 为桶数。当 M ≪ N 时接近线性；但若 M 远大于 N（如 10 个数却取值 0–999），就不合算了。

### 2. 基数排序

把关键字按"位"拆开，逐位做桶排序。基数即进制的基数（十进制为 10，建 10 个桶）。

**LSD（次位优先）**：先按最次位（个位）分桶收集，再按十位，最后按百位。三趟后整体有序。复杂度 O(P(N + B))，P 为位数（P ≈ log_B M），B 为桶数。当 B、P 合适时近乎线性。

### 3. 多关键字排序

一副扑克牌有"花色"（主关键字）与"面值"（次关键字）。MSD（主位优先）先按花色分四桶、桶内再各自排序，不聪明；LSD 先按面值建 13 桶分好、再按花色建 4 桶分——由于前一趟已保证面值有序，同花色内自然按面值有序，**第二趟无需再排序**，一次收集即完成。

基数排序实现正确时是**稳定的**，额外空间需 O(N + B)。

## 四、排序算法的比较

| 算法 | 平均 | 最坏 | 额外空间 | 稳定性 |
|---|---|---|---|---|
| 冒泡/插入 | O(N²) | O(N²) | O(1) | 稳定 |
| 简单选择 | O(N²) | O(N²) | O(1) | 不稳定 |
| 希尔 | O(N^d), d<2 | O(N²) | O(1) | 不稳定 |
| 堆排序 | O(N log N) | O(N log N) | O(1) | 不稳定 |
| 归并 | O(N log N) | O(N log N) | O(N) | 稳定 |
| 快排 | O(N log N) | O(N²) | O(log N) | 不稳定 |
| 基数 | 近线性 | 近线性 | O(N+B) | 稳定 |

简单排序好写、省空间；堆、归并理论上恒为 O(N log N)，归并稳但费空间，堆稳但常数大；快排常数小、实战最快但最坏可构造退化、且递归占栈；基数在关键字位数少时近乎线性，但不通用。没有银弹，选型要看数据特征。
