## 一、数据结构定义

### 1. 从问题到数据结构

课件用"大型超市"作为贯穿全章的例子：商品按类别分区摆放，同类商品在货架上还要考虑补货与下架的效率。把这个过程抽象出来，就得到一条通用路径：

问题抽象 → 数学模型 → 问题求解与实现。

- 商品对应**数据元素**；
- 商品的编码（货架位置）对应**存储结构**；
- 商品的上架、下架、补架对应**操作定义与实现**。

**动机**：同一个"摆放商品"的问题，组织方式不同，插入和查找的效率差别巨大。随便放，插入一步到位但查找要逐个扫；按拼音排序，查找可用二分但插入要挪动大量商品；按类别分区再类内排序，则把两种成本都压下来。数据结构的任务就是为问题选一种组织方式，使目标操作足够快。

注意：效率不只与组织方式有关，还与空间使用、算法是否巧妙有关。递归打印 1 到 $N$ 在 $N$ 很大时因不断保存调用现场而耗尽栈空间，循环版却只占固定空间；直接按定义求多项式 $f(x)=\sum_{i=0}^{n}a_i x^i$ 要 $O(n^2)$ 次乘法，秦九韶法则只需 $O(n)$。

### 2. 数据结构的三要素

**概念** 数据结构是一组具有特定关系的同类数据元素的集合。它包含三个要素：数据的逻辑结构、数据的存储结构，以及操作的定义与实现。

三者层层递进：逻辑结构回答"元素之间是什么关系"（建立数学模型），存储结构回答"关系怎么落到内存里"（物理实现），操作定义与实现回答"在这个模型上能做什么、怎么做"。课件强调：ADT 规定"做什么"，存储结构决定"怎么做"——这是后面把 ADT 与实现分开讨论的依据。

### 3. 数据的逻辑结构

逻辑上，数据元素之间的关系只有四种，统称为数据的逻辑结构。

| 结构 | 元素间关系 | 例子 |
|---|---|---|
| 集合 | 无关系，次序任意 | 超市里同属一区但互不关联的商品 |
| 线性结构 | 一对一，构成有序序列 | 排队结账的顾客 |
| 树形结构 | 一对多，形成层次关系 | 商品类别—子类—单品的层级 |
| 图形结构 | 多对多，每个元素的前驱后继数不限 | 城市道路网 |

注意：逻辑结构只描述"关系"，与元素在内存里放在哪里无关。一棵树既可以用连续数组存，也可以用分散的指针存，逻辑上它仍是树。四种逻辑结构正是后续线性表、树、图各章的组织线索。

### 4. 数据的存储结构

数据的存储结构（即物理结构）是逻辑结构在计算机内的存储方式。课件列出四种：

1. **顺序存储**：把所有元素存放在一段连续的存储空间里，元素的存储位置直接反映逻辑次序（如座椅按编号连排）。
2. **链式存储**：逻辑上相邻的元素在物理上不必相邻，存储位置可以是任意的（如火车车厢用挂钩相连）。
3. **索引存储**：在存储元素的同时附加一张索引表，每项含关键字与地址；关键字唯一标识一个数据项，地址指向该元素的存储地址（如书的目录）。
4. **散列存储（哈希存储）**：把元素存入一个连续区域，每个元素的具体位置由它的关键字经散列（哈希）函数直接计算得到（如邮政编码对应地址）。

**动机**：顺序存储能按下标 $O(1)$ 随机访问，但插入删除要移动元素、容量受限；链式存储插入删除只改指针、按需分配，却失去随机访问能力。第 2、3 章正是围绕这两种基本存储展开，第 11 章再讨论散列。

### 5. 抽象数据类型

**概念** 抽象数据类型（ADT）是一个与数据元素及在数据元素之上的实现无关的数据类型。对使用者来说，无需知道元素的具体类型，只需知道元素之间的逻辑关系，也不必关心它是怎么实现的。

课件给出对照：同样是"加法操作"，整数相加得到整数，浮点数相加得到浮点数——针对两个不同类型要分别定义并实现加法。ADT 的做法是把这些类型抽象掉，统一描述为"数据元素 + 数据关系 + 基本操作"：

```
ADT 抽象数据类型名 {
    数据元素：<数据元素的定义>
    数据关系：<数据关系的定义>
    基本操作：<基本操作的定义>
}
```

注意：ADT 与具体机器、存储结构、算法、编程语言都无关。这样当元素类型从 `int` 改成 `double`，或底层从数组改成链表时，使用方代码无需改动，避免了逐个替换带来的错误风险。线性表、栈、队列在后续章节都先给出 ADT，再讨论其顺序与链式实现。

## 二、算法分析

### 1. 算法的基本概念

课件从四个角度评价算法：

- **正确性**：能够按照预定功能产生正确的输出。
- **易读性**：逻辑清楚、结构清晰，算法易于阅读、理解、维护。
- **健壮性**：对边界条件输入、不频繁出现的输入能产生正确输出；对非法输入能输出相应提示，不会发生崩溃。
- **高效率**：在时间和空间上高效，需要较少的运行时间和存储空间。

课件用欧几里得算法求最大公约数作为算法描述的范例：

```cpp
// 求两个非负整数的最大公约数 gcd(x, y)
int gcd(int x, int y) {
    if (x < y) std::swap(x, y);   // 若 x < y，则交换 x 与 y
    while (x % y != 0) {          // x 不能整除 y 时执行循环
        int r = x % y;            // 计算 x 除以 y 的余数 r
        x = y;                    // 用 y 重新赋值 x
        y = r;                    // 用 r 重新赋值 y
    }
    return y;                     // x 整除 y 时，y 即为最大公约数
}
```

思路：每轮把 $(x,y)$ 替换为 $(y,\,x\bmod y)$，两数单调变小而最大公约数不变，因此循环必定终止，结束时 $y$ 就是答案。这同时体现了正确性与高效率。

### 2. 时间复杂度的度量

通常把算法执行的时间写成数据规模 $n$ 的函数 $T(n)$。影响一段程序实际运行时间的因素有四类：

1. **算法策略**：同样是排序，不同策略的量级不同。
2. **问题的规模**：$n$ 越大，基本操作次数越多。
3. **编译代码的质量**：编译优化程度影响常数因子。
4. **机器性能**：硬件快慢只改变常数，不改变量级。

复杂度分析刻意忽略后两类与具体环境有关的因素，只关心 $T(n)$ 随 $n$ 增长的量级，这样结论与机器、编译器无关。

### 3. 渐近记号

四种常见的渐近时间复杂度表示方法：

| 记号 | 名称 | 类型 | 数学条件 |
|---|---|---|---|
| $T(n)=O(f(n))$ | 大 O | 上界（可等于） | 存在正数 $c,n_0$，使 $n\ge n_0$ 时 $T(n)\le c f(n)$ |
| $T(n)=\Omega(f(n))$ | 大 $\Omega$ | 下界（可等于） | 存在正数 $c,n_0$，使 $n\ge n_0$ 时 $T(n)\ge c f(n)$ |
| $T(n)=\Theta(f(n))$ | 大 $\Theta$ | 紧确界（等于） | 存在正数 $c_1,c_2,n_0$，使 $n\ge n_0$ 时 $c_1 f(n)\le T(n)\le c_2 f(n)$ |
| $T(n)=o(f(n))$ | 小 o | 严格上界 | 对任意 $c>0$，存在 $n_0$，使 $n\ge n_0$ 时 $T(n)\le c f(n)$ |

等价的极限判据：

$$\lim_{n\to\infty}\frac{T(n)}{f(n)}<\infty\ (O),\quad >0\ (\Omega),\quad \in(0,\infty)\ (\Theta),\quad =0\ (o)$$

注意：大 O 表示 $T(n)$ 的数量级小于等于 $f(n)$ 的数量级；小 o 表示**严格小于**，即 $T(n)$ 的数量级严格小于 $f(n)$。写复杂度时通常取能成立的最小上界。

常见复杂度按增长从慢到快排列：

$$O(1) < O(\log n) < O(n) < O(n\log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)$$

$n$ 充分大时，$2^n$ 与 $n!$ 已不可接受；看到 $O(n^2)$ 应本能地想能否降到 $O(n\log n)$——当 $n=10^6$ 时两者相差数十万倍。

### 4. 渐近表示法的计算

两条基本定理把复杂算法拆成片段分别分析。

**规则：求和定理** 若 $T_1(n)=O(f(n))$、$T_2(n)=O(g(n))$，则顺序组合两段程序得

$$T_1(n)+T_2(n)=O(\max(f(n),g(n)))$$

顺序语句、if-else 分支取各段中量级最大者。

**规则：求积定理** 若 $T_1(n)=O(f(n))$、$T_2(n)=O(g(n))$，则嵌套组合得

$$T_1(n)\cdot T_2(n)=O(f(n)\cdot g(n))$$

适用于嵌套的多层循环：外层循环次数乘以内层循环体的复杂度。

注意：$k$ 次多项式只保留最高次项；for 循环的复杂度等于循环次数乘以循环体复杂度。两条定理配合即可分析绝大多数顺序与嵌套结构。

### 5. 最好、最坏与平均情况

同一算法在不同输入上耗时可能相差很大。课件用数组查找举例：在数组 $[6,4,8,1,3]$ 中查找。

- 查找不在数组中的值（如 $x=2$）：逐一比较到末尾仍未找到，比较次数最多，这是**最坏情况**。
- 查找第一个元素（如 $x=6$）：一次即命中，比较次数最少，这是**最好情况**。
- 若各元素被查找的概率相同，平均比较次数的量级仍是 $O(n)$。

通常分析最坏情况 $T_{\text{worst}}(n)$：它给出任何输入下耗时的上界；平均情况依赖输入分布、难以精确定义，故一般不作首要指标。

### 6. 空间复杂度

算法执行时的空间消耗包括三部分：程序代码本身占用的空间、存储数据占用的空间、中间过程使用的辅助空间。空间复杂度 $S(n)$ 度量的是**辅助空间**与数据规模 $n$ 之间的关系，表示方法同时间复杂度。

注意：算法运行的瓶颈常来自内存与外存的巨大差异——每段代码执行前要把代码和数据装入内存，若所需空间超过现有内存，就会出现内存溢出、宕机。因此链栈、递归等"每个元素或每层调用都要额外空间"的实现，必须把这部分空间计入 $S(n)$。

## 三、算法优化

### 1. 连续子序列最大和问题

问题：给定整数序列 $s$，元素存于一维数组 `s.array`，长度为 `s.n`，在数组中找出一个连续子序列，使该子序列各元素之和最大；若所有元素都是负数，返回 0。

本节用同一问题的四种解法，演示如何一步步把 $O(n^3)$ 优化到 $O(n)$。

### 2. O(n³) 朴素算法

**思路**：枚举所有子序列，再找出和最大的。三层循环：第一层定起点 $i$，第二层定终点 $j$，第三层累加 $k$ 从 $i$ 到 $j$ 的和。

用求积定理计算循环次数：

$$\sum_{i=1}^{n}\sum_{j=i}^{n}\sum_{k=i}^{j}1 = \frac{n(n+1)(n+2)}{6} = O(n^3)$$

```cpp
struct Seq {
    std::vector<int> array;
    int n;
};

// 算法 1-7：O(n^3) 朴素算法
int maxSubseqSum1(const Seq& s) {
    int maxSum = 0;
    for (int i = 0; i < s.n; ++i) {
        for (int j = i; j < s.n; ++j) {
            int thisSum = 0;
            for (int k = i; k <= j; ++k)   // 每一段都从头累加
                thisSum += s.array[k];
            if (thisSum > maxSum)
                maxSum = thisSum;
        }
    }
    return maxSum;
}
```

注意：最内层循环重复了"求 $i$ 到 $j$ 的和"这件事。固定 $i$ 时，随着 $j$ 右移，这个和只需在上一轮基础上再加一项——第三层循环完全是多余的。

### 3. 去掉最内层循环：O(n²)

**思路**：固定起点 $i$，让终点 $j$ 从 $i$ 向右移动，`thisSum` 在上一轮基础上累加 `array[j]`，无需重新从 $i$ 加起。

$$\sum_{i=1}^{n}\sum_{j=i}^{n}1 = \frac{n(n+1)}{2} = O(n^2)$$

```cpp
// 算法 1-8：O(n^2) 双重循环
int maxSubseqSum2(const Seq& s) {
    int maxSum = 0;
    for (int i = 0; i < s.n; ++i) {
        int thisSum = 0;                  // 每个起点重新计数
        for (int j = i; j < s.n; ++j) {
            thisSum += s.array[j];        // 在上一轮基础上只加一项
            if (thisSum > maxSum)
                maxSum = thisSum;
        }
    }
    return maxSum;
}
```

### 4. 在线处理：O(n)

**思路**：若当前子列和 `thisSum` 小于 0，它不可能使后续子列和变大，应直接丢弃，从下一个位置重新开始。这样只须单重循环顺序扫描一遍即可求出最大和。

```cpp
// 算法 1-9：O(n) 在线处理
int maxSubseqSum3(const Seq& s) {
    int maxSum = 0, thisSum = 0;
    for (int j = 0; j < s.n; ++j) {
        thisSum += s.array[j];
        if (thisSum > maxSum)
            maxSum = thisSum;             // 随时更新当前最大和
        else if (thisSum < 0)
            thisSum = 0;                  // 负子列丢弃，从下一项重新开始
    }
    return maxSum;
}
```

注意：一旦某个子列和为负，把它接到后面只会拖累后面的和，因此丢弃是安全的。该算法每读入一个数就更新答案，任何时刻中断都能给出当前已读部分的最优解，故称"在线处理"。$O(n)$ 已是问题下界——至少要把每个元素读一遍；其代价是正确性不直观，需用小规模样例逐步走查验证。

### 5. 空间优化：递归与循环

课件用"输出 1 到 $n$ 的所有数字"对比两种实现：

```cpp
// 算法 1-10：递归版，栈空间 O(n)
void recursivePrint(int n) {
    if (n > 0) {
        recursivePrint(n - 1);
        std::cout << n << '\n';
    }
}

// 算法 1-10：循环版，辅助空间 O(1)
void loopPrint(int n) {
    for (int i = 1; i <= n; ++i)
        std::cout << i << '\n';
}
```

注意：递归版直到 $n=0$ 才开始逐层返回并输出，每层调用都要保存当前空间状态，空间复杂度 $O(n)$；$n$ 稍大就可能因栈空间不足而报错（递归爆栈）。循环版只维护一个变量 `i`，无论调用多少次内存消耗都不变，空间复杂度 $O(1)$。这是通过改写算法结构换取空间复杂度的典型例子。

## 本章小结

> 本章从"大型超市"抽象出数据结构的三要素，区分四种逻辑结构与四种存储结构，给出 ADT 的描述方式。算法部分建立 $O/\Omega/\Theta/o$ 四种渐近记号与求和、求积两条计算规则，强调以最坏情况度量时间、以辅助空间度量空间。最后用连续子序列最大和问题完整演示 $O(n^3)\to O(n^2)\to O(n)$ 的优化路径——消除多余循环、利用递推累加、丢弃负前缀；并用递归/循环对比说明空间优化。下一章 [[第2章-线性表.md]] 将在具体结构上应用这些方法。
