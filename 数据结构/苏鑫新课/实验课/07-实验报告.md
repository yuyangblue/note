这次实验要做的是把「先来后到」的普通队列改成「谁重谁先」的优先队列：医院急诊分诊中，严重程度 1（危重）必须排在严重程度 5（轻症）前面，与到达先后无关。实现载体是**小根堆**——一棵用数组存的完全二叉树，根结点始终是优先级最高的病人。整个程序只围绕一条下标公式运转：`arr[1]` 是根，结点 `i` 的左右孩子是 `2i` 和 `2i+1`，父结点是 `i/2`。

## 一、核心数据结构与下标约定

病人记录把「病情」和「身份信息」放在同一个结构里；堆结构只多三个整数，负责维护数组和当前规模。

```c
typedef struct {
    int id;              // 病人ID
    char name[32];       // 姓名
    int severity;        // 严重程度 1=危重 5=轻症
    int arrivalTime;     // 到达时间
    char department[16]; // 科室
} Patient;

typedef struct {
    Patient *arr;   // 堆数组（下标从1开始）
    int size;       // 当前元素数
    int capacity;   // 容量
} Heap;
```

**为什么下标从 1 开始**：`arr[0]` 空着不用，换来的是下标公式最简——结点 `i` 的左孩子 `2i`、右孩子 `2i+1`、父结点 `i/2`。若从 0 开始，这套公式全部要带偏移（左孩子 `2i+1`、右孩子 `2i+2`、父结点 `(i-1)/2`），其中 `(i-1)/2` 在 `i=0` 时还涉及负数取整，边界处理更绕。空出一格的空间代价微不足道，换来的是整段代码的干净。

**堆性质**：任意结点 `i`，其 `severity <=` 左右孩子的 `severity`。由此根 `arr[1]` 就是全局最小，也就是最危重的病人——「查看下一个」才能做到 O(1)。

```
输入科室: 儿科

```

**堆的变化过程**：

| 步骤 | 操作 | 堆数组（下标 1 起） | 发生了什么 |
| :-- | :-- | :-- | :-- |
| 1 | Chen(3) 入队 | `[Chen]` | 第一个元素，直接放置 |
| 2 | Yu(1) 入队 | `[Yu, Chen]` | 放末尾下标 2，`1 < 3`，与父交换，上升到根 |
| 3 | Wang(5) 入队 | `[Yu, Chen, Wang]` | 放末尾下标 3，`5 > 1`，不动 |

对应代码：

```c
void heapifyUp(Heap *h, int idx) {
    while (idx > 1) {                      // 直到根节点
        int parent = idx / 2;              // 父节点下标
        if (h->arr[idx].severity < h->arr[parent].severity) {
            swap(&h->arr[idx], &h->arr[parent]);
            idx = parent;                  // 继续检查父节点
        } else {
            break;                          // 堆性质满足，停止
        }
    }
}
```

**注意**：向上调整只需沿父链走一条路。原因是插入前整棵树已经是合法的堆，新元素放到末尾后，唯一可能被破坏的只有「新元素 ↔ 它的祖先」这条链，兄弟子树完全不受影响。所以最多走树高 `O(log n)` 步就停，不必扫全堆。第 2 步里 Yu 与 Chen 交换后到达下标 1，循环因 `idx > 1` 不成立而结束，正是这个道理。

入队函数本身还负责输入合法性：`static int nextId` 自增生成 ID；`fgets` 读姓名后用 `strcspn` 去掉行尾换行；严重程度用 `scanf` 读入后 `getchar()` 吃掉残留换行，越界值一律按 5（轻症）处理。

```c
Patient peek(Heap *h) {
    return h->arr[1];  // 直接返回根节点
}
```

**这里有一个值得留意的细节**：列表顺序是 `Yu(1), Chen(3), Wang(5)`，它保证了「最危重的在最前」，但**同级病人之间的先后并不保证**。因为 `heapifyUp` 里的比较是严格的 `<`，severity 相等时不交换，先来的留在下面；而 `heapifyDown` 同样只在严格更小时才交换。这算「部分有序」，不是全序。若急诊要求「同级别先到先看」，就需要额外的序号做 tie-break——扩展任务二会处理这一点。

### 4. 出队：根拿走，末尾补根，沿孩子链向下调整

选 2 连续接诊两次：

```
请选择: 2
接诊病人: ID=2, 姓名=Yu, 严重程度=1, 科室=外科

请选择: 2
接诊病人: ID=1, 姓名=Chen, 严重程度=3, 科室=内科
```

出队顺序 `Yu(1) → Chen(3)` 与预期完全一致。核心代码：

```c
Patient dequeue(Heap *h) {
    Patient top = h->arr[1];        // 保存根节点（优先级最高）
    h->arr[1] = h->arr[h->size];    // 末尾移入根
    h->size--;
    heapifyDown(h, 1);              // 向下调整
    return top;
}

void heapifyDown(Heap *h, int idx) {
    int n = h->size;
    while (1) {
        int smallest = idx;
        int left = 2 * idx;
        int right = 2 * idx + 1;
        if (left <= n && h->arr[left].severity < h->arr[smallest].severity)
            smallest = left;
        if (right <= n && h->arr[right].severity < h->arr[smallest].severity)
            smallest = right;
        if (smallest != idx) {
            swap(&h->arr[idx], &h->arr[smallest]);
            idx = smallest;
        } else {
            break;
        }
    }
}
```

**为什么是「末尾移根」而不是「第二个元素上移」**：出队必须维持完全二叉树的形状，而完全二叉树删除结点的合法位置只有最后一个。把末尾元素搬到根，等于只动一个位置就填上了空缺；若把下标 2 的元素上移，下标 2 又空了，还得继续搬，等于整棵树重排。搬完后新根很可能违反堆性质，再向下调整即可——这里只需修「根 ↔ 子孙」这一条路径，仍是 `O(log n)`。

第一次出队时，末尾 Wang(5) 移到根，它的左孩子 Chen(3) 更小，二者交换，堆变成 `[Chen, Wang]`；第二次出队后只剩 `[Wang]`。这与截图 3 之后科室统计里「儿科 1 人」（Wang 是儿科）对得上。

接诊完 Yu 和 Chen，队列里只剩 Wang。选 4、选 5：

![](03-统计与退出.jpg)

```
请选择: 4
等待病人总数: 1
平均等待时间: 2.0（时间单位）

请选择: 5
各科室等待病人统计:

```

**思考：这两个统计各自暴露了一个设计问题。**

其一是**科室统计**：实现是对堆数组做一遍线性扫描，按科室名累加计数，复杂度 O(n)。这个代价可以接受，因为统计是低频操作，而且堆的有序性帮不上忙——堆只保证根最小，同一科室的病人散落在数组各处，没有局部性可利用。

其二是**平均等待时间**：指导代码里 `arrivalTime = (int)time(NULL)` 存的是 Unix 时间戳。若直接对时间戳取平均，得到的是一个「平均到达时刻」，而不是「等待了多久」——两者语义完全不同。截图里显示的是个位数 `2.0`，与时间戳的量级不符，说明实际运行时对到达时间做了归一化（改用入队序号或从 0 起的相对时刻）。这也提示了正确的算法应该是：

```
等待时长 = 当前时刻 - arrivalTime
平均等待时间 = 所有等待病人等待时长之和 / 人数
```

对单人队列，两种写法恰好数值相同，所以这个 bug 在本次小规模测试里被掩盖了；等队列里有多个到达时刻不同的病人，取平均时间戳就会给出毫无物理意义的结果。

## 三、复杂度小结

| 操作 | 实现方式 | 时间复杂度 |
| :-- | :-- | :-- |
| 插入 | 放末尾，向上调整 | O(log n) |
| 出队 | 末尾移根，向下调整 | O(log n) |
| 查看下一个 | 直接返回 `arr[1]` | O(1) |
| 查看列表 / 科室统计 | 全堆线性扫描 | O(n) |

与「用有序数组 + 每次插入后排序」相比，堆的优势在于两端都只需对数时间：有序数组虽然 peek 也是 O(1)，但插入要挪动元素，是 O(n)。急诊场景下入队和出队同样频繁，堆更合适。

### 扩展一：以树形缩进显示堆的完整结构

堆虽然是数组，但逻辑上是一棵树。控制台没有坐标，用「深度 × 缩进」表达层次；遍历顺序取**右子树先打**，这样右孩子显示在上方、左孩子在下方，横过来看就是一棵正立的二叉树。

```c
void printHeapTree(const Heap *h, int idx, int depth) {
    if (idx > h->size) return;                    // 下标越界即空子树
    printHeapTree(h, 2 * idx + 1, depth + 1);     // 右子树先打，显示在上方
    for (int i = 0; i < depth; ++i) printf("    ");
    printf("[id=%d] %s (severity=%d)\n",
           h->arr[idx].id, h->arr[idx].name, h->arr[idx].severity);
    printHeapTree(h, 2 * idx, depth + 1);         // 左子树后打，显示在下方
}
```

调用 `printHeapTree(h, 1, 0)`。三位病人入队后的输出：

```
    [id=3] Wang (severity=5)
[id=2] Yu (severity=1)
    [id=1] Chen (severity=3)
```

根 Yu 顶格；数组下标 1=Yu、2=Chen、3=Wang，所以 Yu 的左孩子是 Chen（下标 2）、右孩子是 Wang（下标 3）。代码先递归右子，右子 Wang 印在上方、左子 Chen 印在下方，两者各缩进一级。注意打印的上下位置与「左右孩子」并不对应——先递归左子会得到上下颠倒的图。这张缩进图与堆数组 `[Yu, Chen, Wang]` 完全对应。接诊掉 Yu 后，末尾 Wang 移到根，向下调整时 Chen(3) 比 Wang(5) 小，二者交换，根变成 Chen，树形随之变成：

```
[id=1] Chen (severity=3)
    [id=3] Wang (severity=5)
```

这张缩进图比列表更直观：列表只能看出「谁是根」，缩进图能同时看出每一层的父子关系，是验证 `heapifyUp` / `heapifyDown` 有没有把孩子挂错的最快办法。

### 扩展二：支持自定义优先级规则

原实现把「severity 最小」硬编码在两处 `<` 比较里。要支持多种规则，先把比较抽象成**优先级分值**（分值越小越优先），再把规则种类存进 `Heap`，两个调整函数统一调用比较器。

```c
typedef enum {
    RULE_SEVERITY = 0,   // 默认：严重程度小者优先
    RULE_AGE_FIRST,      // 年龄大者优先
    RULE_WAIT_WEIGHTED   // 严重程度 + 等待时长加权
} PriorityRule;

typedef struct {
    int id;
    char name[32];
    int severity;
    int age;             // 新增：年龄
    time_t arrivalTime;
    char department[16];
} Patient;

typedef struct {
    Patient *arr;
    int size;
    int capacity;
    PriorityRule rule;   // 新增：当前优先级规则
} Heap;

/* 分值越小越优先 */
static int priorityScore(const Patient *p, PriorityRule rule, time_t now) {
    long waitedMin = (now - p->arrivalTime) / 60;
    switch (rule) {
        case RULE_AGE_FIRST:
            return -p->age;                                  // 年龄越大，分值越小
        case RULE_WAIT_WEIGHTED:
            return p->severity * 10 - (int)waitedMin;        // 每多等 1 分钟，抵掉 0.1 级严重程度
        case RULE_SEVERITY:
        default:
            return p->severity;
    }
}

/* 分值小者优先；同分按 id 排，保证先到先看 */
static int higherPriority(const Patient *a, const Patient *b,
                          PriorityRule rule, time_t now) {
    int sa = priorityScore(a, rule, now);
    int sb = priorityScore(b, rule, now);
    if (sa != sb) return sa < sb;
    return a->id < b->id;
}
```

调整函数里把裸的 `severity` 比较换成比较器（向下调整的写法同理）：

```c
static void siftUp(Heap *h, int idx) {
    time_t now = time(NULL);
    while (idx > 1) {
        int parent = idx / 2;
        if (!higherPriority(&h->arr[idx], &h->arr[parent], h->rule, now)) break;
        swap(&h->arr[idx], &h->arr[parent]);
        idx = parent;
    }
}
```

**规则切换的时机要注意**：`heapifyUp` / `heapifyDown` 只在插入、删除时被调用。如果运行中把规则从「按严重程度」切成「按年龄」，堆里已有元素的相对次序并不会自动重排，此时 peek 拿到的根还是旧规则下的结果。解决办法是切换规则后**重建堆**——从最后一个非叶结点 `size/2` 开始，自底向上对每个结点做一次向下调整，整体 O(n)：

```c
void rebuildHeap(Heap *h) {
    for (int i = h->size / 2; i >= 1; --i)
        siftDown(h, i);
}
```

另外，比较器里加的 `id` tie-break 顺手补上了第二节提到的稳定性缺陷：同分时 ID 小的（先到的）优先，于是「同级先到先看」有了保证。

### 扩展三：堆满时自动扩容

原 `enqueuePatient` 在 `size >= capacity` 时打印「排队已满」就直接返回，容量写死。改成满了先扩容再插入：

```c
static int ensureCapacity(Heap *h) {
    if (h->size < h->capacity - 1) return 1;      // arr[0] 不用，需留一格余量
    int newCap = h->capacity ? h->capacity * 2 : 8;
    Patient *p = (Patient *)realloc(h->arr, (size_t)newCap * sizeof(Patient));
    if (!p) return 0;                              // 失败时原数组仍然有效
    h->arr = p;
    h->capacity = newCap;
    return 1;
}

int enqueue(Heap *h, Patient p) {
    if (!ensureCapacity(h)) return 0;              // 扩容失败才真正拒绝
    h->arr[++h->size] = p;                         // 放到末尾
    siftUp(h, h->size);
    return 1;
}
```

**两个要点**：一是容量按 2 倍增长，这样连续 `n` 次插入的总搬移量是 `8 + 16 + 32 + … + n < 2n`，摊还到每次插入仍是 O(1)；若每次只加 1，总搬移量会变成 O(n²)。二是 `realloc` 必须用临时指针接收返回值——直接赋给 `h->arr` 的话，一旦扩容失败返回 `NULL`，原数组地址就丢了，整个堆无法访问也无法释放。

## 五、总结与思考

1. **优先队列的「优先」不是排序，而是一种局部约束。** 堆只保证「父结点不比孩子差」，所以根一定最优、但第二优在哪并不知道。正是这个弱化换来了插入/出队都是 O(log n)。理解这一点，就不会再期待遍历堆数组能得到一个排好序的序列——那是堆排序要做的事（反复出队），不是堆本身的属性。

2. **向上调整和向下调整看着对称，其实各自只处理一半问题。** 插入破坏的是「新元素 ↔ 祖先」，删除破坏的是「新根 ↔ 子孙」，所以 heapifyUp 只往父链走、heapifyDown 只往孩子链走。把两个方向记成两个函数，比记成一个通用函数更不容易写错，因为每边的终止条件都很明确：到根，或到叶子。

3. **「末尾移根」这一个动作同时维护了形状和规模。** 完全二叉树删结点只能删最后一个，否则形状就断了；把这一个结点搬到根，形状立刻合法，只需再修根那一条路径。这个技巧在别的地方也反复出现——删除堆顶、堆排序的交换，本质都是它。

4. **严格 `<` 带来的是「部分有序」，同级顺序是隐含的不确定性。** 本次三个病人严重程度互不相同，看不出问题；一旦出现同分，「先到先看」是否成立完全取决于调整路径的偶然性。扩展二用 `id` 做 tie-break 把它变成显式规则——这类「不崩溃但结果不唯一」的问题，比段错误更难发现，写代码时应当主动问一句「相等时怎么办」。

5. **「平均到达时刻」和「平均等待时间」只差一个减法，语义却完全不同。** 指导代码用 `time(NULL)` 存到达时间，直接取平均得到的是前者。本次只剩一人，两种算法数值巧合相等，掩盖了错误；扩展到多人多时刻就会暴露。做统计类功能时，先写下量的定义（单位、基准点），再写公式。

6. **规则切换必须伴随重建堆。** 这是把比较逻辑参数化后最容易漏掉的一步：比较器变了，但堆仍按旧比较器组织。这类「状态与不变量脱节」的 bug 不会报错，只会让 peek 悄悄给出错答案。任何改变堆序参数的操作，都要问一句「现有结构还满足新规则吗」。

7. **可继续改进的点**：把固定 32/16 的姓名与科室数组改成动态分配，避免超长输入被截断；把菜单的 `scanf` + `getchar` 混用统一成 `fgets` + `sscanf`，减少缓冲区残留引发的诡异输入；给 `dequeue` 在空堆时返回明确的失败标志（当前直接访问 `arr[1]` 会读到未定义数据）；把年龄、等待权重的系数做成可配置项，而不是写死在 `priorityScore` 里。
