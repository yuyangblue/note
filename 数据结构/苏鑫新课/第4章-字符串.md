## 一、字符串的定义与结构

### 1. 字符串的基本概念

**概念** 字符串（String）是由 $n$ 个字符组成的有限序列 $s = c_0c_1\dots c_{n-1}$（$n \ge 0$）。$n$ 是串长，$n = 0$ 时为空串（记作 $\varnothing$），字符取自某字符集。

串在逻辑上是**元素限定为字符的线性表**。真正把它与一般线性表区别开的是操作粒度：线性表的插入删除以单个元素为单位，串的插入、删除、替换、定位都以**子串**为单位，模式匹配更是把"一个串在另一个串中出现"当作基本动作。本章后半的 KMP 之所以值得单独研究，正因为"在大段文字中找一小段模式"是纯线性表没有的问题。

| 概念 | 含义 | 长度 |
|---|---|---|
| 空串 | 不含任何字符 | 0 |
| 空格串 | 全部由空格字符组成 | 空格个数 |
| 单字符串 | 只含一个字符 | 1 |

空串与空格串不同：空串里连字符都没有，空格串有一个或多个空格。判断空串看串长是否为 0。

**动机** 把字符串单独抽出来，因为它是程序设计中最常用的数据形态（文本、词法单元、基因序列），而"高效查找子串"的 KMP、BM 有独立的理论价值。

### 2. 子串、前缀与后缀

**概念** 串 $s$ 中**连续**的一段字符组成的串称为子串，由起点与长度唯一确定，记作 $s[i..j]$；删去若干字符而不改变剩余相对顺序所得的是子序列，不要求连续。子串一定是子序列，反之不然：`"abc"` 的子串有 `"ab"`，而 `"ac"` 只是子序列。

前缀贴着串首、后缀贴着串尾。长度为 $n$ 的串，其真前缀（不含串自身）为 $s[0..i]$（$0 \le i < n-1$），真后缀为 $s[i..n-1]$（$0 < i \le n-1$）。课件定义用的正是这两个范围，天然排除串自身——这是"最长公共前后缀"有意义的前提：若允许取自身，任何串的最长公共前后缀恒为自身，KMP 的推导就失去意义。

以 `"aabaa"` 为例：真前缀集合 {a, aa, aab, aaba}，真后缀集合 {a, aa, baa, abaa}，公共前后缀 {a, aa}，最长公共前后缀为 `"aa"`（长度 2）。公共前后缀指两集合中的相同子串，最长公共前后缀取其中最长者；交集为空则不存在。

### 3. 字符串的 ADT 与基本操作

```
ADT String {
    数据对象：D = { s_i | s_i ∈ CharacterSet, i = 1, 2, …, n, n > 0 } 或 ∅（空串）
    数据关系：R = { <s_{i-1}, s_i> | s_{i-1}, s_i ∈ D, i = 2, …, n, n > 0 }
    基本操作：
        InitStr(s)              初始化空串 s，最大长度 kMaxSize
        StrCopy(s)              返回复制 s 得到的新串
        StrIsEmpty(s)           判空，空返回 true
        StrInsert(s, pos, t)    在 s 的 pos 位置插入 t
        StrRemove(s, pos, len)  删除 s 中从 pos 起长度为 len 的子串
        SubString(s, pos, len)  返回 s 中从 pos 起长度为 len 的子串
        StrLength(s)            返回串长
        StrConcat(s, t)         返回 s 与 t 联接的新串
        StrCompare(s, t)        比较：s>t 返回 +1，相等 0，s<t 返回 -1
        PatternMatch(s, t)      返回 s 中首次出现 t 的位置，无则返回 NIL
        Replace(s, sub_s, t)    把 s 中所有子串 sub_s 替换为 t
}
```

注意：pos 从 **1** 开始计数，对应数组下标 pos-1，`pos = 1` 表示第 1 个字符之前。课件所有操作都遵循这一约定。

**思路** Replace 可看作 PatternMatch 的反复调用：定位、删除旧子串、插入新串，循环到找不到为止。若新旧子串长度不同，替换后主串长度改变，下一轮搜索起点要随之调整（从插入点之后继续），否则会漏匹配或重复匹配。在 ADT 的全部操作里，`PatternMatch` 是本章核心——从 BF 到 KMP、BM 的演进，都围绕"如何高效实现它"展开。

## 二、字符串的存储实现

### 1. 顺序串

**概念** 顺序串用连续存储单元依次存放字符，本质是顺序表。定长实现用数组加长度指示位：

```cpp
const int kMaxSize = 1024;
struct SeqString {
    vector<char> data;              /* 有效字符在 data[0..length-1] */
    int length = 0;
    SeqString() { data.resize(kMaxSize); }
};
```

顺序串随机访问为 $O(1)$，缺点是长度受限、插入删除要成批搬动字符。以下五个操作全部围绕"搬动下标"展开。

### 2. 顺序串的基本操作（算法 4-1 至 4-5）

```cpp
/* 算法 4-1 插入：在 s 第 pos 个字符之前插入 t */
bool StrInsert(SeqString &s, int pos, const SeqString &t) {
    int n = s.length, m = t.length;
    if (pos < 1 || pos > n + 1 || n + m > kMaxSize) return false;
    for (int i = n - 1; i >= pos - 1; --i)            /* 从后往前搬，腾出 m 个空位 */
        s.data[i + m] = s.data[i];
    for (int i = 0; i < m; ++i) s.data[pos - 1 + i] = t.data[i];
    s.length = n + m;
    return true;
}

/* 算法 4-2 删除：删去从 pos 起长度为 len 的子串，不足则删到末尾 */
bool StrRemove(SeqString &s, int pos, int len) {
    int n = s.length;
    if (pos < 1 || pos > n || len < 1) return false;
    if (pos - 1 + len >= n) s.length = pos - 1;        /* 删到末尾，直接截短 */
    else {
        for (int i = pos - 1 + len; i < n; ++i)        /* 从前往后搬，覆盖被删段 */
            s.data[i - len] = s.data[i];
        s.length = n - len;
    }
    return true;
}

/* 算法 4-3 截取：取 s 中从 pos 起长度为 len 的子串 */
bool SubString(const SeqString &s, int pos, int len, SeqString &sub) {
    if (pos < 1 || pos > s.length || len < 1) return false;
    if (pos - 1 + len > s.length) len = s.length - (pos - 1);
    for (int i = 0; i < len; ++i) sub.data[i] = s.data[pos - 1 + i];
    sub.length = len;
    return true;
}

/* 算法 4-4 连接：把 t 接到 s 末尾 */
bool StrConcat(SeqString &s, const SeqString &t) {
    if (s.length + t.length > kMaxSize) return false;
    for (int i = 0; i < t.length; ++i) s.data[s.length + i] = t.data[i];
    s.length += t.length;
    return true;
}

/* 算法 4-5 比较：s>t 返回 1，相等 0，s<t 返回 -1 */
int StrCompare(const SeqString &s, const SeqString &t) {
    int len = min(s.length, t.length), i = 0;
    while (i < len && s.data[i] == t.data[i]) ++i;
    if (i == len) {
        if (s.length == t.length) return 0;
        return s.length > t.length ? 1 : -1;          /* 前缀相同则长者为大 */
    }
    return s.data[i] > t.data[i] ? 1 : -1;            /* 首个不同字符定胜负 */
}
```

**思路** 插入是"腾空位、**从后往前**搬"，删除是"填空位、**从前往后**搬"。插入若从前往后搬，`s[pos-1]` 写到 `s[pos-1+m]` 时会冲掉尚未搬动的字符；删除时源下标 $i > i-len$，按 $i$ 递增搬运，目标总是已处理过的旧数据。搬动数分别为 $n-pos+1$ 与 $n-pos+1-len$，均为 $O(n)$。截取只复制 $O(len)$，连接复制 $O(m)$。

注意：比较不比长度、也不比字符编码之和——`"ab" < "ba"`（长度相同、字符和相同但首字符 `'a' < 'b'`），`"z" > "aa"`（首字符 `'z' > 'a'`，轮不到比长度）。连续调用连接累积长串的总代价是各次复制长度之和，最坏 $O(n^2)$。

### 3. 链式串

**概念** 链式串用链表存放字符，逻辑相邻的字符物理位置任意，本质是单链表，每个结点存一个字符：

```cpp
struct StrNode { char data; StrNode *next = nullptr; };
struct LinkString { StrNode *head = nullptr; int length = 0; };
```

与顺序串相比，链式串的所有操作都要单独处理表头与 $pos = 1$ 的边界：顺序串里"插到首位"只是下标 0 的特例，链式串里它要改动 head 指针，是独立分支。

### 4. 链式串的基本操作（算法 4-6 至 4-10）

```cpp
/* 算法 4-6 插入：在 s 第 pos 个字符之前插入 t；位置非法则 s 不变 */
bool LinkInsert(LinkString &s, int pos, const LinkString &t) {
    if (t.length == 0) return true;
    if (pos < 1 || pos > s.length + 1) return false;
    StrNode *tail = t.head;
    while (tail->next) tail = tail->next;             /* 找 t 的末结点 */
    if (s.length == 0)              s.head = t.head;  /* s 为空，直接接管 */
    else if (pos == 1) {                              /* 插在表头之前 */
        tail->next = s.head;  s.head = t.head;
    } else {                                          /* 插在第 pos-1 个结点之后 */
        StrNode *p = s.head;
        for (int k = 1; k < pos - 1; ++k) p = p->next;
        tail->next = p->next;  p->next = t.head;
    }
    s.length += t.length;
    return true;
}

/* 算法 4-7 删除：删去从 pos 起长度为 len 的子串 */
bool LinkRemove(LinkString &s, int pos, int len) {
    if (s.length == 0 || pos < 1 || pos > s.length || len < 1) return false;
    StrNode *p = s.head, *prev = nullptr;
    for (int k = 1; k < pos; ++k) { prev = p; p = p->next; }
    for (int k = 0; k < len && p; ++k) {
        StrNode *q = p->next;  delete p;  p = q;  --s.length;
    }
    if (prev) prev->next = p; else s.head = p;
    return true;
}
```

**思路** 链式插入不搬动任何已有结点，只改指针，代价是定位——找 `t` 尾走 $m$ 步、找前驱走 $pos-2$ 步，为 $O(pos+m)$。注意插入后 `t` 的结点被 `s` 借用，不应再释放或使用 `t`。链式删除代价是"定位 $O(pos)$ + 释放 $O(len)$"，串长而删除段短时优于顺序串。

**算法 4-8 截取**：走到第 pos 个结点，复制 len 个新结点；建表时用**临时头结点**统一挂接——申请哑结点当 `tail`，每复制一字符就 `tail->next = 新结点; tail = tail->next;`，最后返回 `dummy.next` 并释放哑结点，省掉"第一个结点"的边界判断。**算法 4-9 连接**：若 `s` 非空走到末结点令 `p->next = t.head`，若空则 `s.head = t.head`，不复制但要走完整条链，为 $O(n)$。**算法 4-10 比较**：双指针 `sp`、`tp` 同步前进，遇首对不同字符按 `data` 判定，一方先到尾则较短者为小，为 $O(\min(n,m))$——比较必须逐字符读，从不因存储结构而变快。课件 4-10 算法有一处笔误（`p ← tp.next` 应为 `tp ← tp.next`），按双指针理解即可。

### 5. 两种存储结构的比较与块链

| 比较项 | 顺序串 | 链式串 |
|---|---|---|
| 取第 $i$ 个字符 | $O(1)$ | $O(i)$ |
| 插入/删除 | $O(n)$ 搬动 | $O(pos)$ 定位，无搬动 |
| 存储密度 | 高 | 低（约 1/9，64 位机） |
| 长度上限 | 受 kMaxSize 限制 | 仅受内存限制 |

链式串最致命的弱点是**存储密度太低**：一个字符配一个指针，64 位机上 `char` 占 1 字节、指针 8 字节，利用率约 1/9。工程上用**块链**折中——每个结点存一个字符数组，结点间用指针串接：

```cpp
const int BlockSize = 4;
struct Block { char data[BlockSize]; int num = 0; Block *next = nullptr; };
```

块链把密度提高到约 $B/(B+8)$（$B = 4$ 时约 1/3），保留链式"插入删除不必整体搬移"的优点；代价是随机访问退化为"先跳块、再块内偏移"，插入删除要处理块的分裂与合并。文本编辑器的 rope、piece table 都是这类思路。

## 三、字符串的模式匹配

### 1. 问题的形式化

**概念** 在串 $s$ 中找出与串 $t$ 相等的子串的操作称为模式匹配（子串定位）。$s$ 是主串（目标串），$t$ 是模式串。主串用 $s[0..n-1]$、模式串用 $t[0..m-1]$（$m \le n$）表示。若存在位移 $p$（$0 \le p \le n-m$）使 $s[p..p+m-1] = t[0..m-1]$，则 $p$ 是一个**有效位移**。

三要素决定算法差异：**比较方向**、**失配后移动多少**、**移动量由什么信息决定**。BF 固定右移 1；KMP 只看模式串自身、由已匹配长度决定；BM 两者都看，取较大位移；KR 不逐字符比，改用整窗哈希。课件列出的算法有 BF、KMP、BM、KR、Sunday 等。

### 2. BF 朴素算法（算法 4-11）

**概念** 朴素模式匹配（Brute Force）：枚举每个等长起点，从模式串第 0 位逐字符比较；失配则模式串整体后移一位重来。

```cpp
/* 返回 t 在 s 中首次出现的起始下标，未找到返回 -1（课件的 NIL） */
int PatternMatchBF(const SeqString &s, const SeqString &t) {
    int n = s.length, m = t.length;
    if (m == 0) return 0;
    if (m > n)  return -1;
    for (int p = 0; p <= n - m; ++p) {                  /* 枚举有效位移 */
        int i = 0;
        while (i < m && s.data[p + i] == t.data[i]) ++i;
        if (i == m) return p;                          /* 整串比完，成功 */
    }
    return -1;
}
```

失配时无条件右移一位、丢弃已匹配的前缀，这是 BF 的缺陷。最坏 $O(nm)$：如 $s = \texttt{"aaaaaaaa"}$、$t = \texttt{"aaab"}$，5 个起点每轮都比到第 4 位才失配，共 20 次比较。注意平均情况并不悲观：字符集大小 $\sigma$、字符随机时每轮期望比较约 $\sigma/(\sigma-1)$ 次，总期望 $O(n)$——BF 的缺陷只在重复字符多或恶意输入时暴露。

### 3. 前缀、后缀与最长公共前后缀

**动机** KMP 要利用"失配前已匹配的部分"。设已匹配 $t[0..j-1]$，它既是主串的一段也是模式串的前缀。右移后要仍有字符对齐，就必须让模式串的某个**前缀**等于这段已匹配串的某个**后缀**——这正是公共前后缀的用武之地。

**概念** 真前缀、真后缀、公共前后缀、最长公共前后缀的定义见第一节。以 `"abab"` 为例：真前缀 {a, ab, aba}、真后缀 {b, ab, bab}，公共前后缀 {ab}，最长公共前后缀 `"ab"`（长度 2）。

规则：公共前后缀必须在**真**前后缀中找，排除串自身。若允许取自身，右移量为 0，算法原地打转。

### 4. 字符串特征向量（next 数组）的定义

**概念** 苏鑫课件把 next 数组称为**字符串特征向量**：长为 $m$ 的模式串 $t$ 的特征向量是 $m$ 维向量 `next`。$next[i]$ 表示特征向量第 $i$ 位分量（$0 \le i < m$），形式化定义为

$$
next[i] =
\begin{cases}
\max\{\,k \mid t[0..k] = t[i-k..i],\ k < i\,\}, & \text{若这样的 } k \text{ 存在}\\
-1, & \text{否则}
\end{cases}
$$

注意：课件这套定义中，**$next[i]$ 不是"长度"，而是 $t[0..i]$ 的最长公共前后缀中，前缀最末字符的下标**。因下标从 0 起，$t[0..i]$ 的最长公共前后缀长度等于 $next[i]+1$；若最长公共前后缀不存在，置 $next[i] = -1$（长度 0）。它与 408/王道教材的 next 定义（$t[0..i-1]$ 最长公共真前后缀的长度）相差一位，本笔记以课件为准。

课件例：`"abcac"` 的特征向量为 $[-1, -1, -1, 0, -1]$，逐位推导：

| $i$ | $t[0..i]$ | 真前缀集合 | 真后缀集合 | 最长公共前后缀 | 前缀末下标 | $next[i]$ |
|---|---|---|---|---|---|---|
| 0 | a | 空 | 空 | 无 | — | -1 |
| 1 | ab | {a} | {b} | 无 | — | -1 |
| 2 | abc | {a, ab} | {c, bc} | 无 | — | -1 |
| 3 | abca | {a, ab, abc} | {a, ca, bca} | a | 0 | 0 |
| 4 | abcac | {a, ab, abc, abca} | {c, ac, cac, bcac} | 无 | — | -1 |

$i=3$ 时子串 `"abca"` 的公共前后缀为 `"a"`，前缀末字符下标为 0，故 $next[3] = 0$（长度 $0+1=1$）。

### 5. next 数组的快速计算（算法 4-13）

**动机** 朴素计算 next 要对每个 $i$ 列举前后缀再逐字比较，达 $O(m^3)$。课件给出 $O(m)$ 递推算法。

**思路** 设已求出 $next[i-1] = j$，它是 $t[0..i-1]$ 的最长公共前后缀的前缀末下标（长度 $j+1$）。考察 $t_b$ 后的字符 $t[i]$ 与 $t_a$ 后的字符 $t[j+1]$：

1. 若 $t[i] = t[j+1]$，则两段公共前后缀各接一字符后仍相等，故 $next[i] = j+1$；
2. 若不等，说明这个长度撑不住，令 $j \leftarrow next[j]$ 退到更短的公共前后缀重试，直到相等或 $j < 0$（无处可退，置 -1）。

课件算法 4-13 伪代码及等价 C++：

```text
next[0] ← -1
for i ← 1 to m-1 do
    j ← next[i-1]
    while j ≥ 0 且 t[i] ≠ t[j+1] do j ← next[j] end
    if t[i] = t[j+1] then next[i] ← j+1 else next[i] ← -1 end
end
```

```cpp
vector<int> GetNext(const SeqString &t) {
    int m = t.length;
    vector<int> next(m, -1);                           /* next[0] = -1 */
    for (int i = 1; i < m; ++i) {
        int j = next[i - 1];
        while (j >= 0 && t.data[i] != t.data[j + 1])    /* 失配则沿 next 回退 */
            j = next[j];
        if (t.data[i] == t.data[j + 1]) next[i] = j + 1;/* 能扩展，长度加一 */
        else                            next[i] = -1;
    }
    return next;
}
```

注意 `while` 要先判 `j >= 0` 再访问 `t.data[j+1]`（`&&` 短路），避免 $j = -1$ 时越界。

**完整走查**：手算 `"abcac"` 的 next，看如何自己算出来。

- $next[0] = -1$（初始化）。
- $i=1$：$j = -1$，while 跳过；比较 $t[1] = \texttt{'b'}$ 与 $t[0] = \texttt{'a'}$，不等 → $next[1] = -1$。
- $i=2$：$j = -1$，比较 $t[2] = \texttt{'c'}$ 与 $t[0] = \texttt{'a'}$，不等 → $next[2] = -1$。
- $i=3$：$j = -1$，比较 $t[3] = \texttt{'a'}$ 与 $t[0] = \texttt{'a'}$，相等 → $next[3] = 0$。
- $i=4$：$j = next[3] = 0$，比较 $t[4] = \texttt{'c'}$ 与 $t[1] = \texttt{'b'}$，不等且 $j \ge 0$，回退 $j = next[0] = -1$；再比较 $t[4] = \texttt{'c'}$ 与 $t[0] = \texttt{'a'}$，仍不等 → $next[4] = -1$。

得 $[-1,-1,-1,0,-1]$，与课件一致。关键困惑点：**while 的 `j >= 0` 只约束"能否继续回退"；`if` 访问的是 $t[j+1]$，故 $j = -1$ 时 $j+1 = 0$ 仍是合法下标**，代表"拿第 0 位来比"。理解这点就能自己推任何串的 next。

复杂度：$j$ 每回退一次至少减 1，而整个过程 $j$ 最多增加 $m$ 次（每次成功扩展加 1），故回退总次数不超过 $m$，整段循环 $O(m)$——这是均摊分析的标准套路，$O(m)$ 是最坏情况的界。

注意：408 的 $next[i]$（$t[0..i-1]$ 最长公共真前后缀长度）与课件特征向量相差一位，换算为 408 的 $next[i] =$ 课件的 $next[i-1]+1$（$i \ge 1$）。如 `"ababc"` 课件为 $[-1,-1,0,1,-1]$、408 为 $[-1,0,0,1,2]$。

### 6. KMP 算法（算法 4-14）

**概念** KMP（Knuth–Morris–Pratt，克努特—莫里斯—普拉特）利用"失配时前 $j$ 位已匹配"的信息，把模式串一次右移多格，而**主串指针全程不回退**。

**规则** 在 next 数组基础上：在模式串第 $i$ 位失配时，把模式串右移，从第 $next[i-1]+1$ 位继续匹配，重复至串末。课件算法 4-14 与等价 C++：

```text
n ← s.length;  m ← t.length;  p ← NIL
if n ≥ m then
    GetNext(t, next);  i ← 0;  j ← 0
    while j < n 且 i < m do
        if s[j] = t[i] then i ← i+1;  j ← j+1
        else if i > 0 then i ← next[i-1]+1    // 模式串右移，主串不动
        else j ← j+1                          // 首位失配，主串前进
    end
    if i = m then p ← j-m
end
return p
```

```cpp
int PatternMatchKMP(const SeqString &s, const SeqString &t) {
    int n = s.length, m = t.length;
    if (m == 0) return 0;
    if (m > n)  return -1;
    vector<int> next = GetNext(t);                     /* 预处理 O(m) */
    int i = 0, j = 0;                                  /* i 指模式串，j 指主串 */
    while (j < n && i < m) {
        if (s.data[j] == t.data[i]) { ++i; ++j; }      /* 相等，同步前进 */
        else if (i > 0) i = next[i - 1] + 1;           /* 失配回退，j 不动 */
        else ++j;                                      /* 首位失配，主串前进 */
    }
    return (i == m) ? (j - m) : -1;
}
```

**思路** 主串指针 $j$ 只在"首字符就失配"（$i = 0$）时前进，其余失配都靠调整 $i$ 让模式串右移。主串只读一遍，比较次数与 $n$ 成正比；计算 next 为 $O(m)$、匹配 $O(n)$，总 $O(n+m)$，额外空间 $O(m)$。

以 $s = \texttt{"ababa"}$、$t = \texttt{"aba"}$ 为例（`"aba"` 的课件 next 为 $[-1,-1,0]$）：前 3 位 a,b,a 对上后，$j=3, i=3$ 而 $j$ 已到 $n$ 边界，循环结束恰有 $i = m = 3$，返回 $j-m = 0$，匹配成功。全程 $j$ 单调递增、从不回退，这正是 KMP 适合大文件流式检索的原因。

### 7. BM 算法的思想

**概念** BM（Boyer–Moore）有两点革新：**从右向左**比较模式串，失配后可一次跳过多个字符。从右往左的好处是——模式串最后一个字符对不上就立刻失配，一次比较排除一个起点；BF、KMP 从左往右比，最坏要把前缀比完才发现末位不对。

**规则** 失配后的位移由两条规则分别给出，取**较大**者：

1. **坏字符规则**：失配时主串中那个对不上的字符 $c$ 称为坏字符，设当前比对的是模式串第 $j$ 位。若 $c$ 在 $t[0..j-1]$ 中最右出现位置为 $k$，位移 $= j-k$；若 $c$ 不在其中，位移 $= j+1$（整个模式串移到坏字符右侧）。
2. **好后缀规则**：失配时已匹配的后缀是有用信息。若该后缀在模式串前面还出现过，就把下一次出现对齐过来；若没有完整出现，就找它的某个后缀，使该后缀恰是模式串的前缀。位移取可行方案中较大者。

**思路** 好后缀的意义：既然这段后缀已和主串对上，下次对齐应尽量让相同结构重新对上，而非拆散。只用坏字符规则的简化版叫 BMH，工程常用。例：$t = \texttt{"abac"}$、$s = \texttt{"ababac"}$，在 $p=0$ 处从右比，$t[3]=\texttt{'c'}$ 对 $s[3]=\texttt{'b'}$ 失配；坏字符 $\texttt{'b'}$ 在 $\texttt{"aba"}$ 中最右出现于 $k=1$，位移 $=3-1=2$，直接跳到 $p=2$ 一次命中，而 BF 要试 3 个起点。BM 预处理 $O(m+\sigma)$、最坏 $O(nm)$，实际文本上远快于 KMP，`grep`、`less` 的核心都是其变体。课件只要求掌握两条规则的思想，不要求完整代码。

### 8. KR 算法的思想

**概念** KR（Rabin–Karp）不比字符、比**数值**：把模式串看作 $d$ 进制数，用哈希 $H(t) = \big(\sum_{i=0}^{m-1} t[i]\,d^{m-1-i}\big) \bmod q$ 映射成整数，主串每个长为 $m$ 的窗口先比哈希、相等再逐字符核验（防碰撞）。

$$H(s[i+1..i+m]) = \big((H(s[i..i+m-1]) - s[i]\,d^{m-1})\,d + s[i+m]\big) \bmod q$$

窗口滑动时一次乘加即可 $O(1)$ 更新，整趟期望 $O(n+m)$，最坏（哈希大量碰撞）$O(nm)$。**思路** KR 的真正优势在多模式匹配：把 $k$ 个模式的哈希放进表，扫描时每窗查一次表，总代价 $O(n+km)$，而 KMP 要跑 $k$ 遍。课件把它概括为"哈希筛选、滚动更新、碰撞核验"三步。注意取模减法可能为负，应写成 `((h - x) % q + q) % q`。

### 9. 四种算法的对比

| 算法 | 比较方向 | 移动依据 | 预处理 | 匹配（最坏） | 特点 |
|---|---|---|---|---|---|
| BF | 左 → 右 | 固定右移 1 | 无 | $O(nm)$ | 最简单，字符集大时平均 $O(n)$ |
| KMP | 左 → 右 | 已匹配长度（特征向量） | $O(m)$ | $O(n)$ | 主串不回退，可流式处理 |
| BM | 右 → 左 | 坏字符 + 好后缀取大 | $O(m+\sigma)$ | $O(nm)$ | 实践最快，跳跃幅度大 |
| KR | 比整窗哈希 | 哈希不等整窗跳过 | $O(m)$ | $O(nm)$ | 期望线性，天然支持多模式 |

选择依据：模式串短、字符集大——BF；要最坏线性保证或流式——KMP；编辑器、命令行检索——BM；多模式或判等去重——KR。三者把"失配后如何利用已知信息"用不同方式做到极致，这是本节灵魂。

## 本章小结

> 字符串是元素限定为字符的线性表，操作以子串为单位；空串长度为 0，与空格串不同。顺序串随机访问快、插入从后往前搬/删除从前往后搬（搬动数 $n-pos+1$ 与 $n-pos+1-len$）；链式串插入删除方便但需定位、密度低，块链是折中。模式匹配中 BF 最坏 $O(nm)$；KMP 用苏鑫课件的"字符串特征向量" next——$next[i]$ 是 $t[0..i]$ 最长公共前后缀的前缀末字符下标（无则 -1，`"abcac"` 为 $[-1,-1,-1,0,-1]$）——失配回退到 $next[i-1]+1$、主串不回退，总 $O(n+m)$；BM 从右向左按坏字符与好后缀取较大位移；KR 用滚动哈希筛选、碰撞核验。下一章 [[第5章-树和二叉树.md]] 从线性的串转向非线性的树。
