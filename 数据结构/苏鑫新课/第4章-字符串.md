## 一、字符串的定义与结构

### 1. 字符串的基本概念

**概念** 字符串（String）是由 $n$ 个字符组成的有限序列，记作 $s = c_0c_1\dots c_{n-1}$（$n \ge 0$）。$n$ 称为串长；$n = 0$ 时为空串，记作 $\varnothing$ 或空双引号。串中的字符取自某个字符集（如 ASCII、Unicode）。

字符串在逻辑上就是**元素限定为字符的线性表**，线性表的"前驱、后继、表头、表尾"对它同样成立。真正把它与一般线性表区别开的，是操作粒度：线性表的插入删除以**单个元素**为单位，而字符串的插入、删除、替换、定位都以**子串**为单位，模式匹配更是直接把"一个串在另一个串中出现"当成基本动作。本章后半部分的 KMP 之所以值得单独研究，正因为"在一大段文字里找一小段模式"是纯线性表所没有的问题。

几组易混的概念：

| 概念 | 含义 | 长度 |
|---|---|---|
| 空串 | 不含任何字符 | 0 |
| 空格串 | 全部由空格字符组成 | 空格个数 |
| 单字符串 | 只含一个字符 | 1 |

空串与空格串不同：空串里连字符都没有，空格串里有一个或多个空格字符。判断空串看的是串长是否为 0。

**动机** 为什么把字符串从线性表里单独抽出来讲？因为它是程序设计里最常用的数据形态——文本、词法单元、基因序列、网络报文本质上都是字符串，而"查找某段子串"的高效算法（KMP、BM）有独立的理论价值，不属于线性表的常规操作范畴。

### 2. 子串、前缀与后缀

**概念** 串 $s$ 中**连续**的一段字符组成的串称为 $s$ 的子串，由起点与长度唯一确定，记作 $s[i..j]$（下标从 0 起，$i \le j$）。从 $s$ 中删去若干字符而不改变剩余字符相对顺序所得的串称为子序列，它不要求连续。子串一定是子序列，子序列不一定是子串：`"abc"` 的子串有 `"ab"`，而 `"ac"` 只是子序列。

**概念** 前缀是贴着串首的子串，后缀是贴着串尾的子串。长度为 $n$ 的串，其真前缀（不含串自身）为 $s[0..i]$（$0 \le i < n-1$），真后缀为 $s[i..n-1]$（$0 < i \le n-1$）。课件在定义前缀、后缀时用的正是这两个范围，天然排除了串自身——这一点是后面"最长公共前后缀"有意义的前提：若允许前缀、后缀等于自身，则任何串的前后缀集合都含自身，"最长公共前后缀"恒等于自身，KMP 的全部推导就失去意义。

三个概念的关系，以 `"aabaa"` 为例：

| 概念 | 定义 | 例（"aabaa"） |
|---|---|---|
| 真前缀集合 | 从第 0 位起、长度小于 $n$ 的子串 | {a, aa, aab, aaba} |
| 真后缀集合 | 到第 $n-1$ 位止、长度小于 $n$ 的子串 | {a, aa, baa, abaa} |
| 公共前后缀 | 两个集合的交集 | {a, aa} |
| 最长公共前后缀 | 交集中最长的元素 | aa，长度 2 |

注意：课件里"公共前后缀"指两个集合中的**相同子串**，而"最长公共前后缀"取其中长度最大者。若两个集合交集为空，则最长公共前后缀不存在。

### 3. 字符串的 ADT 与基本操作

字符串的抽象数据类型如下（数据对象中的 $\mid$ 表示"满足……条件"）：

```
ADT String {
    数据对象：D = { s_i | s_i ∈ CharacterSet, i = 1, 2, …, n, n > 0 } 或 ∅（空串）
    数据关系：R = { <s_{i-1}, s_i> | s_{i-1}, s_i ∈ D, i = 2, …, n, n > 0 }
    基本操作：
        InitStr(s)              初始化空串 s，最大长度 kMaxSize
        StrCopy(s)              返回复制 s 得到的新串
        StrIsEmpty(s)           判空，空返回 true
        StrInsert(s, pos, t)    在 s 的 pos 位置插入 t，返回新 s
        StrRemove(s, pos, len)  删除 s 中从 pos 起长度为 len 的子串
        SubString(s, pos, len)  返回 s 中从 pos 起长度为 len 的子串
        StrLength(s)            返回 s 的长度
        StrConcat(s, t)         返回 s 与 t 联接而成的新串
        StrCompare(s, t)        比较 s、t：s>t 返回 +1，相等 0，s<t 返回 -1
        PatternMatch(s, t)      返回 s 中首次出现 t 的位置，无则返回 NIL
        Replace(s, sub_s, t)    把 s 中所有子串 sub_s 替换为 t
}
```

注意：位置参数 pos 从 **1** 开始计数，对应数组下标 pos-1。`pos = 1` 表示第 1 个字符之前。课件所有操作的输入都遵循这一约定，写 C++ 代码时下标要统一减 1。

**思路** Replace 可以看作 PatternMatch 的反复调用：定位、删除旧子串、插入新串，循环到找不到为止。若新旧子串长度不同，替换后主串长度改变，下一轮的搜索起点要随之调整——接着上次插入点之后继续，否则会漏匹配或重复匹配。

在 ADT 的全部操作里，`PatternMatch` 是本章的核心：前五个操作是线性表操作的翻版，而从 BF 到 KMP、BM 的演进，都是围绕"如何高效实现 PatternMatch"展开的。

## 二、字符串的存储实现

### 1. 顺序串

**概念** 顺序串用一段连续的存储单元依次存放字符，字符的存储位置反映其逻辑关系，本质是顺序表。定长实现用数组加长度指示位：

```cpp
#include <iostream>
#include <vector>
using namespace std;

const int kMaxSize = 1024;

struct SeqString {
    vector<char> data;              /* 有效字符在 data[0..length-1] */
    int length = 0;                 /* 当前串长，不含任何终止符 */
    SeqString() { data.resize(kMaxSize); }
};
```

顺序串的优点是随机访问：给定下标 $i$，取 `data[i]` 为 $O(1)$。缺点是长度受 kMaxSize 限制，插入删除要成批搬动字符。下面五个操作全部围绕"搬动下标"展开。

### 2. 顺序串的基本操作（算法 4-1 至 4-5）

**算法 4-1 字符串插入 StrInsert(s, pos, t)**（课件 p15）

```cpp
/* 在 s 第 pos 个字符之前插入 t；pos ∈ [1, length+1]，空间不足或位置非法返回 false */
bool StrInsert(SeqString &s, int pos, const SeqString &t)
{
    int n = s.length, m = t.length;
    if (pos < 1 || pos > n + 1) return false;           /* 位置不存在 */
    if (n + m > kMaxSize)       return false;           /* 长度超限，退出 */

    for (int i = n - 1; i >= pos - 1; --i)              /* 从后往前搬，腾出 m 个空位 */
        s.data[i + m] = s.data[i];

    for (int i = 0; i < m; ++i)                         /* 把 t 填入空位 */
        s.data[pos - 1 + i] = t.data[i];

    s.length = n + m;
    return true;
}
```

思路：**从后往前**搬动，先把靠后的字符移到新位置，再依次向前，任何字符在搬走之前都不会被覆盖。若从前往后搬，`s[pos-1]` 会被写到 `s[pos-1+m]`，而那里原有的字符还没挪走，就被冲掉了。搬动字符数为 $n - pos + 1$（插入点之后的字符个数），最坏 $pos = 1$ 时搬 $n$ 个，为 $O(n)$。

**算法 4-2 字符串删除 StrRemove(s, pos, len)**（课件 p17）

```cpp
/* 删除从 pos 起长度为 len 的子串；不足 len 个则删到末尾；位置非法返回 false */
bool StrRemove(SeqString &s, int pos, int len)
{
    int n = s.length;
    if (pos < 1 || pos > n || len < 1) return false;

    if (pos - 1 + len >= n) {                           /* 删到末尾：直接截短 */
        s.length = pos - 1;
    } else {
        for (int i = pos - 1 + len; i < n; ++i)         /* 从前往后搬，覆盖被删段 */
            s.data[i - len] = s.data[i];
        s.length = n - len;
    }
    return true;
}
```

思路与插入互为镜像：插入是"腾空位、从后往前搬"，删除是"填空位、从前往后搬"。删除时源下标 $i$ 大于目标下标 $i - len$，按 $i$ 递增搬运，目标位置总是已经处理过的旧数据，不会覆盖尚未搬动的字符。搬动个数为 $n - pos + 1 - len$，为 $O(n)$。

**算法 4-3 字符串截取 SubString(s, pos, len)**（课件 p18）

```cpp
/* 取 s 中从 pos 起长度为 len 的子串存入 sub；不足 len 个则截到末尾 */
bool SubString(const SeqString &s, int pos, int len, SeqString &sub)
{
    int n = s.length;
    if (pos < 1 || pos > n || len < 1) return false;
    if (pos - 1 + len > n) len = n - (pos - 1);         /* 截到末尾 */

    for (int i = 0; i < len; ++i)
        sub.data[i] = s.data[pos - 1 + i];
    sub.length = len;
    return true;
}
```

截取不搬动原串，只复制一段连续存储，复杂度 $O(len)$。课件算法在循环条件里同时判断"未到主串末尾"与"未取够 len"，本质相同。

**算法 4-4 字符串连接 StrConcat(s, t)**（课件 p20）

```cpp
/* 把 t 接到 s 末尾，结果存回 s；空间不足返回 false */
bool StrConcat(SeqString &s, const SeqString &t)
{
    if (s.length + t.length > kMaxSize) return false;

    for (int i = 0; i < t.length; ++i)
        s.data[s.length + i] = t.data[i];               /* 从 s 末尾继续写 */
    s.length += t.length;
    return true;
}
```

注意：连续调用 $k$ 次连接累积出长串时，总代价是各次被复制长度之和，最坏 $O(n^2)$——这与"逐个字符 push_back 触发反复扩容"是同一类代价。

**算法 4-5 字符串比较 StrCompare(s, t)**（课件 p21）

```cpp
/* s > t 返回 1，相等返回 0，s < t 返回 -1 */
int StrCompare(const SeqString &s, const SeqString &t)
{
    int len = min(s.length, t.length);
    int i = 0;
    while (i < len && s.data[i] == t.data[i]) ++i;      /* 逐位比较 */

    if (i == len) {                                     /* 公共前缀走到较短串末尾 */
        if (s.length == t.length) return 0;
        return s.length > t.length ? 1 : -1;            /* 前缀相同则长者为大 */
    }
    return s.data[i] > t.data[i] ? 1 : -1;              /* 首个不同字符定胜负 */
}
```

规则：逐位比较字符的编码值；前缀相同则更长的串更大；全部相同为相等。注意比较的不是长度，也不是各字符编码之和：`"ab" < "ba"`（长度相同、字符和相同，但首字符 `'a' < 'b'`），`"z" > "aa"`（首字符 `'z' > 'a'`，根本轮不到比长度）。

五个操作的下标规律小结：

| 操作 | 搬动方向 | 搬动个数 | 复杂度 |
|---|---|---|---|
| 插入 | 从后往前（腾空位） | $n - pos + 1$ | $O(n)$ |
| 删除 | 从前往后（填空位） | $n - pos + 1 - len$ | $O(n)$ |
| 截取 | 不搬动，仅复制 | $len$ | $O(len)$ |
| 连接 | 追加到末尾 | $m$ | $O(m)$ |
| 比较 | 不搬动，仅比较 | 至多 $\min(n,m)$ | $O(\min(n,m))$ |

### 3. 链式串

**概念** 链式串用链表存放字符，逻辑上相邻的字符在物理位置上不必相邻，本质是单链表。每个结点存一个字符：

```cpp
struct StrNode {
    char data;
    StrNode *next = nullptr;
};

struct LinkString {
    StrNode *head = nullptr;            /* 无头结点 */
    int length = 0;                     /* 串长，便于 O(1) 取长度 */
};
```

与顺序串相比，链式串的所有操作都要单独处理表头与 $pos = 1$ 的边界：顺序串里"插到首位"只是下标 0 的特例，链式串里它要改动 head 指针，是一个独立分支。

### 4. 链式串的基本操作（算法 4-6 至 4-10）

**算法 4-6 链式串插入 StrInsert(s, pos, t)**（课件 p25）

```cpp
/* 在 s 第 pos 个字符之前插入 t；位置非法则 s 不变，返回 false */
bool LinkInsert(LinkString &s, int pos, const LinkString &t)
{
    if (t.length == 0) return true;                     /* 插入空串，无动作 */
    if (pos < 1 || pos > s.length + 1) return false;    /* 位置不存在 */

    StrNode *tail = t.head;
    while (tail->next) tail = tail->next;               /* 先找 t 的末结点 */

    if (s.length == 0) {                                /* s 为空，直接接管 t */
        s.head = t.head;
    } else if (pos == 1) {                              /* 插在表头之前 */
        tail->next = s.head;
        s.head = t.head;
    } else {                                            /* 插在第 pos-1 个结点之后 */
        StrNode *p = s.head;
        for (int k = 1; k < pos - 1; ++k) p = p->next;   /* 定位前驱 */
        tail->next = p->next;
        p->next = t.head;
    }
    s.length += t.length;
    return true;
}
```

思路：链式插入不搬动任何已有结点，只改三根指针。代价是定位——找 `t` 尾结点走 $m$ 步、找前驱走 $pos-2$ 步，故为 $O(pos + m)$。

注意：插入后 `t` 的结点被 `s` 借用，不应再对 `t` 调用释放或继续使用，否则会出现悬空指针。课件原版对非法 $pos$ 采用"置错误码、s 不变"的处理，这里改为返回失败标志，语义一致。

**算法 4-7 链式串删除 StrRemove(s, pos, len)**（课件 p26）

```cpp
/* 删除从 pos 起长度为 len 的子串；不足 len 个则删到末尾 */
bool LinkRemove(LinkString &s, int pos, int len)
{
    if (s.length == 0 || pos < 1 || pos > s.length || len < 1) return false;

    StrNode *p = s.head, *prev = nullptr;
    for (int k = 1; k < pos; ++k) {                     /* 定位第 pos 个结点及其前驱 */
        prev = p;
        p = p->next;
    }
    for (int k = 0; k < len && p; ++k) {                /* 逐个摘链并释放 */
        StrNode *q = p->next;
        delete p;
        p = q;
        --s.length;
    }
    if (prev) prev->next = p;                           /* 前驱越过被删段 */
    else      s.head = p;                               /* 删的是表头 */
    return true;
}
```

链式删除的代价是"定位 $O(pos)$ + 逐个释放 $O(len)$"。当串很长而删除段很短时，它比顺序串的 $O(n-pos)$ 搬动划算；代价是每个字符额外带一个指针，存储密度很低。

**算法 4-8 链式串截取 SubString(s, pos, len)**（课件 p27）

先走到第 pos 个结点，再从它开始复制 len 个新结点。建表时用**临时头结点**统一挂接逻辑：申请一个哑结点当 `tail`，每复制一个字符就 `tail->next = new StrNode{...}; tail = tail->next;`，最后返回 `dummy.next` 并释放哑结点。这样"第一个结点"与"后续结点"不必分开写，省掉一处边界判断。课件算法结尾单独把 `s.head ← tail.next` 再 `delete tail`，做的就是删除这个临时空头结点。

**算法 4-9 链式串连接 StrConcat(s, t)**（课件 p28）

若 `s` 非空，走到 `s` 末结点令 `p->next = t.head`；若 `s` 为空，直接 `s.head = t.head`；最后 `s.length += t.length`。不复制字符，但要走完整条链，代价 $O(n)$；顺序串的同一操作只复制 $m$ 个字符，为 $O(m)$——这是链表"省搬动、费定位"的典型体现。

**算法 4-10 链式串比较 StrCompare(s, t)**（课件 p29）

双指针 `sp`、`tp` 同步前进，遇首个不同字符按 `data` 大小判定；一方先到 `nullptr` 则较短者为小；同时到尾则相等。复杂度 $O(\min(n,m))$，与顺序串相同——比较必须逐个字符读，从不因存储结构而变快。课件算法里有一处笔误（`p ← tp.next` 应为 `tp ← tp.next`），理解时按双指针同步前进即可。

### 5. 两种存储结构的比较与块链

| 比较项 | 顺序串 | 链式串 |
|---|---|---|
| 取第 $i$ 个字符 | $O(1)$ | $O(i)$ |
| 插入/删除 | $O(n)$ 搬动 | $O(pos)$ 定位，无搬动 |
| 存储密度 | 高（浪费末尾容量） | 低（约 1/9，64 位机） |
| 长度上限 | 受 kMaxSize 限制 | 仅受内存限制 |

链式串最致命的弱点是**存储密度太低**：一个结点存 1 个字符却要带 1 个指针，64 位机上 `char` 占 1 字节、指针占 8 字节，利用率约 1/9。工程上常用**块链**折中——每个结点存一个字符数组，结点之间再用指针串接：

```cpp
const int BlockSize = 4;

struct Block {
    char data[BlockSize];               /* 一个结点存 BlockSize 个字符 */
    int num = 0;                        /* 本块实际字符数，末块可能不满 */
    Block *next = nullptr;
};
```

块链把存储密度从 1/9 提高到约 $B/(B+8)$（$B = 4$ 时约 1/3），同时保留链式结构"插入删除不必整体搬移"的优点；代价是随机访问退化为"先跳块、再块内偏移"，插入删除要处理块的分裂与合并。文本编辑器常用的 rope、piece table 都是这类思路。

## 三、字符串的模式匹配

### 1. 问题的形式化

**概念** 在字符串 $s$ 中找出与字符串 $t$ 相等的子串的操作称为模式匹配（又称子串定位）。$s$ 称为主串或目标串，$t$ 称为模式串。

形式化：主串用长度为 $n$ 的数组 $s[0..n-1]$ 表示，模式串用长度为 $m$（$m \le n$）的数组 $t[0..m-1]$ 表示。若存在位移 $p$（$0 \le p \le n-m$），使得

$$s[p..p+m-1] = t[0..m-1]$$

则 $p$ 是一个**有效位移**。匹配就是从 $s$ 中找出所有（通常为首个）有效位移。

三个要素决定了各算法的差异：**比较方向**（从左或从右）、**失配后模式串移动多少**、**移动量由什么信息决定**。BF 每次固定右移 1；KMP 只看模式串自身、由已匹配长度决定移动量；BM 主串与模式串都看，取两条规则给出的较大位移；KR 不逐字符比，改用整窗哈希。课件列出的常见算法有 BF、KMP、BM、KR、Sunday 等。

### 2. BF 朴素算法（算法 4-11）

**概念** 朴素模式匹配（Brute Force，BF 算法）是最简单的暴力解法：枚举模式串与主串等长的每个起点，从模式串第 0 位逐字符比较；一旦失配，模式串整体后移一位，重新从第 0 位比起。

```cpp
/* 返回 t 在 s 中首次出现的起始下标，未找到返回 -1（对应课件的 NIL） */
int PatternMatchBF(const SeqString &s, const SeqString &t)
{
    int n = s.length, m = t.length;
    if (m == 0) return 0;
    if (m > n)  return -1;

    for (int p = 0; p <= n - m; ++p) {                   /* 枚举有效位移 */
        int i = 0;
        while (i < m && s.data[p + i] == t.data[i]) ++i; /* 逐字符比较 */
        if (i == m) return p;                           /* 整串比完，匹配成功 */
    }
    return -1;
}
```

思路：外层 $p$ 枚举起点，内层从 $i = 0$ 开始比对，比满 $m$ 个字符即成功。失配时直接换下一个 $p$，把当前已匹配的前缀信息全部丢弃。

最坏情况为 $O(nm)$。以 $s = \texttt{"aaaaaaaa"}$（$n=8$）、$t = \texttt{"aaab"}$（$m=4$）为例：$p$ 可取 $0$ 到 $4$ 共 5 轮，每轮都比到第 4 位才失配，合计 20 次比较——其中大量字符被重复查看。BF 的缺点正在于此：失配后无条件右移一位、从头重比，没有利用"前几位已经匹配成功"这一信息。

注意：平均情况并不悲观。若字符集大小为 $\sigma$ 且字符随机分布，首个字符就失配的概率为 $1 - 1/\sigma$，每轮期望比较次数约为 $\sigma/(\sigma-1)$，总期望代价 $O(n)$。BF 的缺陷只在重复字符多或恶意输入时暴露，因此实用的简化版 `strstr` 反而常用带优化的 BF。

### 3. 前缀、后缀与最长公共前后缀

**动机** KMP 要利用"失配前已匹配的部分"。设失配时已经匹配了 $t[0..j-1]$，这段既是主串的一段子串，也是模式串的前缀。要让模式串右移后仍有字符对齐，就必须让模式串的某个前缀等于这段已匹配串的某个后缀——这正是"公共前后缀"概念的用武之地。

**概念** 回看第一节的定义：对长度为 $n$ 的串，真前缀为 $s[0..i]$（$0 \le i < n-1$），真后缀为 $s[i..n-1]$（$0 < i \le n-1$）；真前缀集合与真后缀集合中的相同子串称为公共前后缀，其中长度最大的称为最长公共前后缀。

以 `"abab"` 为例：真前缀集合 {a, ab, aba}，真后缀集合 {b, ab, bab}，公共前后缀为 {ab}，最长公共前后缀是 `"ab"`（长度 2）。再看 `"aabaa"`（第一节例），最长公共前后缀是 `"aa"`（长度 2）。

规则：公共前后缀必须在**真**前缀与真后缀中找，即排除串自身。这是 KMP 能推进的硬约束——若允许取自身，右移量就是 0，算法原地打转。

### 4. 字符串特征向量（next 数组）的定义

**概念** 苏鑫课件把 next 数组称为**字符串特征向量**：长度为 $m$ 的模式串 $t$ 的特征向量是一个 $m$ 维向量，通常记作 `next`，用数组存储，所以也叫 next 数组。`next[i]$ 表示特征向量第 $i$ 位分量（$0 \le i < m$），其形式化定义为

$$
\text{next}[i] =
\begin{cases}
\max\{\,k \mid t[0..k] = t[i-k..i],\ k < i\,\}, & \text{若这样的 } k \text{ 存在}\\
-1, & \text{否则}
\end{cases}
$$

注意课件这套定义的关键：**$\text{next}[i]$ 不是"长度"，而是 $t[0..i]$ 的最长公共前后缀中，前缀最末那个字符的下标**。因为下标从 0 起，所以 $t[0..i]$ 的最长公共前后缀长度等于 $\text{next}[i] + 1$；若最长公共前后缀不存在，则置 $\text{next}[i] = -1$（此时长度 0）。

这个"下标而非长度"的写法与 408/王道教材常见的 next 定义相差一位（408 的 $\text{next}[i]$ 是 $t[0..i-1]$ 最长公共真前后缀的长度）。本笔记以苏鑫课件为准，做题时务必先认清是哪一套约定。

课件例：字符串 `"abcac"` 的特征向量为 $[-1, -1, -1, 0, -1]$。逐位推导如下：

| $i$ | 子串 $t[0..i]$ | 真前缀集合 | 真后缀集合 | 最长公共前后缀 | 前缀末字符下标 | next[$i$] |
|---|---|---|---|---|---|---|
| 0 | a | 空 | 空 | 无 | — | -1 |
| 1 | ab | {a} | {b} | 无 | — | -1 |
| 2 | abc | {a, ab} | {c, bc} | 无 | — | -1 |
| 3 | abca | {a, ab, abc} | {a, ca, bca} | a | 0 | 0 |
| 4 | abcac | {a, ab, abc, abca} | {c, ac, cac, bcac} | 无 | — | -1 |

$i=3$ 时子串为 `"abca"`，公共前后缀有 `"a"`，前缀 `"a"` 的末字符下标为 0，故 $\text{next}[3] = 0$（对应最长公共前后缀长度 $= 0+1 = 1$）。其余位置最长公共前后缀均不存在，置 -1。

### 5. next 数组的快速计算（算法 4-13）

**动机** 若朴素计算 next：对每个 $i$ 列举 $t[0..i]$ 的所有前后缀再逐字比较，时间复杂度达 $O(m^3)$，无法满足快速匹配的要求。课件给出一种 $O(m)$ 的递推算法。

**思路** 设已经求出 $\text{next}[i-1] = j$，它表示子串 $t[0..i-1]$ 的最长公共前后缀，前缀记为 $t_a$、后缀记为 $t_b$，有 $t_a = t_b$，且 $j$ 是 $t_a$ 末字符的下标、$j+1$ 是这段公共前后缀的长度。现在要推 $\text{next}[i]$：

1. 考察 $t_b$ 后面的字符，即 $t[i]$；以及 $t_a$ 后面的字符，即 $t[j+1]$。
2. 若 $t[i] = t[j+1]$，则 $t_b$ 接上 $t[i]$ 与 $t_a$ 接上 $t[j+1]$ 完全相等，这就是 $t[0..i]$ 的最长公共前后缀，故 $\text{next}[i] = j+1$。
3. 若 $t[i] \ne t[j+1]$，说明这个长度的公共前后撑不住，退而求其次：令 $j \leftarrow \text{next}[j]$（在 $t_a$ 内部再找更短的公共前后缀），回到第 2 步重试；反复回退直到相等，或 $j < 0$（无处可退），此时 $\text{next}[i] = -1$。

课件给出的伪代码（算法 4-13）如下：

```text
m ← t.length
next[0] ← -1
for i ← 1 to m-1 do
    j ← next[i-1]
    while j ≥ 0 且 t.data[i] ≠ t.data[j+1] do
        j ← next[j]
    end
    if t.data[i] = t.data[j+1] then
        next[i] ← j+1
    else
        next[i] ← -1
    end
end
```

等价的 C++ 实现：

```cpp
/* 求模式串 t 的特征向量 next[0..m-1]，课件约定 */
vector<int> GetNext(const SeqString &t)
{
    int m = t.length;
    vector<int> next(m, -1);                            /* next[0] = -1 */
    for (int i = 1; i < m; ++i) {
        int j = next[i - 1];
        while (j >= 0 && t.data[i] != t.data[j + 1])    /* 失配则沿 next 回退 */
            j = next[j];
        if (t.data[i] == t.data[j + 1])
            next[i] = j + 1;                            /* 能扩展，长度加一 */
        else
            next[i] = -1;                               /* j < 0，无处可退 */
    }
    return next;
}
```

注意 `while` 条件里要先判 `j >= 0` 再访问 `t.data[j+1]`，避免 $j = -1$ 时下标越界——C++ 的 `&&` 短路求值保证了这一点。

**完整走查**：手算 `"abcac"` 的 next，看递推如何自己算出来。

- $\text{next}[0] = -1$（初始化）。
- $i=1$：$j = \text{next}[0] = -1$，while 条件 `j >= 0` 不成立、跳过；进入 `if` 比较 $t[1] = \texttt{'b'}$ 与 $t[j+1] = t[0] = \texttt{'a'}$，不等，故 $\text{next}[1] = -1$。
- $i=2$：$j = \text{next}[1] = -1$，同理比较 $t[2] = \texttt{'c'}$ 与 $t[0] = \texttt{'a'}$，不等，$\text{next}[2] = -1$。
- $i=3$：$j = \text{next}[2] = -1$，比较 $t[3] = \texttt{'a'}$ 与 $t[0] = \texttt{'a'}$，相等，$\text{next}[3] = j+1 = 0$。
- $i=4$：$j = \text{next}[3] = 0$。while 中比较 $t[4] = \texttt{'c'}$ 与 $t[1] = \texttt{'b'}$，不等且 $j \ge 0$，回退 $j = \text{next}[0] = -1$；退出 while 后比较 $t[4] = \texttt{'c'}$ 与 $t[0] = \texttt{'a'}$，仍不等，故 $\text{next}[4] = -1$。

得到 $[-1, -1, -1, 0, -1]$，与课件一致。这里有一个容易困惑的点：**while 的 `j >= 0` 只约束"能否继续回退"；`if` 中访问的是 $t[j+1]$，所以 $j = -1$ 时 $j+1 = 0$ 仍是合法下标**，代表"拿模式串第 0 位来比"。只有当这一步比较也失败时，才置 -1。理解这一点，就能自己推任何串的 next。

复杂度分析：`j` 每进入一次回退分支至少减小，而 `j` 在整个过程中最多增加 $m$ 次（每次成功扩展加 1），因此回退总次数不超过 $m$，整段循环为 $O(m)$。这是均摊分析的标准套路：$O(m)$ 是最坏情况的界，而非偶然的最好情况。

注意：408 教材的 next 定义为 "$t[0..i-1]$ 最长公共真前后缀的长度"，与课件的特征向量相差一位。换算关系是：408 的 $\text{next}[i] = $ 课件的 $\text{next}[i-1] + 1$（$i \ge 1$）。例如 `"ababc"` 在课件里是 $[-1,-1,0,1,-1]$，在 408 里是 $[-1,0,0,1,2]$。两套本质同一张表，只是错开一位；本笔记通篇用课件约定。

### 6. KMP 算法（算法 4-14）

**概念** KMP（Knuth–Morris–Pratt，克努特—莫里斯—普拉特）算法由三位作者提出。其核心思想：BF 在失配时已匹配到第 $j$ 位，说明前 $j-1$ 位匹配成功；利用这部分信息，把模式串一次右移多格，而**主串指针全程不回退**。

**规则** 在 next 数组的基础上：当主串与模式串在模式串第 $i$ 位失配时，把模式串右移，从模式串的第 $\text{next}[i-1] + 1$ 位开始继续匹配，重复直至串末。

课件算法 4-14 的伪代码（$i$ 指向模式串、$j$ 指向主串）：

```text
n ← s.length;  m ← t.length;  p ← NIL
if n ≥ m then
    GetNext(t, next)
    i ← 0;  j ← 0
    while j < n 且 i < m do
        if s.data[j] = t.data[i] then
            i ← i+1;  j ← j+1
        else if i > 0 then
            i ← next[i-1] + 1                // 模式串右移，主串指针不动
        else
            j ← j+1                          // 模式串首位即失配，主串前进一位
        end
    end
    if i = m then p ← j-m
end
return p
```

等价的 C++ 实现（返回首个有效位移，未找到返回 -1）：

```cpp
int PatternMatchKMP(const SeqString &s, const SeqString &t)
{
    int n = s.length, m = t.length;
    if (m == 0) return 0;
    if (m > n)  return -1;

    vector<int> next = GetNext(t);             /* 预处理模式串，O(m) */
    int i = 0, j = 0;                          /* i 指模式串，j 指主串 */
    while (j < n && i < m) {
        if (s.data[j] == t.data[i]) {
            ++i; ++j;                          /* 相等则同步前进 */
        } else if (i > 0) {
            i = next[i - 1] + 1;               /* 失配回退，j 不动 */
        } else {
            ++j;                               /* 首位失配，主串前进 */
        }
    }
    return (i == m) ? (j - m) : -1;
}
```

思路：主串指针 $j$ 只有在"首字符就失配"（$i = 0$）时才前进，其余失配都靠调整 $i$ 让模式串右移。这样主串只读一遍，比较次数与 $n$ 成正比。

**完整走查**：取 $s = \texttt{"abababc"}$、$t = \texttt{"ababc"}$。由 GetNext 可得 `"ababc"` 的课件 next 为 $[-1, -1, 0, 1, -1]$（读者可用上一节的递推自行验证）。

| 步 | $i$（模式） | $j$（主串） | $s[j]$ | $t[i]$ | 动作 |
|---|---|---|---|---|---|
| 1 | 0 | 0 | a | a | 相等 → i=1, j=1 |
| 2 | 1 | 1 | b | b | 相等 → i=2, j=2 |
| 3 | 2 | 2 | a | a | 相等 → i=3, j=3 |
| 4 | 3 | 3 | b | b | 相等 → i=4, j=4 |
| 5 | 4 | 4 | a | c | **失配**，$i \leftarrow \text{next}[3]+1 = 0+1 = 1$ |
| 6 | 1 | 4 | a | b | 失配，$i \leftarrow \text{next}[0]+1 = 0$ |
| 7 | 0 | 4 | a | a | 相等 → i=1, j=5 |
| 8 | 1 | 5 | b | b | 相等 → i=2, j=6 |
| 9 | 2 | 6 | c | a | 失配，$i \leftarrow \text{next}[1]+1 = 0$ |
| 10 | 0 | 6 | c | a | 失配，$i=0$ → j=7，结束 |

返回 -1——这个例子在 $s$ 中其实没有完整匹配（`"ababc"` 不在 `"abababc"` 中，第 5 位起是 `"abc"`）。若把主串换成 $\texttt{"abababca"}$ 并把模式串放在 $p=2$，匹配会在 $j=7$ 时 $i$ 走满 5 而成功，返回 $j-m = 2$。关键观察：**$j$ 一路单调递增，从不回退**，这正是 KMP 能用于大文件流式检索的原因。

复杂度：计算 next 为 $O(m)$，匹配为 $O(n)$，总复杂度 $O(n+m)$。额外空间 $O(m)$ 用于存 next。相比 BF 的 $O(nm)$，KMP 在最坏情况下有本质的改进。

### 7. BM 算法的思想

**概念** BM（Boyer–Moore）算法有两点革新：一是**从右向左**比较模式串，二是失配后可一次跳过多个字符。从右往左比较的好处是——只要模式串最后一个字符对不上，立刻失配，一次比较就排除一个起点；而 BF、KMP 从左往右比，最坏要把前缀比完才发现末位不对。

**规则** 失配后模式串右移多少，由两条规则分别给出，取**较大**者：

1. **坏字符规则**：失配时主串中那个对不上的字符 $c$ 称为坏字符，设当前正与它比对的是模式串第 $j$ 位。
   - 若 $c$ 在 $t[0..j-1]$ 中最右出现位置为 $k$，位移 $= j - k$；
   - 若 $c$ 根本不在 $t[0..j-1]$ 中，位移 $= j + 1$（整个模式串移到坏字符右侧）。

2. **好后缀规则**：失配时已经匹配上的那段后缀是有用信息（称为好后缀）。若该后缀在模式串前面还出现过，就把下一次出现的位置对齐过来；若没有完整出现，就找它的某个后缀，使该后缀恰好是模式串的前缀。位移取可行方案中较大者。

**思路** 好后缀规则的意义：既然这段后缀已经和主串对上了，下一次对齐应尽量让相同的结构重新对上，而不是把它们拆散。只用坏字符规则的简化版叫 BMH（Boyer–Moore–Horspool），实现简单、性能接近，是工程常用变体。

例：$t = \texttt{"abac"}$，主串 $s = \texttt{"ababac"}$。在 $p=0$ 处对齐，从右往左比：$t[3] = \texttt{'c'}$ 对 $s[3] = \texttt{'b'}$，失配。坏字符为 $\texttt{'b'}$，它在 $t[0..2] = \texttt{"aba"}$ 中最右出现于 $k=1$，故位移 $= 3-1 = 2$，直接跳到 $p=2$，一次对齐即匹配成功。BF 则要试 $p=0,1,2$ 三个起点。

BM 的预处理是建坏字符表（大小 $\sigma$）与好后缀表（大小 $m$），代价 $O(m+\sigma)$；匹配最好情况每次跳过整个模式串，比较约 $n/m$ 次；最坏仍为 $O(nm)$。实际文本上（字母表大、模式串长）远快于 KMP，`grep`、`less` 等工具的核心都是 BM 的变体。课件只要求掌握这两条规则的思想，不要求完整代码。

### 8. KR 算法的思想

**概念** KR（Rabin–Karp）换了个思路：不比字符，比**数值**。把模式串看作 $d$ 进制数（$d$ 为字符集大小），用哈希函数把长为 $m$ 的串映射成整数：

$$H(t) = \left(\sum_{i=0}^{m-1} t[i]\cdot d^{\,m-1-i}\right) \bmod q$$

主串中每个长为 $m$ 的窗口也照此计算，先比哈希值；哈希相等再逐字符核验（因为可能存在哈希碰撞）。关键在于窗口滑动时不必重算：去掉最高位、整体左移、补上新字符，

$$H(s[i+1..i+m]) = \big((H(s[i..i+m-1]) - s[i]\cdot d^{\,m-1})\cdot d + s[i+m]\big) \bmod q$$

一次乘加即可 $O(1)$ 更新，整趟扫描期望 $O(n+m)$；最坏情况（哈希大量碰撞）退化为 $O(nm)$。

**思路** KR 的真正优势在**多模式匹配**：若要在文本中同时找 $k$ 个模式串，把 $k$ 个模式的哈希值放进哈希表，扫描时每个窗口查一次表，总代价 $O(n + km)$，而 KMP 需要跑 $k$ 遍。课件在"字符串的查找"总览页把 KR 概括为"哈希筛选、滚动更新、碰撞核验"十二个字，正对应上述三步。

注意：取模减法可能出现负值，C++ 中应写成 `((h - x) % q + q) % q`；$d^{m-1}$ 要预处理，避免每个窗口重算幂。

### 9. 四种算法的对比

| 算法 | 比较方向 | 移动依据 | 预处理 | 匹配（最坏） | 特点 |
|---|---|---|---|---|---|
| BF | 左 → 右 | 固定右移 1 | 无 | $O(nm)$ | 实现最简单，字符集大时平均 $O(n)$ |
| KMP | 左 → 右 | 已匹配长度（模式串自身特征向量） | $O(m)$ | $O(n)$ | 主串不回退，可流式处理 |
| BM | 右 → 左 | 坏字符 + 好后缀，取较大位移 | $O(m+\sigma)$ | $O(nm)$ | 实践中最快，跳跃幅度大 |
| KR | 比整窗哈希 | 哈希不等则整窗跳过 | $O(m)$ | $O(nm)$ | 期望线性，天然支持多模式 |

选择依据：单模式、模式串短且字符集大——BF 足够；需要最坏线性保证或流式处理——KMP；文本编辑器、命令行检索等工程场景——BM；多模式或需要判等、去重——KR / 哈希。

注意：KMP 与 BF 都是从左往右比，但 KMP 的主串指针不回退、移动量由模式串自身决定；BM 从右往左比，移动量同时参考主串与模式串。三者把"失配后如何利用已知信息"这件事用不同方式做到极致，是本节的灵魂。

## 本章小结

> 字符串是元素限定为字符的线性表，区别在于操作以子串为单位；空串长度为 0，与空格串不同。顺序串用连续存储、随机访问快但插入删除要搬动字符（插入从后往前、删除从前往后，搬动个数分别为 $n-pos+1$ 与 $n-pos+1-len$）；链式串插入删除方便但需逐个定位、存储密度低，块链是二者的折中。模式匹配中，BF 每次右移一位、最坏 $O(nm)$；KMP 用苏鑫课件的"字符串特征向量" next 数组——$\text{next}[i]$ 是 $t[0..i]$ 最长公共前后缀的前缀末字符下标（无则 -1，如 `"abcac"` 为 $[-1,-1,-1,0,-1]$）——失配时回退到 $\text{next}[i-1]+1$，主串指针不回退，总复杂度 $O(n+m)$；BM 从右向左比，按坏字符与好后缀两条规则取较大位移；KR 用滚动哈希筛选、碰撞核验。下一章 [[第5章-树和二叉树.md]] 将从线性的串转向非线性的树结构。
