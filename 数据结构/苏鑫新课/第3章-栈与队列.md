## 一、栈

### 1. 栈的定义

**概念** 栈（Stack）是运算只在表的一端进行的线性表，是**访问受限的线性表**。它的特性是后进先出（Last In First Out，LIFO）：元素插入与删除的顺序相反，每次取出（删除）的总是刚压进的元素，最先压入的元素位于栈底。因此栈也称为"下推表"。

- **栈顶（top）**：栈的唯一可访问端，元素插入栈称为入栈或压栈（push），删除称为出栈或弹出（pop）。
- **栈底**：另一端，不可直接访问。
- **空栈**：不含任何元素的栈。

**动机**：为什么要限制访问端？线性表功能强大但过于灵活，很多问题只需要"后进先出"这一个动作——函数调用的返回、回溯时的撤销、表达式中括号的配对，都只需处理最近压入的元素。把操作限制在一端，既够用又让实现更简单、不易出错。

课件列出的典型应用：表达式求值、函数调用、深度优先搜索。

### 2. 栈的 ADT

```
ADT Stack {
    数据对象：{ ai | ai ∈ ElemSet, i = 1..n, n > 0 } 或空表 Φ
    数据关系：<ai, ai+1>，ai 为 ai+1 的前驱（i = 0..n-2）
    基本操作：
        InitStack(stack)    初始化一个空栈
        DestroyStack(stack) 释放栈占用的全部空间
        Clear(stack)        清空栈
        IsEmpty(stack)      判空，空返回真
        IsFull(stack)       判满，满返回真
        Top(stack)          返回栈顶结点但不改变栈
        Push(stack, x)      将 x 压入栈，成为新栈顶
        Pop(stack)          弹出栈顶结点
}
```

**注意**：`Top` 与 `Pop` 的区别——`Top` 只读取栈顶而不改变栈，`Pop` 会移除栈顶。ADT 只规定"做什么"，具体实现留待下一节。

### 3. 出栈序列与卡特兰数

问题：给定长度为 $N$ 的入栈序列，有多少种出栈序列？

- **若要求全部入栈后才允许出栈**：出栈序列只有 1 种，即入栈序列的逆序。
- **若不要求全部入栈后才出栈**：入栈与出栈可交错进行，出栈序列数等于第 $N$ 个卡特兰数

$$C_N=\frac{1}{N+1}\binom{2N}{N}$$

**思路**：设第 $k$ 个元素最先出栈（$k=1..N$）。它出栈前，$1..k-1$ 已入栈且必须在其后、按栈序弹出；它出栈后，剩下的 $N-k$ 个元素再各自构成一个独立的入栈出栈过程。于是递推为 $f(N)=\sum_{k=1}^{N} f(k-1)\,f(N-k)$，$f(0)=1$——这正是卡特兰数递推式。这个分解解释了为什么答案不是简单的 $N!$：栈的后进先出约束排除了大量排列。

### 4. 顺序栈

**概念** 顺序栈（Array-based Stack）用向量实现，本质上是顺序表的简化版——只在一端操作。关键决策是确定哪一端作为栈顶；通常选数组下标增大的一端（表尾）作栈顶，入栈出栈都在尾部进行，$O(1)$ 完成。

```cpp
struct ArrayStack {
    std::vector<int> data;             // 连续空间
    ArrayStack() { data.reserve(16); }
    bool isEmpty() const { return data.empty(); }
    void push(int x) { data.push_back(x); }        // 栈顶在尾部
    int  top() const { return data.back(); }       // 读栈顶
    void pop() { data.pop_back(); }                // 弹栈顶
};
```

若用定长数组手写，则维护 `data[MAXSIZE]` 与栈顶下标 `top`：

- 初始化 `top = -1`（空栈）；
- 入栈：判满（`top == MAXSIZE-1`），执行 `data[++top] = x`（先加后存）；
- 出栈：判空（`top == -1`），执行 `return data[top--]`（先取后减）。

**注意**：栈顶指针的"先动后存"与"先取后减"是顺序栈的基本操作顺序，颠倒会导致覆盖或读到错误元素。

### 5. 链式栈

**概念** 链式栈（Linked Stack）用单链表存储，指针方向从栈顶向下链接——每个结点指向它的下方元素，栈顶结点就是链表头。选择链表头作为栈顶，是因为头结点的插入删除都方便；若把链尾当栈顶，删除时找不到前驱。

```cpp
struct StackNode {
    int data;
    StackNode* next = nullptr;
};
using LinkedStack = StackNode*;        // 指向栈顶

void push(LinkedStack& S, int x) {
    S = new StackNode{x, S};            // 头插，新结点成为栈顶
}
int top(const LinkedStack& S) { return S->data; }
void pop(LinkedStack& S) {
    StackNode* t = S;                   // 暂存栈顶
    S = S->next;                        // 栈顶下移
    delete t;                           // 释放旧栈顶
}
```

**思路**：链栈的判空条件是 `S == nullptr`；`push` 为头插 $O(1)$，`pop` 删头结点也是 $O(1)$。链式栈不需要判满（除非内存耗尽），这是它相对顺序栈的优势。

### 6. 上溢、下溢与双栈共享

- **上溢**：栈满时仍执行入栈；
- **下溢**：栈空时仍执行出栈。

判满、判空就是为了规避这两类越界。顺序栈容量固定，必须显式判满；链式栈只在内存不足时无法分配。

**思路**：一个数组实现两个栈时，让两栈**从两头向中间生长**——栈 1 的栈顶 `top1` 从 $-1$ 向右增长，栈 2 的栈顶 `top2` 从 `MAXSIZE` 向左增长。判满条件是两栈顶相邻，即 `top2 - top1 == 1`，而不是 `top1 + top2 == MAXSIZE`（后者是常见错误，会漏判或误判）。用参数区分操作哪个栈，入栈分别用 `++top1` 与 `--top2`。这样两个栈共享空间，只有当总元素真正填满数组时才上溢，比各自分一半空间更省。

## 二、队列

### 1. 队列的定义

**概念** 队列（Queue）是运算在表的两端进行的线性表，也是访问受限的线性表。它的特性是先进先出（First In First Out，FIFO）：在队尾插入（入队 EnQueue），在队头删除（出队 DeQueue）。

**注意**：队列不允许访问队列内部元素——只能看到队首。这一点在课件中被单独强调，是"访问受限"的准确含义。

**动机**：现实中的排队天然是 FIFO——先来先服务。打印任务、消息缓冲、宽度优先搜索都只需"尾部加入、头部取出"。与栈的 LIFO 相对，队列保持了元素的到达次序。

### 2. 队列的 ADT

```
ADT Queue {
    数据对象：{ ai | ai ∈ ElemSet, i = 1..n, n > 0 } 或空表 Φ
    数据关系：{ <ai, ai+1> | ai, ai+1 ∈ ElemSet, i = 0..n-2 }
    基本操作：
        InitQueue(queue)    初始化空队列
        DestroyQueue(queue) 释放队列占用的全部空间
        Clear(queue)        清空队列
        IsEmpty(queue)      判空
        IsFull(queue)       判满
        GetFront(queue)     返回队首结点但不改变队列
        EnQueue(queue, x)   将 x 插入队尾，成为新队尾
        DeQueue(queue)      删除队首结点
}
```

`GetFront` 与 `DeQueue` 的关系，对应栈中的 `Top` 与 `Pop`：一个只读，一个移除。

### 3. 顺序队列与假溢出

**概念** 顺序队列用数组存储元素，用两个变量分别指向队头与队尾：`Q.front` 指向队头，`Q.rear` 指向队尾。

`Q.rear` 有两种指向约定：

| 约定 | rear 的含义 | 例子取值 |
|---|---|---|
| 实指 | 指向当前队列最后一个有效元素 | `rear = 6`，指向元素 60 |
| 虚指 | 指向最后元素的下一个位置，即下一次入队准备写入的位置 | `rear = 7`，指向 60 之后 |

**注意**：两种约定下 `front` 的初值、判空条件都不同，实现前必须先定约定。课件默认采用**虚指**。

**概念** 溢出分三类：

- **上溢**：队列满时入队；
- **下溢**：队列空时出队；
- **假溢出**：顺序队列特有现象——当队尾指针达到数组最大值（`rear = mSize`）时再入队产生溢出，但此时队列前端可能尚有空闲位置（因为出队已腾出空间）。

**思路**：假溢出的本质是"逻辑上 tail 走到了数组尽头，物理上前面还有空位"。出队让 `front` 前移，留下的空位没有再利用，空间被单方向消耗。解决它有两种办法：一是每次出队后整体平移元素（代价高），二是把数组看成环——这就是循环队列。

### 4. 循环队列

**概念** 循环队列把存储队列的数组首尾相接成一个环：入队 `rear = (rear + 1) % mSize`，出队 `front = (front + 1) % mSize`。指针到达末尾后自动绕回开头，从而复用出队腾出的空间，从根本上解决假溢出。

**注意**：循环队列的空满判定是难点。大小为 $n$ 的数组，`front` 与 `rear` 的相对差距只有 $n$ 种取值，而队列装载状态有 $n+1$ 种（$0$ 到 $n$ 个元素），因此仅凭两个指针无法区分"空"与"满"。两种解决方案：

1. **牺牲一个位置**：队列最多存 $n-1$ 个元素，判空 `front == rear`，判满 `(rear + 1) % mSize == front`；
2. **附加标记**：用 `size` 计数（存满 $n$ 个），或用 `tag` 记录最后一次操作是入队还是删除——最后一次是入队且 `front == rear` 则为满，是删除则为空。

```cpp
struct CircularQueue {
    std::vector<int> data;             // 容量 mSize，牺牲一格
    int front = 0, rear = 0;
    CircularQueue(int m) : data(m) {}
    bool empty() const { return front == rear; }
    bool full()  const { return (rear + 1) % static_cast<int>(data.size()) == front; }
    void enqueue(int x) {
        if (full()) return;
        data[rear] = x;
        rear = (rear + 1) % static_cast<int>(data.size());
    }
    int dequeue() {
        int x = data[front];
        front = (front + 1) % static_cast<int>(data.size());
        return x;
    }
};
```

**思路**：取模运算把线性数组弯成环，是循环队列的全部秘密。所有复杂度仍为 $O(1)$，但空间利用率从"一次性消耗"变成"循环复用"。

### 5. 链式队列

**概念** 链式队列采用单链表存储，每个元素对应链表中一个结点。需要两个指针：`front` 指向链表头（做出队），`rear` 指向链表尾（做入队）。

**注意**：方向不能反过来——单链表在链尾删除时找不到前驱，所以必须让 `front` 管删除、`rear` 管插入。出队时若队列只剩一个元素（`front == rear`），删除后 `front` 与 `rear` 都要置空，否则 `rear` 会悬空。

```cpp
struct QNode { int data; QNode* next = nullptr; };
struct LinkedQueue { QNode* front = nullptr; QNode* rear = nullptr; };

void enqueue(LinkedQueue& Q, int x) {
    QNode* s = new QNode{x, nullptr};
    if (Q.rear) Q.rear->next = s;        // 尾插
    else        Q.front = s;             // 原为空队列
    Q.rear = s;                          // 更新队尾
}
bool dequeue(LinkedQueue& Q, int& out) {
    if (!Q.front) return false;          // 空队列，下溢
    QNode* t = Q.front;
    out = t->data;
    Q.front = Q.front->next;             // 头删
    if (!Q.front) Q.rear = nullptr;      // 删的是最后一个结点
    delete t;
    return true;
}
```

**思路**：链队列不会假溢出（无需判满），出队入队都是 $O(1)$；代价是每个结点多一个指针域。它本质上是"仅有尾指针的单向循环链表"的非循环写法——用 `rear` 管尾插、`front` 管头删。

## 三、栈和队列的应用

### 1. 数制转换

**思路**：非负十进制整数 $N$ 转 $B$ 进制用"除 $B$ 取余法"：反复把 $N$ 除以 $B$，取商继续、取余输出，直到商为 0。最先求得的余数是结果的最低位，最后求得的是最高位——余数的产生顺序与输出顺序正好相反，符合栈的先进后出性质，故用栈缓存。

$$
(66)_{10}=(102)_8:\quad 66/8=8\ \text{余}\ 2,\quad 8/8=1\ \text{余}\ 0,\quad 1/8=0\ \text{余}\ 1
$$

余数依次 2、0、1，逆序输出得 102。

```cpp
void baseConvert(int n, int B) {
    ArrayStack S;                        // 复用前面的顺序栈
    while (n > 0) {
        S.push(n % B);                   // 余数入栈
        n /= B;
    }
    while (!S.isEmpty()) {               // 出栈即逆序输出
        int r = S.top(); S.pop();
        std::cout << r;
    }
    std::cout << '\n';
}
```

**注意**：若 $n=0$，循环不执行，应直接输出 0——栈为空时上面的输出循环不会打印任何字符。

### 2. 表达式的三种形式

表达式的基本符号集为 $\{0,1,\ldots,9,+,-,\times,\div,(,)\}$，语法成分包括表达式、项、因子、常数、数字。

- **中缀表达式**：运算符在操作数中间，如 $23+(34\times45)/(5+6+7)$。符合人的书写习惯，但优先级与括号使求值复杂。中缀语法规则：若有括号先算括号内、由内而外脱括号；无括号或同层时先乘除后加减；同层多个同级运算从左到右。
- **后缀表达式**：运算符在操作数之后，如 `23 34 45 * 5 6 + 7 + / +`。完全不需要括号，求值时从左到右扫描即可。
- **前缀表达式**：运算符在操作数之前，如中缀 $4\times x\times(2\times x+a)-c$ 对应前缀 `- + 4 * x * 2 x + a c`。同样不需要括号。

**动机**：为什么要把中缀转前后缀？中缀的运算符优先级和括号给计算机带来解析负担；前后缀把运算顺序编码进符号排列本身，求值只需一个栈、扫描一遍，复杂度 $O(n)$。这是栈最经典的应用。

### 3. 后缀表达式求值

**规则** 循环读入符号序列（以 `=` 结束）：

1. 读到的元素是操作数，压入栈；
2. 读到的是运算符，从栈中连续弹出两个栈顶操作数，按运算符计算，把结果压回栈；
3. 继续直到结束，此时栈顶元素即表达式的值。

**注意**：弹出两个操作数时有先后——先弹出的是右操作数，后弹出的是左操作数。减法和除法不满足交换律，顺序颠倒会得到错误结果。

```cpp
int evalPostfix(const std::vector<int>& operands,
                const std::vector<char>& ops) {
    ArrayStack S;                        // 简化的整数栈
    for (size_t i = 0, k = 0; i < ops.size(); ++i) {
        if (ops[i] == '=') break;
        if (ops[i] == '#') { S.push(operands[k++]); continue; }  // '#' 标记一个操作数
        int b = S.top(); S.pop();         // 先弹出的是右操作数
        int a = S.top(); S.pop();         // 后弹出的是左操作数
        int r = 0;
        if (ops[i] == '+') r = a + b;
        if (ops[i] == '-') r = a - b;
        if (ops[i] == '*') r = a * b;
        if (ops[i] == '/') r = a / b;
        S.push(r);
    }
    return S.top();
}
```

课件给出的走查以中缀式 $23+(34\times45)/(5+6+7)$ 对应的后缀式 `23 34 45 * 5 6 + 7 + / +` 为例。栈状态变化依次为：读入 `34 45 *` 得 $1530$；读入 `5 6 +` 得 $11$，再读入 `7 +` 得 $18$；此时栈顶两元素为 $1530$ 与 $18$，读入 `/` 得 $85$；最后读入 `+`，与最初的 $23$ 相加得 $108$。用栈模拟时，每读入一个运算符就合并栈顶两项，恰好对应表达式树的后序遍历。

### 4. 中缀转后缀

**思路** 从左到右扫描中缀表达式，用栈存放运算符、开括号以及"开括号后暂不确定计算次序"的符号。栈的作用是暂存那些"还不能输出"的运算符，等优先级更高的运算出现或遇到闭括号时才弹出。

**规则** 逐符号处理：

1. **操作数**：直接输出到后缀序列；
2. **开括号**：入栈；
3. **闭括号**：先判栈空，空则括号不匹配，报错清栈退出；非空则依次弹出并输出，直到遇到一个开括号（开括号丢弃）；若弹到栈空仍未遇到开括号，同样括号不匹配，报错退出；
4. **运算符 op**（四则运算之一）：循环——当栈非空、栈顶不是开括号、且栈顶运算符优先级**不低于**当前运算符时，反复弹出栈顶输出；然后把当前 op 入栈；
5. **结束**：读完全部符号后，栈内剩余元素依次弹出置于输出尾部；若弹出元素中出现开括号，说明括号不匹配，报错退出。

**注意**：规则 4 中"不低于"（$\ge$）保证同优先级运算从左到右结合。例如 `a - b + c`，读到 `+` 时栈顶 `-` 优先级相等，必须先弹出 `-`，得到 `a b -`，再压 `+`，最终 `a b - c +`，正确表达了左结合。

复杂度：每个符号入栈出栈各一次，总时间 $O(n)$。

### 5. 前缀表达式与括号匹配

**前缀求值** 与后缀对称：从右向左扫描，遇操作数压栈，遇运算符弹出两个操作数计算后压回，最终栈顶即结果。

**括号匹配** 是栈的直接使用：

**思路** 从左到右扫描串：

- 遇开括号入栈；
- 遇闭括号时，若栈空则不匹配（闭括号多余）；否则弹出栈顶，检查是否为对应的开括号，不对应则不匹配；
- 扫描结束后栈非空则有未闭合的开括号，不匹配；栈空才匹配。

**注意**：三种失败情形要分别处理——中途栈空（闭括号多余）、括号类型不对应、结束时栈非空（开括号未闭合）。栈的 LIFO 性恰好保证"最近的开括号优先匹配"，这与括号的正确嵌套规则一致。

### 6. 栈与队列的其他应用

- **函数调用与递归**：每次调用把返回地址、参数、局部变量压入调用栈，返回时按后进先出逐层恢复现场。递归爆栈正是调用栈空间耗尽。
- **深度优先搜索（DFS）**：用栈保存待访问的顶点，回溯时弹出最近压入的分支。
- **宽度优先搜索（BFS）**：用队列保存待访问顶点，先进先出保证按层扩展。
- **缓冲区与任务调度**：打印队列、消息队用 FIFO 保证公平；浏览器后退用栈实现最近优先回退。
- **表达式求值、数制转换**：如本节前几目所述，均依赖栈的 LIFO。

**思路**：判断该用栈还是队列，看问题需要"最近优先"（LIFO，栈）还是"先到优先"（FIFO，队列）——这是两类应用的分水岭。

## 本章小结

> 栈与队列都是访问受限的线性表：栈只在一端操作、后进先出，队列在两端操作、先进先出且不允许访问内部元素。实现上，栈有顺序栈与链栈，队列有顺序队列、循环队列与链队列；循环队列用取模解决假溢出，并通过牺牲一格或附加标记解决空满判定。应用部分展示了栈的核心价值——把"产生顺序与需求顺序相反"的问题（数制转换、后缀求值、括号匹配、函数调用）用 LIFO 统一处理，并给出中缀转后缀的完整规则。下一章 [[第4章-字符串.md]] 将把线性表方法应用到字符串这一具体类型。
