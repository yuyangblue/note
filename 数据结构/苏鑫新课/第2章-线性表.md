## 一、线性表的定义与结构

### 1. 什么是线性表

**概念** 线性表是由同一类型数据元素构成的有序序列，记作

$$L=(a_0,a_1,\ldots,a_{n-1})$$

其中 $n$ 为表长，$n=0$ 时称为空表。定义包含两个要点：元素来自同一类型；元素之间存在**位置次序**，而非数值大小关系——$a_i$ 排在 $a_{i+1}$ 前面，是因为它们的位置，不是因为 $a_i \le a_{i+1}$。

**动机**：多项式、字符串、超市货架、待办队列，表面毫无关系，抽象后都是"一排同类元素"。把它们统一成线性表，就能用同一套 ADT 和同一套实现解决一类问题，而不必为每个具体问题重写代码。

### 2. 线性关系的三个关键词

线性关系可归纳为三个关键词：**唯一前驱**、**唯一后继**、**首尾边界**。

- 除首元素外，每个元素有且仅有一个直接前驱；
- 除尾元素外，每个元素有且仅有一个直接后继；
- 首元素无前驱，尾元素无后继，这是两条边界。

**注意**：逻辑相邻不等于物理相邻。$a_i$ 与 $a_{i+1}$ 在逻辑上相邻，但它们的内存地址可以是 $0\text{x}18$ 与 $0\text{xA}4$，完全不相邻。是否相邻取决于采用哪种存储结构，这正是下一节"两条实现路线"的分叉点。

### 3. 线性表的抽象数据类型

ADT 由三部分组成：数据对象、数据关系、基本操作。线性表的 ADT 描述为：

```
ADT List {
    数据对象：同一类型的数据元素集合 { a0, a1, ..., a(n-1) }
    数据关系：除首尾外，每个元素有唯一前驱和唯一后继
    基本操作：InitList  初始化空表        DestroyList 销毁
              ClearList 清空             IsEmpty 判空
              Length    求表长
              Get(i)    取第 i 个元素     Search(x) 按值查找
              Insert(i, x) 在第 i 个位置插入   Remove(i) 删除第 i 个元素
}
```

课件强调：ADT 规定"做什么"，存储结构决定"怎么做"。`Get`、`Search`、`Insert`、`Remove` 是后续实现重点——它们在不同存储结构下的复杂度截然不同。

### 4. 两条实现路线

同一逻辑次序，可以用两种物理组织实现：顺序表用连续空间表达逻辑次序，链表用指针表达逻辑次序。

| 比较维度 | 顺序表 | 链表 |
|---|---|---|
| 随机访问 | 快，$O(1)$ | 需逐结点，$O(n)$ |
| 插入与删除 | 常需移动元素 | 定位后改指针 |
| 空间管理 | 连续、容量受限 | 离散、按需分配 |

**思路**：选择依据来自三方面——访问模式、规模变化、内存环境。随机访问多、规模稳定时选顺序表；频繁插入删除且位置已知时选链表。这个取舍贯穿本章所有实现。

## 二、线性表的顺序存储实现

### 1. 存储模型与地址公式

顺序存储把元素按逻辑次序依次存入一段连续存储单元。首地址、元素大小、下标三者共同决定元素地址：

$$\operatorname{Loc}(i)=\text{base}+i\times \text{sizeof(ElemType)}$$

其中 `base` 为首地址，`i` 为从 0 起算的下标，`sizeof(ElemType)` 为单个元素占用的字节数。

**注意**：必须区分 `length`（当前已用元素数）与 `maxSize`（可用容量）。任何时刻满足 $0\le \text{length}\le \text{maxSize}$；`length` 指向已用与空闲的分界，`maxSize` 是数组实际开辟的大小。把两者混为一谈是越界错误的常见来源。

### 2. 初始化与按位访问

顺序表用三元组描述：`data` 指向连续空间首地址，`length` 为当前元素数，`maxSize` 为最大容量。

```cpp
struct SeqList {
    std::vector<int> data;            // 连续空间，由 vector 管理容量
    SeqList() : data() {}             // 初始化：length = 0，容量待分配
    int length() const { return static_cast<int>(data.size()); }
};
```

按位访问 `Get(i)` 分三步：检查 $0\le i<\text{length}$；按地址公式定位 `base + i*sizeof(ElemType)`，等价于下标 `data[i]`；返回该元素。地址由公式一次算出，不依赖表长，故时间复杂度 $O(1)$。

**注意**：随机访问 $O(1)$ 是顺序表的核心优势，链表做不到这一点。

### 3. 按值查找

在未排序的顺序表中查找值 $x$，从 `data[0]` 逐个比较，找到即返回下标，遍历完仍未找到返回 $-1$。

```cpp
int search(const SeqList& L, int x) {
    for (int i = 0; i < L.length(); ++i)
        if (L.data[i] == x)
            return i;                 // 找到，返回下标
    return -1;                        // 未找到
}
```

**动机**：为什么按值查找仍是 $O(n)$？因为"按下标算地址"的 $O(1)$ 只在已知下标时成立；按值查找不知道下标，只能线性比较。若每个值等概率，平均比较次数约 $n/2$，最坏 $n$ 次。

### 4. 插入

在下标 $i$（0 起始）处插入 $x$，合法范围是 $0\le i\le \text{length}$——注意 $i=\text{length}$ 表示表尾追加，合法。

```cpp
bool insert(SeqList& L, int i, int x) {
    if (i < 0 || i > L.length()) return false;   // 检查位置合法
    L.data.push_back(0);                         // 扩容一位（容量不足时由 vector 处理）
    for (int j = L.length() - 1; j > i; --j)
        L.data[j] = L.data[j - 1];               // 从后往前搬移
    L.data[i] = x;
    return true;
}
```

**规则**：后移必须从后往前进行——先把 `data[i]` 搬到 `data[i+1]`，再搬 `data[i-1]` 到 `data[i]`。若从前往后搬，前面的元素会覆盖尚未搬走的后面元素，造成数据丢失。

插入的代价由**移动次数**主导：表尾插入移动 0 次（最好，$O(1)$）；表头插入移动 $n$ 次（最坏，$O(n)$）；各位置等概率时平均移动 $n/2$ 次（$O(n)$）。

### 5. 删除

删除下标 $i$ 的元素，合法范围 $0\le i<\text{length}$（注意与插入的上界不同）。

```cpp
bool remove(SeqList& L, int i, int& out) {
    if (i < 0 || i >= L.length()) return false;  // 检查位置合法
    out = L.data[i];                             // 先保存被删元素
    for (int j = i; j + 1 < L.length(); ++j)
        L.data[j] = L.data[j + 1];               // 从前往后前移补位
    L.data.pop_back();
    return true;
}
```

**思路**：删除后由后继元素"填补空位"——从 $i$ 开始把每个后继前移一位。前移必须从前往后，理由与插入对称：若从后往前，前面元素会先被后面的覆盖。空间复杂度 $O(1)$。

删除复杂度：删表尾移动 0 次（$O(1)$）；删表头移动 $n-1$ 次（$O(n)$）；平均移动 $(n-1)/2$ 次（$O(n)$）。

### 6. 复杂度、容量与边界

把顺序表的结论汇总：

| 操作 | 时间复杂度 | 说明 |
|---|---|---|
| 按位访问 Get | $O(1)$ | 地址公式直接算出 |
| 按值查找 Search | $O(n)$ | 线性比较 |
| 插入 Insert | $O(n)$ | 平均移动 $n/2$ 个元素 |
| 删除 Remove | $O(n)$ | 平均移动 $(n-1)/2$ 个元素 |

**规则**：插入删除前先检查边界——`length < 0` 是异常，`length = 0` 是空表，`length = maxSize` 是满表。当 $i$ 越界或表满时应拒绝插入或先扩容。扩容的做法是申请更大的连续空间（通常翻倍），把原元素整体复制过去，再释放旧空间。

**注意**：顺序表适合元素相对稳定、读取频繁的场景。若插入删除成为主要操作，整体搬移的代价会使它不如链表。

## 三、线性表的链式存储实现

### 1. 结点与头指针

链式存储用指针表达逻辑次序。结点由数据域 `data` 和指针域 `next` 组成：

```cpp
struct LNode {
    int   data;                        // 数据域
    LNode* next = nullptr;             // 指针域，指向后继
};
using LinkList = LNode*;               // 头指针类型
```

四个要点：结点由 `data` 与 `next` 组成；头指针指向链表第一个结点；尾结点的 `next` 为 `nullptr`；结点的物理位置不必连续。

**动机**：既然物理位置任意，靠什么维持次序？靠每个结点的 `next` 串起后继。头指针是进入整条链的入口——一旦丢失，整条链就无法访问。

### 2. 头结点与空表

链表分"不带头结点"与"带头结点"两种。头结点是不保存有效数据的附加结点，位于首元结点之前。

- 不带头结点：空表判定 `head == nullptr`；对首元结点的插入删除要特殊处理（需修改 `head`）。
- 带头结点：空表判定 `head->next == nullptr`；头结点使首元操作与中间结点操作统一，无需特判。

**思路**：先明确约定（是否带头结点、空表如何表示），再写算法。两种约定下的判空条件、初值都不同，混用会导致隐蔽错误。本章后续代码默认带头结点。

### 3. 求表长与按位访问

链表长度不能像顺序表那样由地址公式直接得到，只能沿 `next` 逐结点计数：

```cpp
int length(const LinkList& head) {
    int cnt = 0;
    for (LNode* p = head->next; p != nullptr; p = p->next)
        ++cnt;
    return cnt;
}
```

按位访问 `Get(i)` 同样要顺着链走：从头结点出发，“走 $i$ 步”到达第 $i$ 个结点。

```cpp
LNode* getKth(const LinkList& head, int i) {
    LNode* p = head->next;
    for (int j = 0; p != nullptr && j < i; ++j)
        p = p->next;                   // 只能逐结点前进
    return p;                          // nullptr 表示越界
}
```

**注意**：不能按地址算第 $i$ 个结点，必须顺着 `next` 走，故时间复杂度 $O(n)$。这是链表失去随机访问的直接后果。

### 4. 按值查找

从首元结点开始，沿 `next` 逐个比较 `data`，找到返回该结点指针，走完链表返回 `nullptr`。

```cpp
LNode* search(const LinkList& head, int x) {
    LNode* p = head->next;
    while (p != nullptr && p->data != x)
        p = p->next;
    return p;                          // 找到返回结点，否则 nullptr
}
```

沿 `next` 移动并比较 `data`，时间复杂度 $O(n)$。

### 5. 插入

在结点 $p$ 之后插入新结点 $s$，真正改变的只有两条边。

```cpp
bool insertAfter(LNode* p, int x) {
    if (p == nullptr) return false;
    LNode* s = new LNode{x, p->next};   // 新结点后继先指向 p 的原后继
    p->next = s;                       // 再让 p 指向新结点
    return true;
}
```

**规则**：两条赋值顺序不能颠倒。必须先 `s->next = p->next` 保存后继，再 `p->next = s`。若先改 `p->next = s`，原后继就再也找不到了，后半条链会丢失。注意 `new` 申请结点，删除时用 `delete` 配对释放。

**动机**：与顺序表对比——链表的插入一旦定位到前驱，修改指针只需 $O(1)$；但"定位到第 $i-1$ 个前驱"本身要 $O(n)$。这解释了为什么链表插入不能笼统说成 $O(1)$。

### 6. 删除

跨过目标结点 $q$：找到前驱 $p$，令 `p->next` 指向 `q->next`，再释放 $q$。

```cpp
bool removeAfter(LNode* p, int& out) {
    if (p == nullptr || p->next == nullptr) return false;
    LNode* q = p->next;                // q 为待删结点
    out = q->data;
    p->next = q->next;                 // 跨过 q
    delete q;                          // 释放空间，避免内存泄漏
    return true;
}
```

**注意**：指针重连与空间释放缺一不可——只断链不 `delete` 会泄漏内存；只 `delete` 不断链会产生悬空指针。删除首元结点时前驱是头结点，故带头结点的写法无需特判。

### 7. 复杂度与结构不变量

链表操作的成本要拆成"定位"与"修改"两段看。

| 阶段 | 操作 | 复杂度 |
|---|---|---|
| 定位 | 按位/按值找到前驱结点 $p$ | $O(n)$ |
| 修改 | 已知 $p$，改指针完成插入删除 | $O(1)$ |

总成本 $=O(n)+O(1)=O(n)$。

**概念** 结构不变量：任何时刻每个结点的 `next` 都指向正确的后继，链不能被改断。插入时"先接后断"、删除时"先跨后放"，都是为了维持这个不变量。

### 8. 双向链表

单链表只能向后走；双向链表在每个结点多一个 `prev` 指针，用空间换取双向移动。

```cpp
struct DNode {
    int   data;
    DNode* prev = nullptr;
    DNode* next = nullptr;
};
```

在 $p$ 与 $q$ 之间插入 $x$，要维护四条链接：

```cpp
x->next = p->next;     // 1
x->prev = p;           // 2
p->next = x;           // 3
x->next->prev = x;     // 4（此时 x->next 即原 q）
```

删除 $x$ 时令 `x->prev->next = x->next` 且 `x->next->prev = x->prev`，前向与后向链接必须成对更新。

**动机**：适用场景是频繁双向遍历，或"已知目标结点时要删除它"——单链表删除需先找前驱（$O(n)$），双向链表可直接由目标结点拿到前驱（$O(1)$）。

### 9. 循环链表

循环链表让尾结点不再是 `nullptr`，而是回指头结点，形成首尾相接的环。

- 单向循环：尾结点的 `next` 指回头结点 `H`；
- 双向循环：进一步让头结点的 `prev` 指向尾结点 `tail`，尾结点的 `next` 指向 `H`。

**注意**：遍历终止条件变了——必须判断"回到起点" `p == start`，而不是 `p == nullptr`；否则会陷入死循环。单向循环从任一结点出发可遍历全表；带头结点时判空仍是 `head->next == head`。

**思路**：仅有尾指针的单向循环链表很实用——尾插时新结点接在 `tail` 之后 $O(1)$，头删时头结点就是 `tail->next`，同样 $O(1)$。这是链式队列的经典实现基础（见 [[第3章-栈与队列.md]]）。

### 10. 静态链表

静态链表用数组模拟链表：数组下标充当指针，结点仍存放 `data` 与 `next`（此处 `next` 存的是下标）。

**思路**：逻辑次序由 `next` 下标决定，与数组物理位置无关。课件例子中逻辑次序 $A\to B\to C\to D$ 对应的物理位置是下标 3、6、1、5。它适合缺少动态指针机制的环境（如早期 Fortran），本质是"固定存储池 + 游标"。本课只要求识别结构与基本思想，不展开算法。

### 11. 块状链表

块状链表是苏鑫课件列为重难点的扩展结构，陈越体系没有。它要同时拿到顺序表的局部性与链表的增长能力：**每个块是一个字符数组，块与块用指针相连**。

```cpp
static const int B = 256;              // 块容量：每块存 B 个字符

struct BlockNode {
    char  data[B];                     // 字符数组，存 B 个字符
    int   len = 0;                     // 本块已存字符数
    BlockNode* next = nullptr;         // 指向下一块（指针 8 字节）
};
using BlockList = BlockNode*;
```

**概念** 存储密度 $=\dfrac{B}{B+8}$。每个块存 $B$ 个有效字符，代价是一个 8 字节指针（64 位机器）。$B$ 越大密度越接近 1，越像顺序存储；$B$ 越小密度越低，指针开销占比越大。这揭示了块大小选择的核心矛盾：大块提高密度，小块提高插入删除的灵活性。

**动机**：纯顺序表插入删除要搬移 $O(n)$ 个元素；纯链表的随机访问要 $O(n)$。块状链表把大数组切成若干块，操作只在一个块内局部进行，块间用指针跳过——这就是"顺序存储的局部性 × 链式存储的增长能力"。

**操作成本 = 块内移动 + 块间遍历**：

- 随机访问第 $i$ 个字符：先从表头沿块链找到所在块，需经过 $m$ 个块（$m\approx n/B$），再在块内数组按下标取字符 $O(1)$。所以访问代价从顺序表的 $O(1)$ **退化**为 $O(m)=O(n/B)$：块越大，块数越少，退化越轻。
- 插入/删除：定位到块后，只在块内数组里移动最多 $B$ 个字符，代价 $O(B)$，远小于整表的 $O(n)$。

**规则**：块分裂与块合并维持结构平衡。插入后某块字符数超过 $B$ 时**分裂**——把该块拆成两个各约 $B/2$ 的块，串接进链；删除后某块字符数过少（低于 $B/2$）时**合并**——与相邻块拼成一个块，释放多余块。分裂保证块不过满、插入有空间；合并保证块不过碎、密度不下降、块数可控。

**思路**：若取 $B\approx\sqrt n$，则块数 $m\approx\sqrt n$，随机访问 $O(\sqrt n)$、单次插入 $O(\sqrt n)$，是两种极端结构之间的折中。课件只讲结构不展开算法，但存储密度、随机访问退化、分裂合并三者是理解它的关键。

## 四、广义表与多重链表

### 1. 广义表

**概念** 广义表是线性表的推广：元素既可以是原子（单元素），也可以是子表。例如 $A=(a,(b,c),d)$ 中，$(b,c)$ 是子表，它构成第二层。广义表能表达嵌套、层次与递归结构。

实现上用标志域区分两类结点：表结点 `tag=1`，含 `head`、`tail` 两个指针域，分别指向表的第一个元素与其余部分；原子结点 `tag=0`，只存一个 atom 值。

```cpp
struct GNode {
    int tag;                           // 0 = 原子，1 = 子表
    union {
        char atom;                     // tag = 0 时有效
        struct { GNode* head; GNode* next; } sub;  // tag = 1 时有效
    };
};
```

**注意**：`union` 让两类结点共享同一空间，用 `tag` 解释当前含义，节省存储。广义表的用途是表示嵌套与层次数据；本课不展开遍历算法。

### 2. 多重链表与十字链表

多重链表的结点可同时属于多个链表，即含多个指针域。

**注意**：双向链表不算多重链表——它的两个指针串的是同一条链。十字链表才是典型：每个非零元素结点同时存放在"行链"和"列链"中，用 `right` 串同行、用 `down` 串同列。

**思路**：稀疏矩阵只存非零元三元组（行、列、值），再用十字链表把同一行、同一列的非零元分别串起来，既压缩了存储，又保留了按行/按列快速访问的能力。舞蹈链（Dancing Links）在此基础上支持结点的快速删除与恢复，用于精确覆盖搜索。三者概念相承：压缩存储 → 双向组织 → 删除与恢复 → 精确覆盖。本课只看思想，不展开算法。

### 3. 多维数组与特殊矩阵

多维数组最终映射到一维连续地址空间。以 $4\times4$ 矩阵为例，行优先按 $a_{00},a_{01},a_{02},a_{03},a_{10},\ldots$ 存放，列优先按 $a_{00},a_{10},a_{20},a_{30},a_{01},\ldots$ 存放。

**概念** 对称矩阵、三角矩阵、带状矩阵中大量元素是重复的或恒为零的，只保存必要元素即可，从而压缩存储。课件只介绍映射与压缩思想，不展开公式推导——但要点明确：把二维下标映射成一维地址，再对特殊矩阵只存必要部分以省空间。

## 五、线性表的应用

### 1. 用有序单链表表示多项式

一元多项式的关键信息是每项的系数 `coef` 与指数 `expon`。用结点存一个非零项，按指数递减排列：

```cpp
struct PolyNode {
    int coef;                          // 系数
    int expon;                         // 指数
    PolyNode* next = nullptr;
};
```

例如 $A(x)=5x^6-3x^3+2x-7$ 存成链 $(5,6)\to(-3,3)\to(2,1)\to(-7,0)$。

四个要点：每个结点保存系数、指数和 `next`；各项按指数递减排列；零系数项通常不存储；有序性为合并算法提供条件。

**思路**：多项式相加像归并一样前进——两个指针分别扫描两条有序链，比较当前项指数：指数大者先挂到结果并前移；指数相等则系数相加，和不为零才挂接，然后两者都前移。因每条链只扫描一遍，时间复杂度 $O(m+n)$，辅助空间 $O(1)$。

### 2. 大整数的链式表示与加法

机器整数位数有限，要表示超大整数，可用链表分块存储：固定每块 4 位，每个结点存一块数字，块值范围 $0\sim9999$。

**思路**：从低位块到高位块逐块相加，每块相加后取模写入、进位向高位传播。例如低位块 $9999+0002=10001$，写 $0001$ 并向高位进 $1$；下一块 $7654+2345+1=10000$，写 $0000$ 再进 $1$。链式表示可突破机器整数类型的位数限制。

**动机**：这与多项式的思路同源——把"大对象"拆成有序的"小块序列"，用线性表组织，再按位归并处理。块大小固定（4 位）正是块状链表思想的一个具体应用。

### 3. 内存管理中的空闲链表

操作系统把空闲内存块组织成按地址或大小排序的空闲块表，这正是有序线性表的应用。

**思路**：分配时查找满足需求的空闲块并按需切分——申请 20 KB 时找到 32 KB 块，切出 20 KB 分配，剩余 12 KB 仍留在表中；释放时把块插回空闲表，并与物理相邻空闲块合并，避免碎片化。

**概念** 内部碎片是已分配块内部未使用的空间；外部碎片是空闲空间分散、难以满足大块申请。线性表在这里的价值是维护有序可用区间——有序性让查找可提前结束，合并让区间尽量连续。

## 本章小结

> 本章先把一类具体问题抽象为线性表，明确其 ADT 与"唯一前驱、唯一后继、首尾边界"三个关键词，再沿顺序与链式两条路线实现。顺序表靠地址公式获得 $O(1)$ 随机访问，代价是插入删除平均搬移 $O(n)$ 个元素；链表靠指针获得 $O(1)$ 的定位后修改，代价是访问要顺链 $O(n)$。在此基础上补充双向链表、循环链表、静态链表，以及作为重难点的块状链表——用存储密度 $B/(B+8)$、随机访问退化和块分裂合并三种视角理解它。最后用多项式、大整数、空闲块表三个应用说明线性表的价值在于"把无序问题组织成有序序列"。下一章 [[第3章-栈与队列.md]] 将讨论两种访问受限的线性表。
