# 第 05 讲 树（下）：堆、哈夫曼树与并查集

> 本讲依据视频 051–064（5.1 堆、5.2 哈夫曼树、5.3 集合表示与查找、小白专场堆中的路径与 File Transfer）整理。
> 学习目标：掌握最大/最小堆的插入、删除与线性建堆；理解哈夫曼树的构造与前缀编码；掌握并查集的双亲表示、按秩归并与路径压缩，能分析其均摊复杂度。

## 一、优先队列与堆

### 1. 什么是堆

CPU 调度、任务排队等场景需要"每次取优先级最高的元素"——即优先队列。朴素实现（无序数组/链表/有序数组/有序链表）总有一侧是 $O(n)$；二叉搜索树又会因反复删根而歪掉。

**堆**：用**完全二叉树**存储，且任一结点的值不小于（最大堆）/不大于（最小堆）其左右子树中的所有结点。完全二叉树天然适合数组存储：根在下标 1，$i$ 的左右孩子在 $2i$、$2i+1$，父结点在 $\lfloor i/2\rfloor$。从根到任意结点的路径值单调递减（最大堆）或递增（最小堆）。

### 2. 插入（最大堆）

把新元素先放到数组末尾，再沿父结点方向向上"筛"：若比父结点大，则父子交换（或父结点下移、新元素上提），直到满足堆序或到达根。在 `H[0]` 放一个比所有元素都大的**哨兵**，可省去 `i>1` 的边界判断。时间 $O(\log n)$。

### 3. 删除（最大堆）

删除的一定是根。把数组最后一个元素临时覆盖到根（Size--），再沿孩子方向向下"筛"：在左右孩子中选较大者与临时值比较，若孩子更大则孩子上提、父指针下移，直到临时值不小于两孩子。时间 $O(\log n)$。

### 4. 建堆

逐次插入 $n$ 个元素需 $O(n\log n)$。**线性建堆**：先把 $n$ 个元素按顺序放入数组形成完全二叉树，再从最后一个非叶结点（下标 $\lfloor n/2\rfloor$）向前，对每个结点做一次"向下筛"（与堆删除的下沉过程相同）。当处理到某结点时，其左右子树都已是堆，一次下沉即可把该子树调成堆。总复杂度 $O(n)$。

【进阶】堆与二叉堆的完整内容见 OI-Wiki：[数据结构/堆](../OI-Wiki/数据结构/堆.md)、[数据结构/二叉堆](../OI-Wiki/数据结构/二叉堆.md)。

## 二、哈夫曼树与哈夫曼编码

### 1. 带权路径长度 WPL

给定 $n$ 个带权叶结点，二叉树的**带权路径长度** $WPL=\sum w_k l_k$（$l_k$ 为叶结点到根的路径长度）。使 WPL 最小的二叉树即**哈夫曼树**（最优二叉树）。例如把百分制成绩分档时，让高频段靠近根、低频段远离根，平均比较次数最少。

### 2. 哈夫曼树的构造

反复选择权值最小的两个结点合并，新结点权值为二者之和，再放回集合；直到只剩一棵树。用最小堆可在 $O(n\log n)$ 内完成。

性质：

- 哈夫曼树中**没有度为 1 的结点**；若有 $n$ 个叶结点，则总结点数为 $2n-1$（由 $n_0=n_2+1$ 得 $n_2=n-1$）。
- 左右子树交换仍是哈夫曼树。
- 当存在多个并列最小值时，可能得到不同构的哈夫曼树，但 WPL 唯一。

### 3. 哈夫曼编码

不等长编码要避免**二义性**，必须使用**前缀码**：任一字符的编码不是另一字符编码的前缀。把字符放在二叉树叶结点上、左分支标 0 右分支标 1，从根到叶的路径即该字符编码——叶结点位置天然保证前缀性质。

按字符频率构造哈夫曼树，频率高的字符离根近、编码短，总编码长度即 WPL，达到最小。等长码（如 ASCII）虽然实现简单，但未利用频率差异；哈夫曼编码是最优前缀编码。

【进阶】哈夫曼树的性质与应用见 OI-Wiki：[数据结构/哈夫曼树](../OI-Wiki/数据结构/哈夫曼树.md)。

## 三、并查集（集合的表示与合并）

### 1. 应用场景

$n$ 台电脑，不断给出"两台电脑之间连了线"，并随时询问两台电脑是否连通。连通关系具有传递性，本质是不断把两个集合合并、查询某元素属于哪个集合——这就是**并查集**（Disjoint Set Union, DSU）。

### 2. 双亲表示法

用一棵树表示一个集合，**树根代表集合名**。结点需要的信息是"父亲是谁"而非"孩子是谁"，故用**双亲表示法**：数组 `S[]` 中 `S[i]` 存 $i$ 的父结点下标；根结点存 `-1`。

进一步简化：若元素本身就是 $0\sim n-1$ 的整数（如电脑编号减一），则**元素下标直接就是结点编号**，连 `Data` 域都不需要。查找根即沿 `S[i]` 一路向上，直到遇到负值。

### 3. 朴素并运算及其问题

把两棵树合并：`S[root2] = root1`（或反之）。若不加控制，反复合并会使树退化成单链，最坏一次 Find 需 $O(n)$，$n$ 次操作达 $O(n^2)$，在 PTA 上直接超时。

### 4. 按秩归并

把**矮树贴到高树上**，或**小树并到大树上**，避免树高增长。巧妙之处在于不另开数组：根结点的负值除了"标记是根"外，其绝对值还可用来表示**树高**或**集合规模**。

- 按高度归并：根结点存 `-高度`。两树等高才把新树高加 1（即根值再减 1）；不等高时高树高度不变。
- 按规模归并：根结点存 `-元素数`。合并后新根值等于两树规模之和（仍为负）。

两种统称**按秩归并**。任意一种都能保证最坏树高为 $O(\log n)$，$n$ 次操作总复杂度 $O(n\log n)$。

### 5. 路径压缩

在 Find 中，找到根之后，把查找路径上经过的每个结点**直接挂到根下面**：

```
if S[x] < 0: return x
else: return S[x] = Find(S[x])
```

一次 Find 看似多做了几次赋值，却把这条路径压扁；之后再查这条路径上的任何结点都接近 $O(1)$。

按秩归并 + 路径压缩交错执行时，$m$ 次查找、$n-1$ 次合并的总复杂度为 $\Theta(m\,\alpha(m,n))$，其中 $\alpha$ 是 Ackermann 反函数（$\log^*$ 量级）。对实际可处理的 $n$，$\alpha$ 不超过 4，工程上可视为常数。

【进阶】并查集的实现、复杂度证明与应用见 OI-Wiki：[数据结构/并查集](../OI-Wiki/数据结构/并查集.md)、[数据结构/并查集复杂度](../OI-Wiki/数据结构/并查集复杂度.md)、[专题/并查集应用](../OI-Wiki/专题/并查集应用.md)。

## 四、小白专场：堆中的路径

给定 $n$ 个元素依次插入空的最小堆，再给出 $m$ 个下标，要求输出从该下标结点到根路径上的所有结点值。最小堆用数组 `H[]` 加哨兵 `H[0] = -inf` 实现，插入即"向上筛"：`i = ++Size; while (H[i/2] > X) { H[i] = H[i/2]; i /= 2; } H[i] = X;`。查询时从给定下标 $j$ 出发，不断 `Print H[j]; j /= 2;` 直到 $j=0$（哨兵处停止）。

## 五、小白专场：File Transfer（并查集应用）

- **题意**：$n$ 台电脑，输入三种指令——`C a b` 查询连通性，`I a b` 连边，`S` 结束并报告连通分量个数。
- **程序框架**：
  1. 初始化 `S[i] = -1`；
  2. `C a b`：`Find(a-1)` 与 `Find(b-1)` 比较，相同输出 `yes`，否则 `no`；
  3. `I a b`：先 Find 两元素根，不同则 Union；
  4. `S`：扫描数组统计负值个数，1 则输出"The network is connected."，否则输出"There are X components."。
- **性能演进**：朴素版（TSSN）在第 6 个测试点超时；调换 Union 方向后另一个测试点超时；加上按秩归并后通过；再叠加路径压缩后达到理论最优。这组对比直观展示了并查集优化的必要性。
