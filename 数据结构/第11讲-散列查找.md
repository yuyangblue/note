# 第 11 讲 散列查找

> 本讲依据视频 124–135（11.1 散列基本思路与散列表、11.2 散列函数构造、11.3 冲突解决、11.4 性能分析、11.5 单词词频统计）整理。
> 学习目标：理解散列"由关键字直接计算地址"的核心思想；掌握除留余数等散列函数构造方法；掌握开放定址（线性/平方探测）与分离链接两类冲突解决策略；能用装填因子与平均查找长度分析散列表性能。

## 一、散列的基本思路

### 1. 为什么需要散列

典型场景：编译器管理变量名。遇到一个变量名，要查它是否定义过、是什么类型。用二分查找要求有序且不便于动态插入；用 AVL 树虽是 O(log N)，但每次比较都要把两个字符串逐字符比下去，很慢。

散列的思路是：设计一个函数，把关键字（哪怕是字符串）直接映射成一个整数地址，放进去和取出来都用同一个函数算位置。如果映射得均匀、冲突少，查找就是常数时间，与数据规模几乎无关。

### 2. 什么是散列表

散列表管理的是"名字 + 属性"二元组的集合（符号表），支持 Init、Find、Insert、Delete。用求余作散列函数：表长 M（常取素数），关键字 key 映射到 key mod M 的位置放元素；查找时用同样函数算出位置，若该位为空（且无删除）即可断定关键字不在表中。

**装填因子** α = 已放元素数 / 表长。它衡量表被填的程度，直接决定冲突多少。

散列要解决两件事：①设计好的散列函数（计算快、映射均匀）；②设计冲突解决策略。

## 二、散列函数的构造

设计原则：计算方便；把不同对象均匀映射到地址空间。

### 1. 数字关键字

- **直接定址法**：散列函数取线性函数，如年份 1990–2011 映射到 0–21，直接 key − 1990。
- **除留余数法**：最常用，H(key) = key mod p，p 一般取表长且为素数，以保证映射均匀。
- **数字分析法**：分析关键字各位的变化规律，取出随机变化大的几位作地址。如手机号后 4 位最随机；身份证号取其中变化随机的几位组合。
- **折叠法**：把长数字拆成几段叠加求和，取结果末几位作地址。
- **平方取中法**：把关键字平方后取中间几位，使每一位都影响结果。

### 2. 字符串关键字

简单做法是把每个字符的 ASCII 相加再求余，但值域太窄（10 位字符相加也只到 0–1270），极易聚集、冲突。

改进：把整个字符串看成一个 **R 进制数**逐位展开（如 R = 32，因为字母加少量符号约 27–32 种）。巧妙的递推计算是：初始值为 0，每读一个字符就把当前值"乘 R 再加字符值"——乘 32 可用左移 5 位实现，最后求余得到地址。这样字符串的每一位都参与了映射。

【进阶】散列函数与哈希表的系统内容见 OI-Wiki：[数据结构/哈希](../OI-Wiki/数据结构/哈希.md)。

## 三、冲突解决：开放定址法

冲突时按某种规则在表内找下一个空位：Hᵢ(key) = (H(key) + dᵢ) mod M。

### 1. 线性探测

dᵢ = i：冲突就依次往后试 H+1、H+2……。实现简单，但会产生**聚集（primary clustering）**——冲突连成一片，越长越容易再冲突。

**平均查找长度 ASL**：成功 ASL = 各元素冲突次数加 1 后求平均；不成功 ASL 则按散列地址分类，同类入口查找过程相同，逐类数到空位为止。线性探测下空位即"不在表中"的终止判据（前提是不真删除）。

### 2. 平方探测（二次探测）

dᵢ = ±i²：探测序列为 H、H+1、H−1、H+4、H−4……，来回跳着找，能显著缓解聚集。但它可能"表有空位却跳不到"。结论：当表长 M 取形如 4k+3 的素数时，只要有空位就一定能找到。

### 3. 平方探测的实现要点

- 表长用 NextPrime 向上取最近素数；
- 每个位置加一个 Info 状态（Empty / Occupied / Deleted），删除用**懒惰删除**：只打标记不真删，否则会断掉后续探测链、误判元素不在表中；
- 用一个计数器 CNum 控制正负号交替：奇数次探测加 i²、偶数次减 i²；
- 越界位置通过反复加减 TableSize 拉回 [0, TableSize)。

### 4. 再散列（Rehashing）

装填因子过高（一般超过 0.85 不可接受，最好控制在 0.5 附近）时，把表扩大为约两倍的新素数表，把旧元素全部按新表长重新散列插入。

## 四、分离链接法（链地址法）

把散列地址相同的元素挂到同一个单向链表上：表数组的每个分量是一个链表头指针。插入就挂到表头，查找就先定位到对应链表再遍历。

- 删除直接摘掉结点，比开放定址方便；
- 表长可能超过表数组大小（装填因子可大于 1）；
- 查找时链表越长越慢，但均匀分摊下平均长度很短。

## 五、散列表的性能分析

散列查找性能取决于三个因素：散列函数是否均匀、冲突解决方法、装填因子 α。

理论平均探测次数（成功 / 不成功或插入）：

- 线性探测：α = 0.5 时成功约 1.5 次、不成功约 2.5 次；α 增大后不成功次数上升极快；
- 平方探测/双散列：α = 0.5 时成功约 1.39、不成功约 2 次，增长更平缓；
- 分离链接：α = 1 时成功约 1.5、不成功（即插入）约 1.37 次。

经验：开放定址法装填因子最好不超过 0.85，线性探测还要更低。

**散列查找的特点总结**：

- 优点：不冲突时一次命中，平均是常数时间，与规模无关；特别适合字符串等关键字比较昂贵的场合；本质是以空间换时间。
- 缺点：不支持找最大/最小、范围查询这类有序性操作（搜索树擅长）。
- 开放定址法省空间、数组操作快但易聚集；分离链接法删除方便、可超容，但链表过长时变慢。

## 六、应用：文件中单词词频统计

给定英文文本，统计所有单词出现频率，输出最高频的前 10% 单词。

- **切词（词法分析）**：单词由大小写字母、数字、下划线组成，其余字符都是分隔符；GetAWord 逐字符把一个单词切出来。
- **动态查找**：每个单词查表，命中则词频 +1，未命中则插入并把词频置 1——正是散列表的 Insert + Count。
- **输出前 10%**：先扫一遍表找最大词频；再开一个数组按词频计数（出现 1 次、2 次……各有多少单词）；据此算出"前 10%"的词频阈值；最后输出达到阈值的单词与词频。
- 短于 3 个字符的串可忽略，结束时 DestroyTable 释放空间。
