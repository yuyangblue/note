## 一、快速排序

### 1. 分治框架与最好/最坏情况

**动机**：没有任何一种排序算法在所有情况下都最好，快速排序也一样——总能构造出让它表现很糟的最坏情况。但对大规模随机数据，只要把每个细节实现到位，它的实际表现相当出色；而它恰恰是"自己写很容易写错"的典型，一个细节没做好就不快了。

**思路**：与归并排序同样是分而治之。从待排数组中取一个**主元**（pivot），把除它以外的元素分成"≤ 主元"和"≥ 主元"两个子集，再递归排两边，最后拼成「左 + 主元 + 右」：

```cpp
void QuickSort(int A[], int N) {
    if (N <= 1) return;                     // 最小集合：1 个元素直接返回
    int pivot = Median3(A, 0, N - 1);
    // 按 pivot 划分出左、右两段（此处为示意，实现见 §5）
    QuickSort(A, leftSize);
    QuickSort(A + leftSize + 1, N - leftSize - 1);
}
```

递归出口是 $N=1$：只有一个元素就不用再排。

**注意**：快排的效率全押在两件事上——**主元选得好不好**、**划分是不是线性时间**。主元选得不好，它就一点都不快；划分过程若耗时太多，同样快不起来。先看两个极端：

- **最好情况**：每次主元都恰好取在中位，把数组等分。这是标准的分治递推，$T(N)=2T(N/2)+O(N)$，得 $O(N\log N)$。
- **最坏情况**：主元总是取到当前序列的最小值（例如输入本身有序、又总取第一个元素作主元），划分出"空集 + $N-1$ 个元素"，递归深度 $N$。此时 $T(N)=T(N-1)+O(N)$，得 $O(N^2)$。

这两个极端决定了后面所有优化的方向：主元要往中位靠，划分要线性。

### 2. 选主元：Median3

**动机**：直接取 `A[0]` 作主元很不明智。若输入已有序，`A[0]` 就是最小元，每一次划分都退化成"空 + $N-1$"，于是 $O(N^2)$——写了个递归函数，结果什么也没做，还慢得离谱。

**思路**：随机取是安全的，但随机函数不便宜。经典做法是**取头、中、尾三个位置的中位数**（Median-of-Three），比随机函数便宜得多。也可以 five-number median、seven-number median，代价略高但更稳。

**规则**：Median3 除了返回主元值，还要顺手把这三个位置排好——小的放 `left`、大的放 `right`、中位数放 `center`。三步比较交换即可：

```cpp
int Median3(int A[], int Left, int Right) {
    int Center = (Left + Right) / 2;
    if (A[Left] > A[Center]) swap(A[Left], A[Center]);
    if (A[Left] > A[Right])  swap(A[Left], A[Right]);
    if (A[Center] > A[Right]) swap(A[Center], A[Right]);
    // 此时 A[Left] ≤ A[Center] ≤ A[Right]
    swap(A[Center], A[Right - 1]);          // 主元藏到 right-1
    return A[Right - 1];
}
```

注意最后那一步"耍的小聪明"：把中位数藏到 `Right-1`。因为头、尾两个位置已经确定分别小于、大于主元，划分时**根本不用考虑它们**，只需处理 `Left+1 .. Right-2` 这一段；把主元放在待处理段的最右端，划分时腾挪最方便。这也是返回值取 `A[Right-1]` 的原因。

### 3. 子集划分

**思路**：设两个"指针" `i`、`j`（其实是数组下标，不是 C 的指针类型）。`i` 从左边向右扫，遇到**大于**主元的元素就停下（它不该待在左边）；`j` 从右边向左扫，遇到**小于**主元的元素就停下；把两者交换，继续扫描，直到 `i` 越过 `j`。

以主元 6 为例（头尾已由 Median3 归位、主元藏在最右）：`i` 指到 8 > 6 停下，`j` 从右扫到 2 < 6 停下，交换二者；`i` 继续走，遇到 9 > 6 停，`j` 退到 5 < 6 停，再交换……最后 `i` 越过 `j`，把主元与 `A[i]` 交换，6 就落在它的最终位置。

**注意**：快排之所以快，关键就在这一步——**主元一经划分就被一次性放到最终正确位置，以后再也不动**。对比插入排序，每次插入会让一堆元素的位置变成临时的，下一张牌进来又要整体后移，同一元素可能被搬很多次。

**规则：碰到等于主元的元素怎么办？** 两种选择，效果截然不同：

- **停下来交换**（本笔记与课件采用）：全等序列（全是 1）时会产生大量无谓交换，但 `i`、`j` 最终停在中间，主元落到中点，每次递归都近似等分——代价是多做了些交换，换来 $O(N\log N)$。
- **不停、继续移动指针**：避免了无谓交换，但全等序列里主元总被放到端点，退化成 $O(N^2)$。

两害相权，选择前者——**宁可多做几次交换，也不要退化**。

### 4. cut off：小规模改用插入排序

**动机**：快排是递归的，递归要占用系统堆栈，每次调用都有大串的进栈出栈，很慢。当数据规模很小时（比如不到 100 个元素），调一次快排还不如直接用简单插入排序快。

**规则**：设一个阈值 `Cutoff`（砍掉多长的一段，由实现者决定）。当当前待排规模小于 `Cutoff` 时**不再递归**，直接调用插入排序返回结果。这样既避开小数据上递归的开销，又不影响大数据上的分治效率。

### 5. 完整实现

把主元、划分、递归、cutoff 拼起来，注意划分循环里先 `++i` / `--j` 再比较（因为 `Left`、`Right-1` 两个边界位已由 Median3 处理过）：

```cpp
void InsertionSort(int A[], int N);          // 第 09 讲的插入排序

void Quicksort(int A[], int Left, int Right) {
    if (Right - Left >= CUTOFF) {            // 规模够大才递归
        int pivot = Median3(A, Left, Right);
        int i = Left, j = Right - 1;
        while (true) {
            while (A[++i] < pivot) {}        // 找到左边第一个 ≥ 主元的
            while (A[--j] > pivot) {}        // 找到右边第一个 ≤ 主元的
            if (i < j) swap(A[i], A[j]);     // 中间还有元素才交换
            else       break;                // i 越过 j，划分结束
        }
        swap(A[i], A[Right - 1]);            // 主元归位
        Quicksort(A, Left, i - 1);           // 递归左半
        Quicksort(A, i + 1, Right);          // 递归右半
    } else {
        InsertionSort(A + Left, Right - Left + 1);  // 小规模直接插入
    }
}

void QuickSort(int A[], int N) {             // 符合统一接口的壳
    Quicksort(A, 0, N - 1);
}
```

**注意**这个"套壳"：`Quicksort` 递归时需要知道当前的左右端，不符合"只传数组和 N"的统一接口；所以外面包一层 `QuickSort`，把起始的 `0` 和 `N-1` 填进去即可。

【进阶】完整实现与不同选主元策略的实测见 OI-Wiki：[算法基础/快速排序](../OI-Wiki/算法基础/快速排序.md)、ICPC：[01-算法基础/02-排序](../ICPC/01-算法基础/02-排序.md)。

## 二、表排序（间接排序）

**动机**：前面的排序都在交换元素本身。若每个待排元素是一个庞大的结构（一本书、一部电影），移动一次的代价不可忽略，频繁交换就变得很恐怖。

**思路**：**不移动元素本身，只移动指向它们位置的"指针"**。定义一个指针数组 `Table`（这里的"指针"只是数组下标，不是 C 的指针类型），初始 `Table[i] = i`，即 `Table[i]` 指向 `A[i]`。此后对 `Table` 排序，比较时用 `A[Table[i]]` 的关键字，交换时只换 `Table` 里的整数。

**规则**：排序完成后，第 0 个该输出的元素是 `A[Table[0]]`，第 1 个是 `A[Table[1]]`，依此类推。若只要求按顺序输出，**一本书都不用动**，照 `Table` 的顺序读出来即可。

注意：表排序对底层用什么排序算法没有要求——上面用插入排序只是演示，任何排序都能套这个"间接"的壳。复杂度多出一个因子：元素移动变成常数时间的下标交换，但比较时要多一次间接寻址。

## 三、物理排序：按环归位

**动机**：若最后**非得把元素物理上排好**（真的要把书按顺序摆上架），怎样在表排序之后高效地搬？

**思路**：利用一个关键结论——**$N$ 个数字的排列一定由若干个互不相交的环组成**。以 `Table` 为例：`Table[0]=3`，就跳到 `Table[3]=1`，再跳到 `Table[1]=5`，再 `Table[5]=0`，回到起点，这四个下标构成一个环。找环时跳过已归位的位置，直到覆盖全部。

**规则**：对一个环，先把首位置的元素取出来暂存到临时变量（书架空出一格）；`Table[0]=3` 说明这格该放原 `A[3]`，搬过来；新空格又是 `Table[3]=1` 该放的位置……直到该放的是最初取走的那本书，从临时变量放回，环结束。

**如何判断环结束**：每当放好一本书，就把它的 `Table[i]` 改写成 `i`（表示已归位）。回头遇到 `Table[i] == i` 时，说明这本书已经放对，不必再搬，环到此为止。

**复杂度**：每个元素至多搬一次；最坏是所有环都是二元环（两两交换），每次交换要走"取出—搬入—放回"三步，共 $N/2$ 个环，即 $3N/2$ 次移动，仍是 $O(N)$。但若单次元素复制的代价是 $m$，整体是 $O(mN)$——这时常数不能忽略。

## 四、桶排序

**动机**：前面所有排序算法都只靠**比较大小**决定位置；有定理说，纯比较排序的最坏情况下界是 $O(N\log N)$。想更快，就得**除了比较还干点别的**。

**思路**：当待排数据的值域很小（只有 $M$ 种可能）时，为每种可能建一个"桶"。例如 4 万个学生、成绩只有 0–100 分（$M=101$）：建 101 个空链表，成绩 88 的学生就插进 88 号桶的链表表头。输出时按桶号从 0 扫到 100，逐桶输出链表，自然有序。

```cpp
void BucketSort(int A[], int N, int M) {
    vector<vector<int>> count(M);             // M 个桶
    for (int i = 0; i < N; ++i)
        count[A[i]].push_back(A[i]);          // 按值入桶
    for (int i = 0; i < M; ++i)                // 按桶号依次输出
        for (int x : count[i]) cout << x << " ";
}
```

**复杂度**：$O(M+N)$——入桶 $O(N)$，扫桶 $O(M)$。当 $M \ll N$（4 万学生、101 个分数）时几乎是线性。

**注意**：桶排序的命门正是 $M$。**当 $M \gg N$ 就不合算了**——比如 10 个数、值域 0–999（$M=1000\approx N^3$），为 10 个数建 1000 个桶纯属浪费。基数排序正是为解决这种情形而来。

## 五、基数排序

### 1. 次位优先 LSD

**思路**：值域虽大，但每个数的**位数很少**（0–999 最多三位，每位只有 10 种可能），而"基数就是每位的进制"。于是按位建桶（十进制建 10 个桶），一位一位地排。**次位优先**（Least Significant Digit First，LSD）从个位开始：

以 `64, 8, 216, 512, 27, 729, 0, 1, 343, 125` 为例——

- **第一趟按个位**入 10 个桶：64→4 号、8→8 号、216→6 号……收集成一串；
- **第二趟按十位**入桶：0、1、8 的十位是 0 聚在一起，5 进 1 号、343 进 4 号……再收集；
- **第三趟按百位**入桶后收集，得到 `0 1 8 27 64 125 216 343 512 729`，完全有序。

**规则**：每一趟都是"分配（按当前位入桶）→ 收集（按桶号串起来）"。关键是**次位优先时收集必须保持桶内顺序（稳定）**，否则前面排好的低位次序会被打乱。

**复杂度**：共 $P$ 趟（$P$ 是位数），每趟 $N+B$（$N$ 个数入桶、$B$ 个桶要扫），总计 $O(P(N+B))$，其中 $B$ 是基数。当基数小、位数少时接近线性，能突破 $O(N\log N)$。

### 2. 主位优先 MSD 与多关键字

**多关键字**：基数排序不只处理整数，还能处理多关键字。一副扑克牌有两个关键字——花色（主）和面值（次），每种关键字都相当于整数里的"一位"。

两种做法：

- **主位优先 MSD**（Most Significant Digit First）：先按主关键字（花色）建 4 个桶分堆，再在每桶内排序，最后合并。问题是桶内仍要调用排序算法。
- **次位优先 LSD**：先按次关键字（面值）建 13 个桶分堆，**直接合并**；再按花色建 4 个桶，**只需按花色放进去、收集**即可，**全程不再排序**。

显然扑克牌这个例子里 LSD 聪明得多——建桶、合并、再建桶、再收集就完事，不用在桶内排序。注意：这只是经验结论，**并非所有情况下 LSD 都比 MSD 快**，留作课后思考。

## 六、排序算法的比较

没有任何算法在任何情况下都最好。把全部内排序放在一起比较（平均/最坏时间、额外空间、稳定性）：

| 算法 | 平均时间 | 最坏时间 | 额外空间 | 稳定性 |
|---|---|---|---|---|
| 冒泡、直接插入 | $O(N^2)$ | $O(N^2)$ | $O(1)$ | 稳定（相邻交换，不必换就不换）|
| 简单选择 | $O(N^2)$ | $O(N^2)$ | $O(1)$ | 不稳定（跳着交换）|
| 希尔 | 约 $O(N^d)$，$1<d<2$ | $O(N^2)$ | $O(1)$ | 不稳定（跳着排）|
| 堆排序 | $O(N\log N)$ | $O(N\log N)$ | $O(1)$ | 不稳定 |
| 归并 | $O(N\log N)$ | $O(N\log N)$ | $O(N)$ | 稳定 |
| 快速排序 | $O(N\log N)$（常数小）| $O(N^2)$ | $O(\log N)$（递归栈）| 不稳定 |
| 基数排序 | 近似线性 $O(P(N+B))$ | 同左 | $O(N+B)$ | 稳定 |

几点结论：

- **简单排序**复杂度差，但程序短、不需要额外空间，适合小规模。
- **希尔**是最先突破 $O(N^2)$ 的算法，好坏取决于增量序列。
- **堆与归并**理论上都是 $O(N\log N)$：堆的常数较大，实际未必快过希尔；归并无论如何都是 $O(N\log N)$ 且稳定，硬伤是要 $O(N)$ 额外空间——数据量大时只能排一半。
- **快排**平均常数很小，实际应用中非常快；代价是可构造出 $O(N^2)$ 的最坏情况，且递归需 $O(\log N)$ 栈空间。
- **基数排序**在特定条件下能突破 $O(N\log N)$ 的下界（它不靠纯比较），接近线性；是否需要、是否合算取决于桶数与趟数。
