## 一、优先队列与堆

### 1. 什么是堆

CPU 调度、任务排队等场景需要"每次取优先级最高的元素"——即优先队列。朴素实现（无序数组/链表/有序数组/有序链表）总有一侧是 $O(n)$；二叉搜索树又会因反复删根而歪掉。

**堆**：用**完全二叉树**存储，且任一结点的值不小于（最大堆）/不大于（最小堆）其左右子树中的所有结点。从根到任意结点的路径值单调递减（最大堆）或递增（最小堆）。

堆的存储直接用完全二叉树的顺序表示——根在下标 1，$i$ 的左右孩子在 $2i$、$2i+1$，父结点在 $\lfloor i/2\rfloor$。这三条公式的推导、0-based 时如何变化、以及"判孩子存在靠 $2i\le n$ 越界而非读内容"，见 [[05a-树和二叉树(上).md#1. 顺序存储（数组）]]，此处不再重复。堆之所以能用数组，正是因为完全二叉树不留空洞，$O(1)$ 就能定位父子。

注意：堆的两个条件缺一不可，反例有两类。一类是**结构性**不满足：结点值满足堆序，但形状不是完全二叉树（中间缺了一个位置），仍然不是堆；另一类是**有序性**不满足：是完全二叉树，每个结点却只比它的左右孩子大，而它的某个孩子的孩子比它还大——"比左右孩子大"不等价于"比左右子树中所有结点都大"。做题时若只盯着父子三点比较，第二类查不出来，要看整条路径。

注意：最大堆与最小堆只需把权值取负即可互换——一组正数的最大值的相反数，就是那组相反数的最小值。因此实现上只写一套，取负就能得到另一种堆。

### 2. 插入（最大堆）

把新元素先放到数组末尾，再沿父结点方向向上"筛"：若比父结点大，则父子交换（或父结点下移、新元素上提），直到满足堆序或到达根。时间 $O(\log n)$。

堆的结构体只有三个分量：`Elements`（指向数组的指针）、`Size`（当前元素个数）、`Capacity`（数组容量）。建空堆时按 `MaxSize+1` 申请空间——多出来的这一格就是 `Elements[0]`，留给哨兵，因为元素从下标 1 起存。

在 `H[0]` 放一个比所有元素都大的**哨兵**，可省去 `i>1` 的边界判断。省掉的判断不是消失了，而是被哨兵接住了：上滤到 $i=1$ 时算出的父结点下标是 $i/2=0$，与 `H[0]` 那个最大值一比必然比不过，循环自然停住。所以哨兵的取值只需满足"比任何可能出现的元素都大"。

### 3. 删除（最大堆）

删除的一定是根。先判空（`IsEmpty`），再把 `H[1]` 存入 `MaxItem` 作为返回值。

具体做法：把最后一个元素取到临时变量 `temp` 里（不是直接覆盖到根），令 `Size--`，然后从根开始向下"筛"——在左右孩子中挑较大者，若它比 `temp` 大就把它上提到父亲位置、父指针继续下移；**循环结束后才把 `temp` 放进最终停留的位置**。时间 $O(\log n)$。

关键是循环的两个条件：

- 判断"有没有左儿子"用 `Parent*2 <= Size`：一旦越界，既无左儿子也无右儿子，循环结束；
- 判断"有没有右儿子"用 `Child != Size`：若左儿子的下标恰好等于 `Size`，它就是数组最后一个元素，右儿子必然不存在。

这两条是"最后一个元素被取走"之后必须重新核对的边界，照抄堆的父子公式而不管 `Size` 会越界。

### 4. 建堆

逐次插入 $n$ 个元素需 $O(n\log n)$。**线性建堆**（Floyd 算法）：先把 $n$ 个元素按给定顺序放入数组形成完全二叉树，再从最后一个非叶结点（下标 $\lfloor n/2\rfloor$）向前，对每个结点做一次"向下筛"（与堆删除的下沉过程相同）。当处理到某结点时，其左右子树都已是堆，一次下沉即可把该子树调成堆。总复杂度 $O(n)$。

为什么是 $O(n)$ 而不是 $O(n\log n)$：下沉的代价与结点**高度**成正比，而完全二叉树里"又多又矮"——倒数第二层有 $2^{h-2}$ 个结点但每个只需下沉 1 层，倒数第三层 $2^{h-3}$ 个每个 2 层……只有根一个结点要沉 $h$ 层。总代价为

$$\sum_{i=1}^{h} 2^{h-i}\cdot i \;=\; O(n)$$

级数收敛（$i/2^{i}$ 求和为常数），故总量线性。这与"逐次插入"不同：插入的上滤方向让多数结点承担了接近 $h$ 的代价。

## 二、哈夫曼树与哈夫曼编码

### 1. 带权路径长度 WPL

给定 $n$ 个带权叶结点，二叉树的**带权路径长度** $WPL=\sum w_k l_k$（$l_k$ 为叶结点到根的路径长度）。使 WPL 最小的二叉树即**哈夫曼树**（最优二叉树）。例如把百分制成绩分档时，让高频段靠近根、低频段远离根，平均比较次数最少。

### 2. 哈夫曼树的构造

反复选择权值最小的两个结点合并，新结点权值为二者之和，再放回集合；直到只剩一棵树。用最小堆可在 $O(n\log n)$ 内完成。

规则：每次"取两个最小、合并、放回"会使集合中元素个数减 1，因此从 $n$ 个结点到 1 棵树，共执行 **$n-1$ 次**合并；循环结束后堆里只剩一个元素，那个元素就是整棵哈夫曼树的根。写代码时循环次数写成 $n$ 会越界，写成 $n-2$ 会漏掉最后一次合并。

性质：

- 哈夫曼树中**没有度为 1 的结点**；若有 $n$ 个叶结点，则总结点数为 $2n-1$（由 $n_0=n_2+1$ 得 $n_2=n-1$，该性质的证明见 [[05a-树和二叉树(上).md#2. 重要性质]]）。
- 左右子树交换仍是哈夫曼树。
- 当存在多个并列最小值时，可能得到不同构的哈夫曼树，但 WPL 唯一。

### 3. 哈夫曼编码

不等长编码要避免**二义性**，必须使用**前缀码**：任一字符的编码不是另一字符编码的前缀。把字符放在二叉树叶结点上、左分支标 0 右分支标 1，从根到叶的路径即该字符编码——叶结点位置天然保证前缀性质。

按字符频率构造哈夫曼树，频率高的字符离根近、编码短，总编码长度即 WPL，达到最小。等长码（如 ASCII）虽然实现简单，但未利用频率差异；哈夫曼编码是最优前缀编码。

等长码需要多少位有一个确定答案：若字符集大小为 $C$，则每个字符需 $\lceil\log_2 C\rceil$ 位——$2^3=8$ 能表示 8 种不同对象，故 7 种字符用 3 位即可。哈夫曼编码节省的正是"等长码位数 $\times$ 字符总数"与 WPL 之差。

注意：哈夫曼编码**不唯一**。构造时若出现并列的最小值，选法不同会得到不同构的树，从而得到不同的编码；但**总的编码长度（WPL）唯一**。做题时若题目给出的是"某组权值对应的哈夫曼编码"并要求判断正误，不能因为"与我的编码不同"就判错，要回到 WPL 或前缀性质上核对。反过来，"最优编码"也不只有哈夫曼一种：当各字符频率相同（或恰为 2 的整数次幂且等长）时，等长码本身就是最优的，所以"最优编码一定是哈夫曼编码"这个逆命题不成立。

【进阶】哈夫曼树的性质与应用见 OI-Wiki：[数据结构/哈夫曼树](../OI-Wiki/数据结构/哈夫曼树.md)。

## 三、并查集（集合的表示与合并）

### 1. 应用场景

$n$ 台电脑，不断给出"两台电脑之间连了线"，并随时询问两台电脑是否连通。连通关系具有传递性，本质是不断把两个集合合并、查询某元素属于哪个集合——这就是**并查集**（Disjoint Set Union, DSU）。

### 2. 双亲表示法

用一棵树表示一个集合，**树根代表集合名**。结点需要的信息是"父亲是谁"而非"孩子是谁"，故用**双亲表示法**：数组 `S[]` 中 `S[i]` 存 $i$ 的父结点下标；根结点存 `-1`。

这也是**集合名可以是一个整数**的原因：集合名就是树根的下标，于是"求元素所属集合"与"求树根"是同一件事。

与 §一 的堆相比，这里的双亲表示法与 05a §三 的儿子—兄弟表示法恰好是两个方向：**儿子—兄弟存"往下"的两个指针**（第一个儿子 + 右邻兄弟），**双亲表示存"往上"的一个指针**。选哪个取决于要做什么操作——并查集只需要不断找根，故只需往上走；遍历子树则需要往下走。

进一步简化：若元素本身就是 $0\sim n-1$ 的整数（如电脑编号减一），则**元素下标直接就是结点编号**，连 `Data` 域都不需要。查找根即沿 `S[i]` 一路向上，直到遇到负值。

```cpp
#include <iostream>
using namespace std;

using SetName = int;          /* 集合名 = 树根的下标 */
using SetType = SetName*;     /* 整个并查集就是一个 int 数组，S[i] 存 i 的父亲 */
```

### 3. 朴素并运算及其问题

把两棵树合并：`S[Root2] = Root1`，也就是**始终把第 2 个集合挂到第 1 个集合下面**。这个方向是约定好的，不是随意的——正因为它固定，退化才有了确定的成因：

若不加控制，反复合并会使树退化成单链。最坏一次 Find 需 $O(n)$，$n$ 次操作累计达 $O(n^2)$，在 PTA 上直接超时。

注意：也正因为方向固定，出题人可以针对性地准备数据——按 `1 2`、`2 3`、`3 4`……这样合并会让第 1 个集合越来越高，把 `1` 挂在最底下反复 Find 就是最坏情况；若把合并顺序反过来，就需要另一组数据才能卡住。**只靠一组测试数据卡不住所有写法**，这正是需要多组测试点的原因。

顺便说明"**TSSN**"：课件里这个缩写指的是 *Too Simple, Sometimes Naive*，用来调侃那种"看起来很简洁、但复杂度会出事"的写法。

### 4. 按秩归并

把**矮树贴到高树上**，或**小树并到大树上**，避免树高增长。巧妙之处在于不另开数组：根结点的负值除了"标记是根"外，其绝对值还可用来表示**树高**或**集合规模**。

注意：初始化时所有元素一律置 `-1`，这里的 `-1` 有两重语义——既表示"它是根"，也表示"这棵树的高度为 1"或"这个集合的规模为 1"。**不要把它读成"负的元素个数"**，那样会得到"集合里有 −1 个元素"的荒谬解释。加一个专门存高度的域当然也行，但那样每个非根结点都要白占一格；利用根结点本就该存负数的特性，一个分量就够两种用途。

- 按高度归并：根结点存 `-高度`。两树等高才把新树高加 1（即根值再减 1）；不等高时高树高度不变。
- 按规模归并：根结点存 `-元素数`。合并后新根值等于两树规模之和（仍为负）。

两种统称**按秩归并**。任意一种都能保证最坏树高为 $O(\log n)$，$n$ 次操作总复杂度 $O(n\log n)$。

两种实现在代码上只差两行：比较的都是 `S[Root1]` 与 `S[Root2]`（都是负数，**值小的反而树更大**），区别在于更新——

```cpp
/* 按高度归并：只有等高时新树高才 +1 */
void Union(SetType S, SetName Root1, SetName Root2)
{
    if (S[Root2] < S[Root1])         /* 集合2更高 → 矮树1 挂到 高树2 */
        S[Root1] = Root2;
    else {
        if (S[Root1] == S[Root2])    /* 等高 → 树高 +1 */
            S[Root1]--;              /* 存的是负树高，故 -- */
        S[Root2] = Root1;            /* 矮树2 挂到 高树1 */
    }
}

/* 按规模归并：新规模恒为两者之和 */
void Union(SetType S, SetName Root1, SetName Root2)
{
    if (S[Root2] < S[Root1]) {       /* 集合2更大 → 小树1 并到 大树2 */
        S[Root2] += S[Root1];        /* 两个负数相加，仍为负 */
        S[Root1] = Root2;
    } else {
        S[Root1] += S[Root2];
        S[Root2] = Root1;
    }
}
```

注意：比较时都是拿两个**负数**比，**值小的那一棵反而更大**（$-5<-3$ 表示规模 5 > 规模 3）。这是并查集代码里最容易写反的一处：若把 `S[Root2] < S[Root1]` 误写成 `>`，矮树就会不断贴到矮树上，优化彻底失效——而且程序不会报错，只是越来越慢。

注意：按高度归并时，`S[root]` 记录的是"树高"这一**估计值**，而路径压缩会直接改变树形却不通知根结点，两者叠加后根里存的数就不再是真实高度了。按规模归并没有这个问题——路径压缩不改变集合的元素个数——所以**与路径压缩搭配时通常选按规模**。这也是课件里说"跟后面一种方法结合更方便"的原因。

### 5. 路径压缩

在 Find 中，找到根之后，把查找路径上经过的每个结点**直接挂到根下面**：

```cpp
SetName Find(SetType S, SetName X)
{
    if (S[X] < 0) return X;                  /* 是根：返回集合名 */
    else return S[X] = Find(S, S[X]);        /* 先找根，再把 X 直接挂到根下 */
}
```

一次 Find 看似多做了几次赋值，却把这条路径压扁；之后再查这条路径上的任何结点都接近 $O(1)$。

注意：上面这段是**尾递归**——`Find(S[x])` 的结果就是本层的返回值，本层不再对它做任何运算。这类递归极易被编译器直接改写成循环，所以实际执行时并没有真的递归调用，不会因路径过长而爆系统栈。这也解释了为什么并查集的 Find 可以放心写成递归形式（对比之下，求树高的 $H(T)=\max(H(左),H(右))+1$ 就不是尾递归，无法这样优化）。

按秩归并 + 路径压缩交错执行时，$m$ 次查找、$n-1$ 次合并的总复杂度为 $\Theta(m\,\alpha(m,n))$，其中 $\alpha$ 是 Ackermann 反函数（$\log^*$ 量级）。对实际可处理的 $n$，$\alpha$ 不超过 4，工程上可视为常数。

$\log^* N$ 的定义本身很直观：**对 $N$ 反复以 2 为底取对数，直到结果 $\le 1$ 为止，取了多少次对数就是 $\log^* N$**。每取一次对数，数字顶部就少一层指数塔，所以增长极其缓慢。对任何现实规模的数据它都不超过 4，这正是"看似用了递归、实则接近常数"的底气所在。

【进阶】并查集的实现、复杂度证明与应用见 OI-Wiki：[数据结构/并查集](../OI-Wiki/数据结构/并查集.md)、[数据结构/并查集复杂度](../OI-Wiki/数据结构/并查集复杂度.md)、[专题/并查集应用](../OI-Wiki/专题/并查集应用.md)。

## 四、小白专场：堆中的路径

给定 $n$ 个元素依次插入空的最小堆，再给出 $m$ 个下标，要求输出从该下标结点到根路径上的所有结点值。最小堆用数组 `H[]` 加哨兵 `H[0]` 实现，插入即"向上筛"：`i = ++Size; while (H[i/2] > X) { H[i] = H[i/2]; i /= 2; } H[i] = X;`。

查询时从给定下标 $j$ 出发，不断 `Print H[j]; j /= 2;` 直到到达根：

```cpp
while (j > 1) {                    /* j>1 表示还没到根 */
    cout << H[j] << " ";
    j /= 2;
}
cout << H[1] << endl;              /* 循环外打印根 */
```

注意：循环条件必须是 **`j > 1`** 而不是 `j > 0`。哨兵 `H[0]` 只是参与比较的"挡板"，**不是路径上的结点**，若让 $j$ 走到 0 就会把 `H[0]` 的值（如 $-10001$）一起打印出来。哨兵的取值依据就是"比任何可能出现的元素都小"：本题元素值域为 $\pm 10000$，故取 $-10001$。

输出格式上每题一行：路径上的值空格分隔，行末换行。

## 五、小白专场：File Transfer（并查集应用）

- **题意**：$n$ 台电脑，输入三种指令——`C a b` 查询连通性，`I a b` 连边，`S` 结束并报告连通分量个数。

## 六、附：树习题选讲——Huffman Codes（05-树9）

- **题意**：给定字符集与各字符频率，再给出若干学生提交的编码方案，判断每份提交是否为**最优前缀码**。
- **难点**：哈夫曼编码**不唯一**，所以不能拿"与我的编码相同"当判据。不唯一来自三处——
  - 整棵树左右镜像（等价于把所有 0、1 对调）；
  - 频率相等的字符位置可以互换；
  - 合并时出现并列最小值，选法不同会得到**不同构**的树。

  三者都不改变总长度。所以判据必须落在**总编码长度**与**前缀性质**这两件本质上，而不是编码的具体形态。

- **两步判定**：
  1. 先算标准答案：把频率放进最小堆，用哈夫曼算法构造出树，再算它的 WPL，即最优编码的总长度；
  2. 长度吻合后，按学生给出的编码逐字符建树，在建树过程中检查前缀性质。

- **WPL 的计算**：递归 `WPL(T, Depth)`，叶结点返回 `Depth * weight`，非叶返回左右子树之和；初始 `Depth = 0`，每下降一层加 1。

注意：根的深度取 **0**，于是叶的"路径长度"正好等于它到根经过的边数，与 §二.1 的 $WPL=\sum w_k l_k$ 定义一致。

- **检查前缀码**：按学生的编码串从根往下走，0 向左、1 向右，沿途在每个落脚点打上"已占用"标记，走完把终点标为该字符的叶子。出现下列两种情形之一即为非前缀码：

  1. **途中撞到带权结点**——还没走完，当前落脚点已经是某个字符的叶子，说明该字符的编码是另一个字符编码的前缀；
  2. **走完时当前结点已有孩子**——当前字符的编码路径，被另一个更长的编码当作前缀使用了。

  两者其实是同一件事的两面：只要存在一对字符，其中一个的编码是另一个的前缀，就必然在树上表现为这两类冲突之一。

注意：`code` 字符串的长度上界是 **$N-1$**。最坏情形下哈夫曼树退化成一条链，$N$ 个叶对应 $N-1$ 个内部结点，最深叶的编码就是 $N-1$ 位。因此按 $N-1$ 声明即可，读入时一旦发现超出，该生必然错误，可以直接判定。

**但判错之后仍要把该生的输入全部读完**——否则残留的字符会被当成下一名学生的开头，导致后续全部判错。这个"提前知道答案但还要把输入吞干净"的处理，在 PTA 这类多组数据的题里反复出现，§三 判别搜索树那题的"发现不一致不能立即 return"是同一个套路。
