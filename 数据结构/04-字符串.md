## 一、字符串的定义与 ADT

### 1. 定义与基本术语

字符串（String）是 $n$ 个字符组成的有限序列，记作 $s = c_1c_2\dots c_n$（$n \ge 0$）。$n=0$ 时为空串；字符串中的字符取自某字符集（如 ASCII）。$n$ 称为串长。

串在逻辑上就是**元素限定为字符的线性表**，因此线性表那一套"前驱、后继、表头、表尾"的术语对串同样成立。真正把串和一般线性表区分开的是操作粒度：线性表的插入删除以**单个元素**为单位，而串的插入、删除、替换、定位都以**子串**为单位，模式匹配更是直接把"一个串在另一个串中出现"作为基本动作。后面 KMP 之所以值得单独研究，正是因为"在一段文本中找一段模式"是纯线性表所没有的问题。

几组容易混淆的概念：

| 概念 | 内容 | 长度 |
|---|---|---|
| 空串 | 不含任何字符，记作 `""` 或 $\varnothing$ | 0 |
| 空格串 | 全部由空格字符组成的串，如 `"   "` | 空格个数 |
| 单字符串 | 只含一个字符，如 `"a"` | 1 |

空串与空格串不是一回事：空串里连字符都没有，空格串里有一到多个空格字符。判断空串时，空串的长度为 0，空格串的长度大于 0。

### 2. 子串、子序列、前缀与后缀

**子串与子序列**：s 中**连续**的一段字符组成的串称为 s 的子串，由起点与长度唯一确定，记作 $s[i..j]$（下标从 0 起，$i \le j$）；$i > j$ 时为空串。空串与 s 自身都是 s 的子串，不含 s 自身的称为真子串。从 s 中删去若干字符（也可不删）而不改变剩余字符相对顺序所得的串称为 s 的子序列，它不要求连续，因而不一定是子串。

子串与子序列的关系是单向的：**子串一定是子序列，子序列不一定是子串**。`"abc"` 的子串有 `"a"`、`"ab"`、`"abc"` 等，而 `"ac"` 只是子序列——它跳过了 `b`。

计数时要先问清"是否含空串、是否含自身"：

| 对象 | 数量（n 个字符互不相同） |
|---|---|
| 全部子串 | $n(n+1)/2 + 1$（含空串） |
| 非空子串 | $n(n+1)/2$ |
| 真子串 | $n(n+1)/2$（含空串、不含自身） |
| 非空真子串 | $n(n+1)/2 - 1$ |
| 非空子序列 | $2^n - 1$ |

非空子串数的推导：固定起点 $i$（$0 \le i < n$），长度可取 $1,2,\dots,n-i$ 共 $n-i$ 种；对 $i$ 求和得 $n+(n-1)+\dots+1 = n(n+1)/2$。若字符有重复，不同起止位置可能得到相同的串，上述计数就只是"子串位置"的个数。

**前缀是贴着串首的子串，后缀是贴着串尾的子串**，真前缀与真后缀则不含串自身。长度 $n$ 的串有 $n$ 个真前缀（含空串，长度为 $0$ 到 $n-1$）和 $n$ 个真后缀。注意"真"字的作用：若允许前缀等于自身，则任何串的前缀集合与后缀集合都包含自身，"最长公共前后缀"就恒为自身而失去意义——KMP 中所有关于前后缀的推导都建立在"真"的前提上。

**前后缀的交集**是后面 KMP 的核心量。以 `"aabaa"` 为例：

| 概念 | 定义 | 例（"aabaa"） |
|---|---|---|
| 真前缀集合 | 长度小于 $n$ 的前缀 | {"", "a", "aa", "aab", "aaba"} |
| 真后缀集合 | 长度小于 $n$ 的后缀 | {"", "a", "aa", "baa", "abaa"} |
| 公共前后缀 | 两个集合的交集 | {"", "a", "aa"} |
| 最长公共前后缀 | 交集中最长的那个 | "aa"，长度 2 |

【进阶】字符串的基础概念与更多术语见 OI-Wiki：[字符串/基础](../OI-Wiki/字符串/基础.md)。

### 3. 字符串的 ADT 与基本操作

**字符串的 ADT**：

- 数据对象：$D = \{s_i \mid s_i \in CharacterSet,\ i=1,2,\dots,n,\ n>0\}$ 或 $\varnothing$（空串）
- 数据关系：$R = \{\langle s_{i-1}, s_i \rangle \mid s_{i-1}, s_i \in D,\ i=2,\dots,n,\ n>0\}$

基本操作：

| 操作 | 说明 |
|---|---|
| InitStr(s) | 初始化空串 s，最大长度 kMaxSize |
| StrCopy(s) | 返回复制字符串 s 得到的新串 |
| StrIsEmpty(s) | 判断 s 是否空串，返回布尔值 |
| StrInsert(s, pos, t) | 在 s 的 pos 位置插入串 t，返回新 s |
| StrRemove(s, pos, len) | 删除 s 从 pos 起长度为 len 的子串 |
| SubString(s, pos, len) | 返回 s 从 pos 起长度为 len 的子串 |
| StrLength(s) | 返回 s 的长度 |
| StrConcat(s, t) | 返回 s 与 t 联接而成的新串 |
| StrCompare(s, t) | 比较大小：$s>t$ 返回 +1，相等 0，$s<t$ 返回 -1 |
| PatternMatch(s, t) | 返回 s 中首次出现 t 的位置，无则返回 NIL |
| Replace(s, sub_s, t) | 把 s 中所有子串 sub_s 替换为 t |

注意：位置 pos 从 1 开始计数（对应数组下标 pos-1）。这与 C 语言以 0 为起点的习惯不同，写代码时下标要统一减去 1；考试中若题目沿用 1 起计数，第 1 个字符的下标就是 1。

Replace 可以看作 PatternMatch 的反复调用：反复定位、删除旧子串、插入新串，直到找不到为止。若新旧串长度不同，还要留意替换后主串长度变化导致的下标偏移（不能沿用上一轮的位置继续找，否则会漏或重）。

### 4. 终止符与存储约定

**终止符与存储约定**：C 风格字符串在末尾自动附加转义字符 `'\0'`（反斜杠 + 零，是一个字符）作终止符，扫到它即认为串结束，其本身不显示。

- 串长不计入 `'\0'`，所需存储空间则为串长 + 1：如 `"shallow"` 长度为 7，至少占 8 字节。答题时注意问的是长度还是空间大小。
- `'\0'` 的 ASCII 码为 0，是最小字符，故前缀相同时更长的串更大（把 `'\0'` 拉入比较即可判定），与 StrCompare 的规则一致。
- 连接要覆盖前一个串的 `'\0'` 并保留后一个串的 `'\0'`；清空只需令首位为 `'\0'`。
- `strlen` 必须逐字符扫描到 `'\0'` 才能得到长度，时间复杂度 $O(n)$；这也是很多实现额外存一个长度指示位的原因。

线性表用**长度指示位**界定范围，字符串用**终止符**当哨兵；也有的实现两者都存，用长度指示位把 StrLength 变成 $O(1)$，终止符则留给 C 标准库函数使用。

比较操作有两个易错点，都是"按字符编码逐位比"这条规则的直接后果：

- 前缀相同时长度决定大小，`"abc" < "abcd"`；
- 大小写与数字字符的次序由 ASCII 表决定，`'Z' = 90 < 'a' = 97`，所以 `"Z" < "a"`；`'0' = 48 < '1' = 49`，所以字符串 `"10" < "9"`（先比首字符 `'1' < '9'` 就结束了，根本轮不到第二位）。若想让 `"10"` 大于 `"9"`，必须先把字符串转成整数再比。

按字节存储还有一层隐性差异：ASCII 中一个字符占 1 字节，而 UTF-8 编码的汉字占 3 字节。若程序中混用"字符数"与"字节数"，`strlen` 得到的长度会大于肉眼看到的字数。

## 二、字符串的顺序存储

### 1. 结构定义

所有字符存放在一段连续的存储空间中，字符的存储位置反映逻辑关系（本质是顺序表）。用数组加长度指示位表示：

```c
#define kMaxSize 100

typedef struct {
    char data[kMaxSize];    /* 存放字符，下标 0 ~ length-1 有效 */
    int  length;            /* 当前串长，不含 '\0' */
} SeqString;
```

顺序串的优点是随机访问——$s[i]$ 直接取到，$O(1)$；缺点是长度受 kMaxSize 限制，插入删除要成批移动字符。下面五个基本操作全部围绕"搬动下标"展开，代码中的注释标出每步搬了多少个字符。

### 2. 插入与删除

**算法 4-1 字符串插入 StrInsert(s, pos, t)**

```c
/* 在 s 的第 pos 个字符之前插入串 t；pos ∈ [1, s.length+1]，pos = length+1 表示接到末尾
   成功返回 1，位置非法或空间不足返回 0 */
int StrInsert(SeqString *s, int pos, SeqString t)
{
    int n = s->length, m = t.length;
    if (pos < 1 || pos > n + 1) return 0;       /* 位置越界 */
    if (n + m > kMaxSize)       return 0;       /* 空间不足，课件版本此时直接退出 */

    for (int i = n - 1; i >= pos - 1; i--)      /* 从最后一个字符起，整体后移 m 位 */
        s->data[i + m] = s->data[i];            /* 先搬 i+m，后搬 i，不会覆盖未搬数据 */

    for (int i = 0; i < m; i++)                 /* 空出的 m 个位置填入 t */
        s->data[pos - 1 + i] = t.data[i];

    s->length = n + m;
    return 1;
}
```

思路：**从后往前**移动元素腾出空位（与顺序表插入一致，防止覆盖）。

为什么必须从后往前：若从 $i = pos-1$ 开始往后移，会先把 $s[pos-1]$ 写到 $s[pos-1+m]$，而后面的字符还没搬，$s[pos-1+m]$ 处原有的字符就被冲掉了。从 $n-1$ 倒着搬，每次都搬到"已经腾空或即将腾空"的位置，任何一个字符在搬走前都不会被覆盖。

搬动字符数为 $n - (pos-1) = n - pos + 1$，即插入点之后的字符个数；最坏情况（$pos = 1$）搬 $n$ 个，时间复杂度 $O(n)$。

**算法 4-2 字符串删除 StrRemove(s, pos, len)**

```c
/* 删除 s 中从第 pos 个字符起长度为 len 的子串
   成功返回 1，位置非法返回 0；若从 pos 起不足 len 个字符，则删到末尾 */
int StrRemove(SeqString *s, int pos, int len)
{
    int n = s->length;
    if (pos < 1 || pos > n || len < 1) return 0;

    if (pos - 1 + len >= n) {                   /* 删到末尾：直接截短 */
        s->length = pos - 1;
    } else {
        for (int i = pos - 1 + len; i < n; i++) /* 从前往后，把后面的字符前移覆盖 */
            s->data[i - len] = s->data[i];
        s->length = n - len;
    }
    return 1;
}
```

思路与插入互为镜像：插入是"腾空位、从后往前搬"，删除是"填空位、从前往后搬"。删除时源下标 $i$ 大于目标下标 $i-len$，按 $i$ 递增的顺序搬运，目标位置总是已经处理过的旧数据，不会覆盖尚未搬动的字符。

搬动字符数为 $n - (pos-1) - len$，即删除区间之后的字符个数，复杂度 $O(n)$。若删除区间一直延伸到串尾，则不必搬运，直接把长度截断即可。

### 3. 截取、连接与比较

**算法 4-3 字符串截取 SubString(s, pos, len)**

```c
/* 取 s 中从第 pos 个字符起长度为 len 的子串，存入 sub
   若从 pos 起不足 len 个字符，则截到末尾 */
int SubString(SeqString s, int pos, int len, SeqString *sub)
{
    int n = s.length;
    if (pos < 1 || pos > n || len < 1) return 0;

    if (pos - 1 + len > n) len = n - (pos - 1); /* 长度不足，截到末尾 */

    for (int i = 0; i < len; i++)
        sub->data[i] = s.data[pos - 1 + i];
    sub->length = len;
    return 1;
}
```

截取是唯一不搬动原串的操作，只是复制一段连续存储，复杂度 $O(len)$。

**算法 4-4 字符串连接 StrConcat(s, t)**

```c
/* 把 t 接到 s 的末尾，结果存回 s；空间不足返回 0 */
int StrConcat(SeqString *s, SeqString t)
{
    if (s->length + t.length > kMaxSize) return 0;

    for (int i = 0; i < t.length; i++)
        s->data[s->length + i] = t.data[i];     /* 从 s 末尾继续写 */
    s->length += t.length;
    return 1;
}
```

连续调用 $k$ 次 StrConcat 累积出长串时，总代价是各次长度之和，最坏 $O(n^2)$——这与"逐个字符 push_back 到数组"的代价相同，也是工程上更倾向预留容量或分块存储的原因。

**算法 4-5 字符串比较 StrCompare(s, t)**

```c
/* s > t 返回 1，相等返回 0，s < t 返回 -1 */
int StrCompare(SeqString s, SeqString t)
{
    int len = s.length < t.length ? s.length : t.length;

    for (int i = 0; i < len; i++)
        if (s.data[i] != t.data[i])                          /* 首个不同字符定胜负 */
            return s.data[i] > t.data[i] ? 1 : -1;

    if (s.length == t.length) return 0;                      /* 公共前缀到头且等长 */
    return s.length > t.length ? 1 : -1;                     /* 长者为大 */
}
```

规则：逐位比较字符；前缀相同则更长的串更大；全部相同为相等。字符比的是它在 ASCII 码表中的数值（`'A'=65`、`'a'=97`，同大小写内按字母表顺序递增）。

注意：字符串比较不是比较长度，也不是比较各字符 ASCII 值之和。`"ab"` 与 `"ba"` 长度相同、字符和相同，但 `"ab" < "ba"`；`"z"` 与 `"aa"` 长度不同，却是 `"z" > "aa"`（首字符 `'z' > 'a'`）。

### 4. 五个操作的下标规律

| 操作 | 搬动方向 | 搬动个数 | 复杂度 |
|---|---|---|---|
| 插入 | 从后往前（腾空位） | $n - pos + 1$ | $O(n)$ |
| 删除 | 从前往后（填空位） | $n - pos + 1 - len$ | $O(n)$ |
| 截取 | 不搬动，仅复制 | $len$ | $O(len)$ |
| 连接 | 追加到末尾 | $m$ | $O(m)$ |
| 比较 | 不搬动，仅比较 | 至多 $\min(n,m)$ | $O(\min(n,m))$ |

统一记法：设串长为 $n$、插入位置为 $pos$（1 起），则**插入点之后的字符都要搬**，共 $n-pos+1$ 个；删除区间之后的字符都要搬，共 $n-pos+1-len$ 个。若 $pos$ 在 $1 \sim n+1$ 上均匀分布，插入的平均搬动量是 $n/2$（对 $n-pos+1$ 求和再除以 $n+1$），删除的相应平均值是 $(n-len)/2$，两者同为 $O(n)$ 量级。

## 三、字符串的链式存储

### 1. 结构定义

每个字符是一个链表结点，逻辑上相邻的元素物理位置任意（本质是链表）。

```c
typedef struct StrNode {
    char data;                  /* 一个结点存一个字符 */
    struct StrNode *next;
} StrNode;

typedef struct {
    StrNode *head;              /* 表头指针，无头结点 */
    int      length;            /* 串长，便于 O(1) 取长度 */
} LinkString;
```

所有操作都需处理表头与 $pos=1$ 的边界：顺序串里"插入到首位"只是下标为 0 的特例，链式串里它却要改动 head 指针，是独立分支。

### 2. 插入与删除

**算法 4-6 链式串插入 StrInsert(s, pos, t)**

```c
/* 在 s 的第 pos 个字符之前插入串 t；pos ∈ [1, s.length+1]
   成功返回 1；pos 非法则 s 不变，返回 0 */
int LinkInsert(LinkString *s, int pos, LinkString t)
{
    if (t.length == 0) return 1;                        /* 插入空串，无动作 */
    if (pos < 1 || pos > s->length + 1) return 0;       /* 位置不存在 */

    StrNode *tail = t.head;
    while (tail->next != NULL) tail = tail->next;       /* 先找 t 的末结点 */

    if (s->length == 0) {                               /* s 为空串，直接接管 t */
        *s = t;
        return 1;
    }
    if (pos == 1) {                                     /* 插在表头之前 */
        tail->next = s->head;
        s->head   = t.head;
    } else {                                            /* 插在第 pos-1 个结点之后 */
        StrNode *p = s->head;
        for (int k = 1; k < pos - 1; k++) p = p->next;   /* 定位第 pos-1 个结点 */
        tail->next = p->next;
        p->next    = t.head;
    }
    s->length += t.length;
    return 1;
}
```

思路：链式插入不需要搬动任何已有结点，只需改三根指针——找到插入点前驱 `p`，把 `t` 的尾结点接到 `p->next`，再把 `p->next` 改指 `t` 的头。定位前驱要走 $pos-2$ 步，故复杂度 $O(pos + m)$，其中 $m$ 是找 `t` 尾结点的代价。

注意两点：一是插入后 `t` 的结点被 s 借用，`t` 这个串本身不应再被释放或使用，否则会出现两个串共用一段链表的悬空指针；二是原课件版本对非法 $pos$ 采用"静默不变、置错误码"的处理，现代码改为返回失败标志，语义一致。

**算法 4-7 链式串删除 StrRemove(s, pos, len)**

```c
/* 删除 s 中从第 pos 个字符起长度为 len 的子串
   若从 pos 起不足 len 个字符，则删到末尾；位置非法返回 0 */
int LinkRemove(LinkString *s, int pos, int len)
{
    if (s->length == 0 || pos < 1 || pos > s->length || len < 1) return 0;

    StrNode *p = s->head, *prev = NULL;
    for (int k = 1; k < pos; k++) {                     /* 定位第 pos 个结点 */
        prev = p;
        p = p->next;
    }

    for (int k = 0; k < len && p != NULL; k++) {        /* 逐个摘链并释放 */
        StrNode *q = p->next;
        free(p);
        p = q;
        s->length--;
    }

    if (prev != NULL) prev->next = p;                   /* 前驱越过被删段 */
    else              s->head   = p;                    /* 删的是表头 */
    return 1;
}
```

链式删除的代价是"定位 $O(pos)$ + 逐个释放 $O(len)$"，与顺序串的 $O(n-pos)$ 搬动相比，在串很长而删除段很短时优势明显。代价是每个字符额外带一个指针，存储密度只有 $1/9$ 左右（64 位机上 `char` 占 1 字节、指针 8 字节）。

### 3. 截取、连接与比较

**算法 4-8 链式串截取 SubString(s, pos, len)**：先走到第 pos 个结点，再从它开始复制 len 个结点到新串（不足则复制到末尾）。建表常用**临时头结点**统一挂接逻辑：申请一个哑结点当 `tail`，每复制一个字符就 `tail->next = 新结点; tail = tail->next;`，最后返回 `dummy.next` 并释放哑结点。这样"第一个结点"与"后续结点"不必分开写，省掉一处边界判断。

**算法 4-9 链式串连接 StrConcat(s, t)**：若 s 非空，走到 s 的末结点，令 `p->next = t.head`；若 s 为空，直接 `s.head = t.head`；最后 `s.length += t.length`。不复制字符，但需要走完 s 的整条链，故代价 $O(n)$；顺序串的同一操作只复制 $m$ 个字符，为 $O(m)$——这是链表"省搬动、费定位"的典型体现。

**算法 4-10 链式串比较 StrCompare(s, t)**：双指针 `sp`、`tp` 同步前进，遇到首对不同字符时按 `data` 大小判定；一方先到 `NULL` 则长度更短的串更小；同时到 `NULL` 则相等。复杂度 $O(\min(n,m))$，与顺序串相同——比较操作从来不因存储结构而变快，因为它必须逐个字符读。

### 4. 块链与两种结构的比较

**小结**：顺序串与链式串的对比同顺序表与链表——顺序串随机访问快、存储密度高，但插入删除需移动元素；链式串插入删除方便，但需逐个定位、每字符一个指针开销大。

链式串最致命的弱点是**存储密度太低**：一个结点存 1 个字符却要带 1 个指针，空间利用率约 1/9（64 位机）。工程上常用**块链**折中——每个结点存一个字符数组，结点之间再用指针串起来：

```c
#define BlockSize 4

typedef struct Block {
    char  data[BlockSize];      /* 一个结点存 BlockSize 个字符 */
    int   num;                  /* 本块实际字符数，末块可能不满 */
    struct Block *next;
} Block;
```

块链把存储密度从 $1/9$ 提高到 $B/(B+8)$ 左右（按 64 位机指针占 8 字节计，$B = 4$ 时约 $1/3$），同时保留了链式结构"插入删除不必整体搬移"的优点；代价是随机访问退化为"先跳块、再块内偏移"，且插入删除时要处理块内分裂与合并。文本编辑器（如早期的 rope、piece table 结构）采用的都是这类思路。

| 比较项 | 顺序串 | 链式串 | 块链 |
|---|---|---|---|
| 取第 i 个字符 | $O(1)$ | $O(i)$ | $O(i/B + B)$ |
| 插入/删除 | $O(n)$ 搬动 | $O(pos)$ 定位，无搬动 | 定位 + 块内移动 |
| 存储密度 | 高（仅浪费末尾容量） | 低（约 $1/9$） | 中高（约 $B/(B+8)$） |
| 长度上限 | 受 kMaxSize 限制 | 仅受内存限制 | 仅受内存限制 |
| 适用场景 | 定长、频繁按下标访问 | 频繁在任意位置插入删除 | 大文本、编辑器内部结构 |

## 四、字符串的模式匹配

### 1. 问题的形式化

**概念**：在字符串 s 中找出与字符串 t 相等的子串的操作称为模式匹配（子串定位）。s 称为主串或目标串，t 称为模式串。

形式化：主串 s 用长度为 n 的数组 $s[0..n-1]$ 表示，模式串 t 用长度为 m（$m \le n$）的数组 $t[0..m-1]$ 表示。若存在 $p$（$0 \le p \le n-m$）使得 $s[p..p+m-1] = t[0..m-1]$，则 p 是一个**有效位移**。匹配就是从 s 中找出有效位移 p。

三个要素决定了算法的差异：**比较的方向**（从左或从右）、**失配后模式串移动多少**、**移动量由什么信息决定**（主串内容、模式串自身，还是两者都看）。BF 只看主串当前的失配位置、每次固定右移 1；KMP 只看模式串自身、移动量由已匹配长度决定；BM 两者都看，取规则给出的较大位移。

常见算法：BF（朴素）、KMP、BM、KR、Sunday 等。

### 2. BF 朴素算法

枚举主串的每个起点，从模式串第 0 位开始逐字符比较；失配则模式串整体后移一位重来。

**算法 4-11 朴素匹配 PatternMatchBF(s, t)**

```c
/* 返回 t 在 s 中首次出现的起始下标，未找到返回 -1 */
int PatternMatchBF(const char *s, const char *t)
{
    int n = strlen(s), m = strlen(t);
    if (m == 0) return 0;
    if (m > n)  return -1;

    for (int p = 0; p <= n - m; p++) {          /* 枚举主串中的每个起点 */
        int i = 0;
        while (i < m && s[p + i] == t[i]) i++;  /* 逐字符比较 */
        if (i == m) return p;                   /* 整串比完，匹配成功 */
    }
    return -1;
}
```

最坏情况 $O(nm)$（如主串全是 `a`、模式串 `aa...ab`，每次都在最后一位失配）。以 $s = \texttt{"aaaaaaaa"}$（$n=8$，全为 `a`）、$t = \texttt{"aaab"}$（$m=4$）为例：$p$ 可取 $0 \sim 4$ 共 5 轮，每轮都要比到第 4 位才失配，合计 20 次比较才确认失败——而其中大部分字符是重复看过的。

思路：设 i 遍历主串、j 遍历模式串、k 记录本轮在主串中的起始位置，三者初值均为 0。字符相等则 i、j 都 +1；失配则 `j ← 0`、`i ← k+1`、`k ← k+1`；j 到达 m 而 i 未到 n 为匹配成功，i 到达 n 而 j 未到 m 为匹配失败，成功时返回定位 k。失配时主串指针要退回本轮起点的下一个位置，这一回退正是 KMP 所要消除的。

平均情况并不悲观：若字符集大小为 $\sigma$ 且字符随机分布，每轮比较的期望次数约为 $\sigma/(\sigma-1)$（首个字符就失配的概率是 $1-1/\sigma$），总期望代价 $O(n)$。BF 的缺陷只在"重复字符很多"或"恶意构造输入"时才暴露，因此实际库函数（如简化版 `strstr`）反而常用带优化的 BF。

### 3. KMP 的核心思想：失配后该退到哪里

**动机**：BF 失配时模式串整体右移一位、从头比较，大量已匹配信息被丢弃。KMP（Knuth–Morris–Pratt，克努特—莫里斯—普拉特）利用"失配时前 j 位已匹配成功"这一信息，把模式串一次右移多格。

先把这句话变成看得见的东西。取 $s = \texttt{"abababc"}$，$t = \texttt{"ababc"}$，在 $p = 0$ 处对齐：

```text
       0 1 2 3 4 5 6
s   =  a b a b a b c
t   =  a b a b c
                   ↑ 在 t[4] 处失配：t[4]='c'，s[4]='a'
```

此时已经匹配的部分是 `"abab"`（长度 4）。BF 会把 t 右移一位，用 `t[0]` 去对 `s[1]`，可 `s[1]='b' ≠ 'a'`，白比一次；再右移一位，才在 $p=2$ 处对上。KMP 的问题是：能不能直接算出"下一个可能成立的位置就是 2"？

能。因为已匹配的 `"abab"` 同时是 s 的一段子串和 t 的一段前缀。要让 t 右移后仍有部分字符对齐，就必须让 t 的某个前缀等于 `"abab"` 的某个后缀：

```text
t 的前缀 "ab"  ==  "abab" 的后缀 "ab"
```

于是把 t 右移 2 位，让 `t[0..1]` 对准 `s[2..3]`，从 `t[2]` 与 `s[4]` 继续比较即可。中间那些位移（$p = 1$）被一步跨过，且**主串指针 s 从未回退**——这是 KMP 全部价值所在。

一般化：设失配时已匹配 $j$ 个字符（即 $t[0..j-1] = s[i-j..i-1]$），令 $k$ 为满足

$$t[0..k-1] = t[j-k..j-1]$$

的最大值（$0 \le k < j$），则模式串右移 $j-k$ 位，令 $j \leftarrow k$，主串指针 $i$ 不动。

三个要点：

- $k$ 只依赖模式串 t 和已匹配长度 $j$，与主串无关，所以可以对 t 预先算一张表，匹配时直接查表；
- $k$ 必须取**最大**的，否则会跳过可能的匹配位置；
- $k < j$ 是硬性要求（真前后缀），否则模式串原地不动，匹配无法推进。

【进阶】KMP 的严格证明与更多变形见 OI-Wiki：[字符串/KMP](../OI-Wiki/字符串/KMP算法.md)、[ICPC/04-字符串/03-KMP](../ICPC/04-字符串/03-KMP.md)。

### 4. next 数组的定义与两套约定

上面那个 $k$ 就是 next 数组存的东西。**next 数组定义（408 / 王道约定，本笔记主线）**：

$$\text{next}[j] = t[0..j-1] \text{ 的最长公共真前后缀的长度},\quad \text{next}[0] = -1$$

按此定义，next 数组与匹配中的回退同位相扣：失配时 `j ← next[j]`。为什么下标要错开一位——`next[j]` 描述的是"已经匹配了 j 个字符"这一状态的去向，而"已经匹配 j 个字符"恰好对应"看了 $t[0..j-1]$"，所以定义里用的是前 $j$ 个字符而非以 $j$ 结尾的子串。$j=0$ 时不存在前驱状态，置 $-1$ 作为哨兵，代码里用 `j == -1` 触发"主串指针前进"。

课件采用的则是另一套：

**next 数组定义（课件 / 武大约定）**：串 t 的特征向量，`next[i]` 表示 $t[0..i]$ 的最长公共前后缀中**前缀最末字符的下标**；若不存在最长公共前后缀则置 -1。因此 $t[0..i]$ 的最长公共前后缀长度为 `next[i] + 1`。

课件例：`"abcac"` 的特征向量为 `[-1, -1, -1, 0, -1]`。

| i | 子串 t[0..i] | 真前缀集合 | 真后缀集合 | 最长公共前后缀 | next[i] |
|---|---|---|---|---|---|
| 0 | a | 空 | 空 | 空 | -1 |
| 1 | ab | {a} | {b} | 空 | -1 |
| 2 | abc | {a,ab} | {c,bc} | 空 | -1 |
| 3 | abca | {a,ab,abc} | {a,ca,bca} | a | 0 |
| 4 | abcac | {a,ab,abc,abca} | {c,ac,cac,bcac} | 空 | -1 |

两套约定相差一位，做题时必须先认准是哪一套：

| 约定 | next[i] 的含义 | `"ababc"` 的 next | 失配回退 |
|---|---|---|---|
| 课件（武大） | $t[0..i]$ 最长公共前后缀的前缀末字符下标（无则 -1） | -1、-1、0、1、-1 | $i \leftarrow \text{next}[i-1]+1$ |
| 408 / 王道 | $t[0..i-1]$ 最长公共真前后缀的长度 | -1、0、0、1、2 | $j \leftarrow \text{next}[j]$ |

换算：408 的 $next[i]$ = 课件的 $next[i-1]+1$（$i \ge 1$），反之课件 $next[i]$ = 408 的 $next[i+1]-1$。差异来自两处选择：下标从 0 还是 1 起，定义的是长度还是长度的下一位置，排列组合共四种，都能自洽，做题时按题目给定的前提走。部分匹配表 PMT 存的是最长公共真前后缀长度本身，与 408 的 next 恰好差 1，有的教材将两者混用；next 也称作前缀函数数组、失配跳转数组。

验证换算关系：`"ababc"` 课件的 next 为 `[-1,-1,0,1,-1]`，逐位取 $next[i-1]+1$ 得 `[-1,0,0,1,2]`，正是 408 的 next。两套本质上存的是同一张表，只是错开了一位。

### 5. next 数组的求法

**手算（408 约定）**：先取 `next[0] = -1`、`next[1] = 0`；若采用从 1 起的下标，整个数组右移一位，变成 `next[1] = 0`、`next[2] = 1`。对位置 i，取出前串 $t[0..i-1]$，从左侧起列出它的所有真前缀、从右侧起列出所有等长真后缀，取两者最长的公共项，其长度 L 即 `next[i] = L`；无公共项则 `next[i] = 0`。所列真前缀与真后缀都不含与前串等长的那一项，否则它恒等于自身而失去意义。

以 `"ababc"`（408 约定）为例：

| i | 前串 t[0..i-1] | 真前缀 | 真后缀 | 最长公共项 | next[i] |
|---|---|---|---|---|---|
| 0 | — | — | — | 约定 | -1 |
| 1 | a | 空 | 空 | 空 | 0 |
| 2 | ab | {a} | {b} | 无 | 0 |
| 3 | aba | {a, ab} | {a, ba} | a（长 1） | 1 |
| 4 | abab | {a, ab, aba} | {b, ab, bab} | ab（长 2） | 2 |

换一个重复字符更多的串 `"aabaaab"`（$n=7$）练手：

| i | 前串 | 真前缀（部分） | 真后缀（部分） | 最长公共项 | next[i] |
|---|---|---|---|---|---|
| 0 | — | — | — | 约定 | -1 |
| 1 | a | 空 | 空 | 空 | 0 |
| 2 | aa | {a} | {a} | a（长 1） | 1 |
| 3 | aab | {a, aa} | {b, ab} | 无 | 0 |
| 4 | aaba | {a, aa, aab} | {a, ba, aba} | a（长 1） | 1 |
| 5 | aabaa | {a, aa, aab, aaba} | {a, aa, baa, abaa} | aa（长 2） | 2 |
| 6 | aabaaa | … | {a, aa, aaa, baaa, abaaa} | aa（长 2） | 2 |

得 `next = [-1, 0, 1, 0, 1, 2, 2]`。

手算的实用技巧：不必真把所有前后缀都列出来。设已算出 `next[i] = k`（即前 $i$ 个字符的最长公共前后缀长度为 $k$），求 `next[i+1]` 时先试 $t[i]$ 是否等于 $t[k]$——相等就把长度扩一位；不等则退到 `next[k]` 处再试。这正是下面递推算法在做的事，手算时照此走比列举快得多。

**递推（O(m)）**：朴素求法需 $O(m^3)$——每个位置列举前后缀、再逐字比较。注意到 next 的计算本身具有"自我匹配"结构：求 $\text{next}[i]$ 时，若已知 $t[0..i-1]$ 的最长公共前后缀长度为 $j$，只需比较 $t[i]$ 与 $t[j]$：

- 若相等，长度扩一位，$\text{next}[i+1] = j+1$；
- 若不等，说明这个长度撑不住，退到第二长的公共前后缀继续试，即 $j \leftarrow \text{next}[j]$，直到相等或 $j = -1$（无处可退，长度归零）。

**算法 4-13 求解 next 数组 GetNext(t, next)**（408 约定）

```c
/* t 长度为 m，求 next[0..m-1]；next[0] = -1 */
void GetNext(const char *t, int next[], int m)
{
    next[0] = -1;
    int i = 0, j = -1;              /* i 为当前待求位置的前一位，j 为候选公共前后缀长度 */

    while (i < m - 1) {
        if (j == -1 || t[i] == t[j]) {   /* 能扩一位，或已退无可退 */
            i++;
            j++;
            next[i] = j;
        } else {
            j = next[j];                  /* 退到次长的公共前后缀 */
        }
    }
}
```

复杂度 $O(m)$：`j` 每次进入 `else` 分支至少减 1，而 `j` 在整个过程中最多增加 $m$ 次（每次进 `if` 分支加 1），因此 `else` 分支总执行次数不超过 $m$，循环总步数 $O(m)$。这种"总增量有限、总回退必然不超过总增量"的论证是均摊分析的标准套路，也说明 $O(m)$ 不是最好情况而是最坏情况的界。

课件的伪代码与上式等价，只是把"长度"换成了"前缀末字符下标"（差 1）：

```text
输入：模式串 t
输出：t 的 next 数组（课件约定）
m ← t.length
next[0] ← -1
for i ← 1 to m-1 do
    j ← next[i-1]
    while j ≥ 0 且 t.data[i] ≠ t.data[j+1] do
        j ← next[j]
    end
    if t.data[i] = t.data[j+1] then
        next[i] ← j+1
    else
        next[i] ← -1
    end
end
```

两个版本的关系对照：记 $L_i$ 为 $t[0..i]$ 的最长公共前后缀长度，则 408 的 `next[i+1] = L_i`，课件的 `next[i] = L_i - 1`。所以同一串 `"ababc"` 在课件里是 `[-1,-1,0,1,-1]`，在 408 里是 `[-1,0,0,1,2]`，逐位相差 1。

### 6. KMP 的匹配过程与完整走查

**KMP 匹配过程**：目标串指针与模式串指针同步前进；字符相等则两者都 +1；失配时若模式串指针 $j > 0$，模式串右移，令 $j \leftarrow \text{next}[j]$ 继续匹配；若 $j = 0$（或 $j = -1$），目标串指针前进一位。匹配全程目标串只向右移动。

**算法 4-14 KMP 匹配 PatternMatchKMP(s, t)**（408 约定）

```c
/* 返回 t 在 s 中首次出现的起始下标，未找到返回 -1
   MAXM 需不小于模式串可能的最大长度 */
#define MAXM 1000

int PatternMatchKMP(const char *s, const char *t)
{
    int n = strlen(s), m = strlen(t);
    if (m == 0) return 0;
    if (m > n)  return -1;

    int next[MAXM];
    GetNext(t, next, m);

    int i = 0, j = 0;
    while (i < n && j < m) {
        if (j == -1 || s[i] == t[j]) {   /* j = -1：首位即失配，主串前进一位 */
            i++;
            j++;
        } else {
            j = next[j];                 /* 模式串右移，主串指针原地不动 */
        }
    }
    return (j == m) ? (i - m) : -1;      /* j 走满说明匹配成功 */
}
```

课件写法用 $i$ 遍历模式串、$j$ 遍历主串，回退到 `next[i-1]+1`：

```text
n ← s.length;  m ← t.length;  p ← NIL
if n ≥ m then
    GetNext(t, next)                    // 课件约定的 next
    i ← 0;  j ← 0
    while j < n 且 i < m do
        if s.data[j] = t.data[i] then
            i ← i+1;  j ← j+1
        else if i > 0 then
            i ← next[i-1] + 1           // 课件回退式
        else
            j ← j+1
        end
    end
    if i = m then p ← j-m
end
return p
```

注意：两种写法都保持主串指针不回退，这也是 KMP 适用于流式文本与大文件分块检索的原因（读一段、匹配一段、丢弃一段，指针只朝一个方向移动）。改用 nextval 时只需把 `next[j]` 换成 `nextval[j]`。

**完整走查**：仍用 $s = \texttt{"abababc"}$（$n=7$）、$t = \texttt{"ababc"}$（$m=5$），`next = [-1, 0, 0, 1, 2]`。

| 步 | i | j | s[i] | t[j] | 动作 | 说明 |
|---|---|---|---|---|---|---|
| 1 | 0 | 0 | a | a | 相等，i、j 各 +1 | 首字符对上 |
| 2 | 1 | 1 | b | b | 相等 → i=2, j=2 | |
| 3 | 2 | 2 | a | a | 相等 → i=3, j=3 | |
| 4 | 3 | 3 | b | b | 相等 → i=4, j=4 | |
| 5 | 4 | 4 | a | c | **失配**，j ← next[4] = 2 | 主串指针停在 4 不动 |
| 6 | 4 | 2 | a | a | 相等 → i=5, j=3 | 模式串已右移 2 位 |
| 7 | 5 | 3 | b | b | 相等 → i=6, j=4 | |
| 8 | 6 | 4 | c | c | 相等 → i=7, j=5 | j = m，匹配成功 |

返回 $i - m = 7 - 5 = 2$，即 `s[2..6] = "ababc"`，验证正确。全程比较 8 次；同例 BF 需要 11 次（$p=0$ 比 5 次、$p=1$ 比 1 次、$p=2$ 比 5 次），且串越长、重复字符越多，差距越大。

### 7. nextval：跳过注定失败的比较

**动机**：若 $t[i] = t[\text{next}[i]]$，则按 next 跳到下标 next[i] 后，该位字符与失配位字符相同，必然再次失配，多出一次无用的比较。nextval 把这种注定失败的跳转提前合并。

举个例子：$t = \texttt{"aaaab"}$，`next = [-1, 0, 1, 2, 3]`。设主串为 `"aaab"`，在 $j=3$（第 4 个 `a`）处与主串的 `b` 失配。按 next 回退：$j \leftarrow \text{next}[3] = 2$，用 $t[2] = \texttt{'a'}$ 与同一个 `b` 比，又失配；再退到 $j=1$，还是 `a`，还是失配。连退三次全是同一个字符，做的都是无用功。nextval 直接把 $j=3$ 的退路指到 $-1$，一步到位。

**nextval 的定义**：`nextval[0] = -1`；对 $i \ge 1$，令 $k = \text{next}[i]$：

- 若 $t[i] \ne t[k]$：`nextval[i] = k`，即沿用 next 值；
- 若 $t[i] = t[k]$：`nextval[i] = nextval[k]`，即继承而一步到位。

沿用前面的例 `"ababc"`（408 约定，`next = [-1, 0, 0, 1, 2]`）：

| i | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| t[i] | a | b | a | b | c |
| next[i] | -1 | 0 | 0 | 1 | 2 |
| nextval[i] | -1 | 0 | -1 | 0 | 2 |

i=2 处 $t[2] = t[0] = \texttt{'a'}$，故继承 `nextval[0] = -1`；i=3 处 $t[3] = t[1] = \texttt{'b'}$，故继承 `nextval[1] = 0`；i=4 处 $t[4] = \texttt{'c'} \ne t[2] = \texttt{'a'}$，故沿用 `next[4] = 2`。nextval 也称作优化或修正的 next 数组，题干出现"优化""修正"字样即指它。

```c
/* 与 GetNext 同一框架，只改动"回退目标"的选择 */
void GetNextval(const char *t, int nextval[], int m)
{
    nextval[0] = -1;
    int i = 0, j = -1;

    while (i < m - 1) {
        if (j == -1 || t[i] == t[j]) {
            i++;
            j++;
            if (t[i] != t[j]) nextval[i] = j;        /* 跳过去不会重蹈覆辙 */
            else              nextval[i] = nextval[j]; /* 跳过去也一样失配，直接继承 */
        } else {
            j = nextval[j];                          /* 注意此处用的是 nextval 而非 next */
        }
    }
}
```

注意 `else` 分支里用的是 `nextval[j]` 而不是 `next[j]`：既然整个数组都改成了"一步到位"的语义，中途回退也必须按新表进行，否则会退到一个已被判定为无用的位置。这是 nextval 代码最常见的笔误。

nextval 并非在所有输入上都更快：`"ababc"` 这类字符交替的模式串，$t[i] \ne t[\text{next}[i]]$ 在多数位置上成立，nextval 与 next 的取值基本相同。只有某字符在模式串中连续重复时（如 `"aaaab"`），改进才体现为成串地跳过无效比较。

### 8. 复杂度与适用场景

KMP 的优点：复杂度 $O(n+m)$ 为线性，主串指针不回退因而适合大文件分块检索，next 数组由模式串单独决定、可与模式串绑定复用（同一模式串多次查找只需计算一次）。缺点：需额外 $O(m)$ 空间，短串上优化不明显，逻辑较 BF 难理解。

| 指标 | BF | KMP | KMP + nextval |
|---|---|---|---|
| 预处理时间 | 无 | $O(m)$ | $O(m)$ |
| 匹配时间（最坏） | $O(nm)$ | $O(n)$ | $O(n)$ |
| 匹配时间（平均） | $O(n)$（字符集大时） | $O(n)$ | $O(n)$ |
| 主串指针回退 | 会 | 不会 | 不会 |
| 额外空间 | $O(1)$ | $O(m)$ | $O(m)$ |
| 支持多模式串 | 否 | 否（可用 AC 自动机扩展） | 否 |

"主串指针不回退"不只是性能问题，还决定了能不能流式处理：若主串是一段正在到达的网络数据或超过内存的大文件，BF 的回退意味着必须保留已读过的内容；KMP 只需记住当前匹配长度，读过的数据可以立即丢弃。

### 9. BM：从右向左的跳跃

BM（Boyer–Moore）有两处革新：**从右往左比较**，以及**一次可以跳过多个字符**。

从右往左比较的好处是——只要模式串**最后一个**字符对不上，就能立刻失配，一次比较排除一个位置；而 BF 从左往右比，最坏要把前缀比完才发现末位不对。

失配后跳过多少，由两条规则分别给出，取较大者：

**坏字符规则**：失配时主串中那个字符 $c$ 称为坏字符，设当前正与它比对的是 $t[j]$。

- 若 $c$ 在 $t[0..j-1]$ 中最右出现位置为 $k$，位移 $= j - k$；
- 若 $c$ 根本不在 $t[0..j-1]$ 中，位移 $= j + 1$（整个模式串移到坏字符右侧）。

**好后缀规则**：失配时已匹配的后缀本身是有用信息。若该后缀在模式串前面还出现过，就把下一次出现对齐过来；若没有完整出现，就找它的某个后缀，使该后缀恰是模式串的前缀。位移取这两种情况中较大的可行值。

例子：$t = \texttt{"abac"}$，主串 $s = \texttt{"ababac"}$。

```text
p=0:  s = a b a b a c
      t = a b a c
                  ↑ j=3：s[3]='b' 与 t[3]='c' 失配
```

坏字符为 `'b'`，它在 $t[0..2] = \texttt{"aba"}$ 中最右出现在 $k=1$。位移 $= j - k = 3 - 1 = 2$，直接跳到 $p=2$：

```text
p=2:  s = a b a b a c
          t = a b a c
```

一次对齐即匹配成功。BF 则要试 $p=0,1,2$ 三个位置，共 9 次比较（$p=0$ 与 $p=2$ 各 4 次，$p=1$ 首字符即失配 1 次）。

BM 的预处理是建两张表（坏字符表大小 $\sigma$、好后缀表大小 $m$），代价 $O(m+\sigma)$；匹配最好情况每次跳过整个模式串，比较 $n/m$ 次，即 $O(n)$；最坏仍为 $O(nm)$，但实际文本上（字母表大、模式串长）远快于 KMP，`grep`、`less` 等工具的核心都是 BM 的变体。只用坏字符规则的简化版叫 BMH（Boyer–Moore–Horspool），实现简单且性能接近。

【进阶】BM 的完整规则与代码见 OI-Wiki：[字符串/BM 算法](../OI-Wiki/字符串/BM算法.md)。

### 10. KR：哈希筛选

KR（Rabin–Karp）换了个思路：不比字符，比**数值**。把模式串看作一个 $d$ 进制数（$d$ 为字符集大小），用哈希函数把长为 $m$ 的串映射成一个整数：

$$H(t) = \left(\sum_{i=0}^{m-1} t[i]\cdot d^{\,m-1-i}\right) \bmod q$$

主串中每个长为 $m$ 的窗口也照此计算，先比哈希值；哈希相等再逐字符核验（因为可能存在碰撞）。关键在于窗口滑动时不必重算：去掉最高位、整体左移、补上新字符，

$$H(s[i+1..i+m]) = \big((H(s[i..i+m-1]) - s[i]\cdot d^{\,m-1})\cdot d + s[i+m]\big) \bmod q$$

一次乘加即可，$O(1)$ 更新，所以整趟扫描 $O(n+m)$（期望）。最坏情况是哈希全部碰撞（如全串同一个字符且 $q$ 选得不好），退化为 $O(nm)$。

注意：取模运算中减法结果可能为负，C 语言里要写成 `((h - x) % q + q) % q` 或改用 `unsigned` 自然溢出。$d^{m-1}$ 也应预处理，避免每个窗口都算一次幂。按字节处理时（文本含中文等多字节内容）$d$ 取 256，且应把字符先转成 `unsigned char` 再入哈希，否则在有符号 `char` 的机器上会出现负值。

KR 的真正优势在**多模式匹配**：若要在文本中同时找 $k$ 个模式串，只需把 $k$ 个模式的哈希值放进哈希表，扫描时每个窗口查一次表，总代价 $O(n + km)$，而 KMP 需要跑 $k$ 遍。字符串哈希的更多用法（判等、最长公共子串、回文判定）见 [OI-Wiki/字符串/哈希](../OI-Wiki/字符串/哈希.md)。

### 11. 四种算法的对比

| 算法 | 比较方向 | 移动依据 | 预处理 | 匹配（最坏） | 特点 |
|---|---|---|---|---|---|
| BF | 左 → 右 | 固定右移 1 | 无 | $O(nm)$ | 实现最简单，字符集大时平均 $O(n)$ |
| KMP | 左 → 右 | 已匹配长度（模式串自身） | $O(m)$ | $O(n)$ | 主串不回退，可流式处理 |
| BM | 右 → 左 | 坏字符 + 好后缀（两者取大） | $O(m+\sigma)$ | $O(nm)$ | 实践中最快，跳跃幅度大 |
| KR | 不逐字符比，比整窗哈希 | 哈希不等则整窗跳过 | $O(m)$ | $O(nm)$ | 期望线性，天然支持多模式 |

选择依据：单模式、模式串短且字符集大——BF 足够；需要最坏线性保证或流式处理——KMP；文本编辑器、命令行检索等工程场景——BM；多模式或需要判等、去重——KR / 哈希。

## 本节重点

- 字符串的本质是受限线性表，区别在于操作以子串为单位；空串长度为 0，空格串长度不为 0，二者不同。
- 子串连续、子序列不连续；子串一定是子序列，反之不然。$n$ 个互异字符的非空子串有 $n(n+1)/2$ 个，非空子序列有 $2^n-1$ 个。
- 顺序串操作的核心是"插入从后往前移、删除从前往后移"，搬动个数分别为 $n-pos+1$ 与 $n-pos+1-len$；链式串操作注意表头与 $pos=1$ 边界。
- 终止符 `'\0'` 不计入串长但占 1 字节空间（长 $n$ 的串至少需 $n+1$ 字节）；比较是逐位比 ASCII 码，前缀相同时长者为大，与长度、字符 ASCII 之和均无关。
- KMP 的出发点：失配时前 $j$ 个字符已匹配，据此找模式串自身的最长公共真前后缀，令 $j$ 退到该长度，主串指针不动。
- next 数组：408 约定下 $\text{next}[j]$ 是 $t[0..j-1]$ 最长公共真前后缀的长度，`next[0] = -1`，回退写 $j \leftarrow \text{next}[j]$；课件约定下 $\text{next}[i]$ 是 $t[0..i]$ 最长公共前后缀的前缀末字符下标（无则 -1），回退写 $i \leftarrow \text{next}[i-1]+1$。两者相差一位，换算为 408 的 $\text{next}[i] =$ 课件的 $\text{next}[i-1]+1$。
- next 的线性求法：能扩位则 $\text{next}[i+1] = j+1$，不能扩则 $j \leftarrow \text{next}[j]$ 继续退，均摊后 $O(m)$。
- nextval：$t[i] \ne t[\text{next}[i]]$ 时 $nextval[i] = \text{next}[i]$，相等时 $nextval[i] = \text{nextval}[\text{next}[i]]$；代码回退时用 `nextval[j]` 而非 `next[j]`。
- KMP 复杂度 $O(n+m)$：next 快速计算 $O(m)$ + 匹配 $O(n)$，目标串指针永不回退；BF、BM、KR 的最坏情况都是 $O(nm)$，BM 与 KR 靠平均性能取胜。
- 注意：next 与 nextval 不要混用；不同教材的 next 可能相差 1，照抄答案前先确认下标起点与定义。
