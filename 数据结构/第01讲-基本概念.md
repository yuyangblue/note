## 0. 这一讲到底在讲啥（先看这段）

这一讲就回答三个问题：

1. **数据结构是啥？** —— 数据怎么"摆"，摆法决定做事快慢
2. **算法是啥？** —— 做同一件事，聪明的做法和笨的做法差多远
3. **怎么比较谁快？** —— 复杂度（这门课最重要的一个概念）

最后一个例子（最大子列和）会用 4 种越来越聪明的算法，把这三件事串起来。

## 1. 数据结构是啥？从三个生活例子讲起

### 1.1 例子①：图书馆怎么摆书

想象一个巨型书城，书乱摆，你找一本书只能从头翻到尾——累死。三种摆法：

| 摆法 | 放新书 | 找书 | 一句话评价 |
|------|--------|------|-----------|
| 随便放 | 哪儿空放哪儿，最快 | 从头翻到尾，最慢 | 找书累死 |
| 按书名拼音排 | 要挪一堆书，慢 | 二分查找，每次砍一半 | 找书快，放书慢 |
| **分类 + 类内按拼音排** | 先定类再插，还行 | 先定类再二分，快 | 两头都不差（最佳） |

> **一句话结论：数据怎么组织（摆），直接决定操作（找/插）快不快。** 这就是"数据结构"的意义。

### 1.2 例子②：打印 1 到 N——递归怎么把程序干爆的

写个函数打印 1 到 N，两种写法：

- **循环版**：一个 for 循环，占的内存是固定的，N 多大都没事
- **递归版**：每递归一层，系统就要"记一笔账"（保存现场），N=10 万时内存被记爆，**程序直接崩溃，一个数字都打不出来**

> **一句话结论：空间用不对，程序直接崩。** 递归代码写起来爽，但内存是有限的。

### 1.3 例子③：算多项式——聪明算法快一个数量级

算 $f(x)=a_0+a_1x+\dots+a_nx^n$：

- **笨算法**：按公式一项项算 $x^i$，乘了约 $n^2/2$ 次
- **秦九韶算法**（几百年前的老祖宗）：把 $x$ 一层层"提公因式"从里往外算，只乘 $n$ 次

用电脑实测，N 不大时两者就差一个数量级（10 倍）。

> **一句话结论：算法巧不巧，速度差一个数量级。**

### 1.4 小结：到底啥是数据结构

**数据结构 = 数据的组织方式 + 和它配套的操作。** 换个说法：

- 书怎么摆 = 数据的**逻辑结构**：排成一队（线性）、分叉（树）、乱网（图）
- 书在架子上怎么放 = **物理存储**：挤在一起（数组）、隔开用链子串（链表）

描述数据结构有个专业术语叫 **ADT（抽象数据类型）**：只关心"有什么数据、能干什么操作"，**不关心内部怎么实现**（就像你用手机，只关心能打电话能上网，不关心里面电路怎么走）。好处：换实现（数组换链表、int 换 double）不影响使用。

## 2. 算法是啥？

### 2.1 定义（人话版）

算法就是**解决一个问题的明确步骤**，五条硬性要求：

1. 步骤**有限**（不能无限循环下去）
2. 可以有 0 个输入，但**必须有输出**（不然没意义）
3. 有限步之后**必须停**（操作系统那种一直跑的不算算法）
4. 每一步**没有歧义**（"差不多放这儿"不行）
5. 描述**不依赖具体语言**（伪代码就行，别纠结是不是 C 还是 Python）

### 2.2 好算法看两个指标

| 指标 | 符号 | 人话 |
|------|------|------|
| 空间复杂度 | $S(n)$ | 跑这个程序要占多少内存 |
| 时间复杂度 | $T(n)$ | 跑这个程序要花多少时间 |

都和**数据规模 $n$** 有关：打印 10 个数和打印 10 万个，时间当然不一样。

考试和做题一般看**最坏情况**：保证任何输入都不会超时/爆内存（"平均"太难算，也没那么有用）。

### 2.3 复杂度怎么记：$O$、$\Omega$、$\Theta$

不用记严格数学定义，先记住**一个表**（增长速度，从慢到快）：

$$\log n \ll n \ll n\log n \ll n^2 \ll n^3 \ll 2^n \ll n!$$

直觉：$n=10^6$ 时，$n^2$ 是 $10^{12}$，$n\log n$ 只有 $2\times10^7$，差几万倍。

- $O(f(n))$ = "最多不超过这么多"（上界）
- $\Omega(f(n))$ = "至少这么多"（下界）
- $\Theta(f(n))$ = "刚好这么多"（上下界一样）

> **老程序员的条件反射：看到 $O(n^2)$ 就想"能不能降到 $O(n\log n)$"。**

> 【进阶·可跳过】$O/\Omega/\Theta$ 的严格定义（$n_0$、常数 $C$）、复杂度分析小技巧（加法取大、乘法嵌套）、常见算法复杂度表 → 看 `OI-Wiki\算法基础\复杂度.md`

## 3. 实战：最大子列和问题（本讲精华）

### 3.1 问题一句话

给一串数（有正有负），找**连续的一段**，让这段的和最大。如果全是负数，答案规定为 0。

例：`[-1, 3, -2, 4, -6, 1, 6, -1]` → 最大和是 `7`（取 `[1, 6]`）。

### 3.2 四种做法，一个比一个聪明

| 算法 | 思路（一句话） | 复杂度 | $n=10^5$ 时实测 |
|------|----------------|--------|----------------|
| ① 暴力三重循环 | 枚举每一段的起点、终点，再从头加一遍 | $O(n^3)$ | 根本跑不完 |
| ② 两重循环 | 起点固定时，终点往后挪一格只加一个数 | $O(n^2)$ | 也跑不完 |
| ③ 分而治之 | 从中间劈开，左右分别算，再算"跨中间"的 | $O(n\log n)$ | 几秒出结果 |
| ④ **在线处理** | 边读边算，**当前和变负就扔掉重来** | $O(n)$ | <1 秒 |

### 3.3 每个算法的"聪明点"（一句话）

- ①→②：别再从头加，**加过的接着加**就行
- ②→③：分治——左边最大、右边最大、跨中间最大，三者取最大
- ③→④：**负的当前和直接扔**。为什么敢扔？因为负数和后面任何数相加只会更小，永远不可能成为"最大子列"的开头。

④ 的代码就这么几行（一定要能默写）：

```
ThisSum = 0, MaxSum = 0
for x in 序列:
    ThisSum += x
    if ThisSum > MaxSum: MaxSum = ThisSum
    elif ThisSum < 0: ThisSum = 0   # 关键！负和扔掉
return MaxSum
```

> **在线处理**：每读一个数就立刻处理，任何时候停下来，答案都是对的。$O(n)$ 已经是最快——总得把每个数读一遍吧。

> 【进阶·可跳过】③分治的复杂度为什么是 $O(n\log n)$：$T(n)=2T(n/2)+cn$ 展开 $\log n$ 层，每层 $cn$ → 看 `OI-Wiki\算法基础\分治.md` 和复杂度篇

## 4. 本讲重点（背下来）

1. **数据结构 = 数据怎么组织 + 能做什么操作**；组织方式决定效率（图书馆例子）
2. **算法五特性**：有限、有输出、能停、无歧义、不依赖语言
3. **复杂度阶梯**：$\log n < n < n\log n < n^2 < 2^n < n!$；看**最坏情况**；$O$ 是上界
4. **最大子列和四连**：$O(n^3) \to O(n^2) \to O(n\log n) \to O(n)$，在线处理最优，负和必扔

> **常见坑**：①全负数序列答案要返回 0（看题意）；②在线处理如果还要输出子列的**起止位置**，得额外记变量（PTA 的 01-复杂度2 就是）。
