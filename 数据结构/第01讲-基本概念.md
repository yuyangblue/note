# 第 01 讲 基本概念：数据结构、算法与复杂度

> 本讲依据视频 001–010（1.1 什么是数据结构、1.2 算法、1.3 最大子列和问题）整理。
> 学习目标：理解数据结构的三个侧面（逻辑结构、存储结构、运算）、算法的定义与复杂度度量、渐进表示法，并能分析最大子列和问题的四种算法。

## 一、什么是数据结构

数据结构没有一个统一的定义，但可以通过三个例子理解它要回答的问题。

### 1. 图书摆放：数据的组织方式

把书放到书架上，本质是把数据存起来。难点不在摆放本身，而在摆放必须服务于两个操作：**新书插入**与**指定图书查找**。

| 摆放方式 | 插入 | 查找 |
|---|---|---|
| 随便放 | 一步到位 | 只能从头扫到尾，规模大时不可接受 |
| 按书名拼音排序 | 需大量移动后续的书 | 可用二分查找，很快 |
| 按类别分区，类内拼音排序 | 先定位类别，移动量小 | 先定位类别，再类内二分 |

结论：**解决问题方法的效率，与数据的组织方式直接相关**。同时，组织方式的选择还与数据规模有关——规模不同，最优策略不同。

### 2. PrintN：空间的使用

用循环打印 1 到 N 与用递归打印 1 到 N，代码都很简短。但 N 取 10 万时，循环版本正常完成，递归版本耗尽内存、非正常终止。原因：循环只占用固定大小的空间；递归每层调用都要保存现场，占用空间随 N 线性增长，最终超出可用内存。

结论：**解决问题方法的效率，与空间的利用效率直接相关**。

### 3. 多项式求值：算法的巧妙程度

给定多项式 $f(x)=\sum_{i=0}^{n} a_i x^i$ 和点 $x$，直接按定义计算：每次计算 $x^i$ 需要 $i-1$ 次乘法，总乘法次数约为 $n^2/2$。秦九韶算法把公因子逐层提出：

$$p = a_n; \quad p = p\cdot x + a_{i} \ (i = n-1, n-2, \dots, 0)$$

每一步只做一次乘法，总乘法次数约为 $n$。用 `clock()` 实测（重复 $10^7$ 次取单次平均），两种算法的耗时相差约一个数量级。

结论：**解决问题方法的效率，与算法的巧妙程度直接相关**。

### 4. 数据结构的三要素

| 要素 | 含义 | 例子 |
|---|---|---|
| 逻辑结构 | 数据对象之间的抽象关系 | 一对一（线性结构）、一对多（树）、多对多（图） |
| 物理（存储）结构 | 逻辑结构在计算机中的实现方式 | 数组（连续存放）、链表（分散存放） |
| 数据运算 | 施加在数据上的操作及实现算法 | 插入、删除、查找 |

### 5. 抽象数据类型（ADT）

ADT 只描述"数据对象集 + 操作集"**是什么**，不关心**如何实现**：与机器、存储结构、算法和编程语言均无关。例如"矩阵"ADT 只描述 Create、GetEntry、Add、Multiply 等操作的语义；元素类型用 ElementType 抽象，存储用二维数组还是十字链表都不影响其定义。

抽象的好处：元素类型变化（如 int 改为 double）或底层实现变化时，使用方代码无需修改，避免了逐个替换类型带来的错误风险。

## 二、算法与算法的度量

### 1. 算法的定义

算法是**有限指令集**，必须满足：可以有输入（也可无输入）、必须产生至少一个输出、在有限步骤后终止、每条指令无歧义、指令目标在计算机可处理范围内、描述与具体语言和实现手段无关（一般用伪代码描述）。

### 2. 空间复杂度与时间复杂度

- **空间复杂度** $S(n)$：程序执行时占用的存储单元长度。
- **时间复杂度** $T(n)$：程序执行耗费的时间。

二者都是数据规模 $n$ 的函数。分析时通常关注**最坏情况复杂度** $T_{worst}(n)$：平均情况难以精确定义，而最坏情况能保证任何输入下的性能上限。

### 3. 渐进表示法

- $T(n)=O(f(n))$：$f(n)$ 是 $T(n)$ 的上界（存在常数 $C$、$n_0$，当 $n\ge n_0$ 时 $T(n)\le C f(n)$）。写 $O$ 时取能得到的**最小**上界。
- $\Omega(f(n))$：下界，写 $\Omega$ 时取**最大**下界。
- $\Theta(f(n))$：同时是上界与下界，表示量级相等。

常见复杂度随 $n$ 增大的增长速度（$n$ 充分大时）：

$$1 < \log n < n < n\log n < n^2 < n^3 < 2^n < n!$$

$\log n$ 增长最慢；$2^n$、$n!$ 在 $n$ 稍大时即不可用。设计算法的一个重要习惯：看到 $O(n^2)$ 应本能地思考能否降到 $O(n\log n)$——当 $n=10^6$ 时，两者相差数十万倍。

### 4. 复杂度分析小技巧

- 两段算法顺序拼接：总复杂度取两段中较大者。
- 两段算法嵌套：复杂度相乘。
- $k$ 阶多项式：只需保留最高次项。
- for 循环：循环次数 × 循环体复杂度。
- if-else：取条件判断与两个分支中的最大者。

【进阶】更系统的复杂度理论（大 O 记号、主定理等）见 OI-Wiki：[算法基础/复杂度](../OI-Wiki/算法基础/复杂度.md)。

## 三、应用实例：最大子列和问题

问题：给定 $N$ 个整数的序列 $\{A_1, A_2, \dots, A_N\}$，求所有连续子列和的最大值；若最大和为负，则输出 0。

| 算法 | 思路 | 复杂度 |
|---|---|---|
| 算法 1 | 三重循环枚举左端 i、右端 j、求和 k，逐一累加 | $O(N^3)$ |
| 算法 2 | 去掉内层求和循环：固定 i，j 每右移一位时累加一项 A[j] | $O(N^2)$ |
| 算法 3 | 分而治之：递归求左半最大子列和、右半最大子列和、跨中线的最大子列和，取三者最大 | $O(N\log N)$ |
| 算法 4 | 在线处理：扫描一遍，当前子列和为负则丢弃并归零，随时更新最大和 | $O(N)$ |

### 四种算法的伪代码

```c
// 算法 1：暴力三重循环，O(N^3)
int MaxSubseqSum1(int A[], int N) {
    int MaxSum = 0;
    for (int i = 0; i < N; i++) {
        for (int j = i; j < N; j++) {
            int ThisSum = 0;
            for (int k = i; k <= j; k++)      // 每一段都从头加起
                ThisSum += A[k];
            if (ThisSum > MaxSum)
                MaxSum = ThisSum;
        }
    }
    return MaxSum;
}
```

```c
// 算法 2：去掉内层求和循环，O(N^2)
int MaxSubseqSum2(int A[], int N) {
    int MaxSum = 0;
    for (int i = 0; i < N; i++) {
        int ThisSum = 0;
        for (int j = i; j < N; j++) {
            ThisSum += A[j];                  // 在上一轮基础上只加一项
            if (ThisSum > MaxSum)
                MaxSum = ThisSum;
        }
    }
    return MaxSum;
}
```

```c
// 算法 3：分而治之，O(N log N)
int MaxSubseqSum3(int A[], int N) {
    return DivideAndConquer(A, 0, N - 1);
}

int DivideAndConquer(int A[], int left, int right) {
    if (left == right)                        // 递归出口：单元素，负数按 0 计
        return A[left] > 0 ? A[left] : 0;
    int mid = (left + right) / 2;
    int MaxLeftSum  = DivideAndConquer(A, left, mid);
    int MaxRightSum = DivideAndConquer(A, mid + 1, right);

    // 跨中线的最大子列和 = 从 mid 向左扫的最大和 + 从 mid+1 向右扫的最大和
    int LeftBorderSum = 0, MaxLeftBorderSum = 0;
    for (int i = mid; i >= left; i--) {
        LeftBorderSum += A[i];
        if (LeftBorderSum > MaxLeftBorderSum)
            MaxLeftBorderSum = LeftBorderSum;
    }
    int RightBorderSum = 0, MaxRightBorderSum = 0;
    for (int i = mid + 1; i <= right; i++) {
        RightBorderSum += A[i];
        if (RightBorderSum > MaxRightBorderSum)
            MaxRightBorderSum = RightBorderSum;
    }
    return max3(MaxLeftSum, MaxRightSum,
                MaxLeftBorderSum + MaxRightBorderSum);
}
```

```c
// 算法 4：在线处理，O(N)
int MaxSubseqSum4(int A[], int N) {
    int MaxSum = 0, ThisSum = 0;
    for (int i = 0; i < N; i++) {
        ThisSum += A[i];
        if (ThisSum > MaxSum)
            MaxSum = ThisSum;                 // 随时更新最大和
        else if (ThisSum < 0)
            ThisSum = 0;                      // 负子列和丢弃，从下一项重新开始
    }
    return MaxSum;
}
```

- 算法 1 的复杂度：直观上看是三层循环嵌套，虽然后两层循环不是 0 到 N，但用求和技巧可证明总运算量仍是 $N^3$ 的常数倍。
- 算法 2 的改进点：对同一左端 i，不同右端 j 的部分和可以递推累加，无需每次从头求和——k 循环完全是多余的。
- 算法 3 的复杂度推导：$T(N) = 2T(N/2) + cN$，$T(1) = O(1)$。逐层展开 $k = \log_2 N$ 层：
  $$T(N) = 2^k T(N/2^k) + ckN = O(N) + cN\log_2 N = O(N\log N)$$
  其中 $cN$ 项来自跨中线扫描——每个元素只被扫一次。
- 算法 4 的正确性：若当前子列和为负，它不可能使后续子列和增大，应直接丢弃、从下一项重新开始；每读入一个数立即更新答案，任何时刻中断输入都能给出当前正确结果，故称"在线处理"。$O(N)$ 已是该问题的下界——至少要把每个元素读一遍。其代价是正确性不直观，需逐步走查验证（见下）。

### 算法 4 走查示例（老师课上演示的 8 个数）

输入 $-1, 3, -2, 4, -6, 1, 6, -1$，`ThisSum`、`MaxSum` 初值均为 0：

| 读入 | ThisSum 累加后 | 动作 | MaxSum |
|---|---|---|---|
| -1 | -1 | 为负 → 丢弃归零 | 0 |
| 3 | 3 | $3 > 0$ → 更新 | 3 |
| -2 | 1 | $1 \le 3$ 且为正 → 保留 | 3 |
| 4 | 5 | $5 > 3$ → 更新 | 5 |
| -6 | -1 | 为负 → 丢弃归零 | 5 |
| 1 | 1 | $1 \le 5$ → 保留 | 5 |
| 6 | 7 | $7 > 5$ → 更新 | 7 |
| -1 | 6 | $6 \le 7$ → 保留 | 7 |

输出 7（对应连续子列 $3, -2, 4, -6, 1, 6$）。若只读前 4 个数就终止输入，返回 5 也是正确解——这正是"在线"的含义：任何时刻中断，都给出当前已读部分的最优答案。

实测（某机器，不含输入输出时间）：$N=10^4$ 时 $O(N^3)$ 已跑不动（NA）；$N=10^5$ 时 $O(N^2)$ 算不下去；$O(N\log N)$ 需数秒；$O(N)$ 小于 1 秒。
