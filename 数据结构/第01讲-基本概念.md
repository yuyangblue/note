## 1. 什么是数据结构

### 1.1 核心思想

程序设计的本质是**数据组织 + 算法设计**。同样的数据，组织方式不同，解决问题的效率天差地别。数据结构就是研究"数据如何组织、如何存储、如何操作"的学科。

**抽象数据类型（ADT，Abstract Data Type）** 三要素：

| 要素 | 含义 | 例子（多项式） |
|------|------|--------------|
| 数据对象集 | 数据的集合 | 系数 + 指数 |
| 操作集 | 对数据对象的操作 | 求值、相加、相乘 |
| 规则 | 操作的前提条件 | 指数非负、系数非零 |

> 白话理解：ADT 只关心"**有什么数据、能做什么操作**"，不关心具体用数组还是链表实现——这就是"抽象"的含义。

### 1.2 数据的逻辑结构 vs 物理存储结构

| 类型 | 说明 | 例子 |
|------|------|------|
| 逻辑结构 | 数据之间的抽象关系（与存储无关） | 线性、树、图、集合 |
| 存储结构 | 在计算机里的实际存放方式 | 顺序存储、链式存储 |

经典公式（Wirth）：**程序 = 算法 + 数据结构**。

### 1.3 常见逻辑结构一览

- **线性结构**：元素一对一的线性关系（线性表、栈、队列、串）
- **树形结构**：一对多的层次关系（二叉树、森林）
- **图形结构**：多对多的网状关系
- **集合**：元素间无逻辑关系，只属于同一集合

## 2. 什么是算法

### 2.1 算法定义与特性

算法是解决特定问题求解步骤的描述。五个特性：

| 特性 | 含义 |
|------|------|
| 有穷性 | 有限步骤内结束 |
| 确定性 | 每步有明确含义，无二义 |
| 可行性 | 每步可执行（当前环境能完成） |
| 输入 | 0 个或多个输入 |
| 输出 | 至少 1 个输出 |

**衡量算法的两个指标**：时间复杂度（跑多快）、空间复杂度（占多少内存）。

### 2.2 时间复杂度

**基本操作数**：加减乘除、赋值、访问变量都算一次基本操作。我们不看"实际运行秒数"（换台机器就不一样），而看**基本操作数量随数据规模增长的趋势**。

**渐近记号**（$O$ / $\Omega$ / $\Theta$）：

| 记号 | 含义 | 类比 |
|------|------|------|
| $f(n)=O(g(n))$ | 上界 | $\le$ |
| $f(n)=\Omega(g(n))$ | 下界 | $\ge$ |
| $f(n)=\Theta(g(n))$ | 上下界都夹住 | $=$（同阶） |

常见复杂度级别（从快到慢）：

$$O(1) < O(\log n) < O(n) < O(n\log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)$$

> 竞赛惯例：$10^7$~$10^8$ 次基本操作 ≈ 1 秒。做题先估规模再定算法——$n \le 10^5$ 用 $O(n\log n)$，$n \le 10^3$ 用 $O(n^2)$，$n \le 20$ 才考虑 $O(2^n)$。

### 2.3 最坏 vs 平均复杂度

| 类型 | 定义 | 使用场景 |
|------|------|---------|
| 最坏时间复杂度 | 每个规模下用时最长的输入 | 竞赛/考试，保证任何数据都能过 |
| 平均复杂度 | 所有输入用时的期望 | 理论研究、部分随机场景 |

> 一般说"这个算法 $O(n^2)$"默认指**最坏情况**。

## 3. 应用实例：最大子列和问题

### 3.1 问题描述

给定 $N$ 个整数序列 $\{A_1, A_2, \dots, A_N\}$，求最大连续子列和（所有连续子序列和的最大值）。

> 例：$[-2, 11, -4, 13, -5, -2]$ 的最大子列和为 $20$（子列 $[11, -4, 13]$）。

### 3.2 四种解法（复杂度递进）

| 算法 | 时间复杂度 | 思路 | 适用 |
|------|-----------|------|------|
| 暴力三重循环 | $O(n^3)$ | 枚举起点 i、终点 j，再求和 | 不适用（太慢） |
| 优化双重循环 | $O(n^2)$ | 枚举起点 i，边加边累计 | 小规模 |
| 分治法 | $O(n\log n)$ | 左半最大 / 右半最大 / 跨中点最大，取三者最大 | 竞赛可用 |
| **在线处理** | $O(n)$ | 一次扫描，当前和为负就丢弃重计 | **最优** |

### 3.3 在线处理算法（重点，必须掌握）

核心思想：**只要当前子列和为负，它对后续结果只有坏处，直接丢弃，从下一个元素重新开始**。

```cpp
int maxSubseqSum(int a[], int n) {
  int thisSum = 0, maxSum = 0;
  for (int i = 0; i < n; ++i) {
    thisSum += a[i];      // 向右累加
    if (thisSum > maxSum)
      maxSum = thisSum;   // 发现更大和，更新答案
    else if (thisSum < 0)
      thisSum = 0;        // 当前子列和为负，不可能作为前缀，丢弃
  }
  return maxSum;
}
```

> **为什么 $O(n)$ 是对的**：最优子列一定不以负数前缀开头。若某前缀和为负，去掉它能得到更大的和，矛盾。

### 3.4 常见坑

- 全为负数时：答案为 0（本算法）还是最大负数（依题意）？**看题目要求**——PTA 01-复杂度1 要求输出具体子列时规则不同
- 分治法边界：递归出口是单个元素；跨中点部分要从中间往两端扩展求最大和
- 只记"最大和"不记"是哪一段"时，需要额外变量记录左右端点（01-复杂度2 要求）

## 4. 本节重点

- 数据结构 = 数据对象集 + 操作集 + 规则（ADT 三要素）
- 程序 = 算法 + 数据结构
- 时间复杂度看"增长趋势"不看"实际秒数"，竞赛默认最坏复杂度
- 复杂度阶梯：$O(1) < O(\log n) < O(n) < O(n\log n) < O(n^2) < O(2^n)$
- **最大子列和：在线处理 $O(n)$ 是最优解，"和为负就丢弃"是核心直觉**
- **常见坑**：全负数边界、分治跨中点部分、需要输出子列端点时记得记录位置
