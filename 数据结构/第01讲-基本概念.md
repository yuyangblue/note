## 1. 什么是数据结构

### 1.1 三个引例：数据组织方式决定效率

**例一：图书摆放（数据组织）**

问题：给你一堆书架和书，怎么摆？摆书不只是"放进去"，还要支持两个操作：**新书插入**、**查找指定书**。三个方案对比：

| 方案 | 插入 | 查找 | 代价 |
|------|------|------|------|
| 随便放 | $O(1)$，哪儿空放哪儿 | 从头扫到尾，书城规模下累死 | 查找极慢 |
| 按书名拼音字母序 | 需移动大量书留空位 | 二分查找，每次缩半 | 插入极慢 |
| **分类 + 各类内按字母序** | 先定类，类内二分定位 | 先定类再二分，规模大幅缩小 | 空间分配、分类粒度要斟酌 |

> **结论**：解决问题方法的效率，**跟数据的组织方式直接相关**。图书摆放=数据组织，书架=存储空间，分类=逻辑结构。

**例二：PrintN（空间使用）**

打印 1 到 N，两种实现：for 循环 vs 递归。

- 循环版：只用临时变量，空间占用**恒定**，N 再大也没问题
- 递归版：每层递归都要把当前函数状态压入系统栈，空间占用 $O(n)$。实测 $N=100000$ 时**直接爆栈非正常退出**，一个数字都没打出来

> **结论**：解决问题方法的效率，**跟空间的利用效率有关**。递归代码简洁，但系统栈空间是有限的。

**例三：多项式求值（算法效率）**

计算多项式 $f(x)=a_0+a_1x+\dots+a_nx^n$ 在给定点 $x$ 的值。

- **算法一（直接翻译定义）**：每项算 $x^i$ 再乘系数。乘法次数 $\sum_{i=1}^{n} i = \frac{n^2+n}{2}$
- **算法二（秦九韶算法/霍纳法则）**：把 $x$ 当公因子层层提取，从里往外算。乘法次数只有 $n$

用 `clock()` 计时（`start=clock()` → 跑函数 → `stop=clock()`，`duration=(stop-start)/CLK_TCK`；函数太快时重复跑 MAXK 次再除以次数），实测两个算法**差一个数量级**。

> **结论**：解决问题方法的效率，**还跟算法的巧妙程度有关**。

### 1.2 数据结构与抽象数据类型（ADT）

**什么是数据结构**：

- 数据对象在计算机中的**组织方式**
- 数据对象不是孤立的，一定跟加在它上面的一**系列操作**相关联，实现这些操作的方法叫**算法**

**两个层次的概念**：

| 概念 | 含义 | 例子 |
|------|------|------|
| 逻辑结构 | 数据之间的抽象关系 | 线性结构（一对一）、树（一对多）、图（多对多） |
| 物理存储结构 | 在内存中实际怎么放 | 连续放（数组）、隔开放（链表） |

**抽象数据类型（ADT）**：`Abstract Data Type`，两个关键词——"数据类型" + "抽象"。

- **数据类型** = 数据对象集 + 与数据集合相关联的操作集
- **抽象** = 描述不依赖于具体实现：与机器无关、与物理存储结构无关、与算法和编程语言无关；只描述"是什么"，不关心"怎么做到的"

**矩阵 ADT 例子**：

```
ADT Matrix
数据对象集：N×M 矩阵，元素用三元组 (a, i, j) 描述（值、行号、列号）
操作集：
  Matrix Create(M, N)        // 建 M×N 空矩阵
  int GetMaxRow(Matrix A)    // 返回总行数
  int GetMaxCol(Matrix A)    // 返回总列数
  ElementType GetEntry(A, i, j)  // 取 (i,j) 处元素
  Matrix Add(A, B)           // 行列一致则相加，否则返回错误标志
  Matrix Multiply(A, B)      // 行数=列数匹配则相乘
```

抽象的好处：元素类型用 `ElementType` 统一（`#define` 一改全换），存储方式（二维数组/十字链表）与实现语言都不影响 ADT 的描述。

## 2. 什么是算法

### 2.1 定义与特性

**算法（Algorithm）** 的五个特性：

| 特性 | 含义 |
|------|------|
| 有限指令集 | 一堆指令，必须是有限的 |
| 接受输入 | 0 个或多个（可以没有输入） |
| 产生输出 | 至少 1 个输出，否则没意义 |
| 有限步骤终止 | 不能无限循环（区别于操作系统这类永不终止的程序） |
| 指令无歧义 + 可执行 | 每步有明确目标、不依赖具体语言和实现手段 |

伪码描述要**抽象**：例如选择排序的伪码，`List` 不必是数组（链表也行），`Swap` 不必是函数（宏也行）——描述算法时这些是"不关心的实现细节"。

### 2.2 什么是好的算法：两个指标

| 指标 | 符号 | 含义 |
|------|------|------|
| 空间复杂度 | $S(n)$ | 程序执行时占用存储单元的长度 |
| 时间复杂度 | $T(n)$ | 程序执行时耗费时间的长度 |

两者都是数据规模 $n$ 的函数。

**空间复杂度实例（递归爆栈）**：递归 PrintN 每层调用都要存状态，占用空间 $S(n)=c\cdot n$，随 $n$ 线性增长；循环版 $S(n)=O(1)$ 恒定。

**时间复杂度实例（多项式）**：算法一乘法 $\frac{n^2+n}{2}$ 次 → $T(n)=c_1n^2+c_2n$；算法二 $n$ 次 → $T(n)=cn$。$n$ 充分大时 $n^2$ 远超 $n$，算法二一定快得多。

**两种复杂度**：

| 类型 | 含义 | 备注 |
|------|------|------|
| 最坏情况复杂度 $T_{worst}(n)$ | 每个规模下用时最长的输入 | **我们通常分析它**，因为平均太难算 |
| 平均复杂度 $T_{avg}(n)$ | 所有输入用时的期望 | 数学上更难 |

> 竞赛/考试默认关心**最坏情况**：保证任何数据都能在规定时间/空间内跑完。

### 2.3 复杂度的渐进表示

$T(n)=O(f(n))$ 表示存在常数 $C$ 和 $n_0$，使得 $n\ge n_0$ 时 $f(n)$ 是 $T(n)$ 的**上界**；$\Omega$ 是**下界**；$\Theta$ 表示既是上界又是下界（同阶）。

**重要注意**：

- 上下界**不唯一**：$O(n)$ 的算法也可写成 $O(n^2)$、$O(n^3)$……但太松没意义
- 写 $O$ 取**最小的上界**，写 $\Omega$ 取**最大的下界**
- 对数的底无关紧要（换底公式只差常数倍），所以都写 $\log n$

**复杂度增长速度表**（$n$ 从 1 到 32）：

| $n$ | 1 | 2 | 4 | 8 | 16 | 32 |
|-----|---|---|---|---|----|----|
| $1$ | 1 | 1 | 1 | 1 | 1 | 1 |
| $\log n$ | 0 | 1 | 2 | 3 | 4 | 5 |
| $n$ | 1 | 2 | 4 | 8 | 16 | 32 |
| $n\log n$ | 0 | 2 | 8 | 24 | 64 | 160 |
| $n^2$ | 1 | 4 | 16 | 64 | 256 | 1024 |
| $n^3$ | 1 | 8 | 64 | 512 | 4096 | 32768 |
| $2^n$ | 2 | 4 | 16 | 256 | 65536 | 4294967296 |
| $n!$ | 1 | 2 | 24 | 40320 | — | — |

**速度排序**（慢到快理解）：

$$\log n \ll n \ll n\log n \ll n^2 \ll n^3 \ll 2^n \ll n!$$

> **专业直觉**：看到 $O(n^2)$ 的算法，本能地想"能不能降到 $O(n\log n)$"。$n=10^6$ 时两者差几十万倍。

**复杂度分析小窍门**：

| 结构 | 规则 |
|------|------|
| 两段顺序拼接 | 总复杂度 = 取两者中**较大**的 |
| 两段嵌套 | 总复杂度 = 两者**相乘** |
| for 循环 | 循环次数 × 循环体复杂度 |
| if-else | 取条件判断、两个分支中**最大**的 |
| k 阶多项式 $T(n)=a_kn^k+\dots+a_0$ | 只保留**最高次项**，其余忽略 |

## 3. 应用实例：最大子列和问题

### 3.1 问题定义

给定 $N$ 个整数的序列 $\{A_1,A_2,\dots,A_N\}$，求所有连续子列 $\sum_{k=i}^{j}A_k$ 中**最大的那个和**；若最大和为负数，则返回 0。

> 例：序列 $[-1, 3, -2, 4, -6, 1, 6, -1]$，最大子列和为 $7$（子列 $[1, 6]$）。

### 3.2 四种算法对比

| 算法 | 思路 | 复杂度 | 实测（$10^5$ 规模） |
|------|------|--------|--------------------|
| 算法1 | 三重循环暴力枚举 i、j、k | $O(n^3)$ | $n=10^4$ 就跑不动（NA） |
| 算法2 | 去掉 k 循环，j 递增时累加 | $O(n^2)$ | $10^5$ 也算不下去 |
| 算法3 | 分而治之 | $O(n\log n)$ | 几秒内出结果 |
| **算法4** | **在线处理** | $O(n)$ | <1 秒出结果 |

### 3.3 算法1 → 算法2 的优化关键

算法1 的笨：当 $j$ 增加 1 时，它又从 $i$ 开始重新加一遍（多余的 k 循环）。**算法2**：对于相同的 $i$，$j$ 每增加 1，只需在之前的部分和上**加一个 $A[j]$** 即可。

### 3.4 算法3：分而治之（$O(n\log n)$）

三步：

1. **分**：把数组从中间一分为二
2. **递归**：分别求左半边最大子列和、右半边最大子列和
3. **治**：从中间切分线分别向左、向右扫描，求**跨边界**最大子列和

答案 = max(左半最大, 右半最大, 跨边界最大)。

**复杂度推导**（重点）：

$$T(n) = 2T(n/2) + cN,\quad T(1)=O(1)$$

逐层展开：$T(n) = 2^kT(n/2^k) + kcN$，当 $n/2^k=1$ 即 $k=\log n$ 时：

$$T(n) = n\cdot O(1) + c\cdot n\log n = O(n\log n)$$

### 3.5 算法4：在线处理（$O(n)$，最快）

核心思想（伪码）：

```
ThisSum = 0, MaxSum = 0
for i in [0, n):
    ThisSum += A[i]
    if ThisSum > MaxSum: MaxSum = ThisSum
    else if ThisSum < 0: ThisSum = 0   # 负子列和直接丢弃
return MaxSum
```

**为什么丢弃负和是对的**：当前子列和为负，往后再加任何数都只会让总和更小，不可能成为最大子列和的前缀，所以从头开始。

**"在线处理"的含义**：每输入一个数据就即时处理；**任何地方终止输入**，算法都能给出当前正确的解。正因如此它只需一次扫描，$O(n)$ 是解决该问题**理论上最快**的复杂度（至少要把每个元素读一遍）。

> 副作用：代码极简但正确性不明显，理解成本略高——这是它的"代价"。

## 4. 本节重点

- 数据结构 = 数据对象在计算机中的**组织方式** + 与其相关的**操作集**（操作实现方法=算法）
- 三个引例的结论：效率与**数据组织方式、空间利用、算法巧妙程度**直接相关
- ADT = 数据对象集 + 操作集，**抽象**=不依赖具体实现（类型、存储、语言都无关）
- 逻辑结构（线性/树/图） vs 物理存储结构（数组/链表）
- 算法五特性：有限指令集、可无输入、必有输出、有限步终止、指令无歧义且可执行
- 好算法指标：$S(n)$ 空间复杂度 + $T(n)$ 时间复杂度，通常分析**最坏情况**
- 渐进记号：$O$ 上界 / $\Omega$ 下界 / $\Theta$ 同阶；写 $O$ 取最小上界
- 复杂度阶梯：$\log n < n < n\log n < n^2 < 2^n < n!$；看到 $n^2$ 本能想降 $n\log n$
- 最大子列和四算法：$O(n^3)\to O(n^2)\to O(n\log n)\to O(n)$，在线处理最优
- **常见坑**：全负数序列答案约定为 0（看题意）；分治的跨边界部分要从中线往两端扩展；在线处理只记和、不记子列端点（需要端点时另加变量）
