## 一、二叉搜索树（BST）

### 1. 定义、性质与查找

静态查找与动态查找的区分见 [[05a-树和二叉树(上).md#1. 静态查找与动态查找]]，此处不重复。这里只需记住动态查找的两难：有序数组查找快，但插入删除要搬动 $O(n)$ 个元素；链表插入删除快，但查找要逐个比对 $O(n)$。二叉搜索树正是为了同时拿到两头的好处：结构上像链表一样可以就地摘下或挂上一个结点，查找时又能像二分一样按大小剪掉一半。代价是效率不再由元素个数决定，而由**树形**决定——这是后面 AVL 树要解决的问题。

二叉搜索树（BST，又称二叉排序树）：可以为空；非空时左子树所有关键字小于根、右子树所有关键字大于根，且左右子树本身也是 BST。

注意：定义里的"所有"不能省，BST 是全树约束而非父子间的局部比较。错法因此有两类。一类是**局部就能看出**的，如课件上那棵根 18 的树：左孩子 10，10 的左孩子 7、右孩子却是 5，而 $5<10$ 挂在 10 的右边，不符合"右孩子大于父"。另一类是**局部全对、全局才出错**的：取根 3、左孩子 2、2 的右孩子 1，父子比较处处成立（$1<2<3$），但 2 的右子树里含 1，而 $1<2$，已违反定义。后者等价地看中序——中序为 $2,1,3$，不再升序。做题时若只逐个核对父子大小，第二类错位查不出来，务必回到"中序必须升序"或"整棵子树"上核对。

关键字互异时，这两件事互为充要：**二叉树是 BST，当且仅当其中序序列严格递增**。所以"判断一棵树是否为 BST"最省事的做法是中序遍历一次看是否单调，$O(n)$ 且不必维护各结点的取值上下界。"二叉排序树"这个中文名即由此而来。先序与后序都不具备这条性质：它们把根排进序列的端点，而根正是全树的分界值，次序由此被打乱。（三种遍历的定义与递归实现见 [[05a-树和二叉树(上).md#1. 先序/中序/后序（递归）]]。）

规则：若 BST 的关键字恰为 $1\sim n$，则任一根的值等于**其左子树结点数加一**，不必试填。因为中序序列就是 $1,2,\dots,n$ 的升序，根在中序里排第"左子树结点数加一"位。只给形状不给数值的题，靠这条一步出答案。

查找从根开始：比根小就往左、大就往右、相等即命中，走到空指针即说明不存在。课件里 `BinTree` 与 `Position` 是同一类型的两个名字——前者强调"一棵树"，后者强调"某结点的地址"，所以函数签名里混用并不矛盾。

```cpp
#include <iostream>
using namespace std;

using ElementType = int;

struct TreeNode {
    ElementType Data;
    TreeNode *Left;
    TreeNode *Right;
};

using BinTree  = TreeNode*;   /* 指向结点的指针：既可指"一棵树"，也可指"某个结点" */
using Position = BinTree;     /* 两者是同一类型，只是强调的侧面不同 */

Position Find(ElementType X, BinTree BST)
{
    if (!BST) return NULL;                       /* 空树：查找失败 */
    if (X > BST->Data)      return Find(X, BST->Right);
    else if (X < BST->Data) return Find(X, BST->Left);
    else                    return BST;          /* 命中 */
}
```

三次递归都是"把下层的返回值原样交回"，本层不做任何运算，这叫**尾递归**。尾递归的栈帧没有存在的必要——不需要等下层返回后再乘加、拼接，所以可以等价地改成循环：

```cpp
Position IterFind(ElementType X, BinTree BST)
{
    while (BST) {
        if (X > BST->Data)      BST = BST->Right;
        else if (X < BST->Data) BST = BST->Left;
        else                    return BST;
    }
    return NULL;                                  /* 走到空，查找失败 */
}
```

能否这样改，只看一条：`return` 后面是不是"对递归结果再做运算"。写成 `return max(H(L),H(R)) + 1` 那样就有活要等下层返回后再干，栈帧不能省。

查找的比较次数不超过树高，效率取决于树形；最坏退化为斜树时 $O(n)$，这正是引入平衡树的动机。

最小与最大的找法是"沿一个方向走到黑"。课件故意给了两种写法——最小用递归、最大用迭代，两者可以互换，不是两个不同的算法。

```cpp
Position FindMin(BinTree BST)          /* 递归：沿左指针到底 */
{
    if (!BST) return NULL;
    else if (!BST->Left) return BST;   /* 没有左孩子，它就是最小 */
    else return FindMin(BST->Left);
}

Position FindMax(BinTree BST)          /* 迭代：沿右指针到底 */
{
    if (BST)
        while (BST->Right) BST = BST->Right;
    return BST;
}
```

注意：最值在**最左/最右**结点上，而不在"叶子"上。最左结点没有左孩子，但**可以有右孩子**，所以普通 BST 中最小值不一定是叶；例如键值 $1,1.5,2$ 建成根 2、左 1、1 的右孩子 1.5，最小值 1 就带着右孩子。

只有在**完全二叉树**中才能断言最小值必为叶：完全二叉树按层从左往右填，有右孩子就必有左孩子，最左结点既无左孩子，也就不可能有右孩子。最大值仍不能断言——$n=6$ 的完全二叉树（关键字 $1\sim 6$）根为 4、右孩子为 6，而 6 只带一个左孩子 5，是内部结点。

### 2. 插入

按查找路径向下走，直到空指针处挂上新结点。关键是要记住"待挂的父亲位置"——递归版本巧妙地利用返回值：每层把递归结果重新赋给 `Left/Right`，到空树时申请新结点并返回其地址，上层自然接回。相同关键字通常忽略或计数。

```cpp
BinTree Insert(ElementType X, BinTree BST)
{
    if (!BST) {                                  /* 空树：新建并返回 */
        BST = new struct TreeNode;
        BST->Data  = X;
        BST->Left  = BST->Right = NULL;
    } else if (X < BST->Data)
        BST->Left  = Insert(X, BST->Left);
    else if (X > BST->Data)
        BST->Right = Insert(X, BST->Right);
    /* X 已存在：什么都不做，保持原结点 */
    return BST;                                  /* 返回本子树的根 */
}
```

插入顺序决定树形，用课件上十二个月份的例子看得最清楚。以 `Jan Feb Mar Apr May Jun July Aug Sep Oct Nov Dec` 的日期顺序依次插入，键的字母序与插入顺序几乎无关，结果右分支 Mar–May–Sept–Oct–Nov 一路深到第 6 层、左分支 Jan–Feb–Apr–Aug–Dec 到第 5 层；而 12 个结点的完全二叉树只有 4 层。**同一组键换一个插入顺序，就得到另一棵树**——树形由插入顺序决定，不由键的集合决定。这一点是理解"为什么必须平衡"的前提：退化不是偶发事故，而是有序输入下的必然结果。

### 3. 删除

分三种情况：

- **叶结点**：直接把父亲对应指针置空；
- **只有一个孩子**：把孩子直接接到父亲上；
- **左右皆非空**：用**右子树最小值**（或左子树最大值）替换被删结点的值，再去删除那个替补结点。替补结点一定在子树最左/最右端，只有至多一个孩子，从而把复杂情况化为前两种。

```cpp
BinTree Delete(ElementType X, BinTree BST)
{
    Position Tmp;
    if (!BST) cout << "要删除的元素未找到";
    else if (X < BST->Data)
        BST->Left  = Delete(X, BST->Left);          /* 左子树递归删除 */
    else if (X > BST->Data)
        BST->Right = Delete(X, BST->Right);         /* 右子树递归删除 */
    else                                            /* 找到要删除的结点 */
        if (BST->Left && BST->Right) {              /* 左右两个孩子 */
            Tmp = FindMin(BST->Right);
            BST->Data  = Tmp->Data;                 /* 用右子树最小值顶上 */
            BST->Right = Delete(BST->Data, BST->Right);
        } else {                                    /* 一个孩子或没有孩子 */
            Tmp = BST;
            if (!BST->Left)       BST = BST->Right; /* 有右孩子或无子结点 */
            else if (!BST->Right) BST = BST->Left;  /* 有左孩子 */
            delete Tmp;
        }
    return BST;
}
```

以一棵树为例走一遍。取根 41，左子树 20（子结点 11 与 29，29 的右孩子 32），右子树 65（子结点 50 与 91）。

递归版本的骨架是"返回值即新根"：`Delete` 每层返回处理之后的子树根，调用方用 `BST->Left = Delete(X, BST->Left)` 接回去。删除可能让子树的根换人，不接回去指针就断了。前三个分支只负责沿查找路径下行，真正干活的是最后那个 `else`。

- 删 11（叶）：41 → 20 → 11，在 11 处 `!BST->Left` 成立，`BST = BST->Right` 得 `NULL`，`free` 后返回 `NULL`，于是 `20->Left = NULL`。叶结点不需要单独的分支：空右孩子就是 `NULL`，走"只有右孩子"那一支与"无子结点"完全等价。
- 删 29（独子）：在 29 处同样走 `!BST->Left`，`BST = BST->Right` 得 32，再 `delete` 掉 29 后返回 32，上层 `20->Right` 便指向 32。所谓"把孩子直接接到父亲上"，在这里就是返回孩子、由上一层赋值完成，本层并不修改父亲的指针。
- 删 41（双子）：`FindMin` 从 65 一路向左得 50；执行 `BST->Data = Tmp->Data` 后根的值变成 50，此刻树里 50 出现两次；再 `BST->Right = Delete(50, 右子树)`，50 在 65 的左边，命中时它没有左孩子，于是返回右孩子 `NULL`，`65->Left` 被置空；返回 65，根的右孩子重新接上。

注意：删 41 那一支里的 `Delete(BST->Data, BST->Right)` 不能写成 `Delete(X, BST->Right)`。`X` 仍是 41，而根的值已被覆盖成 50；拿 41 去右子树里找会一路走到空指针，把 `65->Left` 置成 `NULL`——看起来像"50 被顺手删掉了"，实际只丢了指针而没有 `free`，并且最小结点一旦不在第一层，丢掉的是一整片子树。

注意：双子分支里的 `Tmp` 只是借来取值，不要在此 `delete Tmp`；释放发生在更深一层的递归里，全流程只释放一次。另外，最小结点是子树最左的结点，必然没有左孩子，所以递归进入下一次时 `!BST->Left` 必然成立，不会再次进入双子分支，这就是该算法不需要额外出口的原因。

注意：`if (!BST) cout << "要删除的元素未找到";` 这一支返回 `NULL`，看似会让上层的 `BST->Left` 变成 `NULL` 从而清空子树；实际它只在"被调用者本身为空指针"时触发，赋回去的那个指针原本就是 `NULL`，因此安全。

若结点除关键字外还带其他字段，`BST->Data = Tmp->Data` 须改成整份拷贝；更稳妥的是**链接法**——把最小结点从原位置摘下、直接接到被删结点的位置，不做值覆盖。

## 二、平衡二叉树（AVL）

### 1. 为什么需要平衡

同样 $n$ 个结点，插入顺序不同会得到不同形态的 BST，平均查找长度差异巨大。十二个月份按三种次序插入，键的集合完全相同，ASL 却分别是 $3.5$（自然月份顺序）、$3.0$（`July, Feb, May, Mar, Aug, Jan, Apr, Jun, Oct, Sept, Nov, Dec`）与 $6.5$（按字符串大小顺序，退化成一条链）。若树退化为链，查找从 $O(\log n)$ 退化为 $O(n)$。

**平衡因子**：结点左子树高度减右子树高度。**AVL 树**定义：空树，或任意结点平衡因子绝对值不超过 1。

设 $n_h$ 为高度为 $h$ 的 AVL 树的最少结点数（高度按**边数**计，单结点 $h=0$）。思路是"把平衡条件用到最紧"：

1. 根占一个；
2. 左右子树高度差不能超过 1，而要结点最少就让差**恰好取 1**——两侧同高则结点更多，差为 2 又不合定义；
3. 于是高的一侧高 $h-1$、矮的一侧高 $h-2$，两侧各自都取最少。

$$n_h=n_{h-1}+n_{h-2}+1,\qquad n_0=1,\quad n_1=2$$

两侧谁高都行，互为镜像，所以这样的"最瘦"树形唯一而左右可对调。

注意：$n_1=2$ 而不是 1。高度为 1 的 AVL 树必须是"根加一个孩子"共两个结点，单结点树的树高是 0。初值取错会让整张表错位。式中 $+1$ 只算根，不要与两侧混。

依次算下去是 $1,2,4,7,12,20,33,54,88,\dots$。与斐波那契对照有 $n_h=F_{h+3}-1$（按 $F_1=F_2=1$ 计；课件用 $F_0=F_1=1$，同一式子写成 $n_h=F_{h+2}-1$，只是下标起点不同），即 $n_h+1$ 恰为标准斐波那契项——这是它"看着眼熟"的来源。由 $F_i\sim\phi^i/\sqrt5$、$\phi=(1+\sqrt5)/2\approx1.618$ 得 $n_h=\Theta(\phi^h)$；反过来 $n$ 个结点的 AVL 树高 $h=O(\log n)$，约为 $1.44\log_2 n$，只比完全二叉树的 $\log_2 n$ 多一个常数因子。查找、插入、删除都沿一条根到叶的路径行进，故三者均为 $O(\log n)$。

规则：反问题必考，给 $n$ 问 AVL 树最多几层，就是找满足 $n_h\le n$ 的最大 $h$，查表即可，不必解不等式。$n=12$ 时 $n_4=12$ 而 $n_5=20$，故高度至多 4，即 5 层。

注意：别与满二叉树混淆。高 $h$ 的满二叉树有 $2^{h+1}-1$ 个结点，那是**最多**；$n_h$ 是**最少**。$h=2$ 时前者 7 个、后者 4 个，差距从这里开始拉开。

### 2. 四种旋转调整

插入新结点后，从插入点向上找第一个平衡因子绝对值为 2 的结点（"被破坏者"，课件称"发现者"），看新结点（"麻烦结点"）位于它的哪一侧：

| 麻烦结点位置 | 类型 | 教材叫法（408） | 课件叫法 | 操作（方向按教材命名） |
|---|---|---|---|---|
| 被破坏者的右子树的右子树 | RR | 左单旋 | 右单旋（RR 旋转） | 右孩子上提作新根，被破坏者作它的左孩子 |
| 被破坏者的左子树的左子树 | LL | 右单旋 | 左单旋（LL 旋转） | 左孩子上提作新根，被破坏者作它的右孩子 |
| 被破坏者的左子树的右子树 | LR | 左右双旋 | 左-右双旋 | 先对左子树左旋，再对被破坏者右旋 |
| 被破坏者的右子树的左子树 | RL | 右左双旋 | 右-左双旋 | 先对右子树右旋，再对被破坏者左旋 |

注意：单旋的"左/右"有**两套命名，方向正好相反，指的是同一个动作**。教材（严蔚敏、王道、408）按**转动方向**命名：顺时针转叫右单旋，LL 正是顺时针；课件按**插入位置**命名：LL 的麻烦结点在左边，就叫左单旋。判断时不看名字看动作——**看新根从哪里升上来**：左孩子的左孩子上升，教材叫右旋、课件叫左单旋。答题先按 LL/RR/LR/RL 定类型，再照题目给定的叫法写，别凭印象填"左"或"右"。

旋转时必须保持 BST 性质：中间值结点上提，四块子树按"左小右大"重新挂接。只需调整**最下面**那个失衡点，上层会自动恢复平衡。若插入未引起失衡，树结构不变，但沿路径的平衡因子仍需更新。

换一个插入顺序走一遍，四种类型各出现一次。按 `Mar, May, Nov, Aug, Apr, Jan, Dec, July, Feb` 依次插入：

| 插入 | 发现者 | 麻烦结点位置 | 类型 |
|---|---|---|---|
| Nov | Mar（$-2$） | 右子树 May 的右边 | RR |
| Apr | Mar（$2$） | 左子树 Aug 的左边 | LL |
| Jan | May（$2$） | 左子树 Aug 的右边 | LR |
| Feb | Aug（$-2$） | 右子树 Jan 的左边 | RL |

前两次是单旋。插完 `Mar, May, Nov` 得到右斜链 `Mar → May → Nov`，Mar 的 BF 为 $-2$；May 上提作根，Mar 挂到它左边、Nov 仍在右边，斜链被折成两层。再插 `Aug` 与 `Apr`，Mar 左边长成 `Aug → Apr`，Mar 的 BF 变为 $2$；Aug 上提作根，Mar 挂到它右边。

后两次是双旋，**第一次旋完仍不平衡**，必须连做两次。插 `Jan` 后 May 的 BF 为 $2$，麻烦结点在左子树 Aug 的右边（Mar 之下）：先对 Aug 左旋把 Mar 提到 Aug 的位置，再对 May 右旋把 Mar 提到根；结果 Mar 的左边仍是 Aug（带着 `Apr`）、右边是 May（带着 `Nov`），`Jan` 落到 Aug 的右侧。插 `Feb` 时 Aug 的 BF 为 $-2$，麻烦结点在右子树 Jan 的左边（Dec 之下）：先对 Jan 右旋把 Dec 提上来，再对 Aug 左旋。

继续插入 `June`、`Oct`、`Sept` 补满十二个月，层数为 4，与 12 个结点的完全二叉树相同——这就是"AVL 的高度仍在 $\log_2 n$ 量级"的直观例子，全程共调整六次（RR、LL、LR、RL、LR、RR）。

【进阶】AVL 树的详细推导与实现见 OI-Wiki：[数据结构/AVL树](../OI-Wiki/数据结构/AVL树.md)。

## 三、小白专场：是否同一棵二叉搜索树

### 1. 题意与样例

给定 $N$ 与 $L$：第一行序列用来建基准树，后面 $L$ 行各给一个序列，判别它们是否与基准序列生成**同一棵** BST。输入以 $N=0$ 结束。

课件原数据：

```
4 2
3 1 4 2
3 4 1 2
3 2 4 1
2 1
2 1
1 2
0
```

```
Yes
No
No
```

第一组 $N=4,L=2$，基准 `3 1 4 2` 建出"根 3、左 1（1 的右孩子 2）、右 4"。两个待判序列里，`3 4 1 2` 一致，`3 2 4 1` 不一致。第二组 $N=2,L=1$，基准 `2 1` 的根是 2，而 `1 2` 的根是 1，直接判 No。

**为什么 `3 1 4 2` 与 `3 4 1 2` 同树**：两个序列里 1 和 4 都分居 3 的两侧，插入时互不干扰。1 先来就占住 3 的左边、4 后来占右边，反过来也一样。

**为什么 `3 2 4 1` 不同**：2 与 1 都落在 3 的左侧，2 先插入就成了 3 的**左孩子**，随后 1 只能挂到 2 的左边；而基准序列里 1 是 3 的左孩子、2 挂在 1 的右边。同一个集合 `{1,2}`，谁先来谁占上风。

规则：**落点分居某结点两侧时，先后次序无关；落在同一侧时，先插入的会成为后插入的祖先。** 这句话是整道题的直觉来源，也是下面"标记法"为什么成立的依据。

### 2. 三种思路

1. **分别建两棵树再比较**。按两个序列各建一棵，递归比对是否同形同值。直白，但每个待判序列都要重建一棵树，共 $L$ 次建树。
2. **不建树，递归划分**。以序列首元素为根，把剩余元素按"比根小 / 比根大"分成两组（**保持原顺序**），再递归比较两组。
   - `3 1 2 4` 与 `3 4 1 2`：都划分为 `{1 2} | 3 | {4}`，两组字面相同，递归下去仍相同 → 一致；
   - `3 1 2 4` 与 `3 2 4 1`：后者划分为 `{2 1} | 3 | {4}`，左组是 `{2 1}` 而非 `{1 2}`。集合一样，但首元素不同（2 对 1），递归一步就分叉 → 不一致。
   - 注意比较的是**子序列**不是集合：集合相同、首元素不同，对应的子树就不同。这一点是方法 2 最容易写错的地方。
3. **建一棵基准树，其余序列走查**。只建一次树，后面的序列逐个数在树上走一遍，复用同一棵树。本节采用，也是 PTA 上的标准解法。

### 3. 标记法与走查判别

每个结点加一个 `flag` 字段（0/1），记录它在本次走查中是否已被访问过。

判别规则：把待判序列的数依次在树 T 中按 BST 路径搜索，**每次搜索经过的结点如果此前都出现过，则一致；一旦碰到没出现过的结点，就不一致**。

为什么这等价于"同一棵树"：按 BST 插入，一个新数的落点完全由"路径上已有的结点"决定。只要路径上的结点早已就位，插入次序就改变不了形状；反之若半路撞见一个尚未就位的结点，说明这个数本该先于它出现，两个序列的祖先关系已经不同了。

`flag` 的两种状态对应两种处理：

1. `flag == 1`（此结点已就位）：按大小继续向左或向右。若此时值**正好相等**，说明序列里出现了重复值——BST 中同值不会再次插入，返回不一致。
2. `flag == 0`（此结点尚未就位）：只有值**正好相等**才能把它激活（置 1）并算作通过；若不等，说明这个数本该从别处经过，路径已经分叉，返回不一致。

第一个元素必须先与树根比较，不等则整行直接判不一致。

### 4. 完整实现

结点定义与建树：

```cpp
struct TreeNode {
    int v;
    TreeNode *Left, *Right;
    int flag;                 // 0 未访问，1 已访问
};
using Tree = TreeNode *;

Tree NewNode(int V)
{
    Tree T = new TreeNode;
    T->v = V;
    T->Left = T->Right = nullptr;
    T->flag = 0;
    return T;
}

Tree Insert(Tree T, int V)
{
    if (!T) T = NewNode(V);
    else if (V > T->v) T->Right = Insert(T->Right, V);
    else               T->Left  = Insert(T->Left,  V);
    return T;
}

Tree MakeTree(int N)
{
    int V;
    cin >> V;
    Tree T = NewNode(V);
    for (int i = 1; i < N; i++) { cin >> V; T = Insert(T, V); }
    return T;
}
```

单个数的走查：

```cpp
bool check(Tree T, int V)
{
    if (T->flag) {                        // 这条路已经走过
        if (V < T->v)      return check(T->Left,  V);
        else if (V > T->v) return check(T->Right, V);
        else               return false;  // 已就位又出现同值
    } else {                              // 碰到尚未就位的结点
        if (V == T->v) { T->flag = 1; return true; }
        else return false;                // 落点不符，路径分叉
    }
}
```

整行判别（正确版）：

```cpp
bool Judge(Tree T, int N)
{
    int V, bad = 0;                       // bad = 1 表示已判定不一致
    cin >> V;
    if (V != T->v) bad = 1;               // 首元素必须是根
    else T->flag = 1;
    for (int i = 1; i < N; i++) {
        cin >> V;                         // 无论是否已判错，都要读
        if (!bad && !check(T, V)) bad = 1;
    }
    return !bad;
}
```

清理与主程序：

```cpp
void ResetT(Tree T)
{
    if (T->Left)  ResetT(T->Left);
    if (T->Right) ResetT(T->Right);
    T->flag = 0;
}

void FreeTree(Tree T)
{
    if (T->Left)  FreeTree(T->Left);
    if (T->Right) FreeTree(T->Right);
    delete T;
}

int main()
{
    int N, L;
    cin >> N;
    while (N) {
        cin >> L;
        Tree T = MakeTree(N);
        for (int i = 0; i < L; i++) {
            cout << (Judge(T, N) ? "Yes" : "No") << "\n";
            ResetT(T);                    // 下一轮判别前必须清标记
        }
        FreeTree(T);
        cin >> N;
    }
    return 0;
}
```

### 5. 两个必须知道的坑

**坑一：判定不一致后不能立即 `return`，必须把这一行剩下的数读完。**

课件特意给了对照。错误写法：

```cpp
if (!check(T, V)) return false;      // 后面的数没读，指针停在行中间
```

后果是下一行的读入从这一行的中间开始，整段数据全部错位。实测：把 `3 2 1 4`（在第 2 个数就判错）放在待判序列首位时，正确版输出 `No / Yes`，而错误版错位后读到的 $N$ 不再为 0，输入读完仍在循环里打转。正确做法是用 `bad` 记下"已判错"，循环照常读完 $N$ 个数，最后统一返回。

**坑二：每判别完一行必须 `ResetT` 一次。**

`flag` 是"本次走查"的临时状态，上一行留下的 1 会让下一行直接走进"已就位"分支。实测：给两行**完全相同**的 `3 4 1 2`，正常应输出 `Yes / Yes`；把 `ResetT` 注释掉后变成 `Yes / No`——同一串数字第一遍 Yes、第二遍 No，问题就暴露在这里。

`ResetT` 写成后序（先递归孩子、最后清自己）只是习惯，任何遍历顺序都能清干净。

> 两个坑的共同点：既不崩溃也不报错，只在某些数据上悄悄给出错误结果。课件那组样例测不出坑一（判错的行恰好在末尾），也测不出坑二（每行只判一次），必须自己构造数据才验得出来。

## 四、附：树习题选讲——Complete Binary Search Tree（04-树6）

- **题意**：给定 $N$ 个互不相同的整数，把它们填入一棵**完全二叉搜索树**，输出层序遍历序列。
- **数据结构为什么选数组**：完全二叉树形状固定、没有空洞，父子关系可以直接用下标算出；更关键的是，**数组本身的存放顺序就是层序**，填完按 $0\sim N-1$ 顺序输出即可，不必再写队列做一遍层序遍历。
- **核心算法**：`solve(TRoot, A, left, right)` 处理排序后区间 $[left,right]$ 这一段，把它挂到 `T[TRoot]`：
  1. 算出左子树规模 $L$；
  2. 根就是这一段里的第 $L+1$ 个数：`T[TRoot] = A[left + L]`；
  3. 递归左：`solve(2*TRoot+1, A, left, left+L-1)`；
  4. 递归右：`solve(2*TRoot+2, A, left+L+1, right)`。

第 2 步正是 §一.1 那条性质的直接应用：**BST 的中序就是升序**，所以按中序位置编号，第 $L+1$ 个就是根。这里不需要真的建树再遍历——排序后的数组已经是中序序列，只要知道左子树有几个，根的位置就定了。

- **左子树规模 $L$ 怎么算**（本题唯一的难点）：先求出树里"完美"的部分有几层，再数最底层铺了多少个。

  - $H=\lfloor\log_2(N+1)\rfloor$：完美部分的层数；
  - $X=N-(2^H-1)$：最底层实有结点数；
  - 最底层最多容纳 $2^{H-1}$ 个，故再取 $X\leftarrow\min(X,\,2^{H-1})$；
  - 左子树 = 上面 $H-1$ 层的完美部分 + 最底层靠左的份额：$L=(2^{H-1}-1)+X$。

  注意：最底层的结点**先给左子树**，左子树那一半铺满后才轮到右子树。左右各半，所以一次 `min` 就能截出左子树分到的个数。

注意：本树的根存在 **`T[0]`**，于是左右孩子分别是 $2\cdot TRoot+1$ 与 $2\cdot TRoot+2$。这与堆里 $2i$、$2i+1$ 那套**不是同一个约定**——堆把 0 号留给了哨兵，元素从 1 起存；本题元素直接从 0 存起。两套公式混用会让整棵树错位。

排序直接用标准库即可：`qsort(A, N, sizeof(int), compare)`，四个参数依次是数组首址、元素个数、单个元素的字节数、比较函数；比较函数按"小于/等于/大于"返回负数、零、正数。

## 五、附：线性结构习题选讲——Reversing Linked List

### 1. 什么是抽象的链表

链表是**抽象数据结构**：每个结点存数据 + 存"下一个结点位置"。C/C++ 用原生指针实现，Java 没有指针并不代表没有链表——任何能表示下一结点位置的方式（整数下标、引用）都可以。本题用结构数组模拟内存：数组下标即"地址"，每个分量存 `(地址, 数据, 下一字节下标)`，缺省用 `-1` 表示链尾。

### 2. K 个一组逆转的标准模板

- 链表前先加一个空的头结点（牺牲一点空间换取操作统一）。
- 三个指针：`new`（已逆转部分的新头）、`old`（待逆转部分的旧头）、`tmp`（记住 old 的下一结点，否则改向会丢链）。
- 重复 $K$ 次：`tmp = old->Next; old->Next = new; new = old; old = tmp;`（即把 old 的指向前逆转头）。
- 结束后：原头结点的下一结点（现在是逆转段的尾）接到 `old`（剩余段头），头结点指向 `new`（新段头）。
- 循环次数用计数器 `cnt` 控制；`K=1` 时不动；剩余不足 $K$ 个结点不逆转。

### 3. 为什么不能偷懒

PAT 是黑盒测试。若直接把所有结点按地址排序再每 $K$ 个逆序输出，或用栈模拟，题目会在"内存"里混入若干不在链表上的废结点，使排序/栈做法直接挂掉——这正是"排序者必挂"。

### 4. 边界测试意识

设计/自测一组题必须覆盖：一般情形、地址上下界（00000 与 99999）、结点数恰为 $K$ 的整数倍、$K=N$（整表反转）、$K=1$（不反转）、$N$ 取最大且尾巴长度恰为 $K-1$、以及卡投机取巧的废结点数据。循环多一次少一次、跳出处漏处理，几乎都在这些边界上出错。

【进阶】链表的常见操作与反转技巧见 OI-Wiki：[数据结构/链表](../OI-Wiki/数据结构/链表.md)。
