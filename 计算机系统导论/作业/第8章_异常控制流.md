## 8.9 进程并发时间表

四个进程的存活区间：

| 进程 | 开始时间 | 结束时间 |
| --- | --- | --- |
| A | 5 | 7 |
| B | 2 | 4 |
| C | 3 | 6 |
| D | 1 | 8 |

**并发的判定标准**：两个进程的时间区间有重叠（一个没结束另一个就开始了）。

| 进程对 | 区间重叠？ | 并发地？ |
| --- | --- | --- |
| AB | [5,7] 与 [2,4] 不相交 | 不是 |
| AC | [5,7] 与 [3,6] 在 5–6 重叠 | 是 |
| AD | [5,7] 完全落在 [1,8] 内 | 是 |
| BC | [2,4] 与 [3,6] 在 3–4 重叠 | 是 |
| BD | [2,4] 完全落在 [1,8] 内 | 是 |
| CD | [3,6] 完全落在 [1,8] 内 | 是 |

## 8.10 异常控制流函数的"返回次数"

setjmp、longjmp、execve、fork 四个函数的反常行为：

| 行为 | 匹配函数 | 原因 |
| --- | --- | --- |
| A. 调用一次，返回两次 | fork | 父进程收一次（子 pid），子进程收一次（0） |
| B. 调用一次，从不返回 | execve | 成功后整个地址空间被新程序覆盖，不返回到调用者 |
| B. 调用一次，从不返回 | longjmp | 它不返回到 longjmp 的下一条指令，而是跳回 setjmp 处 |
| C. 调用一次，返回一次或多次 | setjmp | 直接调用返回一次（0）；之后每次 longjmp 跳回来都再返回（非 0 值），所以可能返回多次 |

## 8.11 for 循环里的 Fork（n=2）

```c
int main() {
    int i;
    for (i = 0; i < 2; i++)
        Fork();
    printf("hello\n");
    exit(0);
}
```

**答案：4 个 hello。**

推导：第一次 fork 后进程数翻倍到 2；两个进程都继续跑第二次 fork，翻倍到 4；每个进程都执行一次 printf 然后 exit。`2² = 4`。

## 8.12 doit 里两个 Fork

```c
void doit() {
    Fork();
    Fork();
    printf("hello\n");   // doit 里
    return;
}
int main() {
    doit();
    printf("hello\n");   // main 里
    exit(0);
}
```

**答案：8 个 hello。**

推导：doit 里两次 fork → 进程数 2² = 4；这 4 个进程每个都执行 doit 里的 printf（4 个），然后 return 回 main，再各自执行 main 里的 printf（4 个）。共 8 个。

## 8.13 if(Fork() != 0) 题

```c
int main() {
    int x = 3;
    if (Fork() != 0)
        printf("x=%d\n", ++x);
    printf("x=%d\n", --x);
    exit(0);
}
```

**答案（一种可能输出）：**

```
x=4
x=3
x=2
```

推导：

- 父进程：fork 返回非 0 → 进 if → `++x`：x 从 3 变 4，打印 `x=4`；接着 `--x`：x 从 4 变 3，打印 `x=3`。
- 子进程：fork 返回 0 → 不进 if；直接 `--x`：x 从 3 变 2，打印 `x=2`。

三个打印行内容固定为 `x=4`、`x=3`、`x=2`，但父子并发执行，顺序任意（比如子进程先跑也可能输出 `x=2, x=4, x=3`）。

## 8.14 子进程里 Fork + exit

```c
void doit() {
    if (Fork() == 0) {
        Fork();
        printf("hello\n");
        exit(0);
    }
    return;
}
int main() {
    doit();
    printf("hello\n");
    exit(0);
}
```

**答案：3 个 hello。**

推导：

- 初始进程 P0 调 doit，fork#1 返回非 0 → 跳过 if → return 回 main → 打印 1 个 hello。
- fork#1 的子进程 C1 进 if → 又 fork#2：
  - C1 自己（fork#2 返回非 0）→ 打印 hello 后 exit（1 个）；
  - fork#2 的子进程 → 打印 hello 后 exit（1 个）。

共 1 + 2 = 3 个。注意 if 块里是 `exit(0)`，所以这 2 个子进程打印完就退出，不会回 main。

## 8.15 把子进程里的 exit 换成 return

```c
void doit() {
    if (Fork() == 0) {
        Fork();
        printf("hello\n");
        return;   // 与 8.14 的唯一区别
    }
    return;
}
int main() {
    doit();
    printf("hello\n");
    exit(0);
}
```

**答案：5 个 hello。**

推导：doit 里打印完 hello 是 `return` 而不是 `exit`——if 块里的两个进程（C1 和它 fork 的子进程）return 之后会回到 main，再执行 main 里的 printf：

- P0：main 的 printf（1 个）；
- C1：doit 的 printf（1 个）+ 回 main 再 printf（1 个）；
- C1 fork 出的子进程：doit 的 printf（1 个）+ 回 main 再 printf（1 个）。

共 1 + 2 + 2 = 5 个。这就是 return 和 exit 的差别：return 只是从函数返回，程序继续往下走。

## 8.16 fork 后 counter 是 1 还是 0

```c
int counter = 1;
int main() {
    if (fork() == 0) {
        counter--;
        exit(0);
    } else {
        Wait(NULL);
        printf("counter = %d\n", ++counter);
    }
    exit(0);
}
```

**答案：`counter = 2`。**

推导：fork 后父子各有一份独立的 counter 副本（写时复制）。子进程把自己那份从 1 减到 0 然后 exit，完全不影响父进程。父进程 Wait 回收子进程后，自己的 counter 还是初始的 1，`++counter` 变成 2。子进程改的是自己的副本——这是 fork 后"内存独立"的经典考点。

## 8.18 atexit 与 fork

```c
void end(void) { printf("2"); fflush(stdout); }
int main() {
    if (Fork() == 0)
        atexit(end);          // 只有第一个 fork 的子进程注册了 end
    if (Fork() == 0) {
        printf("0"); fflush(stdout);
    } else {
        printf("1"); fflush(stdout);
    }
    exit(0);   // exit 时才调用 atexit 注册的 end
}
```

四个进程及其输出片段：

| 进程 | 来源 | 是否注册 end | 输出片段 |
| --- | --- | --- | --- |
| P0 | 初始进程 | 否 | 打 `1` |
| C0 | P0 第二个 fork 的子 | 否（继承 P0 的空列表） | 打 `0` |
| C1 | P0 第一个 fork 的子 | 是 | 先打 `1`，exit 时 end 打 `2` → `12` |
| C2 | C1 第二个 fork 的子 | 是（fork 复制了 atexit 列表） | 先打 `0`，exit 时 end 打 `2` → `02` |

**答案：可能的是 A、C、E。**

约束：C1 的 `2` 必须在它的 `1` 之后；C2 的 `2` 必须在它的 `0` 之后。

- A. `112002`：P0→C1→C1的2→C0→C2→C2的2，合法。
- B. `211020`：开头就是 `2`，但任何 `2` 都必须等本进程的 `1`/`0` 先打出来才可能出现，不可能。
- C. `102120`：C1的1→C2的0→C2的2→P0的1→C1的2→C0的0，合法。
- D. `122001`：第二个 `2`（位置3）前面没有它对应的 `0`（`0` 在位置4），不可能。
- E. `100212`：P0的1→C0的0→C2的0→C2的2→C1的1→C1的2，合法。

## 8.19 n 次 fork 打印多少行

```c
void foo(int n) {
    int i;
    for (i = 0; i < n; i++)
        Fork();
    printf("hello\n");
    exit(0);
}
```

**答案：2ⁿ 行。**

推导：每执行一次 fork，现存进程数翻倍。n 次 fork 后进程总数是 2ⁿ，每个进程最后都执行一次 printf 然后 exit，所以打印 2ⁿ 行。

## 8.20 myls：用 execve 复刻 /bin/ls

```c
#include <stdio.h>
#include <unistd.h>
extern char **environ;   /* 由 C 运行库维护的全局环境变量表 */
int main(int argc, char *argv[]) {
    argv[0] = "ls";              /* 把 argv[0] 改成 ls，让 /bin/ls 以为自己叫 ls */
    execve("/bin/ls", argv, environ);
    // 能执行到这里一定是 execve 失败
    perror("execve fail");
    return 1;
}
```

要点：

- `execve("/bin/ls", argv, environ)` 把当前进程整体替换成 /bin/ls，**argv 原样传下去**（命令行参数不变），**environ 原样传下去**（环境变量不变），所以 COLUMNS 环境变量 ls 自己能读到。
- `argv[0] = "ls"`：ls 会根据 argv[0] 的名字决定输出格式（叫 ls 就按多列排），不改的话传进去的是 `myls`，输出行为会不一样。
- execve 成功时不返回，所以后面的 perror 只在失败时执行。

## 8.21 waitpid 决定的输出顺序

```c
int main() {
    if (fork() == 0) {
        printf("a"); fflush(stdout);
        exit(0);
    } else {
        printf("b"); fflush(stdout);
        waitpid(-1, NULL, 0);   // 父进程在这里等子进程结束
    }
    printf("c"); fflush(stdout);
    exit(0);
}
```

**答案：可能的序列是 `abc` 或 `bac`。**

- 子进程打 `a` 后 exit；
- 父进程先打 `b`，然后 waitpid 阻塞等子进程结束，醒来后才能打 `c`；
- 所以 `c` 一定在 `a` 之后（waitpid 保证子进程先结束），但 `b` 和 `a` 谁先谁后不定：父先跑就是 `bac`，子先跑就是 `abc`。`bca`、`cab`、`cba` 都不可能（c 永远在最后）。

## 8.23 信号计数为什么总是 2

子进程连发 5 个 SIGUSR2，父进程 handler 里 `counter++` 后还 `sleep(1)`，结果 counter 总是 2 而不是 5。

**原因：信号不排队。**

Linux 对同一种信号只维护一个 pending 位：handler 正在执行（sleep 这 1 秒里）时，后续到来的 SIGUSR2 不会排队累加，只是把 pending 位置 1；handler 一返回，内核只**再递送一次**这个信号（而不是"补发"这 1 秒里收到的 4 个）。所以 5 个信号实际只触发了 2 次 handler（第一次正常处理 + sleep 期间积攒的信号合并成一次）。

正确做法：handler 里不能靠"一个信号加一次"，要么循环 waitpid 收割所有已终止子进程，要么用信号队列（signalfd / sigwaitinfo）来精确计数。

## 8.25 tfgets：5 秒超时的 fgets

题目：写一个 `tfgets(buf, size, stream)`，用户 5 秒内没输入一行就返回 NULL，否则返回行指针。

```c
#include "csapp.h"
#define TIMEOUT 5
static sigjmp_buf env;   /* 保存跳转环境 */

void sigalrm_handler(int sig)
{
    siglongjmp(env, 1);   /* SIGALRM 到了：直接跳回 sigsetjmp，返回值 1 */
}

char *tfgets(char *buf, int bufsize, FILE *stream)
{
    if (sigsetjmp(env, 1) != 0)   /* 被 SIGALRM 跳回来时，这里返回非 0 */
        return NULL;              /* 超时 → 返回 NULL */
    if (signal(SIGALRM, sigalrm_handler) == SIG_ERR)
        unix_error("set alarm handler error");
    alarm(TIMEOUT);               /* 5 秒后内核给本进程发 SIGALRM */
    return fgets(buf, bufsize, stream);   /* 正常读到一行就返回 */
}
```

关键点：

- `alarm(5)` 启动 5 秒定时器；5 秒内没输入 → 内核发 SIGALRM → handler 里 `siglongjmp` 非本地跳回 `sigsetjmp`，返回值为 1 → tfgets 返回 NULL。
- 用户在 5 秒内输入了 → fgets 正常返回一行指针。此时 alarm 还在跑没关系，定时器到点时进程已经离开 tfgets，SIGALRM 会被默认动作终止进程——所以实际使用时要在外层再 `alarm(0)` 取消定时器（教材标准答案在 fgets 返回前 cancel alarm）。
- 用 `sigsetjmp/siglongjmp` 而不是 `setjmp/longjmp`：因为要正确保存/恢复信号掩码（8.5.6 的异步信号安全要求）。
