D. 参考RFC2616中的HTTP/1.1标准。确定你的浏览器的HTTP请求中每个报头的含义。你可以从www.rfc-editor.org/rfc.html获得RFC2616。



| 报头 | RFC 2616 章节 | 类别 | 含义 |
|------|--------------|------|------|
| `Host: localhost:18080` | §14.23 | 请求报头 | 告诉服务器请求的目标主机名和端口。**HTTP/1.1 强制要求**（HTTP/1.0 中可省略）。它使得同一台服务器（同一个 IP:端口）可以根据域名托管多个网站（虚拟主机）。Tiny 忽略它，真实服务器靠它选择站点 |
| `Connection: keep-alive` | §14.10 | 通用报头 | 连接管理。`keep-alive` 表示希望**持久连接**：一个 TCP 连接上连续发送多个请求/响应，避免每个请求都重新建立 TCP 连接的开销。HTTP/1.1 默认就是持久连接，此头是显式声明 |
| `User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/157.0.0.0 Safari/537.36` | §14.43 | 请求报头 | 客户端身份标识：浏览器类型及版本（Chrome 157）、渲染引擎（WebKit/Blink）、操作系统（Windows 10/11 64 位）。服务器可据此返回适配的页面内容 |
| `Accept: text/html,application/xhtml+xml,...,*/*;q=0.8` | §14.1 | 请求报头 | 浏览器能接受的**响应媒体类型（MIME 类型）清单**及偏好。`;q=` 是质量因子（0~1，默认 1），数值越小越靠后，如 `;q=0.8` 表示"能接受但优先级稍低"；`*/*` 表示兜底"任意类型都行"。服务器据此决定响应的 Content-type 或返回 406 |
| `Accept-Encoding: gzip, deflate, br, zstd` | §14.3 | 请求报头 | 浏览器支持并对响应启用的**内容压缩编码**算法（gzip、deflate、br=Brotli、zstd）。服务器可把响应体压缩后发送，客户端负责解压，节省带宽 |
| `Accept-Language: zh-CN,zh;q=0.9` | §14.4 | 请求报头 | 浏览器用户偏好的**自然语言**：首选简体中文 `zh-CN`，其次任意中文 `zh`（权重 0.9）。服务器据此选择页面语言版本，配合 q 值协商 |
| `Referer: http://localhost:18080/home.html` | §14.36 | 请求报头 | 本次请求的**来源页面** URL。只出现在第二次请求（`/godzilla.gif`、`/favicon.ico`）：浏览器渲染 `home.html` 时发现需要图片，自动补发请求并附上"我是从哪个页面发过来的"。服务器用于防盗链、统计分析。（注意：拼写 Referer 是协议历史上的著名笔误） |



### RFC 2616 之后新增的报头（Chrome 157 新增，2616 中查不到）



| 报头                                                                             | 规范来源               | 含义                                                                                     |
| ------------------------------------------------------------------------------ | ------------------ | -------------------------------------------------------------------------------------- |
| `Upgrade-Insecure-Requests: 1`                                                 | W3C（RFC 7704 相关框架） | 客户端声明"愿意升级到 HTTPS"：若站点支持安全版本，希望服务器重定向过去，属于防混合内容/降级攻击的安全机制                              |
| `sec-ch-ua: "Not-A.Brand";v="99", "Google Chrome";v="157", "Chromium";v="157"` | UA Client Hints    | 结构化版本的 User-Agent：列出浏览器品牌及版本（`Not-A.Brand` 是 Chrome 依隐私政策故意加的假品牌位）                     |
| `sec-ch-ua-mobile: ?0`                                                         | UA Client Hints    | `?0` = 非移动设备，`?1` = 移动设备                                                               |
| `sec-ch-ua-platform: "Windows"`                                                | UA Client Hints    | 操作系统平台名称                                                                               |
| `Sec-Fetch-Site: none` / `same-origin`                                         | Fetch Metadata     | 请求发起者与目标的关系：`none` = 用户在地址栏直接输入（客户端 1/2/3）；`same-origin` = 由同一站点的页面发起（图片子请求，见 Referer） |
| `Sec-Fetch-Mode: navigate` / `no-cors`                                         | Fetch Metadata     | 请求模式：`navigate` = 页面导航（地址栏访问）；`no-cors` = 普通资源加载（图片），不允许跨域读取响应                         |
| `Sec-Fetch-User: ?1`                                                           | Fetch Metadata     | `?1` = 请求由用户主动操作触发（回车/点击），区别于脚本自动发起                                                    |
| `Sec-Fetch-Dest: document` / `image`                                           | Fetch Metadata     | 请求结果的目标用途：`document` = 浏览器要渲染的文档；`image` = 图片资源。服务器可据此拒绝不匹配的请求                         |
