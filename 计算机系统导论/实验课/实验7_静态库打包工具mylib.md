## 1. 实验要求拆解

| 要求 | 对应能力 |
| --- | --- |
| 把多个 `.o` 打包成一个 `.a` | 理解 ar 归档格式（魔数 + 成员头 + 数据） |
| 让链接器能"按符号找成员" | 手写 ar 的 `/` 索引成员（符号表 → 成员号） |
| 支持 `-t`（列成员）、`-x`（解包） | 解析归档：两遍扫描 + 长名表还原 |
| 名字超过 15 字节的处理 | 理解 ar 的 `//` 长名表机制 |

## 2. 核心原理：文件里到底有哪些字节

**ar 格式**自底向上只有三样东西：

```
!<arch>\n            ← 8 字节魔数（注意 \n 是真实字节 0x0A，共 8 字节不是 7）
"/" 索引成员头        ← 符号名 → 成员号 的映射，给链接器快速查表用
"//" 长名表成员头     ← 名字 > 15 字节的成员名集中存放
成员头(60B)+数据 ...  ← 每个 .o 依次排开；成员大小为奇数时补一个 \n 对齐
```

**ELF 侧只用到三样**：ELF 头拿 `e_shoff/e_shnum` 定位节头表 → 找 `SHT_SYMTAB` 节 → 用它的 `sh_link` 找配套字符串表，`strtab + st_name` 即符号名。`st_info` 拆成 bind（LOCAL/GLOBAL/WEAK）和 type（FUNC/OBJECT），只收录全局符号。

**魔数的三重作用**：写入时打头（`fwrite(AR_MAGIC, ...)`）、读取时验明正身（`memcmp` 不对立即返回 -1）、充当所有偏移计算的基准（成员绝对偏移全部从 8 开始算）。

## 3. 实现要点

```
创建（create_archive）
 ├─ ① 收集成员：load_object → elf_scan_syms → 只收全局符号
 ├─ ② 名字 > 15 字节的进 "//" 长名表
 ├─ ③ 建索引：IdxSym{符号名, 成员号} → 按名字排序 → 写进 "/" 成员
 ├─ ④ 预计算每个成员头的绝对偏移 moff[i]
 └─ ⑤ 落盘：魔数 → "/" → "//" → 各 .o

读取（-t / -x）
 └─ ar_parse：两遍扫描——先找 "//" 长名表，再收集普通成员
    └─ ar_member_name：数字名字（如 "/17"）→ 去长名表偏移 17 处还原真名
```

## 4. 验证方法

```bash
make && make test          # tests/run.sh 全套自测
xxd -l 8 -g 1 libmylib.a   # 验证魔数：21 3c 61 72 63 68 3e 0a
file libmylib.a add.o      # "current ar archive" / "ELF 64-bit ... relocatable"
gcc main.c libmylib.a -o app   # 用生成的库真实链接，能跑通才算合格
```

关键判据：`gcc` 用我打包的 `.a` 能链接成功、`nm libmylib.a` 能看到索引成员 `/`，且与 `ar rcs` 产出的库行为等价。

## 5. 踩过的坑

- **`AR_MAGIC` 是 8 字节不是 7**：C 字符串里的 `"\n"` 是真实的 0x0A 字节，长度算错则所有偏移全错；
- **长名表还原**：成员头里 name 字段是 `/17` 这种"长名表内偏移"，要跳到 `//` 数据区从偏移 17 读到 `\n` 才是名字；
- **奇数成员补 `\n`**：少补一个字节，后面所有成员头全部读歪——这类"格式错位"错误表现为越读越乱，定位靠 `xxd` 对拍真实 `ar` 产物。

## 6. 收获

这个实验最大的价值是把"静态库"从一条命令变成了**看得见的字节布局**：链接器 `gcc main.c libmylib.a` 背后做的事（读索引 → 按符号找成员 → 抽出对应 `.o` 参与符号解析），全都对应到我手写的某段代码上。
