## 1. 先把三个前提钉住

### 1.1 fd 是描述符表的下标

`int fd` 里的 `fd` 不是什么句柄对象，就是**进程描述符表的下标**。下标指向的那一格，才存着通往内核打开文件表项的指针。

进程一出生就占着 0、1、2 三格（标准输入、标准输出、标准错误），所以自己第一个 `open` 拿到的必然是 3。课堂上老师反复念这一点，不是为了背常识——它是一切推演的起点：**给你一段代码，先数它开了几个文件、fd 从几开始，再画表。**

顺着这个前提，老师还点了一个自己演示时偷懒的地方：程序直接用了 `argv[1]`，没有检查 `argc`。

```c
int main(int argc, char *argv[])
{
    char *fname = argv[1];   /* argc < 2 时这里就已经越界了 */
```

`argv[1]` 是"第二个元素"，所以 `argc` 至少要等于 2，否则 `argv[1]` 是 NULL，`open` 拿到空指针直接崩。演示程序可以不写，写作业必须写。

### 1.2 位置存在内核，不在你的变量里

**读和写共用同一个 current file position**，不是一个读指针加一个写指针。课堂上口语里"读指针""写指针"混着说，容易听成两回事，实际上只有一份：

- 打开时置 0（`O_APPEND` 是特例，见 [[#4. 例三：创建、截断、追加与覆盖写]]）；
- 每次 `read`/`write` 按实际传输的字节数推进它；
- 它住在**打开文件表项**里，所以"共不共享表项"和"共不共享位置"是同一句话。

正因为位置在内核，你 `fork` 出来的子进程即使拿到了完全一样的 `fd` 数值，也不代表它有一份独立的位置——**数值相同只是下标相同，下标指向哪一格才是关键**。

### 1.3 flags 是位掩码

`open` 的第二个参数不是枚举，是一组**互不重叠的位**，所以能用 `|` 拼。Linux 上的实际取值：

| 宏 | 八进制 | 十进制 | 含义 |
| --- | --- | --- | --- |
| `O_RDONLY` | `0` | 0 | 只读 |
| `O_WRONLY` | `01` | 1 | 只写 |
| `O_RDWR` | `02` | 2 | 可读可写 |
| `O_CREAT` | `0100` | 64 | 不存在则创建 |
| `O_EXCL` | `0200` | 128 | 与 `O_CREAT` 合用，已存在则报错 |
| `O_TRUNC` | `01000` | 512 | 已存在则截断为长度 0 |
| `O_APPEND` | `02000` | 1024 | 每次写之前定位到文件末尾 |

读法有两组。低两位（`O_ACCMODE = 3`）是**三选一**的访问模式：`flags & 3` 得 0/1/2 分别对应只读、只写、读写。从 `O_CREAT` 起，每个宏各自占一个独立的位，所以 `|` 不会有进位冲突，内核用 `flags & O_CREAT` 这样逐位测试就能知道你要什么。

课堂上举的例子 `O_WRONLY|O_CREAT|O_TRUNC`：把 `01`、`0100`、`01000` 三个八进制数按位或起来，得到 `01101`。数值本身不必背，但要记住**为什么能拼**——它们本来就是按位设计的。

顺带一个反直觉点：`O_RDONLY` 的值是 0，一个位都不占。所以它跟谁或都等于对方：`O_RDONLY|O_WRONLY` 算出来就是 1，跟只写完全一样。访问模式这一组是**互斥取一**，靠低两位的取值区分，不能靠按位或叠加；能叠的只有 `O_CREAT`、`O_TRUNC`、`O_APPEND` 这些附加位。

## 2. 例一：三次 open 再加一个 dup2

```c
#include "csapp.h"

int main(int argc, char *argv[])
{
    int fd1, fd2, fd3;
    char c1, c2, c3;
    char *fname = argv[1];

    fd1 = Open(fname, O_RDONLY, 0);
    fd2 = Open(fname, O_RDONLY, 0);
    fd3 = Open(fname, O_RDONLY, 0);
    Dup2(fd2, fd3);
    Read(fd1, &c1, 1);
    Read(fd2, &c2, 1);
    Read(fd3, &c3, 1);
    printf("c1 = %c, c2 = %c, c3 = %c\n", c1, c2, c3);
    return 0;
}
```

文件内容是 `abcde`。逐行推：

| 时刻 | 描述符表（3 号格起） | 各表项位置 | 本次读出 |
| --- | --- | --- | --- |
| 三次 `Open` 之后 | fd1→表项 A，fd2→表项 B，fd3→表项 C | 0 / 0 / 0 | — |
| `Dup2(fd2, fd3)` | fd1→A，fd2→B，fd3→**B**（C 被关掉） | 0 / 0 | — |
| `Read(fd1, &c1, 1)` | 不变 | A：0→1 | `c1 = a` |
| `Read(fd2, &c2, 1)` | 不变 | B：0→1 | `c2 = a` |
| `Read(fd3, &c3, 1)` | 不变 | B：1→2 | `c3 = b` |

**答案：`c1 = a, c2 = a, c3 = b`。**

最容易错的地方在于把"指向同一个文件"读成"指向同一个表项"。三次 `Open` 是**三个独立的表项**，它们只在最底下那个 **v-node**（磁盘上的文件）处汇合：

![课件 p29：两个描述符通过两个打开文件表表项共享同一个磁盘文件](../图片/IO_08_两次open共享文件.png)

所以前两次读各自从 0 开始，都拿到 `'a'`。

`Dup2(fd2, fd3)` 干的事只有两步：先关掉 `fd3` 原来指向的表项 C（引用计数减到 0，内核把它删掉），再把描述符表第 3 格改成指向 B，B 的引用计数加 1。**它复制的是下标里的那个指针，不是文件，也不是位置。** 此后 fd2 和 fd3 是同一份位置的两种叫法。

![课件 p32：`dup2(4,1)` 前后——把描述符表第 1 格改成指向第 4 格原来那个表项](../图片/IO_11_dup2重定向描述符表.png)

## 3. 例二：fork 之后谁读第二个字节

```c
#include "csapp.h"

int main(int argc, char *argv[])
{
    int fd1;
    int s = getpid() & 0x1;
    char c1, c2;
    char *fname = argv[1];

    fd1 = Open(fname, O_RDONLY, 0);
    Read(fd1, &c1, 1);
    if (fork()) {              /* 父进程 */
        sleep(s);
        Read(fd1, &c2, 1);
        printf("Parent: c1 = %c, c2 = %c\n", c1, c2);
    } else {                   /* 子进程 */
        sleep(1 - s);
        Read(fd1, &c2, 1);
        printf("Child: c1 = %c, c2 = %c\n", c1, c2);
    }
    return 0;
}
```

文件还是 `abcde`。

### `s = getpid() & 0x1` 在干什么

取进程号的最低位，也就是**奇偶**。父进程睡 `s` 秒，子进程睡 `1-s` 秒，两者必定一个睡 0 秒、一个睡 1 秒——**先后顺序就被钉死了，而且每跑一次翻一次面**。

为什么不用 `rand()`：不需要引入随机数发生器，进程号在奇偶上本来就是均匀的；更重要的是"父子互补"这一点是确定的，`rand()` 得手动保证两个值不同。老师说的原话大意是：不这么写，父子谁先跑就完全交给调度器，同一份程序跑两次答案不同，没法当例子讲。

### c1 为什么两边都是 a

`Read(fd1, &c1, 1)` 发生在 `fork()` **之前**。`c1` 是普通的局部变量，fork 时被复制一份给子进程（写时复制，父子各一份、值相同），所以两边打印出来都是 `'a'`。

### c2 为什么是 b 和 c 各一个

`fd1` 这个数值在 fork 后被复制了两份，但**两份表项都指向同一个打开文件表项**：

![课件 p31：fork 之后子进程的描述符表是父进程的副本，每个引用计数加 1](../图片/IO_10_fork后共享refcnt.png)

位置只有一份，停在 1。谁先醒谁读走 `'b'` 并把位置推到 2，后醒的只能读 `'c'`。

| 若 `s = 0`（父 PID 为偶） | 若 `s = 1`（父 PID 为奇） |
| --- | --- |
| `Parent: c1 = a, c2 = b` | `Parent: c1 = a, c2 = c` |
| `Child: c1 = a, c2 = c` | `Child: c1 = a, c2 = b` |

这一题本质就是教材练习 10.3，只是那里用 `Wait(NULL)` 强制"子先读、父后读"，答案固定成 `c = o`；这里换成 sleep 让顺序随 PID 翻转，考的是同一个机制。

**一句话区分**：`c1` 走的是"变量复制"（两份），位置走的是"表项共享"（一份）。同一段代码里两种语义并存，这就是这道题的杀伤力所在。

## 4. 例三：创建、截断、追加与覆盖写

```c
#include "csapp.h"

int main(int argc, char *argv[])
{
    int fd1, fd2, fd3;
    char *fname = argv[1];

    fd1 = Open(fname, O_RDWR | O_CREAT | O_TRUNC, S_IRUSR | S_IWUSR);
    Write(fd1, "PQRS", 4);
    fd3 = Open(fname, O_WRONLY | O_APPEND, 0);
    Write(fd3, "JKLMN", 5);
    Dup2(fd1, fd2);
    Write(fd2, "WXYZ", 4);
    Write(fd3, "EF", 2);
    return 0;
}
```

| 步骤 | 文件内容 | fd1 位置 | fd3 位置 | 说明 |
| --- | --- | --- | --- | --- |
| `Open(O_CREAT\|O_TRUNC)` | （空，原内容已被清掉） | 0 | — | 不存在就建，存在就清零 |
| `Write(fd1,"PQRS")` | `PQRS` | 4 | — | 写到哪位置就推到哪 |
| `Open(O_APPEND)` → fd3 | `PQRS` | 4 | 0 | 新表项，位置从 0 起 |
| `Write(fd3,"JKLMN")` | `PQRSJKLMN` | 4 | 9 | append 先跳到末尾再写 |
| `Dup2(fd1, fd2)` | 同上 | 4 | 9 | fd2 与 fd1 共用位置 4 |
| `Write(fd2,"WXYZ")` | `PQRSWXYZN` | 8 | 9 | 从 4 开始**覆盖**了 JKLM |
| `Write(fd3,"EF")` | `PQRSWXYZNEF` | 8 | 11 | 又跳到末尾追加 |

**结果：`PQRSWXYZNEF`。**

三个标志各管一段，别混：

- **`O_CREAT`**：文件不存在时创建它。它只在"新建"时生效，已有文件时不起作用（要配合 `O_EXCL` 才能在已存在时报错）。
- **`O_TRUNC`**：文件存在就把长度截成 0。**这是立刻生效的**——`open` 返回时文件已经空了，不需要等到第一次写。想清空一个日志文件，`open(path, O_WRONLY|O_TRUNC)` 再 `close` 就够。
- **`O_APPEND`**：这不是"打开时把位置移到末尾"，而是**每次 `write` 之前**把位置挪到末尾。注意 fd3 打开时位置还是 0，是第一次写的时候跳到 9 的。Linux 上这个"定位 + 写"是原子的，所以多个进程各自 `open` 同一文件做追加也不会互相覆盖——日志就是这么写的。

还有一个只在创建时才有意义的参数：`S_IRUSR|S_IWUSR`（第三个参数）。文件已存在时它被忽略；新建时还要再被 `umask` 削一刀（见 [[01_系统级IO_UnixIO#4.2 mode 与 umask：新文件的权限位|01 的 §4.2]]），最终权限是 `mode & ~umask`。

最后那两行是本例的重点：`Dup2(fd1, fd2)` 时 `fd2` 还空着，所以不需要关任何东西，直接把描述符表那一格指向 `fd1` 的表项。于是 `fd2` 从**位置 4** 开始写，把 `JKLM` 覆盖成了 `WXYZ`——文件长度没变，内容被改了。**同一份位置，谁写谁推，另一个人接着往下走。**

## 5. 归纳：四种情况一张表

| 场景 | 描述符表 | 打开文件表项 | 文件位置 |
| --- | --- | --- | --- |
| 同一文件 `open` 两次 | 两个独立格 | **两个** | 各自独立 |
| `dup` / `dup2` | 两个格 | **同一个**（引用计数 +1） | **共享** |
| `fork` | 子进程复制整张表 | 指向同样的表项（计数 +1） | **共享** |
| `execve` | 表被保留 | 不变 | **共享**（除非该 fd 设了 `FD_CLOEXEC`） |

一句话：**位置跟着表项走，表项跟着"谁 open 的"走；`fd` 的数值相同不代表位置相同，只有落到同一个表项上才共享。**

也可以反过来记：这几个操作里只有 `open` 会造出新表项，`dup`、`fork`、`execve` 都只是让更多格子指向已有的表项。

## 6. 多进程写同一个文件

课堂上这个问题是从例三的覆盖写引出来的：如果两个人同时往一个文件里写，会怎样？

- **各自 `open`**：两个表项、两个位置，都从 0 开始，谁后写谁覆盖前面的。这就是"内容莫名其妙少了"的来源。
- **`fork` 出来的父子、或者 `dup` 出来的两个描述符**：共享一份位置，写是接续的，不会互相覆盖，但顺序取决于调度，交错位置不可控。
- **`O_APPEND`**：即使各自打开，每次写前都原子地定位到末尾，于是变成"各自接在尾巴上写"，不会覆盖。
- **要真正的互斥**：得用文件锁（`fcntl` 的记录锁、`flock`），这是 `O_APPEND` 给不了的——`O_APPEND` 只保证单次 `write` 的"定位 + 写"不被打断，不保证你连着两次 `write` 之间没人插进来。所以它能保证"不覆盖"，保证不了"内容成块"。

老师课堂上的说法很朴素：多人协作，要么共享同一份东西（顺序接续），要么各拿一份副本（会覆盖），要么加锁。三种方案对应三种场景，没有优劣之分。

## 7. 两个可以借用的类比

**指针变量复制**。`int *p = q;` 复制的是地址这个值，两个指针指向同一块内存。`fork` 复制描述符表就是这个结构——表里每一格都是指针，复制之后两个格子指向同一个表项。而普通的 `int c1` 复制一份就是两份独立的值，谁也影响不到谁。三个例子里 `c1` 和"文件位置"的分野，本质就是这两种复制的分野。

**描述符表是一个数组**。`fd` 是下标，元素是指针。`dup2(a, b)` 就是 `tbl[b] = tbl[a]`（外加把 `b` 原来指向的东西关掉）。`fork` 就是把整个数组 `memcpy` 一份——**数组复制了，但数组里的指针指向的还是原来那些对象**。

两个类比合起来，就够推所有这类题了：先画数组，再画指针指向的几个框，最后看哪几格落在同一个框上。

## 小结

三个例子其实是同一句话的三个侧面：

1. **你手里只有下标**（`fd` 是个整数），文件和位置都在内核；
2. **共享与否不看文件名**，看两个下标是不是落在同一个打开文件表项上；
3. **位置只有一份时，谁写谁推**，读和写也因此互相影响。

推题的标准动作只有三步：数 `open` 次数定表项个数 → 画表看 `dup`/`fork` 之后谁指向谁 → 按顺序推进位置。
