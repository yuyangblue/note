## 1. 互斥之外还要调度

信号量有两件不同的事可做：

- **互斥**：保护临界区，保证同一时刻只有一个线程访问共享资源（上一篇）；
- **调度**：一个线程用信号量操作通知另一个线程「状态中的某个条件已经为真了」。缓冲区满时生产者要等，缓冲区空时消费者要等——光有互斥做不到这种等待，必须靠调度。

## 2. 生产者—消费者问题

生产者线程不断生成**项目（item）**插入有限缓冲区，消费者线程不断从缓冲区取出项目消费。生产者和消费者可以各有多个。

只保证互斥不够：缓冲区满（没有空槽位）时生产者必须等待到有槽位可用；缓冲区空（没有项目）时消费者必须等待到有项目可用。这两个等待条件正好由两个计数信号量承担。

现实系统中很常见，教材举的两个例子：

- **多媒体系统**：生产者编码视频帧，消费者解码并显示；缓冲区减少因各帧编码／解码耗时不同而造成的抖动；
- **图形用户界面**：生产者检测鼠标和键盘事件并插入缓冲区，消费者按某种优先级取出事件显示——点击后机器很卡、过一会儿才有响应，就是事件已经入队但处理不过来。

课堂举的同类例子还有大数据处理中各路数据汇入队列、视频切成多个 slot 交给不同 worker 渲染最后合并。核心思路只有一个：**用缓冲区匹配双方速率，把大块资源切成小块以缩小加锁范围**。

## 3. sbuf：教材的有限缓冲区包

项目存放在动态分配的 `n` 项整数数组里，`front` / `rear` 是环形缓冲的头尾下标，三个信号量同步访问：

```c
typedef struct {
    int  *buf;       /* 缓冲区数组 */
    int   n;         /* 最多多少个槽位 */
    int   front;     /* 第一项在 buf[(front+1) % n] */
    int   rear;      /* 最后一项在 buf[rear % n] */
    sem_t mutex;     /* 保护对 buf 的访问 */
    sem_t slots;     /* 空槽位数 */
    sem_t items;     /* 可用项目数 */
} sbuf_t;
```

```c
void sbuf_init(sbuf_t *sp, int n) {
    sp->buf = Calloc(n, sizeof(int));      /* 申请 n 项空间并清零 */
    sp->n = n;                             /* 缓冲区最多存 n 项 */
    sp->front = sp->rear = 0;              /* front == rear 表示空 */
    Sem_init(&sp->mutex, 0, 1);            /* 二元信号量，用于加锁 */
    Sem_init(&sp->slots, 0, n);            /* 初始有 n 个空槽位 */
    Sem_init(&sp->items, 0, 0);            /* 初始有 0 个项目 */
}

void sbuf_deinit(sbuf_t *sp) {
    Free(sp->buf);                         /* 释放缓冲区，避免泄漏 */
}

void sbuf_insert(sbuf_t *sp, int item) {
    P(&sp->slots);                         /* 等一个空槽位 */
    P(&sp->mutex);                         /* 锁住缓冲区 */
    sp->buf[(++sp->rear) % (sp->n)] = item;/* 在尾部插入 */
    V(&sp->mutex);                         /* 解锁 */
    V(&sp->items);                         /* 宣布有一个新项目 */
}

int sbuf_remove(sbuf_t *sp) {
    int item;
    P(&sp->items);                         /* 等一个可用项目 */
    P(&sp->mutex);                         /* 锁住缓冲区 */
    item = sp->buf[(++sp->front) % (sp->n)];/* 从头部取出 */
    V(&sp->mutex);                         /* 解锁 */
    V(&sp->slots);                         /* 宣布多出一个空槽位 */
    return item;
}
```

取出项目后**不必把旧槽位清零**——下次写入会覆盖它，省掉一次写内存的开销。

## 4. 三个信号量的不变式与加锁顺序

**不变式**：`slots + items == n`。生产者消耗一个 slots、生产一个 items；消费者消耗一个 items、归还一个 slots。缓冲区满时 `slots == 0`，生产者自动阻塞在 `P(slots)`；缓冲区空时 `items == 0`，消费者自动阻塞在 `P(items)`——不需要写任何 `if` 判断。

**规则：先等资源，再加锁**。在 `sbuf_insert` 里是先 `P(slots)` 再 `P(mutex)`，不能反过来。如果先拿到 mutex 再阻塞在 slots 上，这个线程就**占着锁睡觉**，消费者同样拿不到锁，谁也推进不了。

`mutex` 保护的是 `front` / `rear` 和数组元素的读写；`slots` / `items` 只负责计数与等待。三类信号量的职责要分开看。

## 5. 读者—写者问题

一组线程访问同一个共享对象（主存数据结构或磁盘数据库）：**读者**只读，**写者**修改。写者必须独占访问，读者可以和任意多个其他读者共享。

现实例子：航空订座系统允许很多客户同时查看座位分配，但真正订座的客户必须独占数据库；多线程缓存 Web 代理允许很多线程读缓存中的页面，但写入新页面必须独占。

两个变种：

- **第一类（读者优先）**：不要让读者等待，除非已经有写者拿到了对象的使用权；读者不会因为「有写者在等」而等待。
- **第二类（写者优先）**：写者一旦准备好就尽快完成；后到达的读者必须等，即使那个写者还在等待。

教材给的第一类解法：

```c
int readcnt;                 /* 当前在临界区中的读者数，初始为 0 */
sem_t mutex, w;              /* 两者初始都为 1 */

void reader(void) {
    while (1) {
        P(&mutex);
        readcnt++;
        if (readcnt == 1)    /* 第一个进来的读者 */
            P(&w);           /* 锁住写者用的那把锁 */
        V(&mutex);

        /* 临界区：读操作在这里 */

        P(&mutex);
        readcnt--;
        if (readcnt == 0)    /* 最后一个离开的读者 */
            V(&w);           /* 把锁还给写者 */
        V(&mutex);
    }
}

void writer(void) {
    while (1) {
        P(&w);
        /* 临界区：写操作在这里 */
        V(&w);
    }
}
```

`w` 控制对共享对象的访问，`mutex` 保护计数器 `readcnt`。只有第一个读者对 `w` 加锁、最后一个读者对 `w` 解锁，中间进来的读者直接忽略 `w`，于是多个读者可以并行。

**注意**：上述解法存在**饥饿（starvation）**——读者源源不断地到达时，写者可能无限期等待。两类读者—写者问题的正确解法都可能产生饥饿。

课堂还提到 DMA（外部设备直接访问内存）会让缓存与内存中的数据不一致，这是操作系统设计中的另一类难题；教材第 12 章没有展开。

## 6. 预线程化并发服务器

每来一个客户端就创建一个线程，代价不小。**预线程化（prethreading）**改用生产者—消费者模型：服务器由**一个主线程 + 一组工作者线程**构成。

- 主线程不断 `accept`，把得到的已连接描述符放进 `sbuf`（生产者）；
- 每个工作者线程反复从 `sbuf` 取出 connfd，为客户端服务，再等下一个（消费者）；
- 工作者线程数在启动时就固定（教材示例 `NTHREADS 4`），不随连接数变化；
- 工作者线程要先 `pthread_detach` 分离自己，结束后由系统回收，省掉 `join`。

这个模型的两个好处：避免为每个连接创建线程；把「接纳连接」和「处理请求」解耦，前者不会被后者阻塞。多媒体渲染中按 slot 分配 worker 是同一思路。

## 7. echo_cnt 与 pthread_once

预线程化服务器的 `echo_cnt` 在普通 `echo` 之上多记一个全局字节计数 `byte_cnt`。这里第一次出现**从线程例程内部初始化程序包**的写法：

```c
static pthread_once_t once = PTHREAD_ONCE_INIT;
static sem_t mutex;              /* 保护 byte_cnt */

static void init_echo_cnt(void) {
    Sem_init(&mutex, 0, 1);
    byte_cnt = 0;
}

void echo_cnt(int connfd) {
    char buf[MAXLINE];
    rio_t rio;
    size_t n;

    Pthread_once(&once, init_echo_cnt);   /* 第一次调用时初始化 */
    Rio_readinitb(&rio, connfd);
    while ((n = Rio_readlineb(&rio, buf, MAXLINE)) != 0) {
        P(&mutex);
        byte_cnt += n;                    /* 受保护的共享计数 */
        printf("thread %lu received %lu bytes (total %lu)\n",
               (unsigned long)pthread_self(),
               (unsigned long)n, (unsigned long)byte_cnt);
        V(&mutex);
        Rio_writen(connfd, buf, n);
    }
}
```

`pthread_once` 保证 `init_echo_cnt` 在整个进程里**只被执行一次**，且第一个到达的线程执行它，其余线程等它做完再继续。两个要点：

- 好处是**包的使用者不必记得先初始化**——这对库函数尤其重要；
- 代价是每次调用 `echo_cnt` 都要走一遍 `pthread_once`，多数时候它什么也不做。

回调函数的签名固定为 `void (*)(void)`，所以它要初始化的东西必须是文件作用域的 `static` 变量，让回调能直接访问。

## 8. 小结

- 信号量除了互斥，还能调度共享资源：用计数值表达「有空位」／「有项目」；
- sbuf 用 mutex + slots + items 三个信号量实现有限缓冲区；`slots + items == n` 是不变式；
- 规则是先等资源再加锁，否则会占着锁阻塞；
- 读者—写者允许多个读者并行，写者独占；第一类读者优先，但可能造成写者饥饿；
- 预线程化服务器用主线程生产 connfd、工作者线程消费，避免按连接创建线程；
- `pthread_once` 让程序包在第一次被调用时自行初始化。

> **本节重点**：能画出 `sbuf_insert` / `sbuf_remove` 里四个 P/V 的配对关系，并解释为什么 `P(slots)` 必须在 `P(mutex)` 之前。
