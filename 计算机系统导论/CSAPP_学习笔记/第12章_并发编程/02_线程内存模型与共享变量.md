## 1. 共享的判据

课堂一开始提醒：**「全局变量共享、栈变量私有」这个口诀不够用**。反例很容易造：主线程栈上的数组可以通过一个全局指针被对等线程间接引用；写在线程函数里的 `static` 变量也不是私有的。

教材给出的判据只有一句：

> 变量 `x` 是共享的，当且仅当多条线程都引用了 `x` 的**某个实例**。

注意这里的主语是**实例**而不是变量名。同一个名字可能在不同线程的栈里有不同实例，也可能整个进程只有一个实例；判定前得先确定「指的是哪一份」。

## 2. 线程内存模型

概念上，多条线程运行在**单个进程的上下文**里：

**每个线程私有的**：

- 线程 ID（TID）；
- 栈、栈指针（SP）；
- 程序计数器（PC）——线程并行执行，各自指向不同的语句；
- 条件码和通用寄存器；
- 在函数内部声明、未加 `static` 的局部变量（每线程栈里一份）。

**所有线程共享的**：

- 进程的虚拟地址空间：代码段、可读可写数据段、堆、共享库映射区；
- 内核上下文：打开的文件描述符表、信号处理方式、当前工作目录等；
- 全局变量和 `static` 变量（无论在哪里声明，都放在数据段）。

这解释了两件事：第一，线程之间通信不必走 IPC，直接读写共享变量即可；第二，也正因为如此，**非预期的共享**会引入极难复现的错误——这是线程最大的优点，也是最大的缺点。

## 3. 变量实例到内存的映射

把 C 的声明规则放到虚拟地址空间里看，就得到映射规则：

| 声明形式 | 实例数 | 放在哪 |
| --- | --- | --- |
| 全局变量（函数外声明） | 每个变量恰好 1 个 | 数据段／BSS |
| `static` 局部变量（函数内声明） | 每个变量恰好 1 个 | 数据段／BSS |
| 普通局部变量（函数内声明，无 `static`） | **每个线程 1 个** | 各线程的栈 |

特别注意第二行：`static` 写在线程函数里面，只是**作用域**被限制在那个函数，存储期仍然是整个进程。谁先执行到那条声明谁把它初始化为 0，后来者直接复用同一份。

## 4. 例：sharing.c 逐变量判定

```c
char **ptr;                 /* 全局变量：1 个实例，数据段 */

int main() {
    long i;                 /* 主线程局部变量：1 个实例 */
    pthread_t tid;
    char *msgs[2] = {       /* 主线程局部变量：1 个实例 */
        "Hello from foo",
        "Hello from bar"
    };

    ptr = msgs;             /* 全局指针指向主线程栈上的数组 */
    for (i = 0; i < 2; i++)
        Pthread_create(&tid, NULL, thread, (void *)i);
    Pthread_exit(NULL);
}

void *thread(void *vargp) {
    long myid = (long)vargp;        /* 局部变量：每线程各 1 个实例 */
    static int cnt = 0;             /* 局部静态：全进程只有 1 个 */

    printf("[%ld]: %s (cnt=%d)\n",
           myid, ptr[myid], ++cnt);
    return NULL;
}
```

逐个判定：

| 变量 | 实例数 | 是否共享 | 理由 |
| --- | --- | --- | --- |
| `ptr` | 1 | 是 | 全局变量，两条线程都引用它 |
| `msgs` | 1 | 是 | 虽在主线程栈上，但经 `ptr` 被对等线程间接引用 |
| `cnt` | 1 | 是 | `static`，写在线程函数里也只分配一次 |
| `i`（主线程） | 1 | 否 | 只有主线程引用，传给线程的是它的**值** |
| `myid` | 2 | 否 | 两个线程各有自己的栈实例 |

**最容易看错的两处**：

- `cnt`：位置在函数内部，容易误判为私有；实际上 `static` 决定了它只有一份。
- `msgs`：位置在主线程的栈上，容易误判为私有；但 `ptr = msgs` 让对等线程能通过全局指针摸到它。这就是课件 p4 那句「对等线程引用主线程的栈，通过全局变量间接发生」。

课堂还提醒了一个 C 细节：`cnt++` 先返回旧值再加一，`++cnt` 先加一再返回新值；课件示例用的是 `++cnt`，所以打印从 1 开始。录音里口头说成 `cnt++`，只是起始打印值不同，不影响共享判定。

## 5. 从共享到竞态

一旦确认 `cnt` 被多条线程引用，下一步就是问：两条线程同时做 `cnt++`，结果还是可预测的吗？答案必然是否——`cnt++` 在机器级是读、加、写三步，交错顺序由操作系统调度决定。这就是下一篇要处理的**竞态**问题（见 [[03_竞态与信号量]]）。

判定的实际意义正在这里：**先找出共享变量，再决定哪些需要加锁保护**。跳过这一步，要么锁了不该锁的局部变量白白损失性能，要么漏掉像 `msgs` 这样「经全局指针间接共享」的变量。

## 6. 小结

- 共享的判据是「多条线程引用同一变量的某个实例」，不是看声明位置；
- 每个线程私有：TID、栈、SP、PC、条件码、寄存器；
- 所有线程共享：代码、数据、堆、共享库、描述符表等内核上下文；
- 全局变量与 `static` 局部变量各只有一份实例；普通局部变量每线程一份；
- 主线程栈上的数据也能通过对等线程间接共享——`sharing.c` 里的 `msgs` 就是例子。

> **本节重点**：先看实例、再看引用者，最后才谈要不要同步。`static` 不等于私有，栈上不等于不共享。
