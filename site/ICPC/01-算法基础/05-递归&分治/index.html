    1. 大白话引入¶

    递归和分治是算法竞赛里最基础也最容易被绕晕的思想。我们用一个日常场景来理解：

    假设你要知道你们班第一排第一个同学有几支笔，但你懒得一个一个数。你可以让他报数——但每个同学都说"我只知道我自己的，你问我后面的人吧"。于是问题被一层层往后传，直到最后一个同学说"我有 2 支"，然后这个答案一层层往回传，每个人加上自己的，最终传到你这。

    在这个场景里： - 递归："问自己 → 问后一个人" 这种自己调用自己的方式 - 分治：把"统计全班笔数"这个大问题，拆成"统计每个人"的小问题

    算法里这俩经常一起出现——分治是思想（大问题拆小问题），递归是实现手段（函数自己调自己）。

    2. 思维启发 & 思考流程¶

    拿到一道题，怎么想到用递归/分治？

    标志 1：问题可以"变小"¶

    如果一个问题能通过某种操作变成一个更小的同类型问题，那递归就可能是解法。

    举个例子：求 n!。 - 5! = 5 × 4 × 3 × 2 × 1 - 发现 5! = 5 × 4!，而 4! 是同样的问题只是规模更小 - 4! = 4 × 3!……直到 1! = 1

    这就是递归的直觉——"我依赖于一个更小的我"。

    标志 2：问题可以"对半拆"¶

    如果一个大问题可以无重叠地拆成若干个独立的小问题，各自解决后再合并，那就是分治。

    比如排序一个数组： - 把数组从中间切成两半 - 左半边排序、右半边排序 - 合并两个有序数组

    左右排序各自又是同样的"排序问题"，所以递归实现非常自然。

    思考框架¶

    1
2
3
4
    看到大问题 → 问自己三个问题：
① 能不能拆成更小的同类问题？  → 可以 → 递归
② 拆开后的小问题有没有重叠？  → 没有重叠 → 分治
③ 拆到多小可以直接出答案？    → 这就是递归边界（base case）

    新手最容易踩的坑：试图在脑子里把递归的每一层展开去模拟。不要这样做！你只需要相信"函数能正确地解决更小的问题"，然后站在当前层思考就够了。

    3. 核心讲解¶

    3.1 递归三要素¶

    任何一个递归函数，必须包含以下三样东西：

    要素 1：递归边界（Base Case）¶

    问题小到可以直接给出答案，不需要再递归了。

    1
2
    // 阶乘的边界：0! = 1
if (n == 0) return 1;

    没有边界 = 无限递归 = 栈溢出崩溃。

    怎么找边界？想想"问题小到什么程度就不用拆了"——通常是 n = 0、n = 1、数组长度为 1、树为空 这类情况。

    要素 2：递归关系（递推公式）¶

    当前问题和更小问题之间的关系。

    1
2
    // n! = n × (n-1)!
return n * factorial(n - 1);

    这个关系必须让问题规模严格减小，否则永远到不了边界。

    要素 3：返回值与状态的衔接¶

    每一层递归的返回值要能被上一层正确使用。这要求你清楚"函数返回什么"以及"上一层拿这个返回值干什么"。

    关键原则：写递归时，假设子问题已经被正确解决了，你只需要在当前层把子问题的结果组合成当前问题的答案。

    1
2
3
4
5
6
7
    factorial(5)
  → 5 × factorial(4)      // 相信 factorial(4) 会正确返回 24
    → 4 × factorial(3)    // 相信 factorial(3) 会正确返回 6
      → 3 × factorial(2)
        → 2 × factorial(1)
          → 1 × factorial(0)
            → 1           // 边界

    3.2 分治三步骤¶

    分治是递归的一种应用模式，三步走：

    1. 分解（Divide）：把原问题拆成若干个规模更小的独立子问题
    2. 解决（Conquer）：递归地解决每个子问题（到了足够小的规模就直接求解）
    3. 合并（Combine）：把子问题的解组合成原问题的解

    分治和普通递归的区别： - 普通递归通常一次只调用自己一次（单路递归），如阶乘 - 分治通常一次调用自己多次（多路递归），如归并排序一次拆两半、快速幂按奇偶分

    分治的两个前提： - 子问题之间相互独立（没有重叠子问题——有重叠的话应该用 DP） - 子问题的解可以高效合并

    #include <bits/stdc++.h>
using namespace std;

// Fibonacci 数列：f(1)=1, f(2)=1, f(n)=f(n-1)+f(n-2)
// 这是递归的入门例题，但注意：这个写法效率极低（指数级）
// 因为有很多重复计算——算 f(5) 时 f(3) 被算了两次
// 实际竞赛中一定要用记忆化搜索或递推，这里仅为演示递归结构
int fib(int n) {
    // 边界：第1项和第2项都是1
    if (n == 1 || n == 2) return 1;
    // 递归关系：第n项 = 前两项之和
    // 这里调用了两次自己，但两个子问题有重叠（都要算 f(n-2)）
    // 这是低效的根源，也是区分"递归"和"动态规划"的关键
    return fib(n - 1) + fib(n - 2);
}

int main() {
    int n;
    cin >> n;
    cout << fib(n) << endl;
    return 0;
}

    #include <bits/stdc++.h>
using namespace std;

const int MAXN = 100005;
int a[MAXN], tmp[MAXN]; // tmp 是合并时用的辅助数组

// 归并排序：经典的分治算法
// 分治思路：
//   1. 分解：把数组 [l, r] 从中间切成两半
//   2. 解决：递归排序左半边和右半边（子问题）
//   3. 合并：把两个有序数组合并成一个
// 时间复杂度 O(n log n)，空间复杂度 O(n)
void mergeSort(int l, int r) {
    // 边界：区间只剩一个元素，已经有序，不用再拆
    if (l >= r) return;

    // === 1. 分解 ===
    // 取中点，把区间分成 [l, mid] 和 [mid+1, r]
    // 注意 mid = (l+r)/2 在 l+r 很大时可能溢出
    // 写成 mid = l + (r-l)/2 更安全
    int mid = l + (r - l) / 2;

    // === 2. 解决 ===
    // 递归排序左右两半
    // 这里假设 mergeSort 能正确排序子数组
    mergeSort(l, mid);
    mergeSort(mid + 1, r);

    // === 3. 合并 ===zqsw
    // 左右两半已经各自有序，现在合并成一个有序数组
    // i 指向左半边的开头，j 指向右半边的开头
    // k 指向辅助数组 tmp 的写入位置
    int i = l, j = mid + 1, k = l;
    while (i <= mid && j <= r) {
        // 谁小就把谁先放进 tmp
        // 注意：这里用 <= 保证稳定排序（相等时左边的先放）
        if (a[i] <= a[j]) {
            tmp[k++] = a[i++];
        } else {
            tmp[k++] = a[j++];
        }
    }
    // 处理剩下的元素（左半边或右半边可能没放完）
    // 两个 while 最多只会执行一个
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= r)   tmp[k++] = a[j++];

    // 把 tmp 中排好的数据拷回原数组
    // 不拷回去的话，上一层合并时读到的还是乱序的
    for (i = l; i <= r; i++) a[i] = tmp[i];
}

int main() {
    int n;
    cin >> n;
    for (int i = 0; i < n; i++) cin >> a[i];
    mergeSort(0, n - 1);
    for (int i = 0; i < n; i++) cout << a[i] << " \n"[i == n - 1];
    return 0;
}

    归并排序的思考流程：

    步骤 你在干什么 为什么这么做
    取中点拆两半 大问题化小 一个数组拆成两个更短的数组，各自排序更简单
    递归排序左/右 相信子问题能解决 不需要关心递归内部怎么排的，只需要它返回一个有序数组
    双指针合并 组合子问题答案 两个有序数组合并是 O(n) 的，很高效
    拷回原数组 让上层用正确数据 不拷回去的话上层合并时 a[] 还是乱序的

    如果不这么写会怎样？ - 如果不用辅助数组 tmp，直接在原数组上 "原地合并" 非常复杂（需要额外的移动操作），时间复杂度会退化 - 如果合并时不用 <= 而用 <，相等的元素会先放右边的，排序不再稳定（虽然对整数排序没影响，但对结构体排序可能有） - 如果忘了把 tmp 拷回 a，上层递归会看到没有变化的数据，排序失败

    #include <bits/stdc++.h>
using namespace std;

// 快速幂：计算 a^b % mod
// 暴力做法：连乘 b 次 → O(b)，b=10^9 时直接超时
// 分治思想：
//   如果 b 是偶数：a^b = (a^(b/2))^2
//   如果 b 是奇数：a^b = a × a^(b-1) = a × (a^((b-1)/2))^2
// 每次把指数减半，时间复杂度 O(log b)
long long quickPow(long long a, long long b, long long mod) {
    // 边界：任何数的 0 次方都是 1
    if (b == 0) return 1 % mod;

    // 先算 a^(b/2)，只需要递归一次
    // 对比直接 return quickPow(a,b-1,mod)*a — 那种是 O(b)，不是快速幂
    long long half = quickPow(a, b / 2, mod);
    long long result = half * half % mod;

    // 如果 b 是奇数，还要再乘一个 a
    // 为什么不在递归里处理奇数？为了让每次递归指数严格减半
    // 如果 b 是奇数递归 b-1，偶数递归 b/2，递归深度可能到 O(b)
    if (b % 2 == 1) {
        result = result * a % mod;
    }
    return result;
}

// 非递归写法（位运算版本），竞赛中更常用
// 理解上面的递归版后再看这个，本质是一样的
long long quickPowIter(long long a, long long b, long long mod) {
    long long result = 1 % mod;
    while (b > 0) {
        // b 的二进制最低位是 1 → 需要乘上当前的 a
        if (b & 1) result = result * a % mod;
        // a 自乘 → 对应二进制的下一位
        a = a * a % mod;
        // b 右移一位
        b >>= 1;
    }
    return result;
}

int main() {
    long long a, b, mod;
    cin >> a >> b >> mod;
    cout << a << "^" << b << " mod " << mod << " = " << quickPow(a, b, mod) << endl;
    return 0;
}

    计算 3^13
3^13 = 3 × (3^6)^2    ← 13 是奇数，拆出一个 3
3^6  = (3^3)^2        ← 6 是偶数，直接平方
3^3  = 3 × (3^1)^2    ← 3 是奇数
3^1  = 3 × (3^0)^2    ← 边界

递归深度：log₂(13) ≈ 4 层
暴力：13 层
b=10^9 时：log₂(10^9) ≈ 30 层 vs 10^9 层

    本节重点： - 递归三要素：边界（base case）、递推关系（缩小规模）、返回值衔接 - 分治三步骤：分解（Divide）→ 解决（Conquer）→ 合并（Combine） - 递归时不要试图在脑子里展开每一层——相信子问题已经被正确解决，只关注当前层 - 常见坑 1：没有边界 → 栈溢出。检查递归函数是否在所有分支上都能到达边界 - 常见坑 2：子问题有重叠还傻递归 → 指数级复杂度。用记忆化搜索（数组记录已经算过的结果） - 常见坑 3：递归深度太大 → 栈溢出。C++ 默认栈空间有限，深度超过 ~10^5 的递归用迭代或手动栈
