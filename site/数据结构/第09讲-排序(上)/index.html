    第 09 讲 排序（上）：简单排序、希尔、选择堆与归并¶

    本讲依据视频 104–113（9.1 排序基本概念与简单排序、9.2 希尔排序、9.3 选择排序与堆排序、9.4 归并排序）整理。 学习目标：掌握冒泡、插入、希尔、选择、堆、归并六类排序的原理与复杂度，理解"交换相邻元素"的复杂度下界与逆序对概念，能分析各算法的稳定性与适用场景。

    一、排序基本概念¶

    排序是把若干数据按关键字从小到大（或从大到小）重新排列的过程。本讲约定：

    • 统一函数头为 X_Sort(A, N)，A 为待排数组（ElementType），N 为元素个数；
    • 默认讨论基于比较的内部排序（数据全部可放入内存一次性排完），从小到大，元素可比较大小；
    • N 为合法正整数。

    稳定性：任意两个相等的数据，排序前后相对位置不发生改变，称该排序算法是稳定的。例如两个都叫"小明"的学生，若排序前小明1在小明2之前，稳定算法排序后两人仍保持此先后。

    为什么要学这么多排序算法：没有任何一种算法在任何情况下都是最快最好的。每种算法都因数据具有某种特征而成为当时的最优选择——这正是它们被写进教科书的理由。

    二、冒泡排序与插入排序¶

    1. 冒泡排序¶

    冒泡排序像一堆气泡上浮：每次从上到下比较相邻两个元素，若逆序则交换；一趟下来最大的元素必然沉到最底部。下一趟只需对前 n−1 个元素重复。

    伪码核心：外层 p 从 n−1 递减到 0，内层 i 从 0 到 p−1 比较 A[i] 与 A[i+1]，逆序则 Swap。

    改进：加一个 flag 标记本趟是否发生交换；若某趟全程无交换，说明序列已有序，直接 break。

    • 最好情况（本就有序）：O(N)，只需一趟扫描即 break；
    • 最坏情况（完全逆序）：O(N²)；
    • 只有当 A[i] 严格大于 A[i+1] 时才交换，相等不动，故冒泡排序是稳定的；
    • 另一个独特优点：它只沿一个方向扫描、每次交换相邻元素，因此在单向链表上也能方便地实现，其他跳着交换的算法往往做不到。

    2. 插入排序¶

    插入排序像抓扑克牌：手里保持一手有序的牌，新摸一张从右往左比，比它大的牌向后错一位，直到找到自己的空位落位。

    伪码：从第 1 个元素起把 A[i] 暂存为 X，j 从 i−1 向前，只要 A[j] > X 就 A[j+1] = A[j]（向后错一位），直到 A[j] ≤ X，把 X 放到 A[j+1]。

    • 最好情况（顺序输入）：一张牌都不用移动，O(N)；
    • 最坏情况（逆序输入）：每摸一张都要把前面所有牌后移，O(N²)；
    • 严格小于才移位、相等不动，故插入排序也是稳定的；
    • 比冒泡省步骤：冒泡两两交换要三步，插入是成段移动后一次性落位。

    【进阶】冒泡与插入的完整实现见 OI-Wiki：算法基础/冒泡排序、算法基础/插入排序。

    三、时间复杂度下界：逆序对¶

    逆序对：下标 i < j 但 A[i] > A[j]，称 (i, j) 为一对逆序对。

    关键观察：冒泡与插入每次都交换（移动）相邻两个元素，而一次相邻交换恰好消去一个逆序对。因此这两种算法的交换次数，恰好等于原始序列中逆序对的个数 I。

    于是插入排序的精确复杂度为 O(N + I)：至少要扫描一遍所有元素（N），再花与逆序对数成正比的操作。当序列基本有序（I 很小）时，插入排序接近线性，非常快。

    定理：N 个不同元素的序列平均有 Θ(N²) 个逆序对。故任何仅以交换相邻两元素来排序的算法，平均时间复杂度为 Ω(N²)——这是它们不可突破的下界。

    突破方向很自然：每次交换要能跳着进行，一次交换消去多个逆序对。

    四、希尔排序¶

    希尔排序（Shell Sort，1959 年 D. Shell 提出）利用插入排序简单的优点，同时克服它每次只能动相邻元素的缺点。

    1. 基本思路¶

    先定义一个递减增量序列 Dₖ, Dₖ₋₁, …, 1（最后一步必须是 1）。对每个增量 D，把相隔 D 的元素组成一个子序列，用插入排序排好。当最后做 1-间隔（普通插入排序）时，序列已基本有序，大部分逆序对已被前面几趟消掉。

    重要性质：一个 Dₖ-间隔有序的序列，在做 Dₖ₋₁-间隔排序后，仍然保持 Dₖ-间隔有序——更小间隔的排序不会把上一步结果变坏。

    2. 增量序列¶

    • 原始希尔增量：D₁ = ⌊N/2⌋，每次减半直到 1。问题：各增量互为倍数（8,4,2,1），小的增量可能完全不起作用，最坏仍为 Θ(N²)；
    • Hibbard 增量：Dₖ = 2ᵏ − 1，相邻增量互质，最坏 O(N^(3/2))，平均猜想 O(N^(5/4))；
    • Sedgewick 增量：表现更好，平均猜想 O(N^(7/6))，最坏 O(N^(4/3))。

    希尔排序是最先突破 N² 下界的排序算法；因跳着排序，它是不稳定的。实际中几万规模的数据配 Sedgewick 增量效果不错。一个算法可以极简，但复杂度分析极难——希尔排序正是如此。

    【进阶】见 OI-Wiki：算法基础/希尔排序。

    五、选择排序与堆排序¶

    1. 简单选择排序¶

    每趟从 A[i]…A[N−1] 中找最小元，把它与 A[i] 交换。

    • 交换次数最多 N−1 次（线性），但找最小元要扫描剩余全部元素，外层再套一层循环，故无论好坏都是 Θ(N²)；
    • 交换是跳着的（不相邻），可能一次消去多个逆序对；
    • 跳着交换导致它不稳定。

    瓶颈在"找最小元"。看到最小元，自然想到最小堆。

    2. 堆排序¶

    堆排序是对选择排序的改进。

    朴素做法（需额外空间）：BuildHeap 建成最小堆（线性时间），反复 DeleteMin 依次弹出最小元存入临时数组，再拷回原数组。BuildHeap 为 O(N)，N 次 DeleteMin 为 O(N log N)，但要额外 O(N) 空间且有一次完整拷贝。

    就地做法（最大堆）：

    1. BuildMaxHeap 把数组建成最大堆，根 A[0] 即为最大元；
    2. 把根与当前堆尾元素交换——最大元就放到了它最终的位置；
    3. 堆规模减 1，对剩余部分向下过滤调整为最大堆；
    4. 重复直到堆为空。

    这样无需额外数组，最大元逐个"沉底"。

    下标细节：排序接口从 A[0] 开始存元素（用户不留哨兵），故父子下标关系与堆章节中从 A[1] 开始的约定不同，需注意对应关系。

    堆排序平均比较次数略小于 N log N，量级为 O(N log N)，无论最坏还是平均都是 O(N log N)；但常数较大，实际效果未必比 Sedgewick 增量的希尔排序好。它是不稳定的。

    【进阶】见 OI-Wiki：算法基础/选择排序、算法基础/堆排序。

    六、归并排序¶

    1. 两个有序子列的归并¶

    两个已经有序的子列肩并肩放在数组里，用三个"指针"（其实就是下标）L、R、Tmp：比较 L 与 R 所指元素，小者放到 Tmp 所指位置，相应指针前移；直到某一列为空，把另一列剩余部分直接拷入。一趟归并 O(N)。

    把结果从临时数组拷回原数组时要注意：循环里 L 已被++得找不到起点，因此从右往左拷——RightEnd 自始至终没变过。

    2. 递归实现（分而治之）¶

    MSort：若 L < RightEnd，取中点 Center，递归排左半、递归排右半，再 Merge。递推式 T(N) = 2T(N/2) + O(N)，解得 T(N) = O(N log N)——没有最好/最坏/平均之分，任何情况都是 O(N log N)。归并排序是稳定的。

    临时数组只 malloc 一次：统一接口 Merge_Sort(A, N) 在开头申请等长 TmpA，全程只在它的某一段上反复操作、最后 free。若把 TmpA 放在 Merge 内部反复 malloc/free，虽然额外空间仍是 O(N)，但分配/释放次数太多，不合算。

    3. 非递归实现¶

    初始把每个元素看作长度为 1 的有序子列，然后两两归并使子列长度倍增为 2、4、8……直到整个序列有序。

    关键优化：不要每层都开新数组，只需一个临时数组，A→TmpA、TmpA→A 来回倒；每两轮 Merge_Pass 保证最终结果落在 A 中。子列长度 length 从 1 起翻倍，循环到 length ≥ N 为止。最后一段尾巴（奇数个子列、两段长度不等）单独处理。

    归并排序千好万好，唯一硬伤是需要 O(N) 额外空间并反复拷贝，因此内排序里很少用它；但它是外排序的得力工具。

    【进阶】见 OI-Wiki：算法基础/归并排序。
