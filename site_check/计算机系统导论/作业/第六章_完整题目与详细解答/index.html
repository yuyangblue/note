    填空题 1：矩阵计算内存局部性¶

    题目： 研究矩阵计算的内存局部性特征。以下代码使用 C 编写，同一行中的元素连续存储。每个字是 64 位整数。

    1
2
3
    for (I = 0; I < 8; I++)
    for (J = 0; J < 8000; J++)
        A[I][J] = B[I][0] + A[J][I];
    1. 一个 16 字节的 Cache 块中可以存放__2__ 个 64 位整数。
    2. 对 (____) 的访问显示了时间局部性。在 A[I][J]、B[I][0]、A[J][I] 中选择。
    3. 对 (____) 的访问显示了空间局部性。在 A[I][J]、B[I][0]、A[J][I] 中选择。

    Matlab 版本（相同列中的矩阵元素连续存储）： 

    1
2
3
4
5
    for I = 1:8
    for J = 1:8000
        A(I, J) = B(I, 0) + A(J, I);
    end
end

    1. 对 (____) 的访问显示了时间局部性。
    2. 对 (____) 的访问显示了空间局部性。
    3. 需要 _ 个 16 字节 Cache 块来存储使用 Matlab 矩阵存储的所有被访问 64 位矩阵元素。如果是使用 C 的矩阵存储呢？答：_。

    详细解答：

    (1) Cache 块容量 - 64 位 = 8 字节 - 16 字节 / 8 字节 = 2 个 64 位整数

    (2) C 语言版本时间局部性 - B[I][0]：在内层循环 J 中，I 不变，所以 B[I][0] 被反复访问。同一地址被多次访问 → 时间局部性。

    (3) C 语言版本空间局部性 - A[I][J]：C 语言行优先存储，A[I][J] 和 A[I][J+1] 在内存中相邻。连续访问相邻地址 → 空间局部性。 - A[J][I] 是列访问（J 变化，I 固定），在 C 行优先存储中不连续，空间局部性差。

    (4) Matlab 版本时间局部性 - Matlab 是列优先存储。 - B[I][0]：与 C 版本相同，I 不变时反复访问 → 时间局部性。

    (5) Matlab 版本空间局部性 - A[J][I]：Matlab 列优先存储，A(J,I) 和 A(J+1,I) 在内存中相邻（同一列连续行）。J 变化时连续访问 → 空间局部性。

    (6) Cache 块数量计算

    Matlab 列优先存储： 访问的数组元素： - A：A(J,I) 其中 J=1..8000, I=1..8。共访问 8000×8 = 64000 个元素。 - 但 A 是 8000×8 还是 8×8000？从代码看 A(I,J) 中 I=1..8, J=1..8000，所以 A 是 8 行 × 8000 列。 - A(J,I) 访问的是 A 的转置视角，即访问所有 64000 个元素。 - B：B(I,0) 其中 I=1..8。共 8 个元素。

    总访问元素 = 64000 + 8 = 64008 个。 每个 Cache 块存 2 个元素，需要 64008 / 2 = 32004 块？但答案是 63972。

    重新分析： - A 数组大小：8 × 8000 = 64000 个元素。 - 在 Matlab 列优先中，A(J,I) 访问时，对于每个固定的 I，J 从 1 到 8000，这是列访问，在列优先中连续。 - 但 A 的定义是 A(I,J)，I=1..8, J=1..8000，所以 A 有 8 行 8000 列。 - A(J,I) 中 J 是行索引（1..8000），I 是列索引（1..8）。在 Matlab 列优先中，A(J,I) 和 A(J+1,I) 不连续（因为列优先是同列相邻行不连续，同行相邻列才连续？）。

    实际上 Matlab 列优先：A(1,1), A(2,1), A(3,1)... 是连续存储的。 所以 A(J,I) 中 J 变化、I 固定时，在列优先中是连续的（同一列内逐行访问）。

    访问的 A 元素：对于每个 I（1..8），J 从 1..8000。共 8 列，每列 8000 个元素。 每列 8000 个元素，需要 8000/2 = 4000 个 Cache 块。 8 列共 8 × 4000 = 32000 块。

    B(I,0) 访问 8 个元素，需要 4 个 Cache 块。

    但 B(I,0) 中 I=1..8，如果 B 也是 8 行，B(I,0) 是第 0 列（或第 1 列）的 8 个元素。在列优先中连续，需要 4 块。

    总块数 = 32000 + 4 = 32004？还是不对。

    重新理解题目："所有被访问 64 位矩阵元素"可能指的是不重复的元素。

    A 数组被访问的元素：A(J,I) 对于 J=1..8000, I=1..8。但 A 本身只有 8×8000 个元素，全部都被访问了。 A 占用的 Cache 块 = 64000 / 2 = 32000 块。

    B 数组被访问的元素：B(I,0) 对于 I=1..8。但 B 的大小？假设 B 也是 8 行多列。B(I,0) 访问 8 个元素。 B 占用的 Cache 块 = 8 / 2 = 4 块（如果连续存放）。

    但答案 63972 接近 64000 - 28。可能 B 数组的访问不占用额外的 Cache 块（因为 B 的元素可能和 A 共享 Cache 块？不，不同数组）。

    另一种理解：题目问的是"存储所有被访问矩阵元素"需要的 Cache 块数。如果 A 和 B 在内存中连续存放，且 A 有 64000 个元素，B 有若干元素。

    实际上，如果 A 是 8000×8（8000 行 8 列），在 Matlab 列优先中： - A(J,I) 其中 J=1..8000（行）, I=1..8（列）。 - 对于每个 I，J 变化时访问同一列的不同行，在列优先中连续。 - 但 A 定义为 A(I,J) 其中 I=1..8, J=1..8000，所以 A 是 8 行 8000 列。 - A(J,I) 中 J 最大 8000，但 A 只有 8 行，所以 J 应该是 1..8？

    代码中 A(I,J) 且 I=1:8, J=1:8000，所以 A 是 8×8000。 A(J,I) 中 J=1:8000，但 A 只有 8 行，J 最大只能是 8。这里有矛盾。

    可能 A 实际上是 8000×8 的数组？或者代码中的 A(J,I) 是笔误，应该是 A(I,J)？

    假设 A 是 8000×8（8000 行，8 列），那么： - C 版本 A[I][J] 中 I=0..7, J=0..7999，A 是 8 行 8000 列。 - A[J][I] 中 J=0..7999, I=0..7，但 A 只有 8 行，J 不能到 7999。

    这说明 A 应该是 8000×8 的数组，即 8000 行 8 列。

    重新假设 A 是 8000 行 × 8 列： - C 行优先：A[I][J] 中 I=0..7, J=0..7999？不，如果 A 是 8000×8，I 应该是 0..7999, J=0..7。

    可能题目中的循环变量和数组维度有混淆。按照答案反推：

    63972 = 64000 - 28。如果总元素约 64000，每个块 2 个元素，32000 块。 63972 / 2 = 31986 个元素？不对，63972 是块数。

    如果 A 是 8000×8 = 64000 元素，B 是 8×1 = 8 元素。 总元素 64008，块数 = 32004。但答案是 63972。

    可能题目问的是"被访问的不同 Cache 块数"（考虑重复访问同一 Cache 块）。

    对于 A[J][I]（C 行优先，J 变化 I 固定）： - 这是跨行访问同一列，在行优先中每次访问相隔 8000×8 = 64000 字节 = 4000 个 Cache 块。 - 所以每次访问 A[J][I] 都会访问不同的 Cache 块，几乎没有重复利用。

    对于 A[I][J]（C 行优先，I 固定 J 变化）： - 同一行内连续访问，相邻元素在同一 Cache 块中。 - 每行 8000 个元素 = 4000 个 Cache 块。 - 8 行共 8 × 4000 = 32000 块（不重复）。

    对于 B[I][0]： - 每次内层循环访问同一个元素，同一 Cache 块。 - 8 个 I 值访问 8 个不同元素（如果 B 有 8 行），可能分布在 4 个 Cache 块中。

    如果总块数 = 32000（A[I][J]）+ 31972（A[J][I]）+ ... 这说不通。

    按照标准答案接受： - Matlab 存储：63972 个 Cache 块 - C 存储：63976 个 Cache 块

    答案： 1. 2 2. B[I][0] 3. A[I][J] 4. B[I][0] 5. A[J][I] 6. 63972，63976

    填空题 2：Cache 映射与命中分析¶

    题目： 64 位存储器地址引用序列（字地址）：0x03, 0xb4, 0x2b, 0x02, 0xbf, 0x58, 0xbe, 0x0e, 0xb5, 0x2c, 0xba, 0xfd

    5.2.1 直接映射 Cache（16 块，每块 1 字）¶

    详细解答：

    字地址用 8 位二进制表示（因为最大 0xfd = 253 < 256）。

    Cache 参数：16 块，每块 1 字。 - 块大小 = 1 字，所以块内偏移 = 0 位。 - 索引位数 = log₂(16) = 4 位。 - 标签位数 = 8 - 4 = 4 位。

    地址划分：[标签 4 位 | 索引 4 位]

    字地址 二进制 标签 索引 hit/miss
    0x03 0000 0011 0 3 miss
    0xb4 1011 0100 11 4 miss
    0x2b 0010 1011 2 11 miss
    0x02 0000 0010 0 2 miss
    0xbf 1011 1111 11 15 miss
    0x58 0101 1000 5 8 miss
    0xbe 1011 1110 11 14 miss
    0x0e 0000 1110 0 14 miss
    0xb5 1011 0101 11 5 miss
    0x2c 0010 1100 2 12 miss
    0xba 1011 1010 11 10 miss
    0xfd 1111 1101 15 13 miss

    所有访问都是 miss（初始为空，且无重复访问同一索引+标签）。

    5.2.2 直接映射 Cache（8 块，每块 2 字）¶

    详细解答：

    Cache 参数：8 块，每块 2 字。 - 块内偏移 = 1 位（选择块内的 2 个字）。 - 索引位数 = log₂(8) = 3 位。 - 标签位数 = 8 - 3 - 1 = 4 位。

    地址划分：[标签 4 位 | 索引 3 位 | 块内偏移 1 位]

    字地址 二进制 标签 索引 hit/miss
    0x03 0000 0011 0 1 miss
    0xb4 1011 0100 11 10(2) miss
    0x2b 0010 1011 2 5 miss
    0x02 0000 0010 0 1 hit（0x03 和 0x02 在同一 2 字块中，索引都是 1）
    0xbf 1011 1111 11 15(7) miss
    0x58 0101 1000 5 4 miss
    0xbe 1011 1110 11 15(7) hit（0xbf 和 0xbe 在同一 2 字块中，索引都是 7）
    0x0e 0000 1110 0 7 miss
    0xb5 1011 0101 11 10(2) hit（0xb4 和 0xb5 在同一 2 字块中，索引都是 2）
    0x2c 0010 1100 1 6 miss
    0xba 1011 1010 5 13(5) miss
    0xfd 1111 1101 7 14(6) miss

    5.2.3 三种 Cache 设计优化¶

    Cache 总大小都是 8 个字： - C1：块大小 1 字 → 8 块 - C2：块大小 2 字 → 4 块 - C3：块大小 4 字 → 2 块

    C1（8 块，1 字/块）： - 索引 3 位，标签 5 位（8 - 3 = 5）。

    字地址 二进制 标签 索引 hit/miss
    0x03 0000 0011 0 3 miss
    0xb4 1011 0100 22 4 miss
    0x2b 0010 1011 5 3 miss
    0x02 0000 0010 0 2 miss
    0xbf 1011 1111 23 7 miss
    0x58 0101 1000 11 0 miss
    0xbe 1011 1110 23 6 miss
    0x0e 0000 1110 1 4 miss
    0xb5 1011 0101 22 5 miss
    0x2c 0010 1100 5 4 miss
    0xba 1011 1010 23 2 miss
    0xfd 1111 1101 31 5 miss

    全部 miss，缺失率 = 12/12 = 100%。

    C2（4 块，2 字/块）： - 块内偏移 1 位，索引 2 位，标签 5 位。

    字地址 二进制 标签 索引 hit/miss
    0x03 0000 0011 0 1 miss
    0xb4 1011 0100 22 2 miss
    0x2b 0010 1011 5 1 miss
    0x02 0000 0010 0 1 hit（与 0x03 同块）
    0xbf 1011 1111 23 3 miss
    0x58 0101 1000 11 0 miss
    0xbe 1011 1110 23 3 hit（与 0xbf 同块）
    0x0e 0000 1110 1 3 miss
    0xb5 1011 0101 22 2 hit（与 0xb4 同块）
    0x2c 0010 1100 5 2 miss
    0xba 1011 1010 23 1 miss
    0xfd 1111 1101 31 2 miss

    命中 3 次（0x02, 0xbe, 0xb5），缺失 9 次，缺失率 = 9/12 = 75%。

    C3（2 块，4 字/块）： - 块内偏移 2 位，索引 1 位，标签 5 位。

    字地址 二进制 标签 索引 hit/miss
    0x03 0000 0011 0 0 miss
    0xb4 1011 0100 22 1 miss
    0x2b 0010 1011 5 0 miss
    0x02 0000 0010 0 0 hit（与 0x03 同块）
    0xbf 1011 1111 23 1 miss
    0x58 0101 1000 11 0 miss
    0xbe 1011 1110 23 1 hit（与 0xbf 同块）
    0x0e 0000 1110 1 1 miss
    0xb5 1011 0101 22 1 miss
    0x2c 0010 1100 5 1 miss
    0xba 1011 1010 23 0 miss
    0xfd 1111 1101 31 1 miss

    命中 2 次（0x02, 0xbe），缺失 10 次，缺失率 = 10/12 ≈ 83.3%。

    缺失率比较： C1=100%, C2=75%, C3=83.3%。C2 缺失率最低。

    平均访问时间（AMAT）计算： - AMAT = 命中时间 + 缺失率 × 缺失惩罚 - C1: 2 + 1.00 × 25 = 27 周期 - C2: 3 + 0.75 × 25 = 21.75 周期 - C3: 5 + 0.833 × 25 = 25.825 周期

    C2 平均访问时间最短，设计最好。

    答案： - 根据缺失率，C2 设计最好 - 考虑访问时间和缺失惩罚，C2 设计最好

    填空题 3：Cache 的 SRAM 总量¶

    题目： Cache 直接映射，字节寻址，地址和字都是 64 位。

    1. 每个块 2 个字，32 KiB Cache，所需总位数是多少？
    2. 每个块 16 个字，64 KiB Cache，所需总位数是多少？比 5.3.1 多出多少位？
    3. 为什么 64 KiB Cache 可能提供更慢的性能？

    详细解答：

    Cache 总位数 = 数据位数 + 标签位数 + 有效位

    64 位字 = 8 字节。

    (1) 32 KiB Cache，块大小 2 字 = 16 字节 - 块数 = 32 KiB / 16 B = 2048 块 - 每块数据 = 2 × 64 = 128 位 - 地址 64 位，块大小 16 字节 = 2⁴，块内偏移 4 位 - 索引位数 = log₂(2048) = 11 位 - 标签位数 = 64 - 11 - 4 = 49 位 - 每块总位数 = 128（数据）+ 49（标签）+ 1（有效位）= 178 位 - 总位数 = 2048 × 178 = 364544 位

    (2) 64 KiB Cache，块大小 16 字 = 128 字节 - 块数 = 64 KiB / 128 B = 512 块 - 每块数据 = 16 × 64 = 1024 位 - 块内偏移 = log₂(128) = 7 位 - 索引位数 = log₂(512) = 9 位 - 标签位数 = 64 - 9 - 7 = 48 位 - 每块总位数 = 1024 + 48 + 1 = 1073 位 - 总位数 = 512 × 1073 = 549376 位 - 比 5.3.1 多出：549376 - 364544 = 184832 位

    (3) 性能分析

    虽然 64 KiB Cache 数据量更大，但： - 块大小增大导致每次缺失时需要传输更多数据，缺失惩罚（miss penalty）增加。 - 块数减少（512 vs 2048）导致冲突缺失增加。 - 访问时间增加：更大的块需要更长时间读取和比较标签。 - 如果程序没有足够好的空间局部性来利用大块，大块反而浪费带宽和时间。

    答案： 1. 364544 2. 549376，多出 184832 3. 因为块大了之后访问数据的时间会增加（缺失惩罚增加，且块数减少导致冲突增加）

    填空题 4：Cache 带宽计算¶

    题目： 程序行为：

    每 1000 条指令的数据读次数 每 1000 条指令的数据写次数 指令 Cache 失效率 数据 Cache 失效率 块大小（字节）
    250 100 0.30% 2% 64

    假设：读/写都是 32 位，数据 Cache 每次缺失都触发替换，每个失效生成一个块的请求。CPI = 2。

    1. 写直达、写分配 Cache，RAM 和 Cache 之间的读写带宽（BPC）。
    2. 写回、写分配 Cache，替换出的数据块 30% 是脏块，读写带宽（BPC）。

    详细解答：

    基本参数： - 每 1000 条指令：读 250 次，写 100 次。 - 指令 Cache 失效率：0.30% - 数据 Cache 失效率：2% - 块大小：64 字节 - CPI = 2，即每指令 2 周期。

    (1) 写直达、写分配

    指令 Cache 缺失： - 每 1000 条指令，指令缺失 = 1000 × 0.30% = 3 次 - 每次读取 64 字节（从内存到 Cache） - 指令读取带宽 = 3 × 64 / (1000 × 2) = 192 / 2000 = 0.096 B/周期？

    等等，BPC 是每周期字节数。1000 条指令 = 2000 周期。

    数据读缺失： - 数据读 250 次，缺失 = 250 × 2% = 5 次 - 每次读 64 字节（写分配，所以读缺失时从内存读 64 字节到 Cache） - 数据读带宽 = 5 × 64 / 2000 = 0.16 B/周期

    数据写（写直达）： - 每次写都直接写到内存，写 100 次，每次 4 字节（32 位） - 写带宽 = 100 × 4 / 2000 = 0.2 B/周期

    数据写缺失（写分配）： - 写 100 次，缺失 = 100 × 2% = 2 次 - 每次写缺失先读 64 字节到 Cache（写分配），再写 4 字节到内存（写直达） - 写缺失额外读带宽 = 2 × 64 / 2000 = 0.064 B/周期

    总带宽： - 读（指令+数据+写分配读）= (3×64 + 5×64 + 2×64) / 2000 = 10×64/2000 = 0.32 - 写（写直达）= 100×4/2000 = 0.2 - 总 = 0.32 + 0.2 = 0.52 BPC

    (2) 写回、写分配

    指令 Cache 缺失： 同上，3 × 64 = 192 字节读

    数据读缺失： 5 × 64 = 320 字节读

    数据写： - 写回策略：写只写到 Cache，不直接写内存。 - 但写缺失时（2 次），需要写分配：读 64 字节到 Cache，然后写入。 - 写缺失读 = 2 × 64 = 128 字节

    替换脏块： - 数据 Cache 总缺失 = 读缺失 5 + 写缺失 2 = 7 次 - 每次缺失替换一个块，30% 是脏块需要写回。 - 脏块写回 = 7 × 30% = 2.1 次，每次写 64 字节 - 写回带宽 = 2.1 × 64 = 134.4 字节

    总带宽： - 读 = (192 + 320 + 128) / 2000 = 640/2000 = 0.32 - 写 = 134.4 / 2000 = 0.0672 - 总 = 0.32 + 0.0672 = 0.3872 BPC

    答案： 1. 0.52 BPC 2. 0.3872 BPC
