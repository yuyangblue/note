    03 线性 DP¶

    线性 DP：在一维/二维数组上按顺序递推，每个状态只依赖前面的若干个状态。 经典三件套：LIS（最长上升子序列）、LCS（最长公共子序列）、编辑距离。 线性 DP 的关键是想清楚"以谁结尾"——状态定义对了，转移自然就出来了。

    大白话引入¶

    • LIS：在一排照片里挑一个"越来越好看"的子集（可以跳着挑，但顺序不能乱），挑得越多越好。
    • LCS：两个人各发了一条弹幕，找两句话里顺序相同的最长公共部分（不要求连续）。
    • 编辑距离：把 "kitten" 改成 "sitting" 最少要几步？（允许增、删、改一个字符）

    思维启发 & 思考流程¶

    先手算一个最小例子¶

    看 LIS：a = [1, 3, 2, 4]，最长上升子序列多长？

    手算：可以跳着选，1, 3, 4 长度 3；1, 2, 4 也是 3。最长是 3。

    那我是怎么算出来的？我固定了"以某个数结尾"：以 4 结尾，那前面得找一个比 4 小的数接着；以 2 结尾，前面找个比 2 小的…… 把"以谁结尾"固定下来，子问题就清晰了。

    为什么状态是"以 i 结尾"，而不是"前 i 个"？¶

    这是线性 DP 最关键的直觉。两种状态定义：

    • dp[i] = 前 i 个元素的答案 → 没法转移！因为不知道上一个选了谁，就没法判断"递增 / 相等 / 能不能接上去"
    • dp[i] = 以第 i 个元素结尾的答案 → 上一个元素是谁就确定了，转移时只需要枚举"上一个"是谁

    一句话：约束条件（递增、相等）发生在相邻两个被选的元素之间，所以必须知道"最后选的是谁"。这就是"以 i 结尾"的由来。

    拿到线性 DP 题的通用流程¶

    1. 明确序列是什么、要满足什么约束（递增？相等？连续？）
    2. 设计状态：dp[i] 以 i 结尾（二维题则是 dp[i][j]）
    3. 枚举转移：上一个状态 j 满足什么条件才能接到 i 后面？
    4. 答案：注意不是 dp[n]，而是 max(dp[i])（LIS）或 dp[n][m]（LCS）——取决于最优解以谁结尾

    1. LIS 最长上升子序列¶

    状态与转移¶

    • 状态：dp[i] = 以 a[i] 结尾的最长上升子序列长度
    • 转移：dp[i] = max(dp[j] + 1)，其中 j < i 且 a[j] < a[i]（前面的数更小，才能把 i 接上去）
    • 边界：dp[i] = 1（自己单独成序列）
    • 答案：max(dp[1..n]) —— 最优解可能以任意元素结尾，不能直接输出 dp[n]！

    朴素版 O(n²)：先正确，再优化¶

    用 [1, 3, 2, 4] 走一遍：dp[1]=1；dp[2] 看前面比 3 小的（只有 1）→ 2；dp[3] 看前面比 2 小的（1）→ 2；dp[4] 看前面比 4 小的（1,3,2，dp 分别为 1,2,2）→ 3。答案 max = 3 ✅

    #include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> a(n + 1);
    for (int i = 1; i <= n; i++) cin >> a[i];

    vector<int> dp(n + 1, 1);   // dp[i] = 以 a[i] 结尾的最长上升子序列长度，自己单独至少 1
    int ans = 1;
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j < i; j++) {       // 枚举上一个元素
            if (a[j] < a[i])                // 只有更小的才能接在 i 前面
                dp[i] = max(dp[i], dp[j] + 1);
        }
        ans = max(ans, dp[i]);              // 答案不是 dp[n]，是最优解可能以任意元素结尾
    }
    cout << ans << endl;
    return 0;
}

    复杂度：O(n²)，n ≤ 5000 勉强能过；n = 1e5 时 1e10 次操作直接超时，需要下面的优化。

    优化版 O(n log n)：贪心 + 二分¶

    为什么朴素版慢？因为每个 i 都要回头扫一遍所有 j。能不能不扫？

    关键观察：同样是长度 k 的上升子序列，结尾元素越小越好——越小，未来越容易接上更大的数。所以只关心每个长度的"最小结尾"。

    • 维护 tails[k] = 长度为 k+1 的上升子序列的最小结尾元素
    • tails 数组本身单调递增（长度越长，最小结尾不可能更小），可以二分
    • 新元素 x：
    • 找到第一个 ≥ x 的位置（lower_bound），替换它 → 让这个长度的结尾变小，为未来留余地
    • 如果 x 比所有结尾都大 → 扩展新长度

    为什么替换不会丢答案？ 替换只是把"长度 k 的最小结尾"更新得更小，长度本身没变；LIS 长度只有在"x 大于所有结尾"时才增长。tails 的长度就是答案。

    #include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    // tails[k] = 长度为 k+1 的上升子序列的最小结尾元素
    // tails 本身单调递增，可以用二分查找
    vector<int> tails;
    for (int x : a) {
        // 找第一个 >= x 的位置：严格上升用 lower_bound
        auto it = lower_bound(tails.begin(), tails.end(), x);
        if (it == tails.end())
            tails.push_back(x);        // x 比所有结尾都大 → 扩展最长长度
        else
            *it = x;                   // 替换：让该长度的结尾变小，方便以后接更多元素
    }
    cout << tails.size() << endl;      // tails 的长度就是 LIS 长度
    return 0;
}

    如果不这么写会怎样： - 用 upper_bound 代替 lower_bound 就是最长不下降子序列（允许相等），两道题只差一个函数 - 朴素 O(n²) 在 n=1e5 时会超时（1e10 次操作），必须二分优化

    复杂度分析：每个元素一次二分 O(log n)，总 O(n log n)。n=1e5 秒过。

    2. LCS 最长公共子序列¶

    状态与转移¶

    两个序列的问题，状态天然是二维：dp[i][j] = a 的前 i 个和 b 的前 j 个的 LCS 长度。

    从 [i-1][j-1]、[i-1][j]、[i][j-1] 三个方向想（这就是"线性"：每个格子只依赖左、上、左上三个格子）：

    • a[i] == b[j] → 匹配上，各退一格：dp[i][j] = dp[i-1][j-1] + 1
    • 不相等 → 这个字符对不上，丢掉 a 的尾巴或 b 的尾巴，取较大的：dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    • 边界：dp[0][*] = dp[*][0] = 0（空串和任何串的 LCS 是 0）

    手算 a="abcde", b="ace"：dp[5][3] 一路推下来 = 3（"ace" 三个字符顺序出现）✅

    #include <bits/stdc++.h>
using namespace std;

int main() {
    string a, b;
    cin >> a >> b;
    int n = a.size(), m = b.size();
    // 用 1 基下标方便处理边界（dp[0][*] 表示空串）
    a = " " + a;
    b = " " + b;

    vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            if (a[i] == b[j]) {
                // 匹配上了：两边各退一格 + 1
                dp[i][j] = dp[i - 1][j - 1] + 1;
            } else {
                // 没匹配上：丢掉 a 的尾或丢掉 b 的尾，取较大的
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]);
            }
        }
    }
    cout << dp[n][m] << endl;
    return 0;
}

    坑：a = " " + a 是为了 1 基下标。如果不加，dp[i-1] 在 i=0 时会越界，且 a[i-1] 下标混乱。

    复杂度分析：O(n·m) 时间 O(n·m) 空间。n=m=5000 时是 2500 万状态，内存约 100MB，勉强能过；再大要滚动数组压到 O(m)。

    进阶：n、m 到 1e5 的 LCS（如 P1439）O(nm) 直接爆炸，需要把 LCS 转成 LIS（映射 + 二分），见洛谷题。

    3. 编辑距离¶

    状态与转移¶

    问题：把字符串 a 变成 b，允许三种操作（增、删、改一个字符），求最少操作数。

    dp[i][j] = 把 a 的前 i 个字符变成 b 的前 j 个字符的最少操作数。对最后一个字符 a[i]，有三种操作，取最小：

    • 删除：删掉 a[i]，剩下的 a 前 i-1 个去变 b 前 j 个 → dp[i-1][j] + 1
    • 插入：在 a 尾部插入 b[j]（插完 b[j] 就匹配了），剩下的 a 前 i 个去变 b 前 j-1 个 → dp[i][j-1] + 1
    • 替换：把 a[i] 改成 b[j]；若本来就相等则不用改 → dp[i-1][j-1] + (a[i]==b[j] ? 0 : 1)

    边界：dp[i][0] = i（a 全删光）、dp[0][j] = j（b 全插进去）。

    手算 "kitten" → "sitting"：k→s 替换、i 不变、t 不变、t 不变、e→i 替换、n 不变、尾部插 g → 3 步 ✅

    #include <bits/stdc++.h>
using namespace std;

int main() {
    string a, b;
    cin >> a >> b;
    int n = a.size(), m = b.size();

    // dp[i][j] = 把 a 前 i 个字符变成 b 前 j 个字符的最少操作数
    vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));

    // 边界：a 为空 → 全插入；b 为空 → 全删除
    for (int i = 0; i <= n; i++) dp[i][0] = i;
    for (int j = 0; j <= m; j++) dp[0][j] = j;

    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            // 三种操作取最小
            int del = dp[i - 1][j] + 1;          // 删掉 a[i]
            int ins = dp[i][j - 1] + 1;          // 插入 b[j]
            int rep = dp[i - 1][j - 1] + (a[i - 1] == b[j - 1] ? 0 : 1);  // 替换（相同则 0 代价）
            dp[i][j] = min({del, ins, rep});
        }
    }
    cout << dp[n][m] << endl;
    return 0;
}

    坑：编辑距离的边界是全删全插（不是 0！）。如果边界写成 0，空串变非空串会被算成 0 步，答案全错。

    复杂度分析：O(n·m) 时间空间。n=m=1e4 时 1e8 状态，内存吃紧，竞赛中常见优化是滚动数组（只保留上一行）降到 O(m)。

    复杂度总结¶

    算法 时间 空间 适用
    LIS 朴素 O(n²) O(n) n ≤ 5000
    LIS 优化 O(n log n) O(n) n ≤ 1e5+
    LCS O(nm) O(nm)（可滚到 O(m)） n,m ≤ 5000
    编辑距离 O(nm) O(nm)（可滚到 O(m)） n,m ≤ 5000
