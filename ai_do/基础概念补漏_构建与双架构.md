## 一、Makefile 是干嘛的

### 它是什么

一个**纯文本**文件，文件名就叫 `Makefile`（或 `makefile`），写给 `make` 这个命令行工具看。

里面每一条规则长这样：

```
kernel-rv: main.c mm.c trap.c
	gcc -o kernel-rv main.c mm.c trap.c
```

- 冒号**左边**：要产出的东西（叫「目标」target）
- 冒号**右边**：它依赖哪些文件（dependencies）
- 下面缩进的一行：怎么把它造出来（recipe）
- ⚠️ **缩进必须是 Tab，不能是空格**——这是 make 最经典的坑，用空格会报 `*** missing separator`。

### 为什么要它（两个理由）

**理由 1：省事。** 一个内核几百个源文件，不可能每次手敲一长串编译命令。而且 make 会比对时间戳，你只改了一个文件，它就只重新编译受影响的那几个，不用全量重编。

**理由 2（比赛里真正重要的）：它是接口约定。**

评测机拿到你的项目，只会做一件事：进到项目根目录，敲一句 `make all`。

```
评测机  ──(只敲 make all)──▶  Makefile  ──▶  产出 kernel-rv + kernel-la
          ▲
          │
   它不会打开你的 IDE 工程，不认识 Cargo.toml / CMakeLists.txt，
   也不会帮你装依赖
```

所以哪怕你实际用 CMake、用 Cargo、用 Bazel，也**必须**在最外层写一个 Makefile，让 `all` 这个目标去调用你真正的构建系统。

**一句话类比**：评委面前只有一个「播放」键，按下去整部片子要能从头放到尾。Makefile 就是那个键的接线。

〔源：`testsuits-for-oskernel` pre-2025 分支 README「赛题评测指南」段原文："提交的项目根目录中必须包含一个 Makefile 文件，并且可以通过 make all 命令……生成 ELF 格式的 kernel-rv 和 kernel-la 两个文件"〕

### 常见目标名

```
make          不加参数时执行第一个目标
make all      约定的「构建全部」（比赛要求必须有）
make clean    删掉所有编译产物
make run      编译 + 启动模拟器（很多 OS 项目自己约定）
```

〔常识，非本次查证的官方原文〕

## 二、操作系统用什么写的

### 内核本体：只有 C 和 Rust 两个现实选项

| 语言   | 例子                                        | 说明                         |
| ---- | ----------------------------------------- | -------------------------- |
| C    | RT-Thread、Linux                           | 传统选择，2025 官方 base OS 例子之一  |
| Rust | ByteOS、DragonOS、asterinas、**starry-next** | 新趋势，2025 官方 base OS 例子里占多数 |

〔源：`os-competition-info/ref-info-2025.md` 列出的 base OS 例子。其中「RT-Thread 是 C」「其余四个是 Rust」属常识性事实，不是该页原文〕

### 为什么不能是 Python / Java / Go

因为内核**下面没有别人了**：

- 它得自己管内存 —— 没有另一个程序帮它做垃圾回收
- 它得直接读写硬件寄存器 —— 高级语言没有这种语法
- 它得开关中断、设置页表、保存/恢复寄存器 —— 这些都要精确控制到指令级
- 它不能依赖运行时（runtime）—— 因为运行时本身需要 OS 提供服务

带 GC 和虚拟机的语言干不了这活。〔常识〕

### 但一个「OS 工程」里不只一种语言

```
C 或 Rust      内核主体
汇编            开机启动那段、上下文切换、开关中断（C 里嵌不下的部分）
Makefile/shell  构建、测试、跑 QEMU
链接脚本        决定内核被加载到内存的哪个地址
设备树/配置文件 描述硬件长什么样
```

〔常识，依据《StarryMix_导读》中提到的 Rust + 少量汇编 + 构建脚本的工程形态〕

## 三、kernel-rv 和 kernel-la 是什么

### 字面意思

- `rv` = **RISC-V**（读作 risk-five，开源指令集）
- `la` = **LoongArch**（龙芯自研指令集）
- `kernel-rv` = 给 RISC-V CPU 用的内核二进制
- `kernel-la` = 给 LoongArch CPU 用的内核二进制

### 为什么一份源码要编两次

**源码 ≠ 二进制。**

```
源码    = 逻辑，给人看、给编译器看。进程怎么调度、VFS 怎么分层，
          这些跟 CPU 是哪家的没关系 → 写一遍
二进制  = CPU 能直接执行的机器指令。RISC-V 的机器码，
          LoongArch 的 CPU 读不懂 → 必须分别"翻译"两次
```

**类比**：一份菜谱（源码），翻成中文和英文两个版本（两个二进制），给两个说不同语言的厨师看。菜谱内容一样，成品必须有两份。

### ELF 是什么

ELF（Executable and Linkable Format）是 Linux 下**可执行文件和目标文件的标准封装格式**，相当于 Windows 的 `.exe`。

你在自己电脑上 `gcc main.c -o a.out` 编出来的 `a.out`，就是一个 ELF 文件。所以「生成 ELF 格式的 kernel-rv」这句话没什么神秘的，意思就是"编出一个能被加载执行的内核文件"。〔常识〕

### 为什么要两个都交（官方理由）

2025 内核赛道**明确要求内核同时支持 RISC-V64 和 LoongArch64**。所以 `make all` 必须一次把两个都编出来，缺一个就不满足要求。

> 原文："参赛队实现的内核要求支持RISC-V64 & LoongArch64"  
> 〔源：`os-competition-info/ref-info-2025.md`〕

### 这里有个词叫「交叉编译」

你在 x86 的笔记本上写代码、编译，但编出来的东西是给 RISC-V / LoongArch 跑的。**编译的机器 ≠ 运行的机器**，这就叫交叉编译（cross-compilation），用的编译器叫「交叉编译工具链」（如 `riscv64-linux-gnu-gcc`）。

这也是为什么官方要提供 Docker 镜像——里面把两个架构的 QEMU 和工具链都装好了（QEMU 版本 9.2.1，两个架构都是）。  
〔源：测试集 pre-2025 分支 README 中 Docker 容器内的 `qemu-system-riscv64 --version` / `qemu-system-loongarch64 --version` 输出均为 9.2.1〕

## 四、顺带搞懂：源码能共用多少？哪些必须分开写？

这是理解「支持多架构」的关键，也是理解 Starry Mix 架构的钥匙。

```
【架构无关，只写一份】
  进程管理、调度算法、文件系统与 VFS、网络协议栈、信号处理、系统调用表

【架构相关，必须每个架构写一份】
  页表格式与地址翻译、中断控制器（PLIC / 龙芯的中断控制器）、
  开机启动汇编、上下文切换时保存哪些寄存器、
  系统调用陷入指令（RISC-V 是 ecall，LoongArch 是 syscall）
```

**工程做法**：把「架构相关」的那部分单独抽成一层，上层只跟这一层打交道。这样新增一个架构时，只需要补这一层。

**连回 Starry Mix**：它四层架构里的 `axhal`（硬件抽象层，在 ArceOS modules 那一层）干的就是这件事。它决赛文档**新增了「硬件抽象层」一整章**（第 4 章），还新增了「物理设备支持」一章（第 12 章，VisionFive 2 和 2k1000la 两块开发板）——这正好对应「把硬件差异隔离出去，才能上真板子」。  
〔源：`final.pdf` p6-7 架构图；决赛文档目录第 4 章「硬件抽象层」、第 12 章「物理设备支持」〕

## 六、如果周日被问到，怎么说

**问：Makefile 是干嘛的？**

> 给 make 工具看的构建脚本。比赛里它是必须的，因为评测机只会在项目根目录执行 `make all`，然后用产出的 `kernel-rv` 和 `kernel-la` 去跑测试。不管你内部用什么构建系统，外层都得包一个 Makefile。

**问：kernel-rv 和 kernel-la 是什么？**

> 同一份内核源码，用两套交叉编译工具链编出来的两个二进制。rv 是 RISC-V，la 是 LoongArch，因为赛道要求两个架构都支持。ELF 就是 Linux 下可执行文件的标准格式，跟 .exe 一个意思。

**问：操作系统用什么写的？**

> 内核本体是 C 或 Rust，因为内核要自己管内存、直接操作硬件、开关中断，带 GC 的语言干不了。2025 官方给的 base OS 例子里 RT-Thread 是 C，ByteOS、DragonOS、asterinas、starry-next 都是 Rust。
