## proj4（多智能体协作技术）实现方案

鱼汤问「功能挑战赛赛题四怎么实现」，产出 `ai_do/proj4_多智能体协作实现方案_2026-10-25.md`。

核对的一手事实（AIOS / Cerebrum 官方仓库与文档，2026-10-25 查阅）：

- AIOS kernel 是 OS 内核之上的资源抽象层，管 LLM Core / Context / Memory / Storage / Tool / Scheduler，**不是 Linux 内核**。
- **AIOS 官方没有多智能体编排、agent factory 或 agent 通信 API**；Cerebrum 能力边界是 agent 的开发/部署/分发/发现。所以「协作编排器」必须由参赛队自己写，这是本题的参赛增量。
- Agent 硬性规则：继承 `cerebrum/agents/base.py` 的 BaseAgent、必须有 `run()`、所有与 kernel 交互必须走 `send_request`。
- Python 仅支持 3.10 / 3.11；模型后端 vLLM（仅 Linux+GPU）或 ollama；配置文件 `aios/config/config.yaml`，Cerebrum 侧 host/port 须与 kernel 一致。

关键判断（已写进文档）：**绕开 kernel 直连 vLLM/ollama 就拿不到 AIOS 的调度收益，20% 提速指标基本测不出来**。agent 间通信建议走 memory/storage API，不要自己开 socket，否则退化成普通多线程程序。

场景沿用「软件项目故障诊断与复现验证」：4 类 agent（日志/源码/配置/测试复现），L1 四个并行子任务 + L2 三对双向交互 + L3 汇总。20% 基线是**多智能体串行**，不是单智能体。
