- 本轮抓到的硬事实（源：测试集 pre-2025 README 全文，用 raw.githubusercontent 直取可读完整版）：
  - **QEMU 完整启动命令原文**（riscv64 与 loongarch64 各一条）：用 `-kernel {os_file}` 加载内核，**不是**放磁盘镜像；`-drive file={fs}` 是官方测试盘（EXT4 无分区表，根目录放 12 组测试点 + `xxxxx_testcode.sh`）；`-drive file=disk.img` 是选手可选辅助盘；`-nographic` 说明"屏幕输出"就是串口文本，不用写显卡驱动。
  - **Docker 镜像内的工具链版本表**：riscv64-unknown-elf-gcc 8.2.0（裸机编内核）/ riscv64-linux-gnu-gcc 11.4.0 / riscv64-linux-musl-gcc 11.2.1 / buildroot 版 10.2.0 / loongarch64-linux-gnu-gcc 13.2.0 / loongarch64-linux-musl-gcc 13.2.0；cargo 1.86.0-nightly；rustup targets 含 riscv64gc-unknown-none-elf、loongarch64-unknown-none 等。
  - 构建流程原文：`make docker` 进容器 → `make` 构建评测样例和 SD 卡镜像。
- 关键教学结论：工具链命名 `arch-vendor-os-abi`（看到 `unknown-elf` = 裸机）；链接脚本必须写死地址是因为内核开机时无 OS、QEMU `-kernel` 不做重定位（写错症状是静默卡死）。
