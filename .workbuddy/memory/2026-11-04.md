- 字幕 053 原话已核实：「看它的左右两个儿子……取一个大的……跟我做比较」「再看左右儿子里面大的那个」。笔记 §一.3 原本写了"挑较大者"，但**没解释为什么**，也没区分定义与算法，正是疑问的来源。

- 实测数据（C++ 跑过）：`H[1..6]=[100,70,90,30,50,20]` 本身合法（左 70 < 右 90），删根后 `temp=20`：挑 90 → `[90,70,20,30,50]` 合法；只看左孩子 / 挑较小 70 → `[70,30,90,20,50]`，根 70 < 右孩子 90，破坏且**不报错**。注意第一版用的 `temp=80` 演示不了"较小孩子真上提"（80>70 会直接 break），换 20 才两种错法都显形。
- 边界：`Child != Size`（只有左孩子）时无需比较，它就是唯一候选；上滤没有这一步，因为路径上无兄弟。
- 顺带点明定义层：堆序只约束父子链，与 BST「左小右大」是两类约束，故堆只能 O(1) 取最大值、不能按值查找。

## 数据结构：BST vs 最小堆 选择题（答案 D，她错选 B）

题：由同样 n 个整数构成的 BST 与最小堆，哪个说法**不正确**。A BST 高度 ≥ 最小堆高度；B BST 中序升序；C 最小堆根到任一叶路径递增；D 最小堆层序升序。正确答案 D，她选 B。

- **她错选 B 的根因**：把题干的"同一批数构成的两棵树"读成了"同一棵树同时是 BST 和堆"，又把两种结构的遍历性质串了。B 是 BST 定义的直接推论（中序严格递增是充要条件，05b §一.1 已写），与插入顺序无关。
- **D 的反例**（脚本验过）：最小堆 `H[1..5]=[1,2,3,5,4]` 合法（1≤2,3；2≤5,4），层序输出 `1 2 3 5 4`，5>4 非升序。**数组下标只是层序编号，不是排序结果**——这是堆用数组存储带来的典型错觉。最小反例只要 3 个数 `[1,3,2]`。
- **A 的理据**：最小堆必为完全二叉树，高度 ⌊log₂n⌋+1 是 n 结点二叉树的最小可能高度；BST 只能更高，最坏 n 层斜树。枚举 n=1..7 的全部二叉树形状，高度最小值都等于完全二叉树高度，不等式恒成立，与数值无关。
- **C** 是定义直述（父 ≤ 子 ⇒ 路径非递减）。
- 细节：若 n 个整数允许重复，B/C 的"从小到大"应读作非递减/非严格；这类题默认互异，不必在笔记里展开。
