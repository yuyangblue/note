# 笔记库项目约定

## 示例代码一律用 C++（鱼汤 2026-10-29 明确：她不会 C）

数据结构等课程讲义里的示例代码**统一写成 C++**，不要写 C。课件原码多为 C，改写时对应规则：

- `typedef struct X { ... } X;` → `struct X { ... };`（C++ 里标签名就是类型名，不必重复 typedef）
- `typedef struct TreeNode *BinTree;` → `using BinTree = TreeNode*;`
- `malloc(sizeof(T))` → `new T`（失败由异常接管，不必判空）
- `free(p)` → `delete p`；数组用 `new[]` / `delete[]`
- `printf` / `scanf` → `cout` / `cin`，文件顶部加 `#include <iostream>` 与 `using namespace std;`
- 需要 `strlen` / `strcpy` 时加 `#include <cstring>`
- 代码围栏语言标记写 ` ```cpp `，不要写 ` ```c `

例外：课件里刻意给出的**伪代码**（描述算法流程而非可直接编译的代码）保留为 ` ```text `，并在正文说明"伪代码"。

## 往已有笔记里增补内容时：必须贴合原文风格（鱼汤 2026-10-20 明确指出）

增补不是「贴补丁」，要长进原文的结构和语气里。踩过的坑与正确做法：

1. **编号体系不能破坏**。原文是 `### 序号. 主题` 的连续编号（如 04-字符串 §三：1. BF / 2. KMP / 3. BM与KR）。新增内容要么并入已有小节，要么顺延编号；**不要**插入 `### 3. 补充：xxx` 把后面的挤成 `### 4.`，也不要在 `###` 下堆 `#### 补充：xxx`。
2. **引导词只用原文已有的那几个**：`注意：`、`规则：`、`思路：`、`**概念**`、`**动机**`。不要自创「**易错**」「**核心不变式**」「**长度 vs 空间**」「**手算步骤**」「**常见坑**」这类标签。
3. **位置要符合阅读逻辑**。定义类的补充（如另一套 next 约定）放在**定义处**与原文定义并列，不要放到算法之后才说「还有另一套」。
4. **不要口语化**。禁止「白比一次」「看花眼」「整整差一位」「无脑法」这类表达。
5. **引用块 `>` 原文只用在头尾**（头注、本节重点），正文中间不要用。
6. 段落引导用加粗短语 + 列表时，对齐原文写法，如 `**字符串的 ADT**：` + 列表、`**终止符与存储约定**：` + 列表。

## 插图与文案：怎么让笔记更易懂（2026-11-03/04 反复验证）

**总判据：加东西的标准是「它有没有携带文字给不出的信息」，不是「这段内容难不难」。** 14 张新画的图留 8 张；被否的 6 张都不是画得丑，而是把一句现成的话又画了一遍。

**值得画（图里有「一处到另一处」的关系）**：

- 带轨迹/路径：蛛网折线、压缩映像的像落回域内、正交投影的垂直关系
- 带过程/次序：LU 的 `min(i,j)` 推进次序、局部收敛里 δ 怎么定出来
- 带真实数据对比：Steffensen 的 φ 在 x\* 处是平的，而 cos 是斜的
- 带量级/面积对比：Cholesky 省掉的半个上三角

**不值得画**：把一句文字直译成图（单位球、两条近平行线）／教材标配插图（谱半径单位圆）／公式已写全、图只补一句对应（三对角结构）／按公式拟出的曲线。

**两条硬规矩**：

- **先问这一节有没有天然几何结构**。Aitken 是纯代数构造（二阶差商），画了又删——画成任何图形都只能是公式的图形化。
- **曲线必须真算，不能按公式拟**。CG 收敛曲线当时直接取 `k·log₁₀((κ−1)/(κ+1))`，那是「界」不是实测，读图等于重读式子。

**证明补动机**（鱼汤认可，已铺 5 处）：开头一句「整段只做一件事」把目标说破 + 每步三字动作名（先展开／再除／控制右端）+ 破折号接一句为什么这么做。

**算例用「同一道题横向对照」**：五种方法、一个方程、一个初值，各走三步放一张表；表下只写数字本身给出的结论（如 Aitken 与 Steffensen 第 1 步完全相同），不复述表格。

**被否的三类噪音，不要主动加**：总览／导航表（开场引言已够）、「记住这个」小节、章末易错清单。

**删图必查四类依赖**：`![[...]]` / `![](...)` 引用、「上图／下图／图上」方位词、指向图的引导句（「把网格和矩阵并排摆起来：」）、「板书画了…／板书右侧…」这类**描述来源物**的句子。第四类最容易漏——图删了，句子还悬空（鱼汤 2026-11-03 点名的就是这种）。

**去重原则**：定义各留一处、证明各留一处；向量版／推广版只标注「这是定理 X 的向量版」，不重写。

## 笔记目录（2026-10-28 起；数据结构、数值分析、计算方法与优化已铺开）

每篇正文笔记顶部都放可跳转目录，格式固定：

```
## 目录

- [[#二级标题全文]]
  - [[#三级标题全文]]

---
```

位置在头部引用块之后、第一个 `##` 之前；二级用 `- `、三级用两空格缩进；末尾一条 `---` 与正文分隔。只列到三级，`#### 随堂练习` 不进目录。

- **标题必须全篇唯一**。`[[#标题]]` 只匹配第一个，而 MkDocs 会给重复 slug 加 `_1` 后缀、hook 不会，重名等于死链。所以平行结构（顺序串/链式串、堆栈/队列）的小节名要带限定，如 `### 1. 结构定义（顺序串）`。
- **标题里不能出现裸 `|`**。wikilink 把 `|` 当别名分隔符，`## 4. 收敛速度：比值 $|\lambda_2/\lambda_1|$` 的目录条目会被截成 `比值 $` 而变死链。数学里的绝对值写 `\lvert … \rvert`（与表格里 `\|` 破坏表格是同一类问题）。
- **目录条目必须逐字复制标题**（含 `$`、`（2）` 这些符号），不能口语化改写。写 `2.2 为什么 n 个方程…` 而标题是 `$n$ 个方程` 时 slug 不匹配，同样死链。
- 新建笔记时顺手加目录；判断依据是有没有值得跳转的长度，40 行两节的短文件不必加。

## 站点发布机制（MkDocs，2026-10-26 起）

根目录是 Obsidian vault，`docs/` 是发布目录（`.gitignore` 忽略 `docs/*/`，副本不入库），CI 在 `.github/workflows/deploy.yml` 里把课程目录 `cp` 进 `docs/<分区>/` 再构建。

- **新课程上线三件事**：deploy.yml 加 `cp -r`；`hooks/exclude_raw.py` 的 `COURSE_ICONS`/`COURSE_DESCS` 加条目；`docs/index.md` 的统计数字改一下。
- **不要手动往 `docs/<分区>/` 里拷单个文件**：那份副本只是本地预览缓存，`docs/*/` 被 gitignore、CI 每次重新 `cp -r`。而且它停留在旧命名（`第01讲-基本概念.md` 等），与根目录现在的 `01-绪论.md` 编号体系已经脱节，单独拷一个进去只会新旧混杂。要本地预览就重建整个课程目录。（2026-10-27 核实：`临时作业/_sync_docs.py` 只负责把「概率论MIT」「统计学完全教程」同步到 `docs/数学/`，**其它课程与它无关**。）
- **`[[wikilink]]` 由 `hooks/exclude_raw.py` 的 `on_page_markdown` 解析**（roamlinks 已移除）：支持路径/锚点/别名/同页锚点/`![[图片]]`，跨分区按路径后缀匹配。锚点 slug 规则是 `re.sub(r"[-\s]", sep, s)`（逐个替换，**不是 `+`**），见当日日志。**⚠️ 存疑（2026-11-02）**：markdown 3.10.2 官方 slugify 是合并的（`[-\s]+`），实测 19 个带 `+`／`·`／`→` 的标题两种算法差一个连字符；改 hook 前必须先用线上页面的真实 `id` 复核，别凭日志里的推断动手。
- 原始材料不发布，但**正文 `![[...]]` 引用到的图片会放行**（`is_raw` + `collect_embeds`）。
