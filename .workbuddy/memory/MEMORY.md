# 笔记库项目约定

## 代码与增补风格

**示例代码一律写 C++**（她不会 C）。课件原码多为 C，改写规则：`typedef struct X {...} X;` → `struct X {...};`（C++ 标签名即类型名）；`typedef struct T *P` → `using P = T*;`；`malloc/free` → `new/delete`（数组 `new[]/delete[]`，失败由异常接管不判空）；`printf/scanf` → `cout/cin` + `<iostream>` + `using namespace std;`；要 `strlen/strcpy` 加 `<cstring>`；围栏写 ` ```cpp `。课件刻意给的**伪代码**保留 ` ```text ` 并注明「伪代码」。

**增补不是贴补丁，要长进原文的结构和语气里**：

1. **编号体系不能破坏**。原文是 `### 序号. 主题` 连续编号时，新增并入已有小节或顺延；不要插 `### 3. 补充：xxx` 把后面挤走，也不要在 `###` 下堆 `#### 补充：xxx`。
2. **引导词只用原文已有的**：`注意：`、`规则：`、`思路：`、`**概念**`、`**动机**`。不自创「**易错**」「**核心不变式**」「**长度 vs 空间**」「**常见坑**」这类标签。
3. **位置要符合阅读逻辑**：定义类补充放**定义处**与原文并列，不要放到算法之后才说「还有另一套」。
4. **不口语化**：禁「白比一次」「看花眼」「整整差一位」「无脑法」。
5. **引用块 `>` 只用在头尾**（头注、本节重点），正文中间不用。
6. 段首用加粗短语 + 列表时对齐原文写法，如 `**字符串的 ADT**：` + 列表。

## 插图与配文

**总判据：它有没有携带文字给不出的信息**，不是「这段难不难」。14 张图留 8 张，被否的都不是画得丑，而是把一句现成的话又画了一遍。

- **值得画**：带轨迹（蛛网、压缩映像的像落回域内、正交投影的垂直关系）／带过程次序（LU 的 `min(i,j)` 推进、δ 怎么定出来）／带真实数据对比（Steffensen 的 φ 在 x\* 处是平的而 cos 是斜的）／带量级对比（Cholesky 省掉的半个上三角）。
- **不值得画**：把一句话直译成图（单位球、两条近平行线）／教材标配插图（谱半径单位圆）／公式已写全只补一句对应（三对角结构）／按公式拟出的曲线。

**两条硬规矩**：**先问这一节有没有天然几何结构**（Aitken 是纯代数构造，画了又删）；**曲线必须真算**（CG 收敛曲线曾按误差界公式画，那是「界」不是实测，读图等于重读式子）。

**证明补动机**：开头一句「整段只做一件事」把目标说破 + 每步三字动作名（先展开／再除／控制右端）+ 破折号接一句为什么这么做。

**算例用「同一道题横向对照」**：多法一方程一初值各走几步放一张表，表下只写数字本身给出的结论，不复述表格。

**不要主动加的三类噪音**：总览／导航表、「记住这个」小节、章末易错清单。

**删图必查四类依赖**：`![[...]]` / `![](...)` 引用、「上图／下图／图上」方位词、指向图的引导句、「板书画了…／板书右侧…」这类**描述来源物**的句子——第四类最易漏，图删了句子还悬空。**去重**：定义各留一处、证明各留一处，向量版只标注「这是定理 X 的向量版」。

**枝节压到一段为止**：判据同样是「是否改变读者对主线的理解」。可压四类——课堂问答轶事、历史来龙去脉（除非解释某个设计选择）、商业运营背景、与主线无关的名词补充。压法是保留**概念定义** + 它在主线里的位置，其余删净（网络 01 篇 P2P 由 45 行压成 3 段即模板）。

## 内容边界与来源

**按教材范围补充，不越界**（她会明说「不要超出教材范围」）：补的内容必须在教材对应小节找得到出处；**教材只提一句的不要展开**；**下一章的内容不提前写**；但教材的小节标题、旁注、图注都可以进。

**单一来源不能写成定论**：板书／手写稿／转写稿都是二手记录。课堂口述若在另一份材料无从交叉核对，正文要写「按 X 补全」「只有 X 一个来源，不能断言等于课上原题」，区分「直接读到的／反推的／不知道的」，禁止「记下了原题」「课上照讲」。反例：曾把学生笔记里的自洽常数写成课上真题。

**来源标注**：头部引用块加一行（课件 + B站视频链接 + BV 号），不另起「附录」；交叉引用用相对路径式写法（「详见 `OI-Wiki/字符串/基础.md`」）。

## 分篇与目录

一级编号按**主题**切，不按课次。课次信息（日期、录音稿路径、板书张数）只写进头部引用块——一旦与分篇绑定，一节课讲两件事就会塞进一篇。三条重分症状：**标题覆盖不了正文前三成**；**定义在某篇、证明在另一篇**且互相写「证明见 X §N」；一篇塞四五个主题，或两篇各有一段同构复述。

搬迁同步四样（漏一样出死链）：两篇目录、被搬内容的内部自指节号、其他篇的「§N」引用、索引里按篇写的摘要。搬完专扫两类残留：**文件内自指本篇号**、**悬空「例 N」**。

**目录格式**：位置在头部引用块之后、第一个 `##` 之前；只列到三级，`#### 随堂练习` 不进；40 行两节的短文件不必加。

```
## 目录

- [[#二级标题全文]]
  - [[#三级标题全文]]

---
```

- **标题全篇唯一**：`[[#标题]]` 只匹配第一个，重复 slug 在 MkDocs 会加 `_1` 而 hook 不会，重名等于死链。平行结构要带限定，如 `### 1. 结构定义（顺序串）`。
- **标题里不能有裸 `|`**：wikilink 当别名分隔符，绝对值写 `\lvert … \rvert`。
- **表格单元格同样不能有裸 `|`**（曾全库 22 处中招，症状是表头被切、整表错列）：数学内写 `\lvert…\rvert` 或 `\vert`，**不能写 `\|`**（数学里 `\|` 是范数 ‖，会改语义）；代码 span 与纯文本写 `\|`。
- **目录条目逐字复制标题**（含 `$`、`（2）`），口语化改写即 slug 不匹配。

**改 pptx 文字的坑**：一句话常被拆成多个 `<a:r>`，要按 `<p:sp>` 拼全文再按字符区间回写（译文进第一个 run 保颜色，中间置空，末尾留剩余）；`<a:p>` 不一定包裹 `<a:r>`（老格式用空 `<a:pPr/>` 分段），必须按 `<p:sp>` 切；自闭合 `<a:t/>` 要用 `<a:t((?:\s[^>]*[^/>])?)>`，宽松正则会把整段 XML 当文本。只做整块精确匹配，绝不做子串替换（会误伤 `int`、`struct`、`perror`、`MI`/`ALU`/`USB`、`100 Mb/s`、代码与人名）。

## 站点发布（MkDocs）

根目录是 Obsidian vault，`docs/` 是发布目录（`docs/*/` 被 gitignore，副本不入库），CI 在 `.github/workflows/deploy.yml` 里把课程目录 `cp` 进 `docs/<分区>/` 再构建。

- **新课程上线三件事**：deploy.yml 加 `cp -r`；`hooks/exclude_raw.py` 的 `COURSE_ICONS`/`COURSE_DESCS` 加条目；`docs/index.md` 统计数字改一下。
- **不要手动往 `docs/<分区>/` 拷单个文件**：那只是本地预览缓存，CI 每次重建，且它停留在旧命名（`第01讲-…`），与新编号体系脱节，单拷一个只会新旧混杂。要预览就重建整个课程目录。（`临时作业/_sync_docs.py` 只管「概率论MIT」「统计学完全教程」，其它课程与它无关。）
- **`[[wikilink]]` 由 `hooks/exclude_raw.py` 的 `on_page_markdown` 解析**（roamlinks 已移除）：支持路径/锚点/别名/同页锚点/`![[图片]]`，跨分区按路径后缀匹配。锚点 slug 用 `re.sub(r"[-\s]", sep, s)`（逐个替换，不是 `+`）。**⚠️ 存疑**：markdown 3.10.2 官方 slugify 是合并的 `[-\s]+`，实测带 `+`／`·`／`→` 的 19 个标题两种算法差一个连字符；改 hook 前必须用线上页面真实 `id` 复核，别凭推断动手。
- 原始材料不发布，但正文 `![[...]]` 引用到的图片会放行（`is_raw` + `collect_embeds`）。
