- 内容：可重集合（重数 $m(x)$，与普通集合的差别只在重数；优先级可重复，普通集合会挡掉第二个同优先级元素）；严格弱序四条性质（非自反/非对称/传递/不可比较的传递性，第四条是"弱"的来源，保证 $\approx$ 是等价关系、等价类间导出全序）；动机（局部堆序推不出全局最小，除非"相等"可传递）；两个反例（`<=` 违反非自反使 sort 越界；NaN 使 $1\approx\text{NaN}\approx2$ 但 $1<2$，违反第四条）；C++ 比较器代码（相等必须返回 false）。

## highlight 报错修复（11-24）

- 鱼汤控制台报 `Uncaught TypeError: (0, import_components.default) is not a function` at highlight → rules.fence → buildTree → transform。根因：markmap-lib 的 ESM 代码 `import loadLanguages from "prismjs/components/"`，esbuild 把 `prismjs/components/` 解析成了 `components.js`（大 JSON 数据表，导出对象）而非 `components/index.js`（导出函数），`__toESM` 包装后 `.default` 不是函数。
- 修法：不跟构建工具的 CJS 互操作纠缠，直接 patch 打包产物 main.js 里那一行，加 `typeof === function` 判断 + try/catch 兜底。代价：新增语言的高亮加载失效（内置语言如 c/cpp/js 仍高亮），图本身正常。esbuild alias 语法试错过，不可用。
- **经验**：老插件用 esbuild 重编遇到 CJS/ESM 互操作报错，直接用字符串 patch 产物比调 alias 快；patch 前先 grep 定位那一行、patch 后 node --check。
