## 1. 回顾：为什么 0/1 倒序、完全正序

### 大白话

这是背包 DP 的"灵魂问题"。课堂上老师专门用滚动数组推了一遍：

0/1 背包的二维状态 `dp[i][j]`（考虑前 i 个物品、重量恰为 j 的最大价值）只依赖**上一行** `dp[i-1][...]`。滚掉第一维后，**倒序遍历** j 是为了保证：更新 `dp[j]` 时用到的 `dp[j-w[i]]` 还是**上一轮**（没取过当前物品）的值。

- 倒序：`dp[j] = max(dp[j], dp[j-w[i]] + v[i])` 用的全是"旧值" → 每个物品最多取一次 ✅
- 正序：`dp[j-w[i]]` 可能已经是**本轮**更新过的 → 同一物品被反复取 → 恰好变成完全背包 ✅

**一句话记忆**：
- 倒序 = 每个物品只给一次机会（0/1）
- 正序 = 每个物品无限续杯（完全）

### 常见坑

| 坑 | 现象 | 原因 |
|----|------|------|
| 0/1 写成正序 | 答案偏大 | 物品被重复选取 |
| 完全写成倒序 | 答案偏小 | 每个物品只能用一次了 |
| 滚动数组没留旧值 | 覆盖后数据错乱 | 更新顺序不对 |

## 2. 混合背包

### 大白话

三种背包混在一起：有的物品只能拿一次（0/1），有的能拿无限次（完全），有的最多拿 c[i] 次（多重）。像逛超市：酸奶买一送一只能拿一次、饮料无限拿、鸡蛋限购 3 盒。

### 核心思路

不用新算法，**在 DP 循环里按物品类型分流**：

| 物品类型 | 处理方式 |
|---------|---------|
| 0/1 | 倒序枚举容量 |
| 完全 | 正序枚举容量 |
| 多重 | 先二进制拆分，再当 0/1 做（倒序） |

### 代码

```python
def knapsack_mixed(V, items):
    """
    混合背包
    items: [(w, v, type, c), ...]
      type = 0 → 0/1 背包（c 忽略）
      type = 1 → 完全背包（c 忽略）
      type = 2 → 多重背包，最多取 c 个（二进制拆分）
    返回容量 V 的最大价值
    """
    goods = []                     # 把多重物品拆成 0/1 物品
    for w, v, t, c in items:
        if t == 2:                 # 多重：二进制拆分
            k = c                  # 数量
            base = 1
            while k >= base:
                goods.append((w * base, v * base, 0))
                k -= base
                base <<= 1
            if k > 0:
                goods.append((w * k, v * k, 0))
        else:
            goods.append((w, v, t))

    dp = [0] * (V + 1)
    for w, v, t in goods:
        if t == 1:                 # 完全：正序
            for j in range(w, V + 1):
                dp[j] = max(dp[j], dp[j - w] + v)
        else:                      # 0/1（含拆分后的多重）：倒序
            for j in range(V, w - 1, -1):
                dp[j] = max(dp[j], dp[j - w] + v)
    return dp[V]
```

**坑**：多重背包物品**必须先拆分再进循环**，不能在循环里边拆边更新，否则拆出来的"同一个物品的多份"互相干扰。

## 3. 二维费用背包（多维背包）

### 大白话

每个物品有两个"费用维度"，背包也有两个容量限制。比如物品既占重量又占体积，背包既限重又限体积。像搬家：货车既限重量又限体积，每件家具两个都得塞得下。

### 核心思路

状态多加一维：`dp[j][k]` = 第一个费用总和为 j、第二个费用总和为 k 时的最大价值。

**转移**：`dp[j][k] = max(dp[j][k], dp[j-w1][k-w2] + v)`

**遍历顺序**（和维度数无关，只看物品类型）：
- 0/1 型：两维容量都**倒序**
- 完全型：两维容量都**正序**
- 三维、四维费用同理：多一个限制就多加一维下标

### 代码

```python
def knapsack_2d(V1, V2, items):
    """
    二维费用背包（0/1 型）
    items: [(w1, w2, v), ...]
    V1, V2: 两个容量限制
    """
    dp = [[0] * (V2 + 1) for _ in range(V1 + 1)]
    for w1, w2, v in items:
        for j in range(V1, w1 - 1, -1):      # 两维都倒序（0/1）
            for k in range(V2, w2 - 1, -1):
                dp[j][k] = max(dp[j][k], dp[j - w1][k - w2] + v)
    return dp[V1][V2]
```

**坑**：完全背包型二维费用要把两个容量循环都改成**正序**，别只改一个。

## 4. 方案数背包（恰好装满）

### 大白话

不求最大价值，求**方案数**：用若干物品恰好凑出重量 W，有多少种选法。比如用 1、2、5 块的硬币凑 10 块有几种凑法。

### 核心思路

状态语义从"最大价值"换成"方案数"：

`dp[j]` = 凑出重量恰好为 j 的方案数

**转移**（0/1 型，倒序）：
```
dp[j] += dp[j - w[i]]          # 不选已有的方案数 + 选了当前物品的方案数
```

初始：`dp[0] = 1`（什么都不选，凑出 0，一种方案）。

### 代码

```python
def count_schemes_01(V, w):
    """
    0/1 方案数背包：恰好凑出 V 的方案数
    """
    dp = [0] * (V + 1)
    dp[0] = 1                                  # 空集方案
    for wi in w:
        for j in range(V, wi - 1, -1):         # 倒序 → 每物品最多一次
            dp[j] += dp[j - wi]
    return dp[V]
```

**坑**：`dp[0] = 1` 是地基，漏了它所有方案数都是 0。完全背包型方案数同样把循环改正序即可。

## 5. 可撤销背包

### 大白话

场景：先对**全部 N 个物品**跑一遍方案数背包，然后来 Q 个询问——每次**强制不能选第 k 个物品**，问还能不能恰好凑出 W、有多少种方案。

暴力做法是每个询问重新跑一遍 O(NV)，Q 大就超时。可撤销背包的妙处：**把加物品的 DP 反过来操作，把第 k 个物品"退回去"**，O(V) 回答一个询问。

### 核心思路

方案数背包的转移是**加法**：
```
dp_new[j] = dp_old[j] + dp_old[j - w[k]]
```
加法可逆，移项即得**撤销公式**（正向遍历 j）：
```
dp_old[j] = dp_new[j] - dp_new[j - w[k]]      # 注意是 dp_new[j - w[k]]
```

**为什么撤销要正序？** 和 0/1 加物品相反：加物品倒序是为了更新时用的全是"旧值"；撤销时我们手里全是"新值"（全量跑完后的 dp），要求回"旧值"，必须正序遍历，让 `dp[j-w[k]]` 用的是**还没被撤销**（新）的值，才能正确把第 k 个物品的影响逐个扣除。

**注意**：这个方法只对**可逆运算**（加法/方案数）有效。max 不可逆，普通最大价值背包的撤销更麻烦，课堂明确没讲。

### 代码

```python
def knapsack_undo(V, w, queries):
    """
    可撤销背包（方案数版）
    queries: [(k, W), ...]  强制不选第 k 个物品，问凑 W 的方案数
    """
    n = len(w)
    # 1. 全量 0/1 方案数背包
    dp = [0] * (V + 1)
    dp[0] = 1
    for wi in w:
        for j in range(V, wi - 1, -1):
            dp[j] += dp[j - wi]

    # 2. 每个询问：临时"撤销"第 k 个物品
    ans = []
    for k, W in queries:
        wk = w[k]
        tmp = dp[:]                            # 拷贝一份操作
        for j in range(wk, V + 1):             # 正序撤销
            tmp[j] -= tmp[j - wk]
        ans.append(tmp[W] if W >= 0 else 0)
    return ans
```

**坑**：撤销循环**必须正序**；写反了会得到错误答案。另外每次询问要拷贝数组，不要在原 dp 上改（否则下次询问的基准就坏了）。

## 6. 输出最优方案

### 大白话

光知道最大价值还不够，题目可能要求你输出**选了哪几个物品**。思路和最短路输出路径一模一样：记录"这个状态是从谁转移来的"，最后倒着还原。

### 核心思路

0/1 背包的 `dp[j]` 只存了一个数字（最大价值）。再开一个数组记录**转移来源**：`pre[j]` = 达到 `dp[j]` 时最后选的是第几个物品（或上个状态的下标 j'）。

还原时从 `j = V` 出发：如果 `pre[j]` 有记录（选了物品 i），把 i 加入答案，`j -= w[i]`，继续往前跳。

### 代码

```python
def knapsack_01_with_path(V, w, v):
    """
    0/1 背包 + 输出方案
    返回 (最大价值, 选中的物品下标列表)
    """
    n = len(w)
    dp = [0] * (V + 1)
    pre = [-1] * (V + 1)                       # pre[j] = 最后选中的物品下标，-1 表示没有

    for i in range(n):
        for j in range(V, w[i] - 1, -1):
            if dp[j - w[i]] + v[i] > dp[j]:
                dp[j] = dp[j - w[i]] + v[i]
                pre[j] = i                     # 记录来源

    # 倒序还原
    path = []
    j = V
    while j > 0 and pre[j] != -1:
        i = pre[j]
        path.append(i)
        j -= w[i]
    return dp[V], path[::-1]
```

**坑**：还原时 `pre[j]` 要跟 `dp` **同步更新**，只更新 dp 忘了记 pre，还原出来就是错的。完全背包的路径记录同理，但每个物品可能多次入选，还原时**不跳下标**只跳容量。

## 7. 拓展：同余最短路 / 依赖背包

这两个课堂只提了一嘴，作为"自己查"的方向：

### 同余最短路（大容量完全背包）

如果容量 V 巨大（比如 1e15），普通完全背包 O(NV) 直接爆炸。把完全背包转成**图论最短路**：以某个物品重量为模数，跑同余最短路求每个余数类的最小可达重量。形式上和背包很像，但解法完全不同。（课堂提到，未展开）

### 依赖背包

物品之间有"先选 A 才能选 B"的依赖关系，本质和**树上 DP** 很像（选父节点才能选子节点）。课堂明确没讲，放到树形 DP 章节再学更顺。

## 8. 本节重点

> - 顺序即语义：0/1 倒序、完全正序，混合背包按类型分流
> - 多一个限制就多一维：二维费用背包，0/1 型全倒序、完全型全正序
> - 方案数背包 `dp[0]=1`，转移用加法；撤销背包是加法的逆运算，**正序遍历**
> - 输出方案：`pre` 数组记来源，倒序还原（思路同最短路输出路径）
> - **常见坑**：
>   - 多重物品没先二进制拆分就进混合背包循环
>   - 二维费用的两个容量循环顺序不一致（一个倒一个正）
>   - 可撤销背包的撤销循环写成倒序
>   - 方案数背包忘初始化 `dp[0] = 1`
>
> 基础四种背包（0/1、完全、多重、分组）详见 **02-背包DP.md**；依赖背包等树形结构见 **05-树形DP.md**。
